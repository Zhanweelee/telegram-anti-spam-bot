# ADR 0091：隐藏转发显示名里的网址只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0025 默认只删除频道转发。隐藏来源的转发会留下。显示名在 `forward_origin.sender_user_name`，旧字段是 `forward_sender_name`。正文可以是一句普通的话，短链只写在这个名字里。

把名字拼进已有正文会改变 `textSha256`。频道标题、作者签名、真实用户的名字和外部回复上的来源不是这条消息自己的隐藏显示名。

## 决策

- 从 `forward_origin.type === "hidden_user"` 的 `sender_user_name`，以及旧字段 `forward_sender_name`，抽出网址，只留主机名。长度、折叠、邀请判断和 8 个主机名的上限不变。现代字段在前。
- 已有正文时，显示名原文不进正文，也不改内容哈希。
- 没有更前面的正文时，第一段非空隐藏显示名整段成为正文，并以此计算 `textSha256`。
- 不读取频道和群的标题、`author_signature`、`forward_from` 的姓名、`external_reply.origin`。隐藏来源这一类仍然不整类删除。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 已有正文时把显示名拼进去 | 显示名会改变哈希。短链只需要主机名。 |
| 隐藏来源整类删除 | ADR 0025 已经放弃。正常聊天里隐藏转发很常见。 |
| 连频道标题一起抽 | 频道转发默认已经删除。标题仍按 ADR 0025 留在事件外面。 |

## 后果

- 已有正文时，隐藏显示名里的 `https://bit.ly/…` 会走现有短链删除。`https://t.me/+…` 和 `https://t.me/%2B…` 只留下 `t.me`，并记成邀请。
- 普通域名仍保留。显示名原文、路径和邀请码在已有正文时不进事件。
- 显示名成为正文时，整段名字仍参与关键词和内容哈希。
- 没有短链的隐藏转发仍然留下。频道标题和真实用户姓名里的网址仍然不读。
