# ADR 0648：送礼的人画出的全名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

有人送出普通礼物、独特礼物或升级购买时，Android 的 `MessageObject` 用 `replaceWithLink` 把送礼的人画在这行服务文字上。这就是 `UserObject.getUserName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。

见 ADR 0599。当时名的长度大于 0 就丢掉姓。空白也算有名。短链可以只写在姓上。附言、收藏名和发布者用户名仍按原来的方式。见 ADR 0087 和 ADR 0324。

名字本身不进正文。关键词不命中这段全名。

## 决策

- 只在已经会标成 `gift` 的提示上，从 `from` 会画出来的全名留主机名。`gift.gift`、`unique_gift.gift` 或 `gift_upgrade_sent.gift` 是对象时读。空的嵌套对象也读。几种同时出现时仍先认普通礼物，再认独特礼物，再认升级购买。
- 名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读。空格不截断。用户名不读。
- 附言、收藏名和发布者用户名仍按 ADR 0087 和 ADR 0324。送礼的人的名字不进正文，也不改内容哈希。关键词因此不命中这个人的名字。短名、编号、星星数量、发布者标题和本群群名不读。
- 空的外层对象、布尔值和只有附言的对象不读发送者。普通消息不读 `from`。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`gift_card` 仍默认关闭。8 个主机名的上限不变。不退回星星。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续只读名 | 客户端把姓画在同一行里。姓上的短链会留在提示里。 |
| 把送礼的人整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0324。 |
| 连礼物上的 `from_id` 一起读 | Bot API 把这个人放在 `from`。这一轮只改已经在读的这一行。 |

## 后果

- 送礼的人全名里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。礼物本身不变，星星不退回。
- 全名原文、路径和用户名不进事件。内容哈希不变。关键词不命中全名。
- 空白名不挡住姓。空格后面的网址仍读。名的主机名排在姓前面。
- 附言、收藏名和发布者用户名仍按原来的方式。短名、编号和星星数量仍不进事件。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 空的外层对象、布尔值、只有附言的对象和普通消息仍不读发送者。本群群名仍不读。干净的卡片在 `gift_card` 关闭时仍留下。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
