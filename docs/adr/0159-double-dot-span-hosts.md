# ADR 0159：空标签前只留高亮主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0152 和 ADR 0158 按 Android `LinkifyPort.WEB_URL` 留下高亮提前停住的主机名。标签之间的句点后面必须再是一个标签。连续两个句点中间是空标签，匹配会停在前一个标签。

`http://bit.ly../x`、`http://bit.ly..` 和 `http://bit.ly..evil.com/x` 打开的是 `bit.ly`。`http://203.0.113.9../x` 打开的是 `203.0.113.9`。整段解析把多出来的句点留在主机名上，`bit.ly..` 和 `bit.ly..evil.com` 对不上短链，`203.0.113.9..` 也不是四段数字。

中间只有一个句点时仍是一整段主机名。`http://bit.ly.evil.com` 打开的是 `bit.ly.evil.com`。`https://t.me../+邀请码` 停在没有路径的 `t.me`，不能把空标签拿掉再读后面的邀请码。

## 决策

- 正文里的 `http` 或 `https` 再取这段高亮的主机名。句点只在后面还能读出一个标签时才算进主机名。否则主机名停在句点前面。只留主机名。
- 整段解析出的主机名仍然保留。两边都走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。最多 8 个。
- 已经写在 `text_link`、按钮或其它结构化字段里的地址整段打开，不按高亮截断。
- 不把停住之后的路径再当成邀请。路径不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 只留整段解析出的主机名 | 点下去打开的是空标签前面的短链或裸 IP。 |
| 把主机名末尾的句点都删掉再匹配 | `bit.ly..evil.com` 的句点不在末尾，删不掉，短链仍会漏掉。 |
| 去掉空标签后再读邀请路径 | `t.me../+邀请码` 打开的是没有路径的 `t.me`。 |

## 后果

- `http://bit.ly../…`、`http://bit.ly..evil.com/…` 和 `http://203.0.113.9../…` 按现有短链或裸 IP 规则删除。证据仍只有主机名。
- `http://bit.ly.evil.com/…` 留着。
- `https://t.me../+…` 不记成邀请。再套一层仍放行。路径不进证据。
- 端口超过五位数字时，高亮停在端口前面。见 ADR 0160。
