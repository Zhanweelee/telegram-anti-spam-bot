# ADR 0331：超长导出取最近的一页

- 状态：已接受
- 日期：2026-11-04

## 背景

ADR 0327 让 `/export` 先计数。最短 JSON 已经超过 3500 字时只回复条数，不再把审计按页读完。大约二十条最短记录就会这样。管理员从 `/logs` 只能看到最近 10 行，其余审计带不出私聊。

`listAudits` 已经返回最近的一页，上限 100。这一页是一条查询，不是按 100 行把全表读完。

## 决策

- 最短完整文档放得下时，仍调用 `exportAudits`，回复完整 JSON，不写 `omitted`。
- 最短完整文档放不下时，不调用 `exportAudits`。用 `listAudits` 取最近最多 100 条，再留下私聊放得下的最新若干条。页内按时间从早到晚。
- 文档在这时增加正整数 `omitted`。它加上本页条数等于这次的计数。计数比读到的行更小时，省略条数不为负。
- 一条审计自己的 JSON 已经超过 3500 字，或列表是空的，仍只回复计数得到的条数。
- 放得下最短长度、实际 JSON 仍超长时，用已经读出的行取最近一页。这条回复的条数以读到的行为准。
- 不改导出的全量顺序，也不改 30 天保留期。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续只回复条数 | 管理员无法带走最近的审计。 |
| 调用 `exportAudits` 再截断 | 全量导出会按页读完。免费计划一次调用只有 50 次查询，读完之前额度就用完了。 |
| 从最早的一条开始截断 | 私聊里更有用的是刚写入的审计。更早的仍算在 `omitted` 里。 |

## 后果

- 完整导出的 JSON 与 ADR 0008、ADR 0327 相同。
- 截断后的文档多了 `omitted`。适配器不用改。
- 计数和列表之间如果有新审计写入，省略条数用的是计数，本页用的是实际读到的最近一行。
