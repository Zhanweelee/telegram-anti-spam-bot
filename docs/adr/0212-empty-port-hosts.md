# ADR 0212：没有主机名的端口不再另记主机名

- 状态：已接受
- 日期：2026-11-03

## 背景

`http://` 后面可以直接写一到五位端口。Android 把 `http://:80/bit.ly/…`、`https://:443?bit.ly/…` 和 `http://:080/bit.ly/…` 收成一条链接。这条链接没有主机名，路径和问号里的短链、裸 IP 和邀请不会再打开。

扫描若从路径里再认裸域名，就会把这条消息删掉。六位数字不是端口，`http://:999999/bit.ly/…` 会单独打开 `bit.ly`。冒号后面没有数字、端口和路径之间有空格，也会单独打开后面的短链。`http://bit.ly:80/…` 仍是短链。

## 决策

- `://` 后面是一到五位端口，并且紧接着 `/` 或 `?`、还没有主机名时，这一段收到路径或问号结束。里面的主机名不另记。
- 六位数字不是端口。冒号后面没有数字时，后面的网址仍单独打开。
- 端口和路径之间的空格仍切开下一条网址。
- 已经有主机名的端口仍留在原网址里。`http://bit.ly:80/…` 和 `http://example.com:80/…` 不改。
- 每段仍走现有的短链、裸 IP、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 路径里的裸域名继续单记 | `http://:80/bit.ly` 会删掉 Android 留成一条无主机名链接的消息。 |
| 六位数字也收进端口 | `http://:999999/bit.ly` 会漏掉单独打开的短链。 |
| 空格也留在这一段 | `http://:80 /bit.ly` 仍会再打开 `bit.ly`。 |

## 后果

- `http://:80/bit.ly/…`、`https://:443?bit.ly/…` 和 `http://:080/bit.ly/…` 留着。
- `http://:80/203.0.113.10/…` 留着。`http://:80/t.me/+…` 不记成邀请。邀请码不进证据。
- `http://:999999/bit.ly/…`、`http://:/bit.ly/…` 和 `http://:80 /bit.ly/…` 仍删除。
- `http://bit.ly:80/…` 和 `https://t.me/+…` 仍删除。`http://example.com:80/bit.ly/…` 留着。路径不进证据。
