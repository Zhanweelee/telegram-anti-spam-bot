# ADR 0077：投票和清单旁边的网址只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0056 让投票题干成为正文，并明确不把选项和说明写进事件。ADR 0057 对清单任务做了同样的取舍。短链可以只出现在选项、测验说明、投票描述或任务文字里，也可以藏在这些字段的 `text_link` 上。链接规则现在看不到。

把这些原文并进正文会改变 `textSha256`，完成者名字和口令也会进事件。

## 决策

- 从 `poll.options[].text`、`poll.explanation`、`poll.description` 和 `checklist.tasks[].text` 里抽出网址，只留主机名。
- 这些字段上的 `text_link` 走同一套解析。长度、折叠、邀请判断和 8 个主机名的上限不变。
- 选项、说明、描述和任务文字不进入 `message.text`，也不参与内容哈希。
- 不读取投票人、添加者、完成者的名字和 id。不读取游戏附加文字。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把选项和任务文字拼进正文 | 正常投票和清单会改掉哈希。ADR 0056 和 ADR 0057 拒绝的就是这个。 |
| 只抽已知短链 | 普通域名会被漏记。现有规则已经会放过普通域名。 |
| 连游戏说明一起读 | 游戏附加文字是另一处字段。这一轮先盖住投票和清单。 |

## 后果

- 选项或任务里的 `https://bit.ly/…` 会走现有短链删除。`https://t.me/+…` 和 `https://t.me/%2B…` 只留下 `t.me`，并记成邀请。
- 普通域名仍保留。原文、路径和邀请码不进事件。
- 题干和清单标题仍按原来的优先级成为正文。选项和任务里的关键词仍然看不到。
- 游戏附加文字里的网址仍不进事件。
