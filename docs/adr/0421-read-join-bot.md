# ADR 0421：私聊可以查看处理入群申请的 bot

- 状态：已接受
- 日期：2026-11-04

## 背景

入群申请可能由另一个 bot 处理。反垃圾要知道是哪一个，才不会和它抢同一条申请。这个信息在 `getChat` 返回的 `ChatFullInfo.guard_bot` 里。字段只对群管理员可见，值是一个 `User`。

`id` 是那个 bot 的编号。`username` 可选。显示名字和其它用户字段不进这次回复。没有这个字段时，不能把它说成已经没有处理 bot。

## 决策

- 私聊命令 `/joinbot <chatId>`。群 id 匹配 `^-?\d{1,20}$`。多出来的参数不发出请求。群聊里的同样文本不执行。
- 配置里的管理员可以看任意群。接入目录里的人只能看自己的群。
- 调用 `ModerationPort.readJoinBot`。适配器调用 `getChat`，只带 `chat_id`。
- 回复三行：群号、bot 编号、用户名。没有 `guard_bot` 时编号和用户名都写未知。有 bot 但没有用户名时写空。
- `is_bot` 不是 true、编号不是正的安全整数、用户名不是 1 到 32 位的字母数字或下划线、或返回的群号和请求不一致时，整份回复是「参数无效」，不露出已经读到的字段。
- 显示名字、标题、邀请链接和其它用户字段不进回复，也不进日志。
- 日志只写 `operator_rejected` 或命令名，带上 eventId、chatId 和命令名 `joinbot`。不写用户名、名字、异常文本或 token。
- 没有 token 的 Worker 不编一份身份。
- 不调用 `setChatPermissions`，也不改黑名单、封禁或禁言。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 没有 `guard_bot` 就写成没有 | 这个字段只对管理员返回。缺字段和明确没有不是同一件事。 |
| 回复里带上显示名字 | 名字可能是原文。编号和用户名够用来对上那个 bot。 |
| 并进 `/guard` | `/guard` 已经是一长串开关。处理 bot 是另一件事。 |

## 后果

- 成功只表示 Telegram 返回了这个群当前的处理 bot，或这个字段没有返回。
- 一次查看是一次 Telegram 子请求。`/guard` 和 `/perms` 仍是各自的 `getChat`。封禁、禁言和黑名单都不变。
- 30 天保留期不动。
