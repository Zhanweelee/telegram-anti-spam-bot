# ADR 0530：私聊可以看到这个群现在接受哪些礼物

- 状态：已接受
- 日期：2026-11-05

## 背景

群可以分别拒绝无限礼物、限量礼物、独特礼物、会员订阅，以及从频道转入的独特礼物。`getChat` 把这五项放在 `accepted_gift_types` 里。`/guard` 已经读这一份 `ChatFullInfo`，但回复里没有它们。

打开 `gift_card` 会删掉礼物卡片。管理员要先知道这个群现在接不接受这些礼物，才知道卡片还会不会继续出现。Bot API 没有改这五项的方法。

## 决策

- `/guard <chatId>` 在付费媒体后面多写五行：无限礼物、限量礼物、独特礼物、会员订阅、频道礼物。
- 整份 `accepted_gift_types` 缺失时，五行都写未知。对象里某一项缺失也写未知。true 写开，false 写关。
- 对象不是普通对象，或某一项不是布尔值时，整份回复仍是「参数无效」，不露出已经读到的字段。
- 不改接受设置，也不把这些开关写进事件。不调用 `setChatPermissions`。
- 不新增命令。菜单仍是 99 条。`gift_card` 仍按 ADR 0481 删除卡片，星星不退回。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 新命令只看礼物 | 菜单已经 99 条。这五项和慢速、付费门槛一样，都是这个群现在的姿态。 |
| 缺对象当成全部关闭 | 旧的 `getChat` 回复和普通群经常不带这份对象。没返回和明确拒绝不是同一件事。 |
| 增加改接受设置的命令 | 公开的 Bot API 没有对应方法。读到的开关不能在这里改掉。 |

## 后果

- `/guard -100` 能看到这个群现在接受哪些礼物。一次查看仍是一次 `getChat`。
- 打开 `gift_card` 仍删除礼物卡片。接受设置本身不变。
- 付费帖仍按原来的规则留下。30 天保留期没有改。
