# ADR 0073：比较前再收一层 %25HH 字母

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0072 把一层 `%HH` 收成字母、数字、连字符或下划线。再包一层写成 `%25HH` 时，比较仍看到百分号。`b%2569t.ly` 对不上短链。`t.me/+OFF%2545…` 的路径仍含 `%2545`，邀请正则认不出。把 `foldEncodedAlphabet` 再跑一遍也没有用，因为先碰到的是 `%25`，它不是字母。

## 决策

- `foldEncodedAlphabet` 在同一趟里先认 `%25HH`。里面的字节必须是字母、数字、连字符或下划线，才收成那个字符。
- 对不上这组字符的 `%25HH` 原样留下。因此 `%252E`、`%2520` 和 `%252F` 仍留下。
- 第三层 `%252545` 和 `b%252569t.ly` 仍留下。
- 链接检测和 `hostFromUrl` 已经调用这个函数，调用点不变。
- 只影响这次比较。正文和哈希不变。证据仍只留主机名。
- 关键词和正则仍只用 `foldMatchText`。
- 不改 ADR 0026 的基础检测器名单。不引入同形字库。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把函数再跑一遍 | `%2545` 的第一段是 `%25`，不是字母，第二遍仍原样。 |
| 把每个 `%25` 都还原成 `%` | `%252E` 会变成 `%2E`，接着被收成点，`bit%252Ely` 会被当成短链。 |
| 放进关键词折叠 | 这些字节不是格式字符。关键词不该因为 `%2545` 改变比较。 |

## 后果

- `b%2569t.ly` 会记成短链。`t.me/+OFF%2545…` 和按钮上的 `https://t.me/+OFF%2545…` 会记成邀请。
- `bit%252Ely`、`b%252569t.ly` 和 `t.me/+OFF%252545…` 仍放过。
- 邀请码不进事件。直接调用 `extractHosts` 的代码仍扫描原字符串。
