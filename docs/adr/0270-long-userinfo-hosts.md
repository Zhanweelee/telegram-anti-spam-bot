# ADR 0270：超长用户信息后面仍留下主机名

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 的网址用户名最多 64 个字符，密码最多 25 个。再长时，这段用户信息配不上，`@` 后面的网址另开一条。

看得见的正文已经这样切。隐藏的分享 `text` 和分享 `url` 把整段交给地址解析，主机名会收成 `http`，后面的短链就漏了。

放得下的用户信息仍是一条网址。写在另一条网址路径里的同样字符串也不另开。

## 决策

- 分享 `text`、分享 `url`、私聊预填 `tg://msg` 的 `text` 和用户名草稿的 `text`，在 `http://` 或 `https://` 后面数用户名和密码。
- 用户名超过 64，或密码超过 25，并且后面是 `@` 时，从 `@` 后面另抽网址。
- 用户名不超过 64 且密码不超过 25 时，仍是一条。
- 已经写进另一条网址路径里的，不另开。
- 用户名和密码不进证据。路径不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 整段交给地址解析 | 主机名收成 `http`，短链会漏。 |
| 只要有 `@` 就拆开 | 64 个字符以内时，Android 仍把它当成一条。 |
| 路径里的同样字符串也拆 | 它仍属于前一条网址。 |

## 后果

- `t.me/share/url?text=http://` 接 65 个用户名再接 `@http://bit.ly/…` 删除。证据仍只有主机名。
- 分享 `url` 里密码超过 25 时，后面的短链同样删除。
- 64 个字符的用户名，以及写在 `https://example.com/` 路径里的，留着。
