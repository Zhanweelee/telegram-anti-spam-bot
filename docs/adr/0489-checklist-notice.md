# ADR 0489：清单完成提示按群删除

- 状态：已接受
- 日期：2026-11-05

## 背景

清单里的任务被标成完成或取消完成时，群里各有一条服务消息。完成带 `marked_as_done_task_ids`。取消完成带 `marked_as_not_done_task_ids`。嵌套的 `checklist_message` 是另一条消息。新加的任务文字仍按 ADR 0089 成为正文。清单标题仍按 ADR 0057 成为正文。

这两条提示的正文是空的。关键词看不到它们。删掉提示不会把任务标成完成或取消完成。

## 决策

- `checklist_tasks_done.marked_as_done_task_ids` 是非空数组，且每一项都是大于 0 的安全整数时，事件带 `checklistNotice: "done"`。`marked_as_not_done_task_ids` 满足同样条件时带 `undone`。同时出现时先认完成。不写任务号和原清单。
- 空对象、空数组、0、负数、小数、字符串和单独的布尔值不带这个标记。新加的任务不带这个标记，文字仍按 ADR 0089 处理。已有正文时，正文仍按原来的优先级。
- 检测器在 `@tasb/detector-checklist`，id 是 `checklist_notice`。只在 `message.checklistNotice` 是这两种之一时返回 score 1。证据是 `checklist:done` 或 `checklist:undone`。
- 默认规则用同样的 id，关闭。某个群用现有的私聊 `/rule` 打开后，删除这两种提示。没有新命令。菜单仍是 99 条。不调用 `editMessageChecklist`。
- 付费帖仍不删除。见 ADR 0356。
- 不改 ADR 0026 的基础检测器名单。`checklist_notice` 不在里面。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 默认删掉全部完成提示 | 有的群靠这条提示知道任务勾过了。打开之前不改现有群。 |
| 连新加的任务一起删 | 新加的文字已经是正文。关键词和短链仍要看见。见 ADR 0089。 |
| 把任务号或原清单写进证据 | 原清单是另一条消息。任务号不是这条提示的正文。 |
| 新命令 `/checklist` | 菜单只剩一个空位。现有 `/rule` 已经能打开这条规则。ADR 0057 拒绝的是清单内容检测器。 |

## 后果

- 不打开这条规则的群，这两种提示仍留下。新加的任务文字仍参与关键词。
- 打开 `checklist_notice` 后，这个群里的这两种提示会删除。任务完成状态不变。付费帖仍留下。新加的任务可以另开 `checklist_added`。打开 `checklist_notice` 仍不删除这种服务消息。见 ADR 0495。
- 自部署没有额度，打开后就会删除。云模式超过当月次数后，还要把 `checklist_notice` 写进 `QUOTA_BASIC`，否则超额时这条规则会停。
- `chats.json` 整份替换的群要自己加上这条规则，才会有这个开关。
- 30 天保留期不动。
- 勾完或取消勾完的人后来由 ADR 0602 只留下主机名。名字本身仍不进事件。任务号仍不读。空对象、空数组、0、负数、小数、字符串和布尔值仍不读发送者。新加的任务仍不读发送者。嵌套原清单仍不读。
- 勾完或取消勾完后来按全名只留主机名。见 ADR 0627。新加任务的人后来按全名，见 ADR 0628。任务上的完成者仍只读名。
- 对得上的第一条任务后来只留主机名。完成名单非空时只用第一项。其余任务、标题和清单正文仍不读。见 ADR 0655。
- 任务上的完成者后来按全名只留主机名。见 ADR 0641。
