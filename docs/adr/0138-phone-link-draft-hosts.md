# ADR 0138：电话号码链接不是邀请

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0030 把 `t.me/+` 后面 1 到 128 位的路径都当成邀请。ADR 0137 只从 `tg://resolve?phone=` 读 `text`。

桌面端先匹配 `t.me/+` 后全是数字的路径，把它改写成 `tg://resolve?phone=`，查询原样保留。带字母的加号路径才进 `tg://join`。Android 在这段全是数字时把它当成用户名，并同样读 `text`。`www.t.me`、`telegram.me` 和 `telegram.dog` 走同一条。`joinchat/`、`tg://join?invite=` 和其它子域不改写。

全是数字的 `https://t.me/+7999` 因此会打开电话聊天，而不是加入群。短链可以只写在 `text` 里。按邀请删掉这条链接，和已经放行的 `tg://resolve?phone=` 不是同一条入口。

## 决策

- `t.me`、`telegram.me`、`telegram.dog` 以及它们的 `www` 前缀上，路径只有 `+` 和 1 到 128 位数字时，不再记成邀请。
- 这种链接的 `text` 按 ADR 0137 只留主机名。只拆一层。号码、路径和查询里的其它字不进证据，也不进关键词。
- 带字母或符号的加号路径、`joinchat/`、`addlist/`、`tg://join` 和其它子域仍按原来的邀请规则。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 全数字加号路径继续当邀请 | 客户端打开的是电话聊天。同一条入口的 `tg://resolve?phone=` 已经放行。 |
| 任何加号路径都读 `text` | 带字母的路径仍是邀请，外层已经会删。 |
| 把号码记进证据 | 证据仍然只该有主机名。 |

## 后果

- 没有 `text` 的 `https://t.me/+7999` 放行。`text` 是裸 IP、默认短链或邀请时，现有链接规则删除这条消息。证据仍只有主机名。
- `example.com` 留着。带字母的 `t.me/+AbC`、`t.me/joinchat/7999` 和 `tg://join?invite=7999` 仍是邀请。
- 再套一层预填链接仍放行。正文就是这条链接时，链接原文仍在 `message.text`。按钮和隐藏链接只留下主机名。
