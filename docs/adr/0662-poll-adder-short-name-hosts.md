# ADR 0662：投票选项菜单上添加者画出的短名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

一条投票发出之后还可以加人选项。成员长按这个选项时，Android 的 `PollItemMenu` 用 `PollAddedByAtTime` 画出添加者。这个名字来自 `DialogObject.getShortName`。用户就是 `UserObject.getForcedFirstName`。名为空时改用姓。空白不算空。从下标 2 起找第一个空格，找到就把后面丢掉。下标 0 或 1 上的空格不截断。群和频道的短名是标题，空格不截断。

见 ADR 0577。当时按可见名读取，空格后面仍读。加选项和删选项的服务消息后来按 ADR 0659 截断。菜单上的添加者仍读完整名，空格后面的短链会删掉菜单没有画出的后半段。

Bot API 把这个人放在 `poll.options` 的 `added_by_user`，群放在 `added_by_chat`。选项文字仍按原来的方式成为正文。

## 决策

- `added_by_user` 是对象时，从会画出来的短名留主机名。`first_name` 的长度大于 0 时用名，不读姓。名缺失或正好是空字符串，且 `last_name` 是非空字符串时，改用姓。空白名挡住姓。
- 从下标 2 起的第一个空格后面不读。这个空格之前的前缀才抽主机名。没有这样的空格时，整段名字都读。下标 0 或 1 上的空格不截断。
- 没有用户对象时，`added_by_chat.title` 仍整段只留主机名。群标题不按空格截断。群用户名不读。用户和群同时存在时仍只读用户。
- 主机名仍进消息已有的 `hosts`。邀请仍进 `invites`。选项文字里已有短链时，证据仍先记那段文字的主机名。短名不进正文，也不改内容哈希。关键词因此不命中。
- 用户名、用户 id、选项编号、添加时间和嵌套的 `poll_message` 不读。布尔值不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。短链仍走已有的 `links`。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续读空格后面 | 菜单上的短名不画这段。会删掉没有出现在这行里的网址。 |
| 群标题也截断 | `getShortName` 对群和频道用的是标题，不从下标 2 起切空格。 |
| 空白名也改去读姓 | `TextUtils.isEmpty` 只把 null 和长度为 0 当成空。空白名仍挡住姓。 |
| 不再读这个菜单 | 客户端仍把短名画出来。短链可以只写在空格前面。 |
| 新命令 `/adder` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 添加者短名里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。
- 从下标 2 起被空格截掉的后半段不读。下标 0 或 1 上的空格后面仍读。空白名挡住姓。群标题仍整段读。
- 短名原文、路径和用户名不进事件。内容哈希不变。关键词不命中短名。选项文字仍按原来的正文。
- 选项文字里已有短链时，证据仍先记那段文字的主机名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 嵌套的 `poll_message` 仍不读。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
