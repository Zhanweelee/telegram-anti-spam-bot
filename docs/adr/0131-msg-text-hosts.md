# ADR 0131：私聊预填链接的 text 只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

`tg://msg` 和 `tg:msg` 打开一个私聊，并把 `text` 放进输入框。外层没有可判定的主机名。百分号编码的裸 IP、短链和 `tg://join` 可以只写在 `text` 里。链接规则看到的整段是 `tg:`，裸 IP 和入群链接都对不上。

`to` 是收件人用户名。证据里只该有主机名。

再套一层 `tg://msg` 仍停在外层。公开用户名 `t.me/durov?text=`、`tg://search` 和其它网站的 `text` 参数不是这条预填。

## 决策

- `tg://msg` 和 `tg:msg` 从 `text` 抽出网址。主机名和邀请判断与普通链接相同。
- `text` 不进入 `message.text`，也不参与关键词。
- 只拆一层。里层如果还是 `tg://msg` 或分享链接，不再往下拆。
- `to` 不读。`tg://search`、`t.me/名字?text=` 和其它网站的 `text` 参数不读。
- 路径和收件人用户名不进证据，也不进隐藏链接的事件字段。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 预填链接整段都不读 | 裸 IP 和入群链接可以只写在 `text` 上。 |
| 任何网址的 `text` 参数都读 | 普通网站的查询参数不是 Telegram 预填。 |
| 一直往下拆 | 第二层百分号编码也停住。一层够拦住直接转发的预填链接。 |

## 后果

- `text` 里是裸 IP、默认短链或邀请时，现有链接规则删除这条消息。证据仍只有主机名。
- `example.com` 留着。`to` 上的地址、`tg://search` 和 `t.me/durov?text=` 仍按外层判断。
- 按钮上的 `text` 里的关键词留着。正文就是这条链接时，链接原文仍在 `message.text`。
- 公开用户名、`t.me/s/用户名` 和 `tg://resolve` 上的 `text` 后来由 ADR 0137 只留下主机名。帖子路径和 `telegrampassport` 仍不读。
- 抽奖要加入的频道名字后来由 ADR 0132 只留下主机名。频道 id、用户名和中奖者姓名仍不进事件。
