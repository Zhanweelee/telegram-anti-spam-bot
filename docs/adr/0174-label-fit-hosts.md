# ADR 0174：放不下的标签后面打开的主机名也留下

- 状态：已接受
- 日期：2026-11-02

## 背景

Android `LinkifyPort.WEB_URL` 的一个标签最多 63 个字符，并且不能停在 ASCII 单词中间。连字符可以留在标签里面，但整段仍然要在 63 个字符里结束。放不下时，匹配停在连字符前面，后面的网址会再打开一次。

`http://` 加 59 个 `a` 再接 `-http://bit.ly/…` 因此会打开 `bit.ly`。58 个 `a` 再接 `-http` 刚好 63 个字符，仍是同一个主机名。60 个 `a` 再接 `-bit.ly/…` 会单独打开 `bit.ly`。正好 63 个 `a` 再接 `.http` 仍是一个主机名。64 个 `a` 再接点号，后面的协议会再打开一次。没有连字符、直接粘上的长串没有单词边界。路径里的连字符仍属于这一段网址。

## 决策

- 带协议的标签、裸域名和 `www.` 的标签按 Android 的上限读取：1 到 63 个字符。`%HH` 和一个增补平面字符对仍各算一个字符。
- 连字符或下划线只能出现在标签中间。整段标签必须在 63 个字符里以标签字符结束。
- 记号不能停在 ASCII 单词中间。放不下时，后面的网址按自己的一段来抽主机名。
- 放得下的连字符、正好 63 个字符后面的新标签，以及路径里的连字符，仍按整段主机名判断。
- 每段仍走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 切开之后单独的邀请地址仍按邀请读取。超长标签挡住的 `/+…` 不改记成邀请。
- 已经写在 `text_link`、按钮或其它结构化字段里的地址整段打开。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 只在高亮跨度里截断第一个主机名 | 记号把后面的短链吞进同一个标签，第二段不会再打开。 |
| 只要超过 63 个字符就从连字符退回前一个标签 | 放得下的 `-http` 仍是这一个主机名。下划线后面没有单词边界。 |
| 路径里的连字符也切开 | `example.com/` 后面的长串仍是这一段网址。 |

## 后果

- `http://` 加 59 个 `a` 再接 `-http://bit.ly/…`、60 个 `a` 再接 `-bit.ly/…`，以及 60 个 `a` 再接 `-http://203.0.113.141/…`，按现有短链或裸 IP 规则删除。证据仍只有主机名。
- 58 个 `a` 再接 `-http://bit.ly/…`、59 个 `a` 再接 `-bit.ly/…`，以及正好 63 个 `a` 再接 `.http://bit.ly/…` 留着。直接粘上的长串留着。路径里的连字符留着。
- `http://bit.ly_foo/…` 仍留着。`https://t.me-` 加 63 个 `a` 再接 `/+…` 不记成邀请。放不下的标签后面单独的 `https://t.me/+…` 按邀请删除。路径不进证据。
- 没有协议的点分 IPv4，Android 打开时也留下。见 ADR 0175。
