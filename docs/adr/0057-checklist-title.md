# ADR 0057：清单标题进入正文

- 状态：已接受
- 日期：2026-11-01

## 背景

清单消息往往没有 `text`，也没有 `caption`。ADR 0056 只取投票题干和奖品说明，清单标题仍绕过关键词。任务文字和完成者名字如果一并写进事件，会把清单里的普通事项和用户名哈希进去。

## 决策

- 没有 `text`、`caption`、投票题干和奖品说明时，用 `checklist.title` 当正文。截断到 4096，并以此计算 `textSha256`。
- 前面几项已经有非空字符串时，不把标题再拼上去。
- `checklist.title_entities` 里的 `text_link` 走 ADR 0029 的同一套主机名规则。任务上的 `text_entities` 不读。
- 任务文字、完成者名字和 id 不进事件。
- 不新增检测器，也不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把任务文字拼进正文 | 和 ADR 0056 对投票选项的取舍一样。正常清单的事项会改变哈希。 |
| 把清单标题插到投票题干前面 | 一条消息同时带投票和清单时，已经落地的题干优先级会被换掉。 |
| 单独做一个清单检测器 | 标题已经是正文。关键词和正则不用改。 |

## 后果

- 标题里的「免费领取」会命中现有关键词。同一标题在重复窗口里按这段正文计次。
- 任务文字里的关键词仍然看不到。任务上的短链也不会变成主机名。
- 标题上的隐藏短链只留下主机名。邀请码、查询和完成者名字不进事件。
