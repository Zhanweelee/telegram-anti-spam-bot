# ADR 0533：服务消息上的可见名字也走默认正则

- 状态：已接受
- 日期：2026-11-05

## 背景

ADR 0532 会封禁名字里写成「加微x」的新人，也会拒绝这样的申请简介。入群同时还有一条服务消息。封禁删不掉它，因为 `chat_member` 没有这条消息的编号。关键词只认「加微信」，所以这行广告留在群里。

视频聊天邀请、换群主和靠近提醒也把可见名字放进正文。这三条整行删除的规则默认关闭。名字干净时应该留下，名字是这组正则时应该删掉。

普通消息仍不打开 `regex_hint`。

## 决策

- 规则条件增加 `serviceName: true`。它在入群服务消息、视频聊天邀请、换群主或群主离开、靠近提醒上为真。退群、普通消息和其它服务消息为假。
- 新规则 `service_name_regex` 默认打开。条件是 `serviceName`，检测器是现有的 `regex`，命中后 `delete`。
- 证据仍是 `regex:hit`。名字不进证据，也不进日志。
- `regex_hint`、`service_notice`、`call_invite`、`owner_notice` 和 `proximity_notice` 仍默认关闭。关掉其中一条不会关掉 `service_name_regex`。
- 不改 ADR 0026 的基础检测器名单。`regex` 已经在里面，超额后这条规则仍会跑。
- `chats.json` 整份替换的群不会自动带上这条规则。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 默认打开 `regex_hint` | 普通消息会被同一份模式删除。这次要删的是服务消息上的名字。 |
| 默认打开邀请、换群主和靠近提醒 | 名字干净的那几行也会被删掉。 |
| 只处理入群服务消息 | 另外三行用的是同一份可见名字，留下「加微x」是同一个缺口。 |

## 后果

- 这四类服务消息的可见名字命中 `t.me/+`、「加微信」、「加微x」或「加微X」时删除。证据只有 `regex:hit`。
- 名字干净时，这四行仍留下。退群仍不读名字。普通消息仍要打开 `regex_hint`。
- 关掉 `service_name_regex` 后，这种名字回到只看关键词和短链。
- 整份替换规则的群要自己加上这条，才会删除这些服务名字。
- 30 天保留期没有改。
- 已有正文旁边的成员标签后来由 ADR 0534 单独交给同一份正则。标签自己就是正文时仍要打开 `regex_hint`。
- 已有正文旁边的可见名字后来由 ADR 0554 另留在 `memberName`。`service_name_regex` 仍不看字段位置。距离无效的靠近提醒改由 `member_name_regex` 删除。
