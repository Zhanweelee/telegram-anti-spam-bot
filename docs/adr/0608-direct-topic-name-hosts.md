# ADR 0608：频道私信话题的用户只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

频道的私信会进一个话题。客户端把开话题的人的名字画成话题标题。这个人写在 `direct_messages_topic.user`。正文可以是一句干净的「你好」，短链只写在名字里。

普通消息的 `from` 仍不读。见 ADR 0606。把这份名字收成正文会让关键词命中人名。话题号和本群群名也不是这段名字。

发言人不是这个用户时，这条消息是别人的回复。话题标题仍是开话题的人，回复本身不该因为那个人的名字被删。

## 决策

- `direct_messages_topic.user` 是对象，且 `from` 的编号和这个用户相同，才从可见名字留主机名。名的长度大于 0 时只读名。空白也算有名。名缺失或正好是空字符串时改读姓。用户名不读。抽出之前不截断。
- 主机名仍进消息已有的 `hosts`。邀请仍进 `invites`。名字不进正文，也不改内容哈希。关键词因此不命中这个名字。
- 已有链接检测器先看正文，再看这份主机名。正文里已有短链时，证据仍先记正文的主机名。
- 话题号、本群群名不读。发言人不是这个用户时不读。没有 `direct_messages_topic`、布尔值、空对象和布尔值的 `user` 不读。`from` 上的名字在这些情况下仍不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。仍走已有的 `links`。8 个主机名的上限不变。不调用 `editForumTopic`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把名字拼进正文 | 关键词会命中人名，内容哈希也会变。 |
| 任何出现这个字段的消息都读 | 管理员在同一话题里的回复会被删。 |
| 改读 `from` | 普通消息的发送者姓名会进检测。见 ADR 0606。 |
| 新命令 `/topicname` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 开话题的人自己发言，名字里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。话题还在。
- 这个人的名字原文、路径和用户名不进事件，内容哈希不变。名字里的关键词不命中。
- 名的长度大于 0 时，姓和用户名不进事件。正文里已有短链时，证据仍先记正文的主机名。
- `example.com` 和公开的 `t.me/名字` 留着。没有短链的姓名仍留给管理员。付费帖仍不删除。见 ADR 0356。
- 发言人不是话题用户时仍留下。没有话题、布尔值、空对象和空的用户对象仍不读。普通消息的 `from` 仍不读。话题号和本群群名仍不读。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
- 这个人后来按全名只留主机名。名和姓都去掉两端空白，名在前。空白名不挡住姓。空格不截断。见 ADR 0637。发言人不是这个用户时仍不读。
