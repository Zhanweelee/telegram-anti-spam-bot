# ADR 0300：带协议的草稿主机名在多字节百分号前停下

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 的主机名标签不含 `%`。`http://b%E2%85%A0t.ly/…` 拆成 `http://b` 和 `A0t.ly/…`。`http://b%E2%84%B9t.ly/…` 拆成 `http://b` 和 `B9t.ly/…`。`http://bi%CD%8Ft.ly/…` 拆成 `http://bi` 和 `8Ft.ly/…`。这三段都不是短链。

看得见的正文在百分号前结束匹配。隐藏的分享 `text` 把整段带协议的地址收进一条，`new URL` 再把多字节 UTF-8 解出来：`%E2%85%A0` 是罗马数字 `Ⅰ`，映成 `i`；`%E2%84%B9` 是 `ℹ`，也映成 `i`；`%CD%8F` 是字素连接符，解析时被忽略。三条都变成 `bit.ly`。见 ADR 0208。

裸的 `b%E2%85%A0t.ly/…` 已经只读到 `a0t.ly`。`http://%E2%84%B9bit.ly/…` 读到的不是 `bit.ly`。`http://www.b%E2%85%A0t.ly/…` 同样不该收成 `www.bit.ly`。`http://example.com/%E2%84%B9bit.ly/…` 的百分号在路径里。`http://b%E2%85%A0@bit.ly/…` 的百分号在用户信息里，主机名仍是 `bit.ly`。

`http://b%69t.ly/…` 是单字节字母，扫描前已经收成 `bit.ly`。`https://bit.ly%2F…` 和 `https://bit.ly/%E2%85%A0…` 仍是一条短链。`http://bit.ly%E2%85%A0evil.com/…` 仍先留下 `bit.ly`。编码间隔和点状字符仍按原来的折叠处理。

## 决策

- 分享 `text`、私聊预填 `tg://msg` 的 `text` 和用户名草稿的 `text`，在 `http://` 或 `https://` 的主机名里，遇到第一个字节大于等于 `0x80` 的 `%HH` 时，在百分号前加一个空格。
- 百分号到 `/`、`?`、`#` 或空白之前已经出现 `@` 时，这段仍是用户信息，不切开。
- 路径里的 `%HH`、单字节 ASCII 字母数字连字符下划线、编码间隔和百分号编码的点状字符仍留在这一段。
- 不改带协议网址的整段匹配。闭合分享链接里的网址不走这道切开。
- 证据只留主机名。路径不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 先把多字节 UTF-8 解出来再做 IDNA 映射 | 映射结果仍是 `bit.ly`。误报还在。 |
| 停掉全部 `%HH` | `http://b%69t.ly` 和 `https://bit.ly%2F…` 会跟着变。 |
| 路径里的 `%HH` 也停掉 | `http://example.com/%E2%84%B9bit.ly` 可能再拆出短链。 |
| 改掉带协议网址的整段匹配 | 其它已经收进同一条的字符会跟着拆开。 |

## 后果

- `t.me/share/url?text=http://b%E2%85%A0t.ly/…`、`http://b%E2%84%B9t.ly/…`、`http://bi%CD%8Ft.ly/…`、`b%E2%85%A0t.ly/…`、`http://%E2%84%B9bit.ly/…`、`http://www.b%E2%85%A0t.ly/…` 和 `http://example.com/%E2%84%B9bit.ly/…` 留着。
- `http://b%69t.ly/…`、`b%69t.ly/…`、`https://bit.ly%2F…` 和 `https://bit.ly/%E2%85%A0…` 仍按短链删除。证据是 `bit.ly`。路径不进证据。
- `http://bit.ly%E2%85%A0evil.com/…` 仍按短链删除。证据是 `bit.ly`。`http://b%E2%85%A0@bit.ly/…` 仍按短链删除。
- 亚美尼亚文、西里尔文、希腊文和拉丁文里的标点仍可能收成短链。见 ADR 0209。
