# ADR 0442：定时消息只算一次洪泛

- 状态：已接受
- 日期：2026-11-04

## 背景

Bot API 的 `is_from_offline` 为 true 时，这条消息不是用户当下逐条发出的。定时消息、离开回复和问候都会这样标记。它们经常在同一秒里成批发到 webhook。洪泛默认 10 秒 5 条。一组正常的定时消息会跨过这道线，整组被删。见 ADR 0010。

商业连接上的离开回复和问候在读正文前已经忽略。见 ADR 0437。这里剩下的是普通群里的定时消息。

## 决策

- `is_from_offline` 正好是布尔值 true 时，事件记 `offline`。`false`、数字和其它值不记，也不写进事件。
- 未编辑、且没有 `albumId` 的消息如果带 `offline`，洪泛窗口用固定采样号 `offline`。同一人在同一群里的这些消息只占一个名额。
- 带 `albumId` 的仍按相册编号采样。见 ADR 0438。
- 编辑后的消息仍用事件 id。每一条编辑各算一次。
- 重复检测仍按正文或文件摘要，不按这个标记合并。
- 证据摘要仍是 `flood:N`。这个标记不进证据、审计和日志。关键词和链接仍逐条判断。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 每一条定时消息都计数 | 一次发出的几条提醒会被当成洪泛删掉。 |
| 编辑也并进同一次采样 | 反复修改可以绕开洪泛。 |
| 连重复检测也合并 | 同一句广告复制多次就不再计数。 |
| 原样保存任意值 | 这个字段会把正文带进事件。只留 true。 |

## 后果

- 同一人在 10 秒窗口里的未编辑定时消息只占一个名额。这个名额已经到达阈值时，后面的定时消息也会删。
- 采样号还留在最近 32 次里时，再出现的定时消息不再加一。窗口把旧编号挤掉之后，可以再计一次。
- 另一位成员的定时消息另计。
- 30 天保留期不动。
