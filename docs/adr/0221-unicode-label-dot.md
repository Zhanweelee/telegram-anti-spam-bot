# ADR 0221：点号后面的标签字仍算严格域名

- 状态：已接受
- 日期：2026-11-03

## 背景

ADR 0220 在点号后面是严格域名时，把前面的标签字收成 `x`。那条规则只认 ASCII 标签。

`bit.ly点.日本.com/…`、`bit.ly点日.本.com/…`、`bit.ly가.가.com/…`、`203.0.113.10点.日本.com/…` 和 `bit.ly点.中国/…` 在 Android 上都是一条网址。带协议时，地址解析器给出的主机名不是前面的短链或裸 IP。

`bit.ly点.日本.notarealtld/…`、`bit.ly点.日本com/…` 和 `bit.ly点.中国日本/…` 仍只打开 `bit.ly`。`点.日本.bit.ly/…` 前面没有 ASCII，仍打开这条短链。`example.com点.日本.bit.ly/…` 的整条主机名仍以 `.bit.ly` 结尾。

## 决策

- 只改主机名扫描。公开的折叠不改。
- 点号后面的域名可以含 Android 标签字。最后一个标签仍必须是 Android 的严格顶级域。
- ASCII 顶级域在后面紧贴非 ASCII 时结束，例如 `com日本`。非 ASCII 顶级域在后面紧贴 ASCII 时结束，例如 `中国com`。两边都不是 ASCII 词字符时不拆开，例如 `中国日本`。
- 点号后面不是严格域名时，留下这些标签字。空标签 `..` 不收成 `x`。`http://` 和 `https://` 前面的标签字仍留下。前面没有 ASCII 的标签字仍留下。
- 停住扫描也按这一步，避免粘连扫描收成 `x` 之后又从原文读出短链。
- 每段仍走现有的短链、裸 IP、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 只认 ASCII 标签 | `bit.ly点.日本.com/…` 仍按短链删除。Android 只打开这一整条。 |
| 见到严格顶级域的前缀就收成 `x` | `bit.ly点.中国日本/…` 会把已经打开的 `bit.ly` 粘没。 |
| 在抽主机名时跳过前缀，不收成 `x` | 旁路纯文本仍按原文读出 `bit.ly`。 |

## 后果

- `bit.ly点.日本.com/…`、`203.0.113.10点.日本.com/…`、`bit.ly点.中国/…`、`bit.ly点.中国com/…` 和 `http://bit.ly点.日本.com/…` 留着。
- `bit.ly点.日本.notarealtld/…`、`bit.ly点.日本com/…` 和 `bit.ly点.中国日本/…` 按短链删除。证据是 `bit.ly`。
- `example.com点.日本.bit.ly/…` 和 `bit.ly点.日本.bit.ly/…` 仍按短链删除。证据是收成 `x` 之后的主机名。
- `点.日本.bit.ly/…` 仍按短链删除。路径不进证据。
- 句号和点状间隔号后面的域名也可以含 Android 标签字。见 ADR 0222。
