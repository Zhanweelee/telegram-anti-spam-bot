# ADR 0296：编码主机名贴在草稿分隔符后面时在百分号处停下

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 不会在匹配前把主机名里的 `%HH` 收成字母，也不会把 `%2E` 收成点。`%2Bb%69t.ly/…`、`%2Fb%69t.ly/…`、`%2Db%69t.ly/…` 和 `%252Db%69t.ly/…` 打开的是 `69t.ly`，不是 `bit.ly`。`%2Bbit%2Ely/…` 什么都不打开。`%2Bb%2569t.ly/…` 打开的是 `2569t.ly`。

换行或制表符隔开时也一样。`example.com%2B\nb%69t.ly/…` 打开的是 `example.com` 和 `69t.ly`。普通空格后面的 `b%69t.ly`、单独的 `b%69t.ly`、`bit%2Ely` 和 `http://b%69t.ly/…` 仍打开 `bit.ly`。

最后一个点是字面点时，后面的路径挂在停下的主机名上。`%2Bb%69t.ly/http://t.co/…` 不打开 `t.co`。最后一个点是 `%2E` 时，后面的网址会打开。`%2Bbit%2Ely/http://t.co/…` 打开 `t.co`。`%252E` 仍不是点。

`%2B2b%77ww.bit.ly/…` 打开的是 `77ww.bit.ly`。`%2F`、`%2D` 和 `%252D` 同样在百分号处停下，这个主机名仍以 `.bit.ly` 结尾。

看得见的正文已经这样切。隐藏的分享 `text` 先把最后一段收成 `arpa`，`77ww.bit.ly` 不再以 `.bit.ly` 结尾。换行又先换成普通空格，`b%69t.ly` 被收成 `bit.ly`。见 ADR 0200。

## 决策

- 分享 `text`、私聊预填 `tg://msg` 的 `text` 和用户名草稿的 `text`，不在路径里、也不紧挨 `http://` 或 `https://` 的 `%2B`、`%2F`、`%2D` 和 `%252D`，后面的主机名还含百分号时，在能接上字面主机名或点分 IPv4 的那个百分号处改成空格，两位十六进制留下。
- 分隔符和主机名之间可以隔着会被吃掉的换行或制表符。普通空格不在此列。
- 路径里的分隔符、`%252E`、单独的 `b%69t.ly` 和 `bit%2Ely` 仍按原规则。最后一个点是 `%2E` 时，后面的网址仍打开。
- 证据只留主机名。路径不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续把最后一段收成 `arpa` | `77ww.bit.ly` 不再以 `.bit.ly` 结尾，短链会漏掉。 |
| 先把换行换成普通空格 | `b%69t.ly` 会收成 `bit.ly`，不该删的消息会被删掉。 |
| 主机名里的 `%HH` 一律解码 | `%2Bb%69t.ly` 会变成 `bit.ly`。 |

## 后果

- `t.me/share/url?text=%2Bb%69t.ly/…`、`%2Bbit%2Ely/…`、`%2Bb%2569t.ly/…` 和换行或制表符隔开的 `b%69t.ly` 留着。`%2F`、`%2D` 和 `%252D` 同样留着。
- `%2B2b%77ww.bit.ly/…`、`%2F2f%77ww.bit.ly/…`、`%2D2d%77ww.bit.ly/…` 和 `%252D2d%77ww.bit.ly/…` 按短链删除。证据是 `77ww.bit.ly`。路径不进证据。
- 普通空格后面的 `b%69t.ly`、单独的 `b%69t.ly`、`bit%2Ely` 和 `http://b%69t.ly/…` 仍按短链删除。
- `%2Bbit%2Ely/http://t.co/…` 按短链删除。证据是 `t.co`。`%2Bb%69t.ly/http://t.co/…` 留着。
- `%2B203%2E0%2E113%2E168/…` 留着。
- 协议正后面的 `%0A` 仍会被删掉，`http://%0Abit.ly` 会收成 `bit.ly`。见 ADR 0297。
