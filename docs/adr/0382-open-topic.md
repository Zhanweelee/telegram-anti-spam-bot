# ADR 0382：私聊可以重新打开论坛话题

- 状态：已接受
- 日期：2026-11-04

## 背景

`/closetopic` 关掉一个论坛话题之后，管理员还需要把它打开。误关或者风波过去之后，不能只靠再拉一次 bot。

官方 `reopenGeneralForumTopic` 重新打开通用话题。参数只有 `chat_id`。如果通用话题当时是隐藏的，这次会一起显示出来。`reopenForumTopic` 重新打开一个指定话题，还要 `message_thread_id`。两边都要求 bot 是管理员，并且有 `can_manage_topics`。指定话题的创建者可以没有这项权限。成功时返回 True。

这两次调用都不删除消息，也不改置顶。单独把通用话题显示出来是 `unhideGeneralForumTopic`，它不负责重新打开。

没有 token 时，内存适配器可以把这次请求记下来。私聊如果复用这次成功，回复会写成话题已经打开。

## 决策

- 私聊命令 `/opentopic <chatId> [threadId]`。群 id 匹配 `^-?\d{1,20}$`。话题号和消息号使用同一条规则：`/^[1-9]\d{0,15}$/`，并且是安全整数。群聊里的同样文本不执行。
- 配置中的管理员可以操作任意群。接入目录里的人只能操作自己的群。
- 不带话题号时调用 `ModerationPort.openTopic`，不带 `threadId`。适配器调用 `reopenGeneralForumTopic`。
- 带话题号时，同一次请求调用 `reopenForumTopic`，只带这个 `message_thread_id`。不把 `1` 改写成通用话题的方法。
- 不调用 `unhideGeneralForumTopic`、`closeForumTopic` 或 `deleteForumTopic`。不带消息号。
- 回复写明消息还在。不带话题号时写明原先隐藏的通用话题会重新显示，其它话题不在这次里。
- 没有 token、没有这个方法，话题号不合法，或调用失败时回复「参数无效」。日志只写 `operator_rejected`，带上 eventId、chatId 和命令名。不写异常文本或 token。
- 没有 token 的 Worker 不把内存里的记录回复成已经成功。
- 不修改黑名单、白名单、封禁或禁言。不读取消息正文。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把话题号 `1` 当成通用话题 | 通用话题有自己的方法，不接收话题号。两条接口的范围官方是分开写的。 |
| 重新打开通用话题时再调一次取消隐藏 | `reopenGeneralForumTopic` 已经会把隐藏的通用话题显示出来。再调一次是第二次子请求。 |
| 只重新打开，回复不提隐藏 | 通用话题被隐藏时，这一次会把它显示出来。管理员需要在回复里看到这个范围。 |
| 回复写成消息已经恢复 | 成功只表示这个话题被重新打开。消息本来就还在。 |
| 没有 token 时也回复「已打开」 | 话题还关着。管理员会以为成员已经可以发言。 |

## 后果

- 成功只表示 Telegram 接受了这一次重新打开。缺少 `can_manage_topics`，或这个群不是论坛时，回复是「参数无效」。指定话题的创建者可以没有这项权限，由 Telegram 判断。
- 不带话题号时，其它话题保持原样。带话题号时，通用话题和别的话题保持原样。隐藏的通用话题只在不带话题号的这一次里重新显示。
- 一次重新打开是一次 Telegram 子请求。封禁、禁言和黑名单都不变。
- 30 天保留期不动。
