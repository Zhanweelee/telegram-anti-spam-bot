# ADR 0624：离开的人画出的全名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

有人离开群，或被移出群时，Android 的 `MessageObject` 在 `TL_messageActionChatDeleteUser` 上用 `replaceWithLink` 把离开的人画进这行服务文字。这里没有打开短名，所以名字是 `UserObject.getUserName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。

Bot API 把这个人放在 `left_chat_member`。操作的人写在 `from`，已经按全名只留主机名，排在后面。见 ADR 0623。这行通常没有别的正文。

短链可以只写在姓上。名的长度大于 0 时如果丢掉姓，这条短链就留在提示里。把整段收成正文会改变内容哈希，关键词也会命中名字。

## 决策

- 从本条消息上的 `left_chat_member` 会画出来的全名留主机名。名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读。空格不截断。
- 主机名仍进消息已有的 `hosts`，排在操作的人前面。邀请仍进 `invites`。操作的人的名字里已有短链时，证据仍先记离开的人的主机名。正文里已有短链时，证据仍先记正文的主机名。全名不进正文，不进 `memberName`，也不改内容哈希。关键词因此不命中。
- 用户名不读。用户编号不读。本群群名不读。布尔值不读。操作的人仍按 ADR 0623。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`service_notice` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。退群本身不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续只读名 | 客户端把姓画在同一行里。姓上的短链会留在群里。 |
| 把名字整段当成正文 | 关键词会命中人名。正常离开的人会被误删。见 ADR 0118。 |
| 每条服务提示的人都改成全名 | 助推这行用的是名。付款成功这行也只读名。见 ADR 0583 与 ADR 0618。 |
| 新命令 `/leavename` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 离开的人全名里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。人还是离开了。
- 全名原文、路径和用户名不进事件。内容哈希不变。关键词不命中全名。
- 空白名不挡住姓。空格后面的网址仍读。离开的人的主机名排在操作的人前面。
- 正文里已有短链时，证据仍先记正文的主机名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 布尔值仍不读。管理员仍豁免。干净的退群提示在 `service_notice` 关闭时仍留下。操作的人仍按 ADR 0623。云额度的基础检测器名单没有改。30 天保留期没有改。
