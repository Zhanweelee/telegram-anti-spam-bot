# ADR 0532：入群名字和申请简介也走默认正则

- 状态：已接受
- 日期：2026-11-05

## 背景

关键词只做包含。「加微信」盖不住「加微x」和「加微X」。这组变体已经在正则检测器的默认模式里，但检测器只读消息正文。入群可见名字、改过的成员标签和入群申请简介都在 `profile` 上，于是只发验证，或者把申请留给管理员。

`regex_hint` 仍默认关闭。普通句子里的误伤会删消息。名字和简介更短，而且模式只有 `t.me/+` 和「加微」加一个指定字。

## 决策

- 正则检测器同时看消息正文和 `profile`。两边都空就返回未命中。先看正文。
- 命中仍只记一条证据：`regex:hit`。名字、简介和模式都不进证据，也不进日志。`test` 抛错仍记 `regex_failed` 并返回未命中。
- 新规则 `join_regex` 对 `chat_member` 启用，检测器是现有的 `regex`，命中后 `ban`。它和 `join_name`、`join_link` 分开。关掉其中一条不会关掉另外两条。
- `join_request` 的检测器加上这份 `regex`。聚合仍是 max。命中后仍是 `decline`。不新开一条申请规则。
- `regex_hint` 仍默认关闭，并且只看消息。不改 ADR 0026 的基础检测器名单。
- 不读取进群用的邀请链接，也不把姓名拼进申请简介。
- `chats.json` 整份替换的群不会自动带上 `join_regex`，申请规则里也不会自动多出 `regex`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把 `regex` 并进 `join_name` | 关键词和这组模式不能分别关闭。 |
| 默认打开 `regex_hint` | 普通消息会被同一份模式删除。名字和简介才是这次要补的缺口。 |
| 再加一条申请规则 | 申请本来就把关键词和短链放在同一条里。多一条 id 只是为了分开关闭。 |
| 新命令 `/regex` | 菜单已经 99 条。模式仍是检测器里的默认列表。 |

## 后果

- 可见名字或新标签里出现 `t.me/+`、「加微信」、「加微x」或「加微X」时封禁，不发验证按钮。证据只有 `regex:hit`。
- 申请简介里的同一组模式会被拒绝。姓名、邀请链接和普通网址仍不因此拒绝。
- 关掉 `join_regex` 后，这种名字回到只验证。关键词和短链仍按各自的规则。
- 关掉 `join_request` 后，简介不再因为关键词、短链或这些模式被拒绝。
- 普通消息仍要打开 `regex_hint` 才会按这些模式删除。
- 入群服务消息、视频聊天邀请、换群主和靠近提醒上的同一份名字后来由 ADR 0533 删除。
- 整份替换规则的群要自己加上 `join_regex`，并在申请规则里写上 `regex`。
- 30 天保留期没有改。
