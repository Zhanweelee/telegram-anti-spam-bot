# ADR 0570：游戏附加文字上的按标识提及也走同一条规则

- 状态：已接受
- 日期：2026-11-05

## 背景

游戏消息的正文是标题。`game.text` 是附加文字，已有标题时留在 `gameText`。官方说这段 `text_entities` 可以带用户名、网址和命令。`text_mention` 把用户编号放在实体上，关键词看不见被点的人。

打开 `text_mention` 的群会删掉正文上的点名，附加文字上的同一处仍留下。封面和动图的文件编号仍不能因为这次进入事件。

## 决策

- `game.text_entities` 里，`type` 正好是 `text_mention`，并且 `user.id` 是大于 0 的安全整数时，事件同样带 `asTextMention: true`。
- 缺用户、布尔值、字符串编号和 0 仍不带这个标记。说明 `description` 没有实体列表，不另读。
- 用户编号、名字和用户名不进事件，也不进证据。附加文字看得见的字仍留在原来的字段。标题仍是正文。正文和 `textSha256` 不变。
- 封面 `file_id`、动图 `file_id` 和 MIME 仍不进事件。
- 仍用检测器 `text_mention`。证据仍是 `entity:text_mention`。不新增规则，不新增命令。菜单仍是 99 条。
- 规则仍默认关闭。打开之后，这种附加文字上的提及也删除。付费帖仍不删除。
- 不改 ADR 0026 的基础检测器名单。`text_mention` 仍不在里面。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 另开一条规则 | 这是同一处隐藏的用户编号。分开开关会让群管开漏一处。 |
| 把用户编号写进证据 | 用户编号不进事件。 |
| 连说明 `description` 一起扫实体 | 官方类型上说明没有实体列表。 |
| 把附加文字并进标题 | 标题已经是正文。并进去会改哈希。 |

## 后果

- 规则关闭时，游戏附加文字上的按标识提及留下。看得见的字仍参与关键词。用户编号仍不进事件。
- 打开 `text_mention` 后，这种附加文字会删除。封面和动图文件编号仍不进事件。
- 付费帖仍留下。0 和缺用户不带这个标记。
- 自部署没有额度，打开后就会删除。云模式超过当月次数后，还要把 `text_mention` 写进 `QUOTA_BASIC`，否则超额时这条规则会停。
- `chats.json` 整份替换的群要自己加上 `text_mention`，否则 `/rule` 会拒绝。
- 30 天保留期没有改。
