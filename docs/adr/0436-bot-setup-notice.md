# ADR 0436：机器人还不能管理时私聊提醒

- 状态：已接受
- 日期：2026-11-04

## 背景

ADR 0027 把 `my_chat_member` 收成 `admin` 或 `gone`。普通成员也记成 `gone`，目录会清掉这一群。操作者把 bot 拉进群但没给管理员时，收不到任何说明。给了管理员但没给删除或限制成员时也一样。`/cani` 能查当前权限，但要操作者自己想到去问。见 ADR 0435。

## 决策

- 目录状态仍只有 `admin` 和 `gone`。普通成员和还在群里的受限成员仍是 `gone`，不授予接入目录。
- 事件可以多带 `botSeat: "in"`。状态是 `member`，或 `restricted` 且 `is_member` 为 true 或缺了这个字段时带上。`is_member` 为 false 或不是布尔值时不带。`left` 和 `kicked` 不带。
- 事件可以同时带 `botDelete` 和 `botRestrict`，值是 `on` 或 `off`。只在两个字段都是布尔值时写入。缺一个或不是布尔值时两个都不写，事件仍是 `admin`。`creator` 两个都写 `on`，不读 `can_*`。
- Worker 在写入目录之后调用 `botSetupNotice`。需要提醒时，用 `ReplyPort` 发给操作者的用户 id，不发到群里。
- 两条权限都是 `on`，或两个权限字段都缺，不发。`left` 和 `kicked` 不发。
- 只缺删除、只缺限制、两条都缺，以及还在群里但不是管理员，各发一句。正文指出群 id，并指向私聊 `/cani`。
- 群 id 或操作者 id 不匹配 `^-?\d{1,20}$` 时不发。
- 没有回复端口时跳过。发送抛错记 `bot_setup_notice_failed`，只带事件 id 和群 id。不写正文、异常文本和 token。目录不回滚。
- 不新增命令。不调用 `promoteChatMember`。不改 `/cani`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 给目录增加 `member` | 接入目录把不是 `gone` 的状态当成授权。普通成员会获得管理这一群的资格。 |
| 在群里发提醒 | 群里的人都会看见。权限说明只给改了 bot 的那个人。 |
| 离开或被移出时也私聊 | 操作者已经完成移出。再发一条没有管理动作可做。 |
| 把每一项权限存进目录 | 权限会变。目录仍只回答谁可以管理这一群。`/cani` 读当前值。 |

## 后果

- 操作者没和 bot 说过话时，Telegram 会拒绝私聊。目录已经写完，发送失败只记日志。
- `restricted` 缺 `is_member` 时仍当成还在群里，和 `/kick`、`/member` 一样。
- 管理员对象缺布尔值时不提醒，避免把不完整的更新说成没有权限。
- `/cani` 仍是事后复查。30 天保留期不动。
