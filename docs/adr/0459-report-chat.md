# ADR 0459：每个群可以选择上报目的地

- 状态：已接受
- 日期：2026-11-04

## 背景

ADR 0021 把 `report` 发给配置里的第一个管理员。ADR 0458 让群管可以把一条规则换成 `report`。云上的群管不是那个配置管理员，通知仍落到维护者私聊，群里的人收不到。

## 决策

- `RuntimeStore` 增加 `getReportChat`、`setReportChat`、`clearReportChat`。一个群最多一个目的地，值是 `^-?\d{1,20}$`。
- 没设置时仍发给配置里的第一个非空管理员。没有回复端口或没有管理员时，上报仍是 `report_unavailable`。
- 私聊 `/report <chatId>` 只读。没改过回复「上报默认」，不写出配置管理员的编号。`/report <chatId> <targetId>` 写入。`reset` 删掉记录。
- 目的地不能等于这个群自己的编号。那样上报会写回正在检测的群。命令回复「参数无效」，不写入。流水线读到同样的记录时也忽略，改回默认目的地。
- 内存最多 256 个群。已有的群可以改。新群放不下时回复「参数无效」，日志是 `report_chat_full`。
- 配了 `POLICY_KV` 时写在 `runtime-report` 键。原来的运行时文档和动作键都不改。坏文档读成没设置。每个 isolate 缓存 60 秒。相同的值不写。
- 群聊里的同样文本不执行。接入目录里的人只能改自己的群。读或写失败回复「参数无效」，日志是 `operator_rejected`。不写姓名、消息原文或 token。这条命令不调用 Telegram。
- 通知正文仍是 `formatReportNotice`。不增加证据摘要，也不给每个管理员各发一条。
- 默认规则仍不包含 `report`。不改 `default.json`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 发给这个群在目录里的每一位管理员 | ADR 0021 已经拒绝。一次命中会变成多次 `sendMessage`。 |
| 把目的地写进运行时文档 | 旧 Worker 看到多出来的字段会把开关和 dry-run 一起丢掉。 |
| 允许发回本群 | 上报消息会再进入检测。默认正文不含原文，但仍会占洪泛次数。 |
| 在回复里写出默认管理员编号 | 群管不需要看到维护者的编号。没改过就写「默认」。 |

## 后果

- `/report -100 77` 之后，这个群的 `report` 发到 77。别的群仍走默认管理员。
- 菜单多一条 `/report`，一共 92 条。
- 云额度的基础检测器名单没有改。30 天保留期没有改。
