# ADR 0264：查询里的非法百分号仍留下主机名

- 状态：已接受
- 日期：2026-11-03

## 背景

Android `Uri.getQueryParameter` 和桌面端 `QUrl::fromPercentEncoding` 遇到不完整的 `%` 时留下这个字符，继续解码后面的内容。两个十六进制数字组成的字节按 UTF-8 解释。拼不成合法 UTF-8 时换成替换字符，不把整段查询丢掉。

`decodeURIComponent` 在 `%FF`、`%C3` 这类序列上会抛错。`t.me/durov?text=http://bit.ly/%FFoffer231` 的草稿仍是短链，主机名是 `bit.ly`。整段丢掉就会漏掉它。

`%` 后面不是两个十六进制数字时，路径在这里停住。`%2http://bit.ly` 前面是数字，后面的网址没有词边界，客户端不会单独打开。

## 决策

- `text`、分享和私聊预填的 `url`、以及 `callback_url` 先把 `+` 换成空格，再解码百分号。
- 两个十六进制数字按 UTF-8 解码。非法序列换成 U+FFFD。
- 不完整的 `%` 留在原处。
- `%2B` 仍是加号。`%20` 仍是空格。
- 解码后的文本仍按现有规则拆主机名。只拆一层。
- 词边界接不上的网址不另算一条。
- 查询值不进入正文，也不参与关键词。路径不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 非法序列整段丢掉 | `http://bit.ly/%FF…` 的短链会漏掉。 |
| 不完整的 `%` 也拆开后面的网址 | `%2http://bit.ly` 没有词边界，客户端不会打开。 |
| 非法字节按 Latin-1 留下 | 两边都把非法 UTF-8 收成替换字符。 |

## 后果

- `t.me/用户名?text=http://bit.ly/%FF…`、`text=http://bit.ly/offer%FF` 和 `tg://msg_url?url=` 里同样的序列删除。证据仍只有主机名。
- `https://example.com/%2http://bit.ly/…` 留着。
- `%2B` 编码的加号仍粘住后面的网址。
- 正文里的百分号仍按 ADR 0197 处理。这条只改查询值。
