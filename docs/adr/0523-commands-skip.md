# ADR 0523：私聊可以接着看后面的命令

- 状态：已接受
- 日期：2026-11-05

## 背景

设置私聊菜单之后，`/commands` 会读回 99 条。每行是命令名、说明和临时标记。缺 `is_ephemeral` 时标记是「未知」。这份回复在 3500 字处停下，第一页停在 `repeat`，最后写 `+4`。后面的 `rulemute`、`verifyfor`、`verifyfail` 和 `allowhost` 已经在菜单里，回复里只剩个数。

## 决策

- `/commands [private] [skip <count>]`。`private` 仍然只表示私聊菜单。
- `count` 是 0 到 99999 的整数，不允许前导零。不写 `skip` 或 `count` 为 0 时，回复与原来相同。
- `count` 大于 0 时，先按原来的顺序跳过前面的 `count` 条，再从下一条开始用同一条 3500 字的规则往下列。这一页放得下时不再写 `+N`。
- 标题仍是菜单里的总条数。`+N` 只数这一页没列出的条数。
- 跳过的条数已经不少于菜单条数，或空菜单写了大于 0 的 `count` 时，回复「参数无效」。缺数字、数字不合法也是「参数无效」。多出来的词回复用法。
- 只有配置里的管理员可以看。参数不合法时不调用 `getMyCommands`。合法的 `skip` 在确认权限之后才读取。
- 不新增命令。菜单仍是 99 条。`/commands` 的菜单描述改为带上 `skip`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 缩短每条说明 | 说明就是命令用法。缩短之后菜单里看不出参数。 |
| 在 `+N` 后面写下一页的命令 | 现有回复用 `+N` 解析。下一页的起点就是已经看过的条数。 |
| 只给 `/help` | `/help` 列的是语法，不列 Telegram 上实际存着的菜单和临时标记。 |

## 后果

- `/commands skip 95` 能看到 `rulemute`、`verifyfor`、`verifyfail` 和 `allowhost`。
- 不写 `skip` 时，第一页仍停在 `repeat`，最后仍是 `+4`。
- 已经设过命令菜单的部署，要再执行一次设置命令，菜单描述才会带上 `skip`。
- 30 天保留期没有改。
