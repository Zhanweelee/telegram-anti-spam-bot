# ADR 0273：主机名后面的标点仍留下后面的主机名

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 读完主机名和一到五位数字的端口之后，路径才从 `/` 或 `?` 开始。`! # $ & ( ) * + , ; = ~` 以及不是端口的 `:` 写在主机名紧后面时，结束这一段。后面的网址另开一条。

看得见的正文已经这样切。隐藏的分享 `text` 和分享 `url` 把整段交给地址解析。`http://example.com!http://bit.ly/…` 的主机名收成 `example.com!http`，短链留在路径里。`#` 收成片段。不是端口的 `:` 让整段解析失败。

斜杠或问号后面的同一批标点仍属于前一条路径。`user:pass@bit.ly` 仍是一条。

## 决策

- 分享 `text`、分享 `url`、私聊预填 `tg://msg` 的 `text` 和用户名草稿的 `text`，在 `http://` 或 `https://` 的主机名后面认这批标点。
- 路径还没开始时，从标点后面另抽网址。
- `/` 或 `?` 已经开始之后，这些标点仍留在这一条里。
- 一到五位数字的端口，以及 `user:pass@`，仍属于这一条。
- `https://t.me!/+…` 不改记成邀请。标点后面单独的邀请地址仍按邀请读取。
- 路径和邀请码不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 整段交给地址解析 | 短链留在路径、片段里，或整段解析失败。 |
| 路径里的同一标点也拆开 | `example.com/!http://bit.ly` 仍是一个网址。 |
| 所有冒号都结束主机名 | `user:pass@bit.ly` 和 `:80` 会记错主机名。 |

## 后果

- `t.me/share/url?text=http://example.com!http://bit.ly/…`、`#` 后面的 `t.co`，以及不是端口的 `:` 后面的裸 IP，删除。证据仍只有主机名。
- 分享 `url` 里的同样写法同样删除。
- `example.com/!http://bit.ly` 和 `example.com/?http://bit.ly` 留着。`user:pass@bit.ly` 仍按短链删除。
- `https://t.me!/+…` 不改记成邀请。`example.com!https://t.me/+…` 按邀请删除。路径不进证据。
- 裸域名和 `www.` 在最后一个标签结束时，后面的短链后来同样留下。见 ADR 0274。
