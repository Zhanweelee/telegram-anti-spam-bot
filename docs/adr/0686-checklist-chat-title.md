# ADR 0686：清单的发送者是聊天时只读聊天标题

- 状态：已接受
- 日期：2026-11-06

## 背景

有人勾完、取消勾完或新加清单任务时，Android 的 `TL_messageActionTodoCompletions` 和 `TL_messageActionTodoAppendTasks` 用 `replaceWithLink` 画出发送者。发送者是用户时，画出全名。发送者是聊天时，画出这个聊天的标题。标题不截断。自己操作的那条不画名字。Bot 不区分是不是自己发出。

Bot API 把完成和取消完成放在 `checklist_tasks_done`，把新加任务放在 `checklist_tasks_added`。发送者是聊天时，`sender_chat` 是那个聊天，`from` 是占位用户。见 `telegram-bot-api` 的 `messageSenderChat`。

ADR 0627 和 ADR 0628 仍从 `from` 的全名留主机名。占位用户的名字不是这行画出的字。编号和本群相同时，通用代发规则也不读标题。

## 决策

- 已经会标成 `checklistNotice` 或 `asChecklistAdded` 的提示上，`sender_chat` 是对象时，只从 `sender_chat.title` 留主机名，不从 `from` 留主机名。标题不截断。用户名不读。频道、群和超级群都一样。编号和本群相同时也读。
- 没有 `sender_chat` 时，仍从 `from` 的全名留主机名。名和姓都去掉两端空白，名在前。空白名不挡住姓。空格不截断。
- 不从 `chat.title` 另读。
- 勾完时，标题排在对得上的第一条任务前面。新加时，编号不同的标题由通用代发规则先读，排在任务文字前面。编号相同时，任务文字排在前面。
- 任务文字、完成者和四条起只读前三条仍按原来的规则。空数组、空字符串和布尔值仍不读发送者。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`checklist_notice` 和 `checklist_added` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不调用 `editMessageChecklist`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续读 `from` | 占位用户的名字不在这行里。短链会删掉一条没有这个名字的提示，标题上的短链又会留下。 |
| 本群匿名不读群名 | Android 画的就是这个聊天的标题。通用代发规则在编号相同时不读它。 |
| 只改勾完，不改新加 | 两行都用 `replaceWithLink` 画同一个发送者。 |
| 新命令 | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 聊天勾完、取消勾完或新加任务时，标题里的短链、邀请或裸 IP 会留下主机名。证据只有主机名。任务本身还在。
- 本群自己操作时，默认仍因管理员豁免而留下。关掉豁免后会删。别的聊天发到这个群时不豁免。
- 占位用户的名字不再留下主机名。用户仍按全名。
- 空数组、空字符串和布尔值仍不读发送者。`example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。
- 30 天保留期没有改。
