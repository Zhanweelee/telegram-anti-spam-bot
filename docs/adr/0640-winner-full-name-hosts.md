# ADR 0640：公开抽奖结果上画出的中奖者全名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

抽奖结束且中奖者公开时，结果页画出每一位中奖者。Android 的 `GiveawayResultsMessageCell` 用 `UserObject.getUserName` 画这行。这就是 `ContactsController.formatName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。像素截断、变音符号和从右到左的控制符不在这里复现。

见 ADR 0580。当时名的长度大于 0 就丢掉姓。空白也算有名。短链可以只写在姓上。举办频道标题已经先抽出。见 ADR 0132。进行中的抽奖没有中奖者名单。嵌套在 `giveaway_completed.giveaway_message` 里的结束公告是另一条消息。创建公告和私下结束上画出的发送者仍只读名。见 ADR 0590。

把名字收成正文会让关键词命中人名，也和原文默认不落盘冲突。

## 决策

- 只读本条消息上的 `giveaway_winners.winners`。每一位公开中奖者按会画出来的全名留主机名。名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读名字。空格不截断。
- 主机名仍进消息已有的 `hosts`。邀请仍进 `invites`。举办频道标题仍按 ADR 0132 先抽出。中奖者主机名排在它后面。8 个主机名的上限不变。
- 名字不进正文，也不改内容哈希。关键词因此不命中这个名字。用户名、用户 id、`winner_count` 和 `winners_selection_date` 不读。
- 进行中的 `giveaway` 没有 `winners`，不从那里读中奖者。嵌套的 `giveaway_message` 不读。创建公告和私下结束的发送者仍只读名。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`giveaway_card` 仍默认关闭。关掉时，短链仍走已有的 `links`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续只读名 | 结果页把姓画在同一行里。姓上的短链会留在消息里。 |
| 把名字拼进正文 | 关键词会命中人名，内容哈希也会变。见 ADR 0032。 |
| 连创建公告的发送者一起改成全名 | 那一行仍只画名。见 ADR 0590。 |
| 新命令 `/winnername` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- `giveaway_card` 关闭时，中奖者全名里的短链、邀请或裸 IP 仍会删除这条消息。证据只有主机名。
- 全名原文、路径和用户名不进事件。内容哈希不变。关键词不命中全名。
- 空白名不挡住姓。空格后面的网址仍读。
- 举办频道标题里已有短链时，证据仍先记那段标题的主机名。正文里已有短链时，证据仍先记正文的主机名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 进行中的抽奖和嵌套的 `giveaway_message` 仍不读中奖者。创建公告和私下结束仍只读名。用户名、用户编号、中奖人数和开奖时间仍不读。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
