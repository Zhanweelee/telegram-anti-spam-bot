# ADR 0716：置顶清单标题上的文字链接只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

置顶一条清单时，Android 把清单标题当成这条消息的文字。`MessageTodoName` 就是标题本身。`generatePinMessageText` 再只画前 20 个 UTF-16 码元。标题上的 `text_link` 会跟着这段文字画成可点的链接。任务正文不画。见 ADR 0654。

Bot API 把标题放在 `pinned_message.checklist.title`，把链接放在 `title_entities`。ADR 0654 只从看得见的标题里取主机名，所以「点这里」背后的短链会漏掉。

消息上的 `entities` 对不上这段标题。文字消息的链接仍按 ADR 0715。任务上的链接不在这条提示里。

这段预览不进正文。关键词不命中标题，也不命中链接地址。

## 决策

- 置顶预览来自清单标题时，除了前 20 个码元里的普通网址，还读取 `title_entities` 里的 `text_link`。
- `offset` 必须是大于等于 0 的安全整数，并且小于实际画出的那段标题长度。标题更短时，这段长度就是标题长度。
- 空标题不读链接。任务正文和任务上的链接不读。消息上的 `entities` 不套到标题上。
- 只留链接地址里的主机名。标题原文和路径不进事件。
- 文字消息的文字链接仍按 ADR 0715。账单说明仍不套用实体。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`pin_notice` 仍默认关闭。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 整段标题上的文字链接都读 | 第 21 个码元起的链接没有画在这条提示上。 |
| 标题较短时仍按 20 个码元读 | 客户端只在截出来的那段上画链接。 |
| 任务上的链接也读 | 置顶提示不画任务。 |
| 把消息实体套到标题上 | 标题的链接在 `title_entities`，起点对不上消息实体。 |
| 把链接地址抄进正文 | 关键词会命中地址。内容哈希也会变。 |

## 后果

- 置顶清单标题前 20 个码元里的文字链接出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。置顶本身还在。
- 第 21 个码元起的链接、标题原文、路径和任务不进事件。内容哈希不变。关键词不命中标题。
- 文字消息的文字链接仍按 ADR 0715。账单说明仍不套用实体。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- `pin_notice` 仍默认关闭。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
- 这段标题上的文字链接后来由 ADR 0785 要求长度大于 0。长度越过末尾时仍算画出来。第 21 个码元起仍不读。任务仍不读。
