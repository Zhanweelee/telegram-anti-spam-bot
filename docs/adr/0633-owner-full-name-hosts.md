# ADR 0633：交群的人画出的全名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

群主换人时，Android 的 `MessageObject` 在 `TL_messageActionChangeCreator` 上用 `replaceWithLink` 把操作的人画进这行服务文字，再画新群主。待确认交群的 `TL_messageActionNewCreatorPending` 先画待确认的新群主，再用 `replaceWithLink` 画操作的人。这就是 `UserObject.getUserName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。这两条都没有跳过自己。

Bot API 把换人放在 `chat_owner_changed.new_owner`，把离开放在 `chat_owner_left`。见 ADR 0595。当时名的长度大于 0 就丢掉姓。这份 Android 源码里没有名叫 `chat_owner_left` 的动作。现有条件在离开对象上仍读 `from`，空对象也读。新群主的名字仍按正文。见 ADR 0120。

换背景和拉进视频聊天这两行仍只读名。短链可以只写在姓上。把整段收成正文会改变内容哈希，关键词也会命中名字。

## 决策

- 只在已经会标成 `ownerNotice` 的提示上，从 `from` 会画出来的全名留主机名。换人要有新群主对象。离开只要是对象，空对象也读。两条同时出现时仍先认换人。
- 名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读。空格不截断。用户名不读。
- 新群主的名字仍按 ADR 0120 成为正文。已有别的正文时仍留在 `memberName`。新群主名字里的主机名仍排在全名前面。交群的人的全名不进正文，也不改内容哈希。关键词因此不命中。本群群名不读。正文里已有短链时，证据仍先记正文的主机名。
- 空的换人对象和布尔值不读发送者。普通消息不读 `from`。换背景和拉进视频聊天仍按原来的名。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`owner_notice` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不改群主。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续只读名 | 客户端把姓画在同一行里。姓上的短链会留在提示里。 |
| 把名字整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0120。 |
| 离开不读发送者 | 没有下一位时正文是空的。短链可以只写在离开的人的姓上。 |
| 换背景或拉人进视频聊天也改成全名 | 那两行用的是名。姓上的短链并没有出现在那一行。见 ADR 0593 与 ADR 0596。 |
| 新命令 `/ownername` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 交群或离开的人，全名里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。群主本身不变。
- 全名原文、路径和用户名不进事件。内容哈希不变。关键词不命中全名。
- 空白名不挡住姓。空格后面的网址仍读。新群主的名字仍按原来的正文。
- 新群主名字里已有短链时，证据仍先记那段名字的主机名。正文里已有短链时，证据仍先记正文的主机名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 拉进视频聊天后来按全名只留主机名。见 ADR 0634。换背景仍只读名。空的换人对象、布尔值和普通消息仍不读发送者。管理员仍豁免。干净的提示在 `owner_notice` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
