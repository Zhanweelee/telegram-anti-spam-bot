# ADR 0201：编码间隔不再贴出下一条主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

Android 不会在匹配前删掉百分号编码的换行、制表符、不换行空格或零宽字符。`%0Abit.ly/…` 打开的是 `0abit.ly`。`%09bit.ly/…`、`%C2%A0bit.ly/…`、`%E2%80%8Bbit.ly/…` 和 `%250Abit.ly/…` 也是把十六进制留在主机名开头。`%0A203.0.113.168/…` 不会打开这个地址。

`%09http://bit.ly/…`、`http%0A://bit.ly/…` 和 `ht%0Atp://bit.ly/…` 什么都不打开。`http:%0A//bit.ly/…` 会打开后面的 `bit.ly`。真正的换行后面仍会打开。

`%0Awww.bit.ly/…` 打开的是 `0awww.bit.ly`。这个主机名仍以 `.bit.ly` 结尾。`%0A.bit.ly/…` 打开的是 `0a.bit.ly`。`http://bit.ly%0Aevil.com/…` 仍先打开 `bit.ly`。

标签中间的编码仍要去掉。`bit%E2%80%8B.ly` 和 `b%0Ait.ly` 仍按短链删除。`t.me/+` 中间的 `%E2%80%8B` 仍是邀请。公开的 `foldEncodedGaps` 仍整段去掉这些编码。

主机名扫描如果先把贴在前面的 `%0A` 删掉，`%0Abit.ly` 会变成 `bit.ly`，`%0A203.0.113.168` 会变成一条裸 IP，`ht%0Atp://bit.ly` 会变成 `http://bit.ly`。

## 决策

- 只改主机名扫描。公开的 `foldEncodedGaps` 仍去掉每一段 `foldMatchText` 会删掉的百分号编码，含第二层 `%25HH`。
- 主机名扫描里，编码间隔前面不是 ASCII 标签字符时留下。标签字符是字母、数字、下划线或连字符。
- 编码间隔后面只隔着字母就到 `://` 时也留下。`ht%0Atp://` 和 `http%0A://` 都算。
- 标签中间的编码仍去掉。`bit%E2%80%8B.ly` 和邀请码中间的零宽编码仍收成原来的结果。
- 真正的换行、制表符和不换行空格仍先去掉。`%20` 仍保留。
- 每段仍走现有的短链、裸 IP、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 主机名扫描里的编码间隔一律留下 | `bit%E2%80%8B.ly` 和邀请码中间的零宽编码会漏掉。 |
| 公开的 `foldEncodedGaps` 一起改 | 结构化网址和已有调用仍要整段去掉这些编码。 |
| 只留 `%0A` | `%09`、`%C2%A0`、`%E2%80%8B` 和 `%250A` 仍会贴出短链。 |

## 后果

- `%0Abit.ly/…`、`%09bit.ly/…`、`%C2%A0bit.ly/…`、`%E2%80%8Bbit.ly/…` 和 `%250Abit.ly/…` 留着。`%0A203.0.113.168/…` 留着。
- `%09http://bit.ly/…`、`http%0A://bit.ly/…`、`ht%0Atp://bit.ly/…` 和 `http://%0Abit.ly/…` 留着。
- `bit%E2%80%8B.ly`、`b%0Ait.ly`、换行后面的 `bit.ly` 和 `http:%0A//bit.ly/…` 仍按短链删除。
- `%0Awww.bit.ly/…` 和 `%0A.bit.ly/…` 仍按短链删除。证据是 `0awww.bit.ly` 和 `0a.bit.ly`。
- `http://bit.ly%0A…` 仍按 `bit.ly` 删除。`http://203.0.113.168%0A…` 仍按这个地址删除。`t.me/+` 中间的零宽编码仍按邀请删除。路径不进证据。
- 百分号编码的点状间隔号贴在已经写完的主机名或协议前面时不再收成点。见 ADR 0202。
