# ADR 0242：壁纸短名不读 text，用户名仍读

- 状态：已接受
- 日期：2026-11-03

## 背景

Android `LaunchActivity` 在路径以小写 `bg/` 开头时打开壁纸，不把 `text` 写进输入框。命令大小写不同、或路径对不上这道斜杠时，链接继续按用户名解析，`text` 仍写进输入框。桌面端把 `bg/` 后面符合 `[A-Za-z0-9._~-]+` 的一段收成 `tg://bg`，并保留原来的查询参数。壁纸预览只读 `mode`、`bg_color`、`gradient`、`color`、`slug`、`intensity` 和 `rotation`，不读 `text`。短名后面的斜杠对不上这个式子，桌面端把它收成应用名或帖子，普通用户仍写草稿。波浪号和连字符都在这个字符集里。

`t.me/bg?text=`、末尾只有斜杠，以及 `bg.t.me?text=` 收成 `tg://resolve`，普通用户仍写草稿。`bg.t.me/数字` 两边都不写草稿。`tg://resolve?domain=bg` 仍是用户名。

## 决策

- `t.me`、`telegram.me`、`telegram.dog` 以及一层 `www.` 上，第一段正好是小写 `bg`，路径不以斜杠结束，且正好还有一段、这段匹配 `[A-Za-z0-9._~-]+` 时，不从 `text` 抽主机名。
- `bg.t.me` 后面正好一段、且这段匹配同一字符集时同样不读。没有路径时仍读。
- 末尾斜杠，以及命令不是小写 `bg` 时仍读。
- `t.me/bg`、`t.me/bg/` 和 `tg://resolve?domain=bg` 仍读。
- 这个主机名走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。`text` 不进入正文，也不参与关键词。
- 用户名和短名不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续把 `bg` 放进保留名 | `t.me/bg?text=` 会漏掉。两边都把它当成用户名。 |
| 查询里留着 `text` 就继续读 | 桌面端保留查询是为了壁纸的颜色和强度。`withUrlParams` 不读 `text`。 |
| 波浪号仍按应用名读 | 桌面端壁纸字符集包含波浪号。`paper~now` 两边都打开壁纸。 |
| 命令不区分大小写 | Android 只认小写 `bg/`。`Bg/短名` 仍写草稿。 |
| 末尾再多一道斜杠也不读 | 桌面端把 `bg/短名/` 收成应用名或帖子，仍写草稿。 |
| 全数字的第二段仍按帖子读 | 没有多余斜杠时，两边都不把它写成帖子草稿。 |

## 后果

- `t.me/bg`、`t.me/bg/`、`bg.t.me`、`tg://resolve?domain=bg`、`t.me/Bg/短名` 和 `t.me/bg/短名/` 的 `text` 是裸 IP、默认短链或邀请时删除。证据仍只有主机名。
- `t.me/bg/paper209`、`bg/paper-now`、`bg/paper~now` 和 `bg.t.me/数字` 留着。
- 用户名和短名不进证据。
