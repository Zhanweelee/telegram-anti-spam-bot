# ADR 0722：引用条上的文字链接不能越过正文

- 状态：已接受
- 日期：2026-11-07

## 背景

普通回复的引用条画出说明或正文的前 150 个 UTF-16 码元。起点落在这段里的文字链接才读。见 ADR 0711。没有任务号时，清单标题同样只取前 150 个码元。见 ADR 0709。

Android 先看链接起点有没有落在整段正文里。起点大于或等于正文长度时，这段链接不会画上去。正文短于 150 个码元时，引用条只画出这段正文。

现在的窗口按 150 判断。正文只有两个码元时，起点在第 2 个码元之后、又小于 150 的文字链接仍会留下主机名。这条链接没有画在引用条上。

## 决策

- 说明、正文和清单标题上的文字链接，起点必须小于画出的长度。画出的长度是正文长度和 150 里较小的那个。
- 起点落在画出的这段里时，仍只留主机名。起点正好等于正文长度时不读。
- 第 151 个码元起仍不读。原文不进正文。预览不改内容哈希。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续按 150 判断 | 正文更短时，没画上去的链接会删掉这条回复。 |
| 只改说明，不改清单标题 | 清单标题同样先画出标题，再套 150 的窗口。 |
| 把链接原文拼进正文 | 关键词会命中没画出来的地址。 |

## 后果

- 起点越过正文的文字链接不再留下主机名。仍落在画出的这段里的短链、邀请或裸 IP 会删除。证据只有主机名。
- 被截断的路径不进事件。关键词不命中这行。内容哈希不变。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
