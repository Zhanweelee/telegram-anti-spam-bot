# ADR 0217：写完的主机名和后面的域名之间的点状间隔号收成一个点

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 把中间点、项目符号、全角句点和同类点状间隔号算进标签。`bit.ly·evil.com/…`、`www.bit.ly．evil.com/…` 和 `203.0.113.10·evil.com/…` 各是一条链接。连续两个间隔号也连成一条。斜杠前面的 `bit.ly·/…` 只打开 `bit.ly`。`bit.ly·evil·com/…` 在第一个间隔号前停住，只打开 `bit.ly`。

粘连扫描已经把这些间隔号收成 ASCII 点。停住扫描故意留下它们，用来找回被路径吞掉的下一条网址。留下以后，`bit.ly·evil.com` 又被读成短链，`203.0.113.10·evil.com` 又被读成裸 IP。两个间隔号在粘连扫描里会先收成一个点再留下第二个，同样停在 `bit.ly`。

`bit·ly` 仍由粘连扫描收成短链。停住扫描不把唯一的间隔号收成点。`example.com.·http://bit.ly` 的间隔号跟在 ASCII 点后面，后面的网址仍单独打开。

## 决策

- 只改主机名扫描。公开的 `foldDotLookalikes` 和关键词比较不改。
- 写完的裸主机名或点分 IPv4 后面，一段点状间隔号或句号在后面是 ASCII 域名时收成一个点。已经收成点、后面还粘着间隔号的，也收成这一个点。
- 斜杠、路径，以及后面不是 ASCII 域名时，间隔号留着。`bit.ly·evil·com` 仍按 `bit.ly` 删除。
- 间隔号是主机名里唯一的点时，停住扫描留着。粘连扫描仍收成短链。
- 每段仍走现有的短链、裸 IP、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 停住扫描也收掉全部间隔号 | `bit．ly．com/http://t.co` 会把后面的短链吞进路径。停住扫描就是为了留下它。 |
| 只改粘连扫描 | 停住扫描仍从 `bit.ly·evil.com` 读出 `bit.ly`。 |
| 后面还有间隔号也收成域名 | `bit.ly·evil·com` 会留着。Android 只打开 `bit.ly`。 |

## 后果

- `bit.ly·evil.com/…`、`www.bit.ly．evil.com/…`、`bit.ly··evil.com/…` 和 `203.0.113.10·evil.com/…` 留着。
- `example.com·bit.ly/…` 仍按短链删除。证据是 `example.com.bit.ly`。
- `203.0.113.10·bit.ly/…` 按短链删除。证据是 `203.0.113.10.bit.ly`，不是那条裸 IP。
- `bit.ly·/…` 和 `bit.ly·evil·com/…` 仍按 `bit.ly` 删除。`bit·ly/…` 仍删除。
- `example.com.·http://bit.ly/…` 仍按后面的短链删除。路径不进证据。
