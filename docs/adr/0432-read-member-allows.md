# ADR 0432：私聊可以查看一个人的单独限制

- 状态：已接受
- 日期：2026-11-04

## 背景

`/member` 只回报身份、是否还在群里，以及封禁或限制的到期时间。`/perms` 回报的是全群默认权限。一个人被单独限制时，16 项权限可以各不相同。管理员从 `/member` 只能看到「禁言中」，看不出哪一项还开着。

`getChatMember` 在状态是 `restricted` 时带上这些布尔值。其它状态没有这组字段。`/perms` 会把缺省的反应和话题权限收成另一项开关。单独限制如果沿用这套收法，会把没返回的字段写成已经允许。

## 决策

- 私聊命令 `/allows <chatId> <actorId>`。两个 id 都要匹配 `^-?\d{1,20}$`。多出来的参数不发出请求。群聊里的同样文本不执行。
- 配置中的管理员可以查看任意群。接入目录里的人只能查看自己的群。
- 命令调用 `ModerationPort.readMemberAllows`。配了 token 时，Telegram 适配器调用 `getChatMember`，参数只有 `chat_id` 和 `user_id`。
- 返回的 `user.id` 必须和请求的成员号一致。名字、用户名和标签不进入回复，也不进入日志。
- 状态是 `creator`、`administrator`、`member`、`left` 或 `kicked` 时，回复单独限制无。不读取这些状态上偶然出现的权限字段。
- 状态是 `restricted` 时，16 个布尔值都必须在。`true` 写 on，`false` 写 off。缺字段或不是布尔值时整份回复是「参数无效」，不写出已经读到的项。
- `is_member` 缺省时写人还在。不是布尔值时整份回复是「参数无效」。`until_date` 为 0 或缺省时不写到期。正整数写成 unix 秒。
- 没有 token、没有这个方法，或调用失败时回复「参数无效」。日志只写 `operator_rejected`，带上 eventId、chatId 和命令名。不写异常文本、token、名字或标签。
- 不调用 `restrictChatMember`。不修改 `/member` 和 `/perms`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把权限行加进 `/member` | `/member` 的回复已经固定。普通成员会多出一串并非单独限制的开关。 |
| 缺字段时沿用 `/perms` 的收法 | 会把没返回的反应或话题写成已经允许。单独限制的布尔值在文档里是必填。 |
| 没有 token 时回复全部 off | 人可能并没有被限制。管理员会按一份编出来的开关做决定。 |

## 后果

- 看一个人的单独限制是一次 `getChatMember`。`/member` 仍是另一次请求。
- 30 天保留期不动。
