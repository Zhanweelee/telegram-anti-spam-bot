# ADR 0317：连字符末尾的草稿文字字母留在带协议的标签里

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 在带协议主机名以连字符结束时，仍把后面的希腊文、西里尔文、亚美尼亚文和非 ASCII 拉丁字母算进这条链接。`http://bit.ly-α/…`、`http://bit.ly--α/…`、`http://www.bit.ly-α/…` 和 `http://203.0.113.10-ա/…` 的主机名不是前面的短链或裸 IP。`http://bit.ly-α.bit.ly/…` 的主机名仍以 `bit.ly` 结尾。见 ADR 0230。

没有协议的 `bit.ly-α/…` 和 `www.bit.ly-α/…` 只打开前面的短链。`#`、空格、换行、单独的连字符和连字符后再接一个点也退回短链。

`http://bit.ly-α@evil.com/…` 在看得见的正文里仍打开 `bit.ly`。隐藏草稿先把连字符和字母收成同一个标签，`@` 就变成用户信息，主机名记成 `evil.com`。没有协议时，这段字母留在标签里，短链不再单独打开。

## 决策

- 分享 `text`、私聊预填 `tg://msg` 的 `text` 和用户名草稿的 `text`，在 `http://` 或 `https://` 的主机名末尾先有一个或多个连字符，再是一段这类字母，而且紧接着是 `@` 时，先把连字符和这段字母换成空格。
- 没有协议时，写完的裸主机名或 `www.` 后面的连字符加这段字母直接拿掉，前面的短链单独打开。
- 主机名取最长的严格域名，不在中间的短链后缀停住。点分 IPv4 同样。
- 路径、问号、结尾、写完的端口和再接一个域名时，带协议的字母仍交给主机名扫描。
- `#`、空格、换行、单独的连字符和连字符后再接一个点仍按原来的规则收掉。
- 不改带协议网址的整段匹配。闭合分享链接里的网址不走这道切开。公开的折叠不改。
- 证据只留主机名。路径不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 连字符后面的字母一律收掉 | `http://bit.ly-α/…` 会按短链删除。Android 打开的不是 `bit.ly`。 |
| `@` 前面的字母也留在标签里 | `http://bit.ly-α@evil.com/…` 会漏掉已经打开的短链。 |
| 没有协议也留下 | `bit.ly-α/…` 会漏掉。Android 只打开 `bit.ly`。 |

## 后果

- `t.me/share/url?text=http://bit.ly-α/…`、`http://bit.ly--α/…`、`http://www.bit.ly-α/…`、`http://203.0.113.10-ա/…` 和 `http://bit.ly-α/http://t.co/…` 留着。路径不进证据。
- `http://bit.ly-α.bit.ly/…` 仍按短链删除。证据是 `bit.xn--ly--qxc.bit.ly`。
- `bit.ly-α/…` 和 `www.bit.ly-α/…` 仍按短链删除。
- `http://bit.ly-α@evil.com/…`、`http://bit.ly-α#…`、换行和中间有空格的写法仍按短链删除。证据是 `bit.ly`。
- `http://bit.ly-/…` 和 `http://bit.ly-.α/…` 仍按短链删除。
- 第 61 个字母仍让短链单独打开。`bαit.ly` 仍按短链删除。
