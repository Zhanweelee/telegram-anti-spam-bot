# ADR 0660：新加清单任务只读画出的前三条

- 状态：已接受
- 日期：2026-11-06

## 背景

有人给清单补上任务时，Android 的 `TL_messageActionTodoAppendTasks` 把任务标题画进服务消息。一条、两条或三条时，这几条标题都画出来。四条起只画 `list` 的前三条，其余只显示还剩几条。标题来自 `formatTaskTitle`，文字和实体都在这三条里。完成者画在清单卡片上，不画在这条服务消息的第四条之后。

Bot API 把这些任务放在 `checklist_tasks_added.tasks`。先前按数组顺序读完全部文字、文字链接、按标识提及、自定义表情和完成者。第四条起的短链会删掉客户端没有画出的后半段。

三条及以内仍全部画出。清单自己的 `checklist.tasks` 在卡片上逐条画出，不受这条限制。见 ADR 0089、ADR 0552、ADR 0567、ADR 0572 和 ADR 0641。

## 决策

- `checklist_tasks_added.tasks` 的长度大于等于 4 时，只读下标 0、1、2。这三条的 `text`、`text_entities` 和完成者仍按原来的方式留主机名。文字链接、按标识提及和自定义表情也只看这三条。
- 第四条起的文字、文字链接、按标识提及、自定义表情和完成者不读。不进正文，也不进 `addedText`。
- 长度是 1、2 或 3 时，仍全部读。空文字仍跳过正文拼接，但不把后面一条提前算进这三条。数组长度按原始条目计，包括空对象。
- 正文和 `addedText` 仍把会画出来的非空文字用一个普通空格拼起来。已有别的正文时，这段最多 3029 字。画出的任务里，第 3030 字起仍不进字段，主机名仍从整段抽取。
- 发送者仍按全名。只要数组里还有一条长度大于 0 的文字，就仍读这个人。清单自己的任务不受影响。嵌套的 `checklist_message` 不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`checklist_added` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续读第四条起 | 服务消息不画这些标题。会删掉没有出现在这行里的网址。 |
| 清单卡片也只读前三条 | 卡片逐条画出全部任务。这条限制只属于新加任务的服务消息。 |
| 按非空文字计数到三条 | 客户端用的是数组长度，空条目仍占一个位置。 |
| 新命令 `/addedtasks` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 四条起，前三条里的短链、邀请或裸 IP 会删除这条提示。证据只有主机名。第四条起的短链留下。
- 三条及以内仍全部参与正文、`addedText` 和主机名。
- 第四条起的原文、路径、提及、表情和完成者不进事件。关键词不命中这段。内容哈希不含这段。
- 画出的任务超过 3029 字时，字段仍截断，主机名仍从整段抽取。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 发送者仍按全名。清单自己的任务不受影响。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
