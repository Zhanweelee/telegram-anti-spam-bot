# ADR 0535：正文旁边的按钮文字也走关键词和默认正则

- 状态：已接受
- 日期：2026-11-05

## 背景

ADR 0063 在没有更前面的正文时，把内联按钮的 `text` 拼成正文。已有正文或文件名时，按钮上的「免费领取」看不见。ADR 0086 只从这段文字抽出主机名。短链仍会删除，「加微x」会留下。

按钮自己成为正文时，现有关键词已经能读到整段。`regex_hint` 仍默认关闭，所以只有一颗「加微x」按钮时继续留下。

回调数据、复制到剪贴板的句子和回复键盘仍不是用户看见的按钮文字。

## 决策

- 已有别的正文，且内联按钮文字去掉两端空白后仍有字时，事件另留 `buttonText`。只留拼好之后的前 256 字。按钮之间仍用一个普通空格分开。
- 按钮文字自己就是正文时不设这个字段。正文和 `textSha256` 仍按 ADR 0063。
- 关键词和 `regex` 同时看正文、`senderTag`、`buttonText` 和 `profile`。证据仍是原来的摘要。按钮原文不进证据，也不进日志。
- 规则条件增加 `buttonText: true`。消息上有这个字段时为真。
- 新规则 `button_text_regex` 默认打开。条件是 `buttonText`，检测器是现有的 `regex`，命中后 `delete`。
- 「免费领取」和「加微信」仍走已经打开的关键词规则。
- `regex_hint` 仍默认关闭。关掉它不会关掉 `button_text_regex`。
- 不读取 `callback_data`、`copy_text` 的句子和回复键盘。`url` 仍只留主机名。
- 不改 ADR 0026 的基础检测器名单。`keyword` 和 `regex` 已经在里面，超额后这两条仍会跑。
- `chats.json` 整份替换的群不会自动带上 `button_text_regex`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 默认打开 `regex_hint` | 普通消息会被同一份模式删除。这次要读的是正文旁边的按钮。 |
| 把按钮文字拼进正文 | 会改变 `textSha256`。ADR 0063 已经拒绝。 |
| 连回调数据和回复键盘一起读 | 那不是这条消息上看得见的按钮文字。 |

## 后果

- 正文旁边的按钮含「免费领取」或「加微信」时，按关键词删除。含 `t.me/+`、「加微x」或「加微X」时，按 `button_text_regex` 删除。证据不含按钮原文。
- 按钮干净时消息留下。按钮自己就是正文时，「加微x」仍要打开 `regex_hint`。
- 第 257 个字符起不进事件。主机名仍从整段按钮文字抽取。写在按钮文字里的路径会留在 `buttonText`，不进审计。
- 回调数据、复制句子和回复键盘仍不进事件。
- 关掉 `button_text_regex` 后，这种按钮回到只看关键词和短链。
- 整份替换规则的群要自己加上这条，才会删除按钮上的「加微x」。
- 30 天保留期没有改。
