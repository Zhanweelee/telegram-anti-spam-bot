# ADR 0699：回复抬头只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

回复一条消息时，Android 在引用条上画出被回复的人。普通回复先看这条被回复的消息是不是转发。是转发时，名字来自 `getForwardedName`：用户是 `UserObject.getUserName`，群和频道是标题，隐藏转发是 `from_name`。不是转发时，用户仍是全名，聊天是标题。发送者编号是 0 时，才改用所在频道的标题。

名和姓都先去掉两端空白，名在前。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。被回复的原文画在名字下面，不和名字拼成一段。来源签名不画在这个名字里。有外部回复时，这行改画外部来源，不画本条 `reply_to_message` 上的人。

Bot API 把本条回复放在 `reply_to_message`。转发来源放在 `forward_origin`，旧字段是 `forward_from`、`forward_from_chat` 和 `forward_sender_name`。外部回复另放在 `external_reply`。

ADR 0547 不把被回复的原文收进事件。ADR 0618 的付款文字也不画回复发送者。引用条上的名字仍会留下短链。

## 决策

- `reply_to_message` 是对象，且没有 `external_reply` 对象时，从引用条上会画出来的名字留主机名。
- 被回复的消息能画出转发来源时，只读那个来源，不读转发者。现代来源优先。用户读全名。群和频道只读标题。隐藏显示名整段留下。来源签名不读。来源缺了才改读转发者。
- 没有转发来源时，`sender_chat` 是对象就读标题，不读 `from`。没有这个对象时，`from` 读全名。名和姓都去掉两端空白，名在前。空白名不挡住姓。空格不截断。两边都没有时，只有 `chat.type` 正好是 `channel` 才读频道标题。群标题不因此改读。
- 标题不截断。编号和本群相同也读。用户名不读。
- 被回复的原文、说明、手动引用和外部回复不读。外部来源上画出的名字后来由 ADR 0700 只留主机名。
- 主机名仍进消息已有的 `hosts`。邀请仍进 `invites`。名字不进正文，也不改内容哈希。关键词因此不命中。正文里已有短链时，证据仍先记正文的主机名。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。短链仍走已有的 `links`。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 连被回复的原文一起读 | 原文是上一条消息。引用条上的名字才画在这一条里。 |
| 连外部回复一起读 | 外部回复是另一条消息的预览。有它时这行不再画本条回复的人。 |
| 来源签名也读 | `getForwardedName` 不把签名放进这个名字。 |
| 群没有发送者时也读群名 | 这个回退只用频道编号。 |
| 新命令 | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 引用条上的名字出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。
- 被回复的原文、说明、签名和用户名仍不进事件。名字不改内容哈希。关键词不命中这个名字。外部来源上画出的名字后来由 ADR 0700 只留主机名。预览正文、链接预览和来源签名仍不读。
- 正文里已有短链时，证据仍先记正文的主机名。付款文字上的名字和账单标题仍按原来的顺序排在前面。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 没有回复时不读。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
