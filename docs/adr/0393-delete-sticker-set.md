# ADR 0393：私聊可以删除一个群贴纸包

- 状态：已接受
- 日期：2026-11-04

## 背景

超级群的群贴纸包被换成垃圾贴纸时，管理员要能拿掉它，同时留下消息。官方有一次只删群贴纸包的调用。

`deleteChatStickerSet` 删除一个超级群的群贴纸包。参数只有 `chat_id`。bot 必须是管理员，并且有相应的管理权限。`getChat` 可能带有可选字段 `can_set_sticker_set`，用来判断 bot 能不能用这个方法。成功时返回 True。

这条调用不设置新的贴纸包，也不读取贴纸包名字。

没有 token 时，内存适配器可以把这次请求记下来。私聊如果复用这次成功，回复会写成贴纸包已经删除。贴纸包名字不能进回复或日志。

## 决策

- 私聊命令 `/delstickers <chatId>`。群 id 匹配 `^-?\d{1,20}$`。多出来的参数不发出请求。群聊里的同样文本不执行。
- 配置中的管理员可以操作任意群。接入目录里的人只能操作自己的群。
- 调用 `ModerationPort.deleteStickerSet`。适配器调用 `deleteChatStickerSet`，只带 `chat_id`。
- 不调用 `setChatStickerSet`。不调用 `getChat`。不读取贴纸包名字。
- 回复写明群贴纸包被请求删除，消息还在。
- 没有 token、没有这个方法，群号不合法，或调用失败时回复「参数无效」。日志只写 `operator_rejected`，带上 eventId、chatId 和命令名。不写异常文本、token、原文或贴纸包名字。
- 没有 token 的 Worker 不把内存里的记录回复成已经成功。
- 不修改黑名单、白名单、封禁或禁言。不读取消息正文。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 先用 `getChat` 看 `can_set_sticker_set` | 多一次子请求，还会带回标题、简介和邀请链接。删除本身不需要这些。 |
| 换成另一个贴纸包 | 官方有直接删除的方法。设置新包还要交出贴纸包名字。 |
| 私聊群号在本地直接拒绝 | 群号和私聊号的形状会重叠。不是超级群或缺少权限时，由 Telegram 返回失败。 |
| 没有 token 时也回复「已删除」 | 贴纸包还在。管理员会以为已经拿掉。 |

## 后果

- 成功只表示 Telegram 接受了这一次删除。不是超级群、没有群贴纸包，或缺少相应管理权限时，回复是「参数无效」。
- 消息还在。
- 一次删除是一次 Telegram 子请求。封禁、禁言和黑名单都不变。
- 30 天保留期不动。
