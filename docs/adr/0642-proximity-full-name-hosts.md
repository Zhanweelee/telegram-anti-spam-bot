# ADR 0642：靠近提醒上画出的两个人的全名成为正文

- 状态：已接受
- 日期：2026-11-06

## 背景

两个人共享实时位置并靠近时，Android 的 `MessageObject` 在 `TL_messageActionGeoProximityReached` 上用 `replaceWithLink` 画出触发者和设置者。这就是 `UserObject.getUserName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。

见 ADR 0121。当时正文还收了用户名。短链可以只写在姓上，也可以只写在用户名上。用户名上的词并没有画出来。操作的人写在 `from`，这行服务文字不画这个人。见 ADR 0597。

没有更前面的正文时，这两个人的名字就是正文。已有正文时，名字另留在 `memberName`。见 ADR 0554。

## 决策

- `proximity_alert_triggered` 的 `traveler` 再 `watcher`，按会画出来的全名成为正文。名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读这个人。空格不截断。用户名不读。
- 没有更前面的正文时，这段全名就是正文。已有正文时，拼起来的整段自己不是正文，就另留前 4096 字在 `memberName`。主机名仍从这段全名抽取。
- 距离是大于等于 0 的安全整数时，`from` 仍只读名。名的长度大于 0 时不读姓。空白也算有名。这个人的名字不进正文。负数、小数、字符串、布尔值和空对象不读 `from`。
- 用户 id、距离、语言代码和本群群名不读。入群名单、视频聊天邀请和换群主仍按原来的可见名字，含用户名。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`proximity_notice` 仍默认关闭。短链仍走已有的 `links`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续把用户名收进正文 | 这行服务文字不画用户名。用户名上的短链和关键词会删掉看不见的字。 |
| 连操作的人改成全名 | 这行不画 `from`。见 ADR 0597。 |
| 把全名改成只留主机名、不进正文 | 关键词广告名会留在靠近这行上。见 ADR 0121。 |
| 新命令 `/nearname` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 两个人全名里的短链、邀请或裸 IP 会删除这条靠近提醒。证据只有主机名。
- 全名里的关键词仍命中这段正文。用户名里的关键词不命中。用户名不进事件。
- 空白名不挡住姓。空格后面的网址仍读。
- 已有别的正文时，证据仍先记正文的主机名。这段全名另留在 `memberName`。
- 消息发送者后来由 ADR 0697 不读。触发者和设置者的全名仍按正文。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 入群、邀请和换群主的可见名字仍含用户名。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
