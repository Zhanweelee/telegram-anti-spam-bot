# ADR 0727：后加任务上的文字链接不能越过正文

- 状态：已接受
- 日期：2026-11-07

## 背景

有人给清单补上任务时，服务消息画出这些任务的标题。一条到三条都画出来。四条起只画前三条。见 ADR 0660。

Android 用 `formatTaskTitle` 画每一条。它再交给 `formatTextWithEntities`。文字链接的起点大于或等于这条任务文字时，链接不会画上去。

现在画出的任务会读全部文字链接。起点已经越过正文的链接仍会留下主机名。

清单气泡上的任务已经要求起点落在任务文字里。见 ADR 0726。后加任务是另一条服务消息。

## 决策

- `checklist_tasks_added` 上会画出来的每一条任务，文字链接的起点必须小于这条 `text` 的长度。
- 四条起仍只看前三条。第四条起的文字链接仍不读。
- 任务文字里的普通网址仍读。仍只留主机名。
- 勾完的任务、投票选项、游戏说明、礼物和引用不在这条里。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`checklist_added` 仍默认关闭。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续读全部文字链接 | 没画上去的链接会删掉这条提示。 |
| 勾完的任务也一起改 | 那是另一条服务消息。这条只改新加的任务。 |
| 第四条也按正文长度过滤 | 第四条本来就不画，已经不读。 |

## 后果

- 起点越过画出的任务文字的文字链接不再留下主机名。仍落在这段文字里的短链、邀请或裸 IP 会删除。证据只有主机名。
- 被截断的路径不进事件。写在任务里的路径在已有正文时仍留在 `addedText`。关键词不命中没画上去的链接。内容哈希不变。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
