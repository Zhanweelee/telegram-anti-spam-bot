# ADR 0104：一层百分号编码的括号点收成点

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0103 把 `[.]`、`(.)` 和 `{.}` 收成 ASCII 点。百分号编码的 `%5B.%5D` 仍把主机名拆开。`%5B` 不在 ADR 0072 的字母表里，所以那一层不会先把它收成括号。

第二层 `%255B` 和 `%252E` 按既有规则留下。

## 决策

- 抽主机名之前，一层 `%5B.%5D`、`%28.%29`、`%7B.%7D` 收成 ASCII 点。中间的点可以是 `.`、`%2E` 或句号 `。`。大小写不区分。
- 第二层 `%255B.%255D` 和 `%5B%252E%5D` 不收。
- 括号里的普通空格仍不收。单独的句号仍不收。
- 关键词和正则不走这一层。
- 事件里的正文和 `textSha256` 不变。不新增检测器，也不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把所有 `%5B` 收成括号 | 只会动包住点的这一对。其它括号仍留在正文里。 |
| 连第二层一起收 | `%252E` 和 `%25HH` 的第二层分隔符已经留下。这一对同样留下。 |
| 在关键词里也收 | `不是免费%5B.%5D领取` 不该对上 `免费领取`。 |

## 后果

- `bit%5B.%5Dly/…` 和 `bit%5B%2E%5Dly/…` 走现有短链规则。`t%28.%29me/+…` 走现有邀请规则。
- `example%5B.%5Dcom` 仍保留。
- `bit%255B.%255Dly` 和 `bit%5B%252E%5Dly` 仍抽不出来。
- 关键词 `免费领取` 不命中 `不是免费%5B.%5D领取`。
- 重复计数仍按原文哈希。
