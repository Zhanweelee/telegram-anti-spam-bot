# ADR 0163：间隔前停住的主机名也留下

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0065 和 ADR 0067 在抽主机名前去掉制表符、换行、不换行空格，以及这些字符的一层百分号编码。`bit.\nly` 因此仍能对上短链。

Android `LinkifyPort.WEB_URL` 不会跨过这些字符。`http://bit.ly\tevil.com` 和 `http://bit.ly%0Aevil.com` 打开的是 `bit.ly`。去掉间隔之后，主机名变成 `bit.lyevil.com`，对不上短链，也不是四段数字。`http://203.0.113.130\u00A0…` 同样打开 `203.0.113.130`。

普通空格仍把地址拆开。夹在标签中间的间隔仍先去掉，被拆开的短链和邀请保持原来的命中。

## 决策

- 粘连扫描继续去掉这些间隔。另外再用保留间隔的折叠抽一遍主机名，并入同一次判断。
- 两边都走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 邀请仍只从粘连扫描读取。间隔后面的路径不因为这次扫描改记成邀请。
- 已经写在 `text_link`、按钮或其它结构化字段里的地址整段打开。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 只留粘连后的主机名 | 点下去打开的是间隔前面的短链或裸 IP。 |
| 间隔一律保留、不再粘连 | `bit.\nly` 和百分号编码的零宽字符会漏掉。 |
| 间隔后面的路径改记成邀请 | `t.me` 和制表符后面的邀请码，Android 打开的是没有路径的 `t.me`。现有粘连结果保持不变。 |

## 后果

- `http://bit.ly` 后接制表符或 `%0A`，以及 `http://203.0.113.130` 后接不换行空格，按现有短链或裸 IP 规则删除。证据仍只有主机名。
- `http://example.com` 后接制表符留着。普通空格仍拆开地址。
- `bit.\nly` 和 `t.me/+` 中间的零宽字符仍按粘连结果删除。路径不进证据。
- 百分号编码的点、字母和方括号包住的点前，高亮停住的主机名另外留下。见 ADR 0164。
