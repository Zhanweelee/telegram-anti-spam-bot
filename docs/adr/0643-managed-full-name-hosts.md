# ADR 0643：新建受管 bot 上画出的全名成为正文

- 状态：已接受
- 日期：2026-11-06

## 背景

用户新建一个由当前 bot 管理的 bot 时，Android 的 `MessageObject` 在 `TL_messageActionManagedBotCreated` 上用 `replaceWithLink` 画出这个新 bot。这就是 `UserObject.getUserName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。

见 ADR 0322。当时正文还收了用户名。短链可以只写在姓上，也可以只写在用户名上。用户名上的词并没有画出来。

这行还会画对话另一头的人。从用户的客户端看，那是正在对话的父 bot，不是这条更新上的 `chat` 或 `from`。

没有更前面的正文时，新 bot 的名字就是正文。已有正文时，名字另留在 `managedName`。见 ADR 0556。

## 决策

- `managed_bot_created.bot` 按会画出来的全名成为正文。名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读这个人。空格不截断。用户名不读。
- 没有更前面的正文时，这段全名就是正文。已有正文时，拼起来的整段自己不是正文，就另留前 4096 字在 `managedName`。主机名仍从这段全名抽取。
- 不读取 bot 编号、`is_bot`、`language_code`、令牌、`from` 上的姓名和 `chat` 的标题或名字。对话另一头的人不在这条更新上。
- 分享来的用户、入群名单、视频聊天邀请和换群主仍按原来的可见名字，含用户名。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。短链仍走已有的 `links`。`managed_name_regex` 仍只看这段画出的全名。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续把用户名收进正文 | 这行服务文字不画用户名。用户名上的短链和关键词会删掉看不见的字。 |
| 连对话另一头的人一起读 | 客户端画的是父 bot。更新里的私聊对象是创建者，不是这行上的第二个人。 |
| 把全名改成只留主机名、不进正文 | 关键词广告名会留在新建 bot 这行上。见 ADR 0322。 |
| 连入群、邀请和分享用户一起去掉用户名 | 这一轮只改这行画出的新 bot。 |

## 后果

- 新 bot 全名里的短链、邀请或裸 IP 会删除这条服务消息。证据只有主机名。
- 全名里的关键词仍命中这段正文。用户名里的关键词不命中。用户名不进事件。
- 空白名不挡住姓。空格后面的网址仍读。
- 已有别的正文时，证据仍先记正文的主机名。这段全名另留在 `managedName`。和正文相同的全名不重复留。
- 创建者的姓和用户名不进事件。bot 编号和令牌仍不读。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 分享用户、入群、邀请和换群主的可见名字仍含用户名。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
