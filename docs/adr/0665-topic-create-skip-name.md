# ADR 0665：新建话题不再读发送者的名字

- 状态：已接受
- 日期：2026-11-06

## 背景

新建论坛话题时，Android 的 `MessageObject` 在 `TL_messageActionTopicCreate` 上把这行设成 `TopicCreated`。英文是 “Topic was created”。短句 `TopicWasCreatedAction` 只把话题名填进 “%s”。两处都不画创建的人。

改名、换图标、关掉、重开、隐藏和重新显示仍用 `ContactsController.formatName` 画出全名。见 ADR 0626 与 ADR 0625。

Bot API 把新建放在 `forum_topic_created`。ADR 0605 和 ADR 0626 仍从 `from` 读名。名上的短链会删掉一条成员看不到这个名字的提示。话题名已经按原来的正文读取。

## 决策

- `forum_topic_created.name` 长度大于 0 时，不从 `from` 抽主机名。空白名字也算新建。名、姓和用户名都不读。
- 同一条上还有改名时，仍先认新建，因此也不读发送者。空的新建名字仍落到改名，改名和只换图标仍按全名。
- 话题名仍按原来的正文。话题名里的短链仍删除。图标颜色和自定义表情编号仍不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`topic_notice` 仍默认关闭。8 个主机名的上限不变。不调用 `editForumTopic`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 新建继续只读名 | 这行不画人。名上的短链不是成员看到的字。 |
| 新建改成全名 | 姓同样不在这行里。 |
| 话题名也不读 | 成员仍看得到话题名。 |

## 后果

- 新建话题上，发送者名字里的短链、邀请或裸 IP 不再删除这条消息。话题名里的短链仍会删。
- 名字不进事件。内容哈希不变。关键词不命中这些名字。
- 改名、只换图标、关掉、重开、隐藏和重新显示仍按全名删除。发送者是频道时后来由 ADR 0672 只读频道标题。付费帖仍不删除。见 ADR 0356。
- `topic_notice` 关闭时，干净的新建提示仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
