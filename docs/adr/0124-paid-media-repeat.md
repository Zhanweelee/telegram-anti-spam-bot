# ADR 0124：没有说明的付费媒体参加重复判断

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0052 和 ADR 0123 让没有正文的顶层文件和富文本文件用文件摘要参加 `repeat`。付费图片、没有文件名的付费视频和付费实况照片不在顶层字段上。没有说明时正文是空字符串，同一份文件可以连发而不触发默认的 `repeat`。

ADR 0090 只从付费视频文件名抽主机名。文件 id 仍不能原样进事件。星星数量和预览尺寸也不是文件。

## 决策

- 顶层或富文本已经有媒体类别时，仍用那一个，不改用付费媒体里的文件。
- 两者都没有时，按 `paid_media.paid_media` 的数组顺序取第一份文件。预览没有文件，跳过。
- 付费图片用最后一张尺寸，类别是 `photo`。付费视频用 `video.file_unique_id`，类别是 `video`。
- 付费实况照片用 `live_photo.file_unique_id`，类别记成 `video`。这份 id 属于短视频。里面的静态尺寸不另写一份摘要。
- 能读到长度在 1 到 256 的 `file_unique_id` 时，写 `mediaSha256`。摘要是类别和这份 id 的 sha256。id 不进事件。过长或缺失的 id 只留类别，并且不再看后面的项。
- 正文非空时，`repeat` 仍用 `textSha256`。付费视频文件名仍按 ADR 0090 成为正文。没有说明、也没有文件名时用这份摘要。
- 不读取 `star_count`、预览尺寸、`mime_type` 和 `file_id`。不从这些字段抽主机名。不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 另做检测器 | `repeat` 已经默认开启。 |
| 把文件 id 原样放进事件 | 审计和日志会带上平台文件标识。 |
| 实况照片改用静态尺寸 | 短视频才是这份付费实况照片稳定的文件 id。静态尺寸可以缺。 |
| 有文件名时改按文件摘要计次 | 和 ADR 0052、ADR 0090 冲突。文件名仍是正文。 |

## 后果

- 60 秒内同一份没有说明的付费图片、视频或实况照片出现 3 次，现有 `repeat` 规则会删除。
- 不同文件各自计数。只有类别、没有摘要的消息仍不参加重复。
- 有说明或文件名时仍按正文计次。文件 id、星星数量和预览尺寸不进事件。
- 普通消息上的实况照片仍走顶层 `photo`。Bot API 在设置 `live_photo` 时也会设置 `photo`。
