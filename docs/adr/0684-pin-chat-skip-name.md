# ADR 0684：聊天置顶时不读占位名字

- 状态：已接受
- 日期：2026-11-06

## 背景

管理员把一条消息置顶时，Android 的 `TL_messageActionPinMessage` 在 `fromUser` 为空时取本群，再交给 `generatePinMessageText`。画出的名字是 `fromUser != null ? fromUser : chat`。`chat` 是这条消息所在的群，不是 `sender_chat`。付费媒体那一行同样用本群群名，否则用 `UserObject.getUserName`。

发送者是聊天时，Bot API 把聊天放在 `sender_chat`，`from` 是占位用户。占位用户的名字不在这行里。本群群名在这行里，但置顶一直不读本群群名。见 ADR 0586 与 ADR 0620。

编号和本群不同时，通用代发规则已经读过 `sender_chat.title`。编号相同时那条规则跳过。

## 决策

- `pinned_message.message_id` 是大于 0 的安全整数，且 `sender_chat` 是对象时，不从 `from` 留主机名。这条置顶规则也不读 `sender_chat.title`，也不读 `chat.title`。
- 没有 `sender_chat` 时，仍从 `from` 的全名留主机名。名和姓都去掉两端空白，名在前。空白名不挡住姓。空格不截断。
- 编号和本群不同时，聊天标题仍由通用代发规则读取，排在预览前面。编号相同时仍不读这份标题。
- 文字、账单说明和清单标题的前 20 个码元，以及游戏标题，仍只留主机名。第 21 个码元起仍不读。
- 空对象、0、负数、小数、字符串和布尔值的 `pinned_message` 仍不读发送者。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`pin_notice` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不调用 `unpinChatMessage`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续读 `from` | 占位用户的名字不在这行里。短链会删掉一条没有这个名字的提示。 |
| 改读本群群名 | 这行确实画本群群名。置顶从一开始就不读本群群名，群名是管理员自己写的。 |
| 改读 `sender_chat.title` | Android 画的是本群，不是代发聊天。编号不同的标题已经由通用规则读取。 |
| 新命令 | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 本群自己置顶时，占位名字里的短链不再删除。本群群名仍不读。预览里的短链仍会删。关掉管理员豁免后，预览短链仍会删。
- 别的聊天发到这个群时，标题里的短链仍会删，占位名字不再留下主机名。
- 用户仍按全名。
- 不是真实置顶提示时，发送者仍不读。`example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。
- 30 天保留期没有改。
