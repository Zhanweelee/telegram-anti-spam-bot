# ADR 0654：置顶账单和清单上画出的预览只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

置顶一条账单时，Android 把账单说明当成这条消息的文字，再由 `generatePinMessageText` 画出前 20 个 UTF-16 码元。账单标题不在这行里。置顶一条清单时，`MessageTodoName` 就是标题本身，提示同样只画前 20 个码元。任务正文不画。见 ADR 0653。

地点、骰子和抽奖在这条提示里是固定说法。旁边的正文、地点名和奖品说明不画。

这段预览不进正文。关键词不命中这 20 个字。

## 决策

- `pinned_message` 上 `invoice` 是对象时，只读 `description` 的前 20 个 UTF-16 码元。空字符串和不存在的说明都不读。不读 `title`，也不改去读 `text`。
- `checklist` 是对象时，只读 `title` 的前 20 个 UTF-16 码元。空标题不读。不读任务，也不改去读 `text`。
- `venue`、`dice`、`giveaway`、`giveaway_winners` 是对象时，不读 `text` 和这些对象里的名字、说明。
- 游戏仍读整个标题。文字消息仍只读 `text` 的前 20 个码元。见 ADR 0653。
- 预览不进正文，内容哈希不变。被置顶的人、消息号和金额不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`pin_notice` 仍默认关闭。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 账单改读标题 | 置顶这行画的是说明，标题不在这 20 个码元里。付款成功那条仍另读被回复账单的标题。 |
| 整段说明和标题都读 | 客户端只画前 20 个码元。 |
| 空说明改读旁边的正文 | 说明为空时这行是「置顶了一条消息」，不画正文。 |
| 把预览抄进正文 | 关键词会命中这 20 个字。 |

## 后果

- 置顶账单说明或清单标题的前 20 个码元里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。置顶本身还在。
- 第 21 个码元起的路径、账单标题、任务、地点名、奖品说明和被置顶的人不进事件。内容哈希不变。关键词不命中预览。
- 空说明和空标题不读旁边的正文。地点、骰子和抽奖的固定说法不读旁边的正文。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 游戏和文字预览仍按 ADR 0653。发送者仍按 ADR 0620 读全名。`pin_notice` 仍默认关闭。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
