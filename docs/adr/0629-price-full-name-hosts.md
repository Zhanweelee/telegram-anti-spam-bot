# ADR 0629：改价的人画出的全名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

有人改付费发言的星星数量，或改频道私信开关时，Android 的 `MessageObject` 在 `TL_messageActionPaidMessagesPrice` 上用 `replaceWithLink` 把这个人画进这行服务文字。这就是 `UserObject.getUserName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。自己改价时这行不画名字。

Bot API 把付费发言放在 `paid_message_price_changed`，把私信开关放在 `direct_message_price_changed`。星星数量大于等于 0，或开关正好是布尔值时，这条提示成立。见 ADR 0585。当时名的长度大于 0 就丢掉姓。

助推这行仍只读名。付款成功这行仍只读名。加选项这行画的是短名。短链可以只写在姓上。把整段收成正文会改变内容哈希，关键词也会命中名字。

## 决策

- 只在已经会标成 `priceNotice` 的提示上，从 `from` 会画出来的全名留主机名。`paid_message_star_count` 是大于等于 0 的安全整数时读。否则 `are_direct_messages_enabled` 正好是布尔值时读。同时出现时仍先认付费发言。
- 名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读。空格不截断。用户名不读。
- 全名不进正文，也不改内容哈希。关键词因此不命中。星星数量和开关不读。本群群名不读。正文里已有短链时，证据仍先记正文的主机名。
- 空对象、负数、小数、字符串和单独的布尔值不读发送者。普通消息不读 `from`。助推仍按原来的名。付款成功仍按原来的名。加选项或删选项仍按原来的名。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`price_notice` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不调用改价接口。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续只读名 | 客户端把姓画在同一行里。姓上的短链会留在提示里。 |
| 把名字整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0487。 |
| 助推和付款成功也改成全名 | 这两行用的是名。姓上的短链并没有出现在那一行。见 ADR 0583 与 ADR 0618。 |
| 加选项也改成全名 | 加选项这行画的是短名。姓并没有画在那一行。 |
| 新命令 `/pricename` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 改付费发言或私信开关的人，全名里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。价格和私信开关不变。
- 全名原文、路径和用户名不进事件。内容哈希不变。关键词不命中全名。
- 空白名不挡住姓。空格后面的网址仍读。星星数量和开关仍不读。
- 正文里已有短链时，证据仍先记正文的主机名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 助推和付款成功仍只读名。加选项或删选项仍只读名。空对象、负数、小数、字符串、布尔值和普通消息仍不读发送者。管理员仍豁免。干净的提示在 `price_notice` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
- 发送者是频道时，后来由 ADR 0671 只读频道标题，不读 `from`。其他人仍按全名。
