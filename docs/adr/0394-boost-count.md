# ADR 0394：私聊可以查看一个人的助推次数

- 状态：已接受
- 日期：2026-11-04

## 背景

管理员想知道一个人给这个聊天加了多少次助推。官方有一次读出列表的调用。

`getUserChatBoosts` 返回一个用户加到聊天里的助推列表。bot 需要这个聊天的管理权限。参数是 `chat_id` 和 `user_id`。结果是 `UserChatBoosts`，里面的 `boosts` 是 `ChatBoost` 数组。每一项带助推号、开始时间、到期时间，以及来源。来源里有用户对象。

次数是这个数组的长度。0 也是次数。

没有 token 时不能编一个数字。名字、助推号和到期时间不能进回复或日志。

## 决策

- 私聊命令 `/boosts <chatId> <userId>`。群 id 和成员 id 匹配 `^-?\d{1,20}$`。少一个编号或多出来的参数不发出请求。群聊里的同样文本不执行。
- 配置中的管理员可以查看任意群。接入目录里的人只能查看自己的群。
- 调用 `ModerationPort.readBoostCount`。适配器调用 `getUserChatBoosts`，带 `chat_id` 和 `user_id`。
- 只读取 `result.boosts` 的长度。`boosts` 不是数组，或结果里没有这个字段时，回复「参数无效」。
- 不读取名字、助推号、来源或到期时间。
- 回复只写这个整数。0 也写出来。
- 没有 token、没有这个方法，编号不合法，或调用失败时回复「参数无效」。日志只写 `operator_rejected`，带上 eventId、chatId 和命令名。不写异常文本、token、原文、名字或助推号。
- 没有 token 的 Worker 不编一个数字。内存适配器同样抛出 `boosts_unavailable`。
- 不修改黑名单、白名单、封禁或禁言。不读取消息正文。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把每一条助推的来源和用户写进回复 | 来源里有用户对象。管理员要的是次数。 |
| 没有 `boosts` 时回复 0 | 缺少字段和空列表不是同一件事。空列表才是 0。 |
| 没有 token 时回复 0 | 管理员会以为这个人没有助推。 |

## 后果

- 成功只表示 Telegram 返回了一个 `boosts` 数组。缺少管理权限时，回复是「参数无效」。
- 回复只有次数。
- 一次查看是一次 Telegram 子请求。封禁、禁言和黑名单都不变。
- 30 天保留期不动。
