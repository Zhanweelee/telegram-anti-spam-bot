# ADR 0650：付款失败和退款建议帖上画出的话题用户全名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

建议帖付款失败时，Android 的 `getActionSuggestionApprovalText` 用 `DialogObject.getName` 把话题用户画进“余额不够”那一行。退款时，`MessageObject` 同样用这个全名拼退款文字。这就是 `UserObject.getUserName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。

这个人是 `saved_peer_id`。Bot API 把它放在 `direct_messages_topic.user`。见 ADR 0637。当时只有发言人就是这个用户，才从话题标题留主机名。付款失败和退款这行即使发言人是别人，也会画出这个用户。`from` 仍只读名。见 ADR 0601。通过和付款这两行不画这个人。嵌套原帖不画。

名字本身不进正文。关键词不命中这段全名。

## 决策

- 只在已经会标成 `postNotice` 的 `failed` 或 `refunded` 上，从 `direct_messages_topic.user` 会画出来的全名留主机名。失败要有价格对象，空的价格对象也读。退款原因正好是 `post_deleted` 或 `payment_refunded`。
- 名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读。空格不截断。用户名不读。发言人编号不同也读。
- 通过和付款不读这个用户。同时出现时仍先认通过，再认失败，再认付款，再认退款。`from` 仍按 ADR 0601 只读名。普通消息的话题标题仍只在发言人就是这个用户时读。见 ADR 0637。
- 话题号、频道标题、嵌套原帖、价格和退款原因不读。没有话题、布尔值和空的用户对象不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`post_notice` 仍默认关闭。8 个主机名的上限不变。不调用 `approveSuggestedPost` 或 `declineSuggestedPost`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 发言人不同就不读 | 退款和余额不够这两行仍画出话题用户。姓上的短链会留在提示里。 |
| 通过和付款也读 | 这两行不画这个人。见 Android 的通过文案。 |
| 把这个人整段当成正文 | 关键词会命中人名。普通话题标题的条件也会被打开。见 ADR 0637。 |
| 连嵌套原帖一起读 | 原帖是另一条消息。见 ADR 0488。 |

## 后果

- 付款失败或退款这行的话题用户全名里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。稿子状态不变。
- 全名原文、路径、用户名、话题号和频道标题不进事件。内容哈希不变。关键词不命中全名。
- 空白名不挡住姓。空格后面的网址仍读。发言人不是这个人时也读。
- `from` 仍只读名，空白名仍挡住姓。没标价或金额为 0 的通过，以及付款，仍不读话题用户。金额大于 0 的通过后来另读。见 ADR 0651。普通消息的话题标题仍只在发言人就是这个用户时读。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 没有话题、布尔值、空的用户对象、其它退款原因和空的通过对象仍不读。嵌套原帖仍不读。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
