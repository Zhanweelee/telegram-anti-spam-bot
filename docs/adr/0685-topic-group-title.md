# ADR 0685：话题的发送者是群时只读群标题

- 状态：已接受
- 日期：2026-11-06

## 背景

有人改话题名字、只换图标，或关掉、重开、隐藏、重新显示话题时，Android 的 `TL_messageActionTopicEdit` 在发送者是聊天时画出这个聊天的标题。`replaceWithLink` 对聊天用标题，空格不截断。群和超级群也一样，不只有频道。

Bot API 把改名和换图标放在 `forum_topic_edited`，把关掉、重开、隐藏和重新显示放在四个对象上。发送者是聊天时，`sender_chat` 是那个聊天，`from` 是占位用户。见 `telegram-bot-api` 的 `messageSenderChat`。

ADR 0672 只在 `sender_chat.type` 正好是 `channel` 时读标题。群和超级群仍读占位用户的全名。编号和本群相同时，通用代发规则不读这份标题，占位名字却会留下主机名。

新建话题这行仍不画人。见 ADR 0665。

## 决策

- 已经会标成 `topicNotice: "edited"`，或 `forumNotice` 是关掉、重开、隐藏、重新显示时，`sender_chat` 是对象就只从 `sender_chat.title` 留主机名，不从 `from` 留主机名。标题不截断。用户名不读。频道、群和超级群都一样。编号和本群相同时也读。
- 没有 `sender_chat` 时，仍从 `from` 的全名留主机名。名和姓都去掉两端空白，名在前。空白名不挡住姓。空格不截断。
- 不从 `chat.title` 另读。
- 编号和本群不同时，通用代发规则先读标题，话题名的主机名排在后面。编号相同时，话题名排在前面，这条规则再补标题。
- 新建话题仍不读发送者。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`topic_notice` 和 `forum_notice` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不调用改话题、关闭、打开、隐藏或显示话题的方法。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 群继续读 `from` | 占位用户的名字不在这行里。短链会删掉一条没有这个名字的提示，群标题上的短链又会留下。 |
| 本群匿名仍不读群名 | Android 画的就是这个群的标题。通用代发规则在编号相同时不读它。 |
| 新建话题也读群名 | 新建这行不画人，也不画标题。 |
| 新命令 | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 改名、换图标、关掉、重开、隐藏或重新显示的发送者是群或超级群时，标题里的短链、邀请或裸 IP 会留下主机名。证据只有主机名。话题开关不变。
- 本群自己改话题时，默认仍因管理员豁免而留下。关掉豁免后，标题里的短链会删。别的聊天发到这个群时不豁免。
- 占位用户的名字不再留下主机名。用户仍按全名。频道仍读标题。
- 新建仍不读发送者。`example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。
- 30 天保留期没有改。
