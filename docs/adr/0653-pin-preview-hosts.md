# ADR 0653：置顶提示上画出的原文预览只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

管理员把一条消息置顶时，Android 的 `generatePinMessageText` 会把被置顶的内容画进这条服务消息。文字消息画 `messageText` 的前 20 个 UTF-16 码元，再加省略号。游戏画 `game.title`，不截断。图片、视频、动图、语音、圆形视频、贴纸、文件、位置、实时位置、联系人和投票用固定说法，不画原文。付费媒体画置顶的人，不画媒体说明。见 ADR 0482 与 ADR 0620。

Bot API 把被置顶的消息放在 `pinned_message`。文字在 `text`。游戏标题在 `game.title`。前 20 个码元和游戏标题里的短链会画在群里。第 21 个码元起不画。

这段预览不进正文。关键词不命中这 20 个字，也不命中游戏标题。

## 决策

- `pinned_message.message_id` 是大于 0 的安全整数时，从会画出来的预览只留主机名。
- 文字消息只读 `text` 的前 20 个 UTF-16 码元。空字符串不读。第 21 个码元起不读。
- `game` 是对象时，读整个 `game.title`，不读 `text`，也不读说明。
- `audio`、`video`、`animation`、`voice`、`video_note`、`sticker`、`document`、`location`、`contact`、`poll`、`paid_media` 是对象，或 `photo` 是非空数组时，不读 `text` 和说明。这些提示画固定说法。
- 被置顶的人、消息号、实体和说明不读。预览不进正文，内容哈希不变。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`pin_notice` 仍默认关闭。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 整段原文都读 | 客户端只画前 20 个码元。后面的短链没有画在这条提示上。 |
| 把预览抄进正文 | 关键词会命中这 20 个字。内容哈希也会变。 |
| 图片说明也读 | 置顶图片时这行是固定的「照片」，不画说明。 |
| 游戏标题也只读 20 个码元 | 客户端把整个标题画出来。 |

## 后果

- 置顶提示画出的前 20 个码元或游戏标题里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。置顶本身还在。
- 预览原文、第 21 个码元起的路径、说明、被置顶的人和消息号不进事件。内容哈希不变。关键词不命中预览。
- 图片、视频、文件、位置、联系人、投票和付费媒体的原文不读。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 账单说明和清单标题后来同样只读前 20 个码元。空说明不改去读正文。地点、骰子和抽奖的固定说法不读旁边的正文。见 ADR 0654。富文本预览的前 20 个码元后来由 ADR 0714 也只留主机名。文字预览上的文字链接后来由 ADR 0715 也只留主机名。
- 发送者仍按 ADR 0620 读全名。`pin_notice` 仍默认关闭。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
