# ADR 0672：话题的发送者是频道时只读频道标题

- 状态：已接受
- 日期：2026-11-06

## 背景

有人改话题名字、只换图标，或关掉、重开、隐藏、重新显示话题时，Android 的 `MessageObject` 在 `TL_messageActionTopicEdit` 上先看发送者。发送者是用户时，用 `ContactsController.formatName` 画出全名。发送者是聊天时，画出这个聊天的标题。`replaceWithLink` 对聊天用标题，空格不截断。

Bot API 把改名和换图标放在 `forum_topic_edited`，把关掉、重开、隐藏和重新显示放在四个对象上。频道发到超级群时，`sender_chat.type` 是 `channel`，`from` 是占位用户。见 `telegram-bot-api` 的 `messageSenderChat`。

ADR 0626 和 ADR 0625 仍从 `from` 留主机名。占位用户的名字不是这行画出的字。频道标题上的短链会留在提示里。新建话题这行仍不画人。见 ADR 0665。

## 决策

- 已经会标成 `topicNotice: "edited"`，或 `forumNotice` 是关掉、重开、隐藏、重新显示时，`sender_chat.type` 正好是 `channel` 就只从 `sender_chat.title` 留主机名，不从 `from` 留主机名。标题不截断。用户名不读。
- 发送者不是频道时，仍从 `from` 的全名留主机名。名和姓都去掉两端空白，名在前。空白名不挡住姓。空格不截断。
- 新建话题仍不从 `from` 抽主机名。超级群匿名身份仍不把本群群名收进来。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`topic_notice` 和 `forum_notice` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不调用改话题的接口。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 频道标题继续不读 | 这行把频道标题画出来。标题上的短链会留在提示里。 |
| 频道也读 `from` | 占位用户的名字不在这行里。 |
| 超级群匿名也改读群名 | 那是本群群名。这次只补广播频道。 |
| 新建话题也读频道标题 | 新建这行不画人，也不画频道标题。 |
| 新命令 | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 改名、换图标、关掉、重开、隐藏或重新显示的发送者是频道时，频道标题里的短链、邀请或裸 IP 会留下主机名。证据只有主机名。话题开关不变。
- 占位用户的名字不再留下主机名。其他人的全名仍会删。
- 标题原文、路径和用户名不进事件。内容哈希不变。关键词不命中标题和全名。
- 话题名里的短链仍删除，并排在频道标题前面。正文里的短链仍先记。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 新建仍不读发送者。超级群匿名后来由 ADR 0685 只读这个群的标题，不读占位名字。用户仍按全名。空对象、布尔值和普通消息仍不读发送者。管理员仍豁免。干净的提示在对应规则关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
