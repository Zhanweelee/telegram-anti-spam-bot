# ADR 0333：规则回复按行截断

- 状态：已接受
- 日期：2026-11-04

## 背景

私聊 `/rules` 把每一条规则拼成一行。默认规则大约十几条，放得进 3500 字。规则数组没有上限。自定义规则一多，整段回复会超过 Telegram `sendMessage` 的 4096 字。适配器会把文本切到 4096，最后一行可能只剩一半，也看不出后面还有规则。

## 决策

- 完整回复不超过 3500 字时，正文保持现在的标题和规则行。
- 放不下时保留标题，按原来的顺序保留前面的若干条完整规则行。最后一行写上没列出的条数。
- 空规则仍只回复 `none`。
- 不改规则文件，也不为了缩短回复去关掉规则。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续交给适配器切到 4096 | 切口会落在一行中间，管理员以为规则到这里结束。 |
| 给规则数组加一个放得进私聊的上限 | 检测用的规则和回复长度是两件事。长规则仍应执行。 |
| 只回复条数 | 短列表现在能看到每条规则的状态。放不下时仍应列出前面的行。 |

## 后果

- 私聊看到的是前缀和剩余条数。没列出来的规则仍在执行。
- 这条命令的回复停在 3500 字以内。适配器对其他超长文本仍会切开。
- 额度和 30 天保留期不动。
- 默认规则变长之后，第一页不再包含后面的入群规则。`/rules` 后来由 ADR 0521 接受 `skip`，从指定条数继续列。不写 `skip` 时仍是这一页。
