# ADR 0617：商业账号代发时，时间戳旁的 bot 全名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

商业账号让 bot 代发时，Android 的 `ChatMessageCell.measureTime` 在 `via_business_bot_id` 非 0 时，把 `UserObject.getUserName(botUser)` 画在时间戳旁边。这段名字接在时间后面。

`getUserName` 先取 `ContactsController.formatName(first_name, last_name)`。默认顺序是名在前、姓在后。两边都先去掉两端空白。名去掉空白后还有字，才画名，再在非空的姓前面加一个空格。名去掉空白后是空的，就只画姓。两边都空时，Bot API 的用户对象没有电话，时间戳旁不画名字。用户名不在这行里。

像素级省略、变音符号和从右向左标记仍交给后面已有的主机名折叠。这次不在抽取前再削一层。

Bot API 把这个 bot 放在 `sender_business_bot`。布尔值不是对象。带非空 `business_connection_id` 的更新仍先被忽略，所以商业账号自己收到的那份副本不到这里。普通群消息上只要这个对象在，就读会画出来的全名。`via_bot` 的显示名仍按 ADR 0033 不读。没有这个对象时，普通 `from` 仍不读。

短链可以只写在这个全名上。把整段名字收成正文会改变内容哈希，关键词也会命中名字。

## 决策

- `sender_business_bot` 是对象时，从会画出来的全名留主机名。
- `first_name` 和 `last_name` 都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，只读姓。两边都空时不读。抽出之前先截到正文长度上限。
- 空格不截断。`Go https://…` 这种全名整段都读。
- 主机名仍进消息已有的 `hosts`。邀请仍进 `invites`。作者签名和成员标签里已有短链时，这两边的主机名仍排在前面。正文里已有短链时，证据仍先记正文的主机名。全名不进正文，也不改内容哈希。关键词因此不命中。
- 用户名、电话、bot id、普通 `from`、`via_bot` 的显示名、本群群名，以及和本群编号相同的 `sender_chat.title` 不读。布尔值的 `sender_business_bot` 不读。有这个对象时，作者签名和成员标签仍照旧读取。
- 非空 `business_connection_id` 的更新仍先忽略，不读这个名字。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。短链仍走已有的 `links`。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 连 `via_bot` 的显示名一起读 | inline bot 的名字仍按 ADR 0033 留在事件外面。时间戳旁画的是 `sender_business_bot`。 |
| 按客座短名从下标 2 截断 | 时间戳旁画的是去掉空白后的全名，空格后面仍在屏幕上。 |
| 名字空了再读电话 | Bot API 的用户对象不带电话。时间戳旁这时不画字。 |
| 把全名整段当成正文 | 会改变哈希，关键词也会命中名字。 |
| 新命令 `/businessbot` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 时间戳旁 bot 全名里的短链、邀请或裸 IP 会删除这条消息。证据只有主机名。
- 全名原文、路径和用户名不进事件。内容哈希不变。关键词不命中全名。
- 名去掉空白后是空的时改读姓。两边都是空白时不读。空格后面的网址仍读。
- 作者签名和成员标签的主机名仍排在这个全名前面。正文里已有短链时，证据仍先记正文的主机名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 带非空 `business_connection_id` 的更新仍先忽略。`via_bot` 的显示名仍不读。普通 `from` 仍不读。
- 管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
