# ADR 0326：`/forget` 直接返回删除条数

- 状态：已接受
- 日期：2026-11-03

## 背景

`/forget` 先调用 `exportAudits`，只为了数有多少条，然后再 `deleteAudits`。D1 导出按 100 行一页读出全部审计，并放进同一次请求的内存。免费计划每次调用最多 50 个子请求、10 ms CPU。审计一多，删除还没发出，请求就已经用完额度。

`/export` 仍然需要这份全文。删除只需要条数。

## 决策

- `deleteAudits` 返回删除的行数。范围仍是 `tenantId`，可选 `chatId`。规则和白名单不动。
- D1 用这一条 `DELETE` 结果里的 `meta.changes`。没有非负整数条数时抛出固定错误 `delete_changes_missing`，不把数据库返回的文本写进日志。
- `/forget` 只调用 `deleteAudits`，用返回值回复「已删除 N 条」。不再先导出。
- 30 天自动清理仍然不做。保留期仍是 ADR 0003。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续先导出再删 | 条数只是导出的长度，免费额度会先被读请求用完。 |
| 另加一个 `countAudits` | 删除和计数分成两次，中间插入的审计会对不上回复。 |
| 条数缺失时回复 0 | 行可能已经删掉，0 会让管理员以为没删。 |

## 后果

- 每个 `Storage` 的 `deleteAudits` 都要返回条数，并继续跑 `bindStorageContract`。
- `/forget` 在 D1 上按页删除，见 ADR 0361。仍不先导出。`/export` 仍按页读出全部审计。
- 驱动没有报告条数时，行可能已经删除，私聊回复「参数无效」。再执行一次会看到 0。
