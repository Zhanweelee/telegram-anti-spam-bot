# ADR 0027：拉进群并设为管理员即完成接入

- 状态：已接受
- 日期：2026-11-01

## 背景

公共 bot 的接入应该是：把 bot 拉进群，并授予管理员。群主随后在私聊里管理这一群的规则、白名单、日志和额度。之前 `my_chat_member` 被忽略，只有写进 `ADMIN_USER_IDS` 的人能下命令。

core 仍然不能读取部署模式。付费不在这次范围内。

## 决策

- 群和超级群的 `my_chat_member` 收成 `kind: "bot_membership"`，状态只有 `admin` 或 `gone`。不保留群名、用户名和昵称。私聊和频道忽略。
- 操作者的用户 id 记入 isolate 内存里的接入目录，最多 256 个群，每群最多 32 人。之后 `chat_member` 里新成为管理员的人也会记入；离开管理员时去掉。bot 不再是管理员时清掉这一群。
- 目录满了记 `chat_directory_full` 并放过。抛错记 `chat_directory_failed`，不写异常文本。重启后目录清空。不写 D1 或 KV。
- `ADMIN_USER_IDS` 仍可管理全部群。目录里的人只能操作自己的群，不能导出或删除整个租户的审计。`/chats` 只列出群 id。
- 部署要重新 `setWebhook`，把 `my_chat_member` 放进 `allowed_updates`。
- 不接支付。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 每次私聊命令调用 `getChatMember` | 免费计划的子请求不该花在每次命令上。成员变更本身已经把管理员身份送到 webhook。 |
| 只让 `ADMIN_USER_IDS` 管理 | 公共 bot 的群主无法自助，接入没有完成。 |
| 把群名存下来方便辨认 | 群名和正文一样不能进事件、目录或日志。 |

## 后果

- 已经设过 webhook 的部署要重设一次，否则 bot 被拉进群时仍然没有记录。
- 当时已经是管理员、但之后状态没变的人，要等下一次升降级才会进入目录。授予 bot 管理员的那个人会立即进入。
- isolate 重启后，群主要等下一次成员变更，或者由配置中的管理员继续操作。
- 改群名服务消息里的网址后来由 ADR 0114 只留下主机名。群名本身仍不进事件。
- 加入或移入社区的名字后来由 ADR 0115 只留下主机名。名字本身仍不进事件。
- 缺删除或限制权限，或还在群里但不是管理员时，给操作者发一条私聊。目录状态不变。见 ADR 0436。
