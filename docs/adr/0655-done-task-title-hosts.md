# ADR 0655：清单完成提示上画出的任务只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

清单里的任务被标成完成或取消完成时，Android 的 `TL_messageActionTodoCompletions` 只画一条任务。完成名单非空时用第一项，否则用取消完成名单的第一项。这项能在被回复的清单里对上时，整段任务文字画进这行，形如 marked “任务” as done。对不上时只画「标成完成」，不画任务。见 ADR 0489。

Bot API 把原清单放在 `checklist_tasks_done.checklist_message`。任务文字在 `checklist.tasks` 里，按 `id` 对上。文字链接跟这段一起画出来。

其余任务、清单标题和清单正文不在这行里。任务文字不进正文。关键词不命中这段任务。

## 决策

- `checklist_tasks_done` 是对象时，完成名单是非空数组就只用第一项。这项是安全整数，并且 `checklist_message.checklist.tasks` 里有相同 `id` 时，从这条任务的 `text` 和 `text_entities` 里的文字链接留主机名。
- 完成名单是空数组或缺省时，取消完成名单按同样规则取第一项。
- 完成名单非空但第一项不是安全整数时，不改去读取消完成名单。
- 对不上、没有嵌套清单、任务不是数组时不读。同一编号出现多次时用清单里的第一条。
- 不读其余任务、清单标题、`checklist_message.text`、任务号和完成者。任务文字不进正文，内容哈希不变。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`checklist_notice` 仍默认关闭。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 每条被勾的任务都读 | 客户端只把第一项画进这行。后面的短链没有出现在这条提示上。 |
| 第一项读不出来就改读取消完成 | 完成名单非空时，这行用的就是完成名单的第一项。 |
| 把任务抄进正文 | 关键词会命中任务文字。新加任务的正文规则不套到完成提示上。 |
| 改读清单标题 | 这行画的是对上的那条任务，不是标题。 |

## 后果

- 完成提示上画出的那条任务里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。任务完成状态不变。
- 任务原文、路径、其余任务、标题、清单正文、任务号和完成者不进事件。内容哈希不变。关键词不命中这段任务。
- 对不上或没有嵌套清单时仍不读。完成名单第一项不是安全整数时不读取消完成名单。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 勾完的人仍按 ADR 0627 读全名。`checklist_notice` 仍默认关闭。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
