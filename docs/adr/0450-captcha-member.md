# ADR 0450：私聊再要求一次入群验证

- 状态：已接受
- 日期：2026-11-04

## 背景

入群验证只在有人从群外进来时发生。bot 后加入的群里，已经在里面的人不会再碰到这颗按钮。管理员现在只能禁言、封禁或移出，没有办法让这个人补一次验证。

## 决策

- 私聊命令 `/captcha <chatId> <actorId>`。两个 id 都要匹配 `^-?\d{1,20}$`。多出来的参数不发出请求。群聊里的同样文本不执行。
- 配置里的管理员可以要求任意群。接入目录里的人只能要求自己的群。
- 命令调用现有的 `beginChallenge`，目标是参数里的群和成员，不是操作者自己的私聊。限制时长 300 秒，和入群验证相同。
- 限制成功后，向目标群静音发出和入群时相同的正文和两颗按钮。完成回复发到操作者的私聊。
- 按钮请求失败时，解除这次限制并删除挑战。回复是「参数无效」。应答成功但读不到消息号时，限制留着，和入群验证相同。
- 同一个人已有未完成的验证时，换一次 nonce，并删掉旧按钮。
- nonce 不进回复，也不进日志。没有 token、缺挑战存储或调用失败时回复「参数无效」，不把内存记录当成已经限制。
- 不新增检测器，不改 `new_member`，不改 `captcha_challenges` 的字段。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 让 `/mute` 顺便发按钮 | 禁言和验证是两件事。禁言 3600 秒，验证仍是 300 秒。 |
| 先 `getChatMember` 再限制 | 不在群里或是管理员时，`restrictChatMember` 会失败并回滚。不必多一次查询。 |
| 把验证消息发到私聊 | 按钮要出现在被验证的那个群里，成员才点得到。 |

## 后果

- 已经在群里的人可以被要求再点一次按钮。点对仍只放行一次。点错仍只提示。
- 入群时的自动验证没有改。
- 云额度的基础检测器名单没有改。30 天保留期没有改。
