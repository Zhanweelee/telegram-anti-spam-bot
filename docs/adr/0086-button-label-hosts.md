# ADR 0086：按钮文字里的网址只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0063 在没有更前面的正文时，把内联按钮的 `text` 拼成正文。已有正文时，按钮文字留在事件外面。按钮的 `url`、`copy_text`、`login_url` 和 `web_app` 已经只留主机名。写在按钮可见文字里的短链，在已有正文时仍然看不到。

把按钮文字拼进已有正文会改变 `textSha256`。`callback_data` 和回复键盘仍不能进事件。

## 决策

- 从 `inline_keyboard` 每个按钮的 `text` 抽出网址，只留主机名。长度、折叠、邀请判断和 8 个主机名的上限不变。顺序在这个按钮的 `url` 之前。
- 已有正文时，按钮文字不进正文，也不改内容哈希。
- 没有更前面的正文时，按钮文字仍按 ADR 0063 整段成为正文。这条正文里的网址由链接规则从正文看见，同时也记在主机名列表里。
- 不读取 `callback_data`。不读取 `keyboard`。`url`、`copy_text`、`login_url` 和 `web_app` 仍按原来的规则。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 已有正文时把按钮文字拼进去 | 按钮文字会改变哈希。短链只需要主机名。 |
| 连 `callback_data` 一起抽 | 那是回调数据，不是用户看见的地址。 |
| 读取回复键盘 | 入站 `Message.reply_markup` 只有内联键盘。 |

## 后果

- 已有正文时，按钮文字里的 `https://bit.ly/…` 会走现有短链删除。`https://t.me/+…` 和 `https://t.me/%2B…` 只留下 `t.me`，并记成邀请。
- 普通域名仍保留。按钮文字、路径和邀请码在已有正文时不进事件。
- 按钮文字成为正文时，整段文字仍参与关键词和内容哈希。
- `callback_data` 和回复键盘里的网址仍然不读。按钮文字里的关键词在已有正文时仍然看不到。
