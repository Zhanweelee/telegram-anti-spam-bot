# ADR 0028：入群昵称命中关键词就封禁

- 状态：已接受
- 日期：2026-11-01

## 背景

新成员可以在开口之前，用昵称、姓氏或用户名投放广告。入群事件以前只做按钮验证，昵称被直接丢掉。验证按钮挡不住已经显示在成员列表里的广告名。

昵称和正文一样不能进日志或审计原文。

## 决策

- 只有「从群外加入」的 `chat_member` 带 `profile`。内容是 `first_name`、`last_name`、`username` 用空格拼起来，最长 256 字符，并带 sha256。其它资料字段丢掉。已经在群里的升降级不带 `profile`。
- 关键词检测器同时看消息正文和这份昵称。证据仍是 `keyword:` 加配置里的词，不抄整段昵称。审计在没有消息时只存昵称哈希。
- 默认规则 `join_name` 对 `chat_member` 启用，命中后 `ban`。`spam_keywords` 加上 `when: message`，避免入群被误当成删消息。
- 决策已经是 mute 或 ban 时，captcha 记 `superseded`，不再限制或发按钮。普通入群仍走 `new_member`。
- `chats.json` 整份替换的群不会自动带上 `join_name`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 昵称只留在平台层，core 看不到 | 检测会离开流水线，规则无法关闭或换动作。 |
| 命中后只发验证，不封禁 | 广告名在验证完成前已经暴露。封禁比再发一次按钮省子请求。 |
| 把昵称写进审计摘要 | 和「原文默认不落盘」冲突。哈希够用来对照。 |

## 后果

- 昵称恰好包含默认词「免费领取」或「加微信」的新成员会被封禁，不会收到验证按钮。
- 关掉 `join_name` 后，这些人回到只验证。
- 整份替换规则的群要自己加上这条，才会封禁广告昵称。
- 入群申请的简介后来由 ADR 0116 拒绝。姓名仍只在真正入群时检查。
