# ADR 0198：编码斜杠不再拼出裸主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

Android 不会在匹配前把 `%2F` 收成斜杠。`%2Fbit.ly/…`、`see%2Fbit.ly/…` 和 `www%2Fbit.ly/…` 打开的是 `2fbit.ly`，不是 `bit.ly`。`%2F203.0.113.165/…` 不会打开这个地址。`example.com%2Fbit.ly/…` 只打开前面的主机名。

`%2Fexample.com/bit.ly/…` 是一整段，主机名是 `2fexample.com`。路径里的短链不会再拆出来。

真正的斜杠仍然会拆开。`/bit.ly/…` 会打开短链。换行、空格、制表符或再写一个斜杠隔在 `%2F` 和主机名之间时，后面的短链也会打开。`http:%2F/bit.ly/…` 会打开短链。`t.me%2F+…` 仍是邀请。`https://bit.ly%2F…` 仍是短链。

`example.com%2Fwww.bit.ly/…` 打开的是 `2fwww.bit.ly`。这个主机名仍以 `.bit.ly` 结尾。

粘连扫描如果先把 `%2F` 收成斜杠，`%2Fbit.ly` 会变成 `/bit.ly`。短链被多出来的边界打开。`%2F203.0.113.165` 会变成一条裸 IP。

## 决策

- 协议已经收成 `!x` 之后，把紧挨在裸主机名或点分 IPv4 前面的 `%2F` 换掉。
- 裸主机名保留标签和路径，最后一段换成 `arpa`，前面加 `!`。`!` 让前面的主机名结束。`arpa` 让短链后缀对不上，路径仍挂在这一段上。
- 点分 IPv4 换成 `!0.arpa`。路径仍挂在这一段上。
- 紧挨在已经写好的 `http://` 或 `https://` 前面的 `%2F` 仍换成 `!x`。能拼出协议的 `%2F` 仍按 ADR 0196 处理。
- 换行、空格、制表符或字面斜杠隔开的 `%2F` 仍收成斜杠。其它位置的 `%2F` 仍收成斜杠。`%252F` 仍保留。
- 每段仍走现有的短链、裸 IP、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| `%2F` 一律不再收成斜杠 | `t.me%2F+…` 和 `https://bit.ly%2F…` 会漏掉。 |
| 只换成 `!x`，主机名原样留下 | `www.bit.ly` 会变成 `xwww.bit.ly`，仍以 `.bit.ly` 结尾。 |
| 删掉 `%2F` 和后面的主机名 | `%2Fexample.com/bit.ly` 会剩下 `/bit.ly`，多出一个短链。 |

## 后果

- `%2Fbit.ly/…`、`see%2Fbit.ly/…`、`www%2Fbit.ly/…` 和 `example.com%2Fbit.ly/…` 留着。`%2Fexample.com/bit.ly/…` 留着。
- `%2F203.0.113.165/…` 留着。`203.0.113.165%2Fbit.ly/…` 仍按裸 IP 删除。证据是这个地址，不是后面的短链。
- `/bit.ly/…`、换行、空格、制表符或字面斜杠隔开的 `%2F`，以及 `http:%2F/bit.ly/…` 和 `https://bit.ly%2F…`，仍按短链删除。`t.me%2F+…` 仍按邀请删除。路径和邀请码不进证据。
- `https://bit.ly%2Fhttp://t.co/…` 仍按短链删除。证据是 `bit.ly`。
- `example.com%2Fwww.bit.ly/…` 仍按短链删除。证据是 `2fwww.bit.ly`。
- 百分号编码的连字符紧挨着裸主机名时不再收成连字符。见 ADR 0199。
