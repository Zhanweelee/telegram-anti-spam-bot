# ADR 0029：隐藏链接只保留主机名

- 状态：已接受
- 日期：2026-11-01

## 背景

Telegram 的 `text_link` 把网址藏在「点这里」后面，可见正文里没有这段 URL。链接检测只扫正文，所以藏起来的短链接和裸 IP 会漏掉。

整段 URL 不能写进 `message.text`。路径和查询可能是密钥，写进去还会改变内容哈希。

## 决策

- 消息可以带可选 `hosts`，最多 8 个。每个是小写主机名，长度 1 到 253，只含 `a-z`、数字、点和连字符，不能有 `..`，也不能以点开头或结尾。
- 平台只从 `entities` 和 `caption_entities` 里的 `text_link` 取主机名。只要 `http` 和 `https`。URL 长于 2048、其它协议，或主机名里出现 `:`（含 IPv6）都丢掉。路径和查询丢掉。重复的主机名丢掉。
- 链接检测把正文里解析出的主机名和 `hosts` 并在一起，仍然最多看 8 个。正文为空但带了主机名时也会扫。默认规则 `links` 不变：短链接和裸 IP 删除，普通网址保留。
- 没有新增依赖，也没有新增 Worker 变量。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把 URL 拼进正文再检测 | 路径和查询会进入哈希，密钥可能落进事件。 |
| 为隐藏链接单独做一条规则 | 短链、裸 IP 和黑名单已经在 `links` 里。再开一条会重复配置。 |
| 保存完整 URL 供审计 | 和「原文默认不落盘」冲突。证据继续只写原因加主机名。 |

## 后果

- 藏在 `t.me` 后面的邀请路径只剩下主机名 `t.me`。它不是默认短链，除非黑名单或信誉源命中，否则保留。
- 内联按钮的 `url` 后来由 ADR 0053 走同一份主机名规则。没有更前面的正文时，按钮文字后来由 ADR 0063 成为正文。已有正文时仍不并进去。
- 正文已经解析出 8 个主机名时，后面的隐藏主机名不再看。
- 非 `http`/`https` 的 `text_link` 被忽略。
- 分享、私聊预填和 Passport 回调后来可以长于 2048，停在 16384。见 ADR 0265。其它链接仍按本条丢掉。
- `text_mention` 的用户编号仍不取成主机名，也不进事件。这种提及可以另开 `text_mention`。见 ADR 0514。
- 正文上的文字链接后来由 ADR 0737 要求起点小于这段正文。正文不是字符串时，文字链接后来由 ADR 0797 不再读取。说明上的文字链接后来由 ADR 0738 要求起点小于这段说明。说明不是字符串时，文字链接后来由 ADR 0796 不再读取。
