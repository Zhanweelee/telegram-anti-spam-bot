# ADR 0709：没有任务号时，回复的清单标题只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

回复一整张清单、而不是某一条任务时，Android 仍把清单标题放进这条消息的预览。英文文案 `MessageTodoName` 就是 `%s`，所以这一行就是标题。标题长过 150 个 UTF-16 码元时，引用条只画前面这一段。标题为空时改画固定字样「Checklist」。有说明时改画说明。带引用时改画引用。

ADR 0702 只在 `reply_to_checklist_task_id` 对得上时读任务，对不上才读标题。没有这个编号时，标题仍画在引用条上，短链可以只写在这里。

## 决策

- 没有任务号，前面的引用条也没有占住，且 `reply_to_message.checklist` 是对象时，从 `title` 的前 150 个码元留主机名。
- `title_entities` 里的文字链接，只有 `offset` 落在这 150 个码元里才读。
- 标题为空时仍占住这一行，不改读旁边的文件名。任务不读。
- `caption` 或 `text` 的长度大于 0 时不读。带引用时不读。说明、正文和引用仍不进事件。
- 有任务号时仍按 ADR 0702。外部回复上的清单标题仍按 ADR 0704。文字链接的起点后来由 ADR 0735 必须小于整段标题。
- 标题不进正文，也不改内容哈希。关键词因此不命中。正文里已有短链时，证据仍先记正文的主机名。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。短链仍走已有的 `links`。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 没有任务号时整份清单都读 | 引用条只画标题，不画任务。 |
| 150 个码元之后也读 | 客户端只把前 150 个码元放进这一行。 |
| 有说明时也读标题 | 有说明时引用条画的是说明。 |
| 把标题收进正文 | 它是引用条上的一行。关键词仍只看这条消息自己的正文。 |

## 后果

- 没有任务号的清单回复，标题前 150 个码元里的短链会删除这条回复。证据只有主机名。
- 第 151 个码元起、任务、说明和引用里的短链不删除。标题短于 150 个码元时，起点也不能超过标题。见 ADR 0722。
- 标题不改内容哈希。关键词不命中标题。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
