# ADR 0338：同一事件只计一次洪泛和重复

- 状态：已接受
- 日期：2026-11-04

## 背景

洪泛和重复在检测时调用 `observe`，每次都压入一个时间戳。流水线先跑检测器，再占审计。Telegram 重试同一个 update 时，事件 id 不变，检测会再跑一遍。同一次投递落到这个窗口，会把 10 秒 5 条或 60 秒 3 条再记一次。

ADR 0010 把窗口留在内存。默认次数和窗口不动。不写 KV 或 D1。

## 决策

- `observe` 可以带 `eventId`。同一个 key 上，这个 id 已经在最近 32 个有效 id 里出现过，就不再压入时间戳，返回当前窗口里的样本数。
- id 只接受 1 到 128 个字符的字母、数字、下划线、点、冒号和连字符。其它值照旧每次都计。
- 没传 id 的调用仍每次加一条样本。Webhook 预算不传 id。
- 洪泛和重复检测器把事件 id 传进去。Durable Object 原样转发这次观察。
- 样本过期后，已经记住的 id 不把这条消息塞回窗口。这个 key 被清掉，或该 id 被挤出最近 32 个之后，可以再计。
- 默认仍是洪泛 10 秒 5 条、重复 60 秒 3 条。每个 key 最多 32 个样本。不写 KV 或 D1。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 记住这个 key 的全部事件 id | 一个忙群会把 isolate 内存撑满。重试只发生在刚处理过的几条里。 |
| 把已计 id 写进 KV 或 D1 | ADR 0010 拒绝为洪泛再写存储。 |
| 改掉 5 条或 3 条 | 这次只避免同一次投递被记两次。 |
| 检测之前先占审计 | 占住之前仍要跑检测。窗口自己认得这次事件。 |

## 后果

- 同一个 isolate 或同一个 Durable Object 上的重试不再多计洪泛和重复。
- 没绑定 `RATE_WINDOW` 时，落到另一个 isolate 的重试仍会计一次。那边的窗口本来就是另一份内存。
- 超过最近 32 个有效 id 之后，同一个 id 可以再计一次。
- 30 天保留期不动。默认阈值不动。
