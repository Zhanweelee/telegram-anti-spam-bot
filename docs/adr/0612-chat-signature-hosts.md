# ADR 0612：群来源的签名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

匿名管理员在群里发的消息转到别处时，客户端在抬头画出这个人的签名。签名写在 `forward_origin.type === "chat"` 的 `author_signature`。没有现代来源时，旧字段是 `forward_signature`，旁边的 `forward_from_chat` 不是频道。群标题已经只留主机名。见 ADR 0579。`chat_forward` 默认关闭，签名里的短链仍会留下。

成员转发的频道签名已经只留主机名。见 ADR 0611。讨论组原帖的来源签名仍按 ADR 0445。

把签名收成正文会让关键词命中作者名，也和原文默认不落盘冲突。

## 决策

- 现代 `forward_origin.type === "chat"` 时，`author_signature` 只留主机名。没有现代来源、也没有隐藏显示名、也没有 `forward_from`，并且 `forward_from_chat` 不是频道时，读 `forward_signature`。
- 签名长度大于 0 才读。空白也算有签名。空字符串不落到旧字段。用户名不读。群标题仍按 ADR 0579。抽出之前不截断。
- 主机名仍进消息已有的 `hosts`。邀请仍进 `invites`。群标题里已有短链时，证据仍先记标题的主机名。正文里已有短链时，证据仍先记正文的主机名。签名不进正文，也不改内容哈希。关键词因此不命中这个签名。
- 用户来源上的 `author_signature` 不读。频道来源仍按 ADR 0610 和 ADR 0611。讨论组原帖仍按 ADR 0445。外部回复不读。已有隐藏显示名时不读旧的群签名。发送者姓名和本群群名不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`chat_forward` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把签名拼进正文 | 关键词会命中作者名，签名也会改内容哈希。 |
| 只靠 `chat_forward` | 这条规则默认关闭。打开之前，签名里的短链仍留下。 |
| 连用户来源的签名一起读 | 用户抬头画的是名和姓。见 ADR 0579。 |
| 连外部回复一起读 | 外部回复是另一条消息的预览。 |
| 新命令 `/chatsign` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 群来源的签名里出现短链、邀请或裸 IP 时，会删除这条消息。证据只有主机名。`chat_forward` 仍默认关闭。
- 签名原文、路径和用户名不进事件。内容哈希不变。签名里的关键词不命中。
- 群标题里已有短链时，证据仍先记标题的主机名。正文里已有短链时，证据仍先记正文的主机名。空白签名不落到用户名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 用户来源的签名、讨论组原帖的来源签名、外部回复、隐藏显示名旁边的旧群签名、发送者姓名和本群群名仍不读。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
