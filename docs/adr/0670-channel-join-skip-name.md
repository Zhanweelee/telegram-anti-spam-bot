# ADR 0670：频道自己加入不再读名字

- 状态：已接受
- 日期：2026-11-06

## 背景

有人自己加入广播频道时，Android 的 `MessageObject` 在 `TL_messageActionChatAddUser` 上，加入的人就是发送者，并且所在聊天是频道而不是超级群，把这行设成 `ChannelJoined`。英文是 “You joined this channel”。这句不画加入的人，也不画发送者。

群和超级群仍用 `replaceWithLink` 画出全名。别人把人拉进频道时，仍画出被拉的人和拉人的人。见 ADR 0622 与 ADR 0645。

Bot API 把频道放在 `chat.type === "channel"`，把加入的人放在 `new_chat_members`，把发送者放在 `from`。名单里只有一个用户，并且编号和 `from.id` 相同时，就是自己加入。ADR 0645 仍把这份名单收成正文。名上的短链会删掉一条成员看不到这个名字的提示。

## 决策

- `chat.type` 正好是 `channel`，并且 `new_chat_members` 里只有一个用户，编号和 `from.id` 相同且都是安全整数时，不从这份名单抽主机名，也不从 `from` 抽主机名。名、姓和用户名都不读。
- 这条仍标成 `notice: "join"`。没有别的正文时，正文是空的。已有别的正文时，不另留 `memberName`。
- 群和超级群仍按全名。别人拉进频道仍按全名，拉人的人仍只留主机名。没有 `chat`，或类型不是 `channel` 时仍按全名。名单不止一个人，或编号对不上时仍按全名。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`service_notice` 仍默认关闭。8 个主机名的上限不变。不改入群。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 频道自己加入继续按名单 | 这行不画人。名上的短链不是成员看到的字。 |
| 超级群自己加入也不读 | 超级群这行仍画全名。 |
| 别人拉进频道也不读 | 那一行仍画出被拉的人和拉人的人。 |
| 新命令 | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 频道自己加入时，名单和发送者名字里的短链、邀请或裸 IP 不再删除这条消息。群、超级群和别人拉进频道仍会删。发送者是聊天时后来由 ADR 0677 只读这个聊天的标题。频道自己加入仍不读标题。
- 名字不进事件。自己加入且没有别的正文时，内容哈希按空正文计算。关键词不命中这些名字。
- 正文里的短链仍删除。`example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 退群仍读离开的人。空数组、非用户对象、布尔值和普通消息仍不读发送者。管理员仍豁免。干净的提示在 `service_notice` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
