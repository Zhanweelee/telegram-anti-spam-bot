# ADR 0649：退款这行画出的对方全名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

有人收到退款时，Android 的 `MessageObject` 用 `replaceWithLink` 把对方画在这行服务文字上。这就是 `UserObject.getUserName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。金额和币种也画在这行里，账单标题不画。

见 ADR 0618。付款成功这行用的是 `getFirstName`，名的长度大于 0 就丢掉姓。当时退款没有读，因为 `refunded_payment` 里没有这个人。私聊对象上的 `first_name` 和 `last_name` 就是这行画出的对方。群里的对方不是一个用户，群名不画。

名字本身不进正文。关键词不命中这段全名。

## 决策

- `successful_payment` 不是对象，且 `refunded_payment` 是对象，并且 `chat.type` 正好是 `private` 时，从私聊对方会画出来的全名留主机名。
- 名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读。空格不截断。用户名不读。
- 同一条上已经有付款成功对象时，仍先按 ADR 0618 读付款成功。退款这行不另读账单标题。
- 用户名、私聊 `title`、发言人 `from`、群名、群对象上的 `first_name`、`invoice_payload`、收费编号和被回复的账单标题不读。布尔值的 `refunded_payment` 不读。没有这个对象时，私聊对方的名字仍不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。短链仍走已有的 `links`。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续不读退款 | 客户端把姓画在同一行里。姓上的短链会留在提示里。 |
| 退款也只读名 | 这行用的是全名。付款成功那行才只读名。见 ADR 0618。 |
| 群里也读群名或发言人 | 群里这行画出的人没有放在 `refunded_payment` 上。群名不是这个人。 |
| 连账单标题一起读 | 退款这行不画账单标题。付款成功那行才画。 |

## 后果

- 私聊退款这行的全名里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。
- 全名原文、路径、用户名、载荷和收费编号不进事件。内容哈希不变。关键词不命中全名。
- 空白名不挡住姓。空格后面的网址仍读。名的主机名排在姓前面。
- 付款成功仍只读名，空白名仍挡住姓。同一条上先认付款成功。退款不读账单标题。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 群里的群名和发言人不读。布尔值不读。没有退款对象时，私聊对方的名字仍不读。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
