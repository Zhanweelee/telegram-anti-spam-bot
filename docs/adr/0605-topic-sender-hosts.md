# ADR 0605：新建或改名话题的人，名字只留主机名

- 状态：已接受
- 日期：2026-11-05

## 背景

有人新建论坛话题，或改话题名时，客户端把这个人的名字画在服务消息上。名字写在 `from`。话题名当时已经按原来的方式成为正文。见 ADR 0088 和 ADR 0496。短链可以只写在这个人的名字里。

关掉、重开、隐藏和重新显示仍按 ADR 0589。那四条提示没有话题名。ADR 0589 当时没有读新建和改名，是因为话题名已经是正文，不能再把这个人的名字收进正文。这次只留主机名，名字本身仍不进事件。

把 `from` 收成正文会让普通发言者的姓名也进检测。`topic_notice` 默认关闭，干净的话题名仍留下。空对象和布尔值仍然不是这条提示。只改图标时没有名字，正文是空的，这条提示仍然成立。

## 决策

- 只在已经会标成 `topicNotice` 的提示上，从 `from` 的可见名字留主机名。`forum_topic_created.name` 是长度大于 0 的字符串时读。空白也算有文字。否则改看 `forum_topic_edited`：名字长度大于 0，或 `icon_custom_emoji_id` 是字符串时读。空的图标编号也算字符串。同时出现时先认新建。新建的名字是空字符串时落到改名。`is_name_implicit` 不改变是否读取。
- `first_name` 的长度大于 0 时只读名。空白也算有名。名缺失或正好是空字符串时改读姓。用户名不读。抽出之前不截断。
- 话题名仍按 ADR 0088 成为正文。已有别的正文时仍留在 `topicName`。这个人的名字不进正文，也不改内容哈希。关键词因此不命中这个人的名字。图标颜色和自定义表情编号不读。话题名里已有的主机名仍排在这个人前面。本群群名不读。
- 空对象和布尔值不读发送者。普通消息不读 `from`。关掉、重开、隐藏和重新显示仍按 ADR 0589。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`topic_notice` 仍默认关闭。8 个主机名的上限不变。不调用 `editForumTopic`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把这个人整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0496。 |
| 并进 `topic_notice` | 打开新建和改名的群并不一定要按名字里的短链删。话题名仍是正文。 |
| 连关掉和重开一起改条件 | 那四条已经按 ADR 0589 读发送者。新建和改名只在 `topicNotice` 上。 |
| 新命令 `/topicname` | 菜单只剩一个空位。现有 `links` 已经能删短链。 |

## 后果

- 新建或改名话题的人，名字里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。话题还在。
- 这个人的名字原文、路径和用户名不进事件，内容哈希不变。名字里的关键词不命中。
- 名的长度大于 0 时，姓和用户名不进事件。话题名仍按原来的正文。话题名里已有短链时，证据仍先记那段名字的主机名。
- `example.com` 和公开的 `t.me/名字` 留着。付费帖仍不删除。见 ADR 0356。
- 空对象、布尔值和普通消息仍不读发送者。空白名字仍读。只改图标时仍读发送者。图标颜色和自定义表情编号仍不进事件。本群群名仍不读。干净的话题名在 `topic_notice` 关闭时仍留下。关掉、重开、隐藏和重新显示仍按 ADR 0589。云额度的基础检测器名单没有改。30 天保留期没有改。
