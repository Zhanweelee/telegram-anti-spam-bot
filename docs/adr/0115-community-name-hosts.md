# ADR 0115：社区名字只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

群被移入社区，或自己加入社区时，成员看见一条服务消息。社区名字在 `community_chat_added.community.name` 或 `community_chat_joined.community.name`。这句名字里可以只放短链或邀请。消息往往没有 `text`。

`Community` 只有 `id` 和 `name`。`community_chat_removed` 目前不带字段。`chat.title` 会附在每一条消息上，不是这一次加入或移入的内容。

把社区名字当成正文会把名字写进事件和内容哈希。

## 决策

- 从加入和移入两条服务消息的 `community.name` 抽出网址，只留主机名。折叠、长度、邀请判断和 8 个主机名的上限与旁路纯文本相同。
- 社区名字不进入 `message.text`，也不参与内容哈希。没有别的正文时，正文仍是空字符串。
- 不读取 `community.id`、`community_chat_removed`、`chat.title` 和用户姓名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把社区名字当成正文 | 名字会进事件。和 ADR 0114 对改群名的选择一样。 |
| 每条消息都扫 `chat.title` | 群名会跟着每条消息重复计一次主机名。 |
| 加入和移入的服务消息整段都不读 | 短链可以只写在这次看得见的社区名字里。 |

## 后果

- 加入或移入社区的服务消息里的短链、邀请或裸 IP 按现有链接规则命中。路径和邀请码不进事件。
- 社区名字里的关键词仍然看不到。名字原文不进事件。某个群后来可以打开 `community_notice` 删除移入、加入和移出这三行。社区名字和社区 id 仍不进事件。见 ADR 0477。
- 移出对象上的其它字段仍不抽主机名。社区 id、附在其它消息上的群名和真实姓名不进事件。
- 移入、加入或移出社区的人后来由 ADR 0594 只留下主机名。名字本身仍不进事件。没有社区对象的移入或加入，以及普通消息，仍不读发送者。移出对象上的其它字段仍不读。加入后来按全名。见 ADR 0636。移入和移出仍只读名。社区名字仍排在前面。
