# ADR 0464：每个群可以改验证时长

- 状态：已接受
- 日期：2026-11-04

## 背景

入群验证和私聊 `/captcha` 共用 300 秒。ADR 0450 把这两处绑在同一段时长上。ADR 0463 改了规则禁言秒数，并留下验证时长不动。云上的群管现在可以改自动禁言，却不能改新人要等多久。

## 决策

- `RuntimeStore` 增加 `getCaptchaTtl`、`setCaptchaTtl`、`clearCaptchaTtl`。一个群一个整数秒。
- 秒数是 30 到 86400 的整数，含两端。短于 30 秒时 Telegram 会把成员当成永久限制。长于一天超出验证动作已经接受的上限。
- 没设置时仍是 300 秒。写成 300，或 `reset`，都删掉记录。
- 私聊 `/verifyfor <chatId>` 只读。`/verifyfor <chatId> <seconds>` 写入。`reset` 回到 300 秒。
- 入群时的 `captcha` 动作和私聊 `/captcha` 读同一份记录。私聊 `/mute` 不写秒数时仍是 3600 秒。
- 内存最多 256 个群，和禁言、重复、洪泛、关键词、开关各用一份名额。已有的群可以改。新群放不下时回复「参数无效」，日志是 `captcha_ttl_full`。
- 配了 `POLICY_KV` 时写在 `runtime-captcha` 键。原来的运行时文档、动作键、上报键、洪泛键、关键词键、重复键和禁言键都不改。坏文档读成没设置。每个 isolate 缓存 60 秒。相同的值不写。
- 群聊里的同样文本不执行。接入目录里的人只能改自己的群。读或写失败回复「参数无效」，日志是 `operator_rejected`。不写姓名、消息原文或 token。这条命令不调用 Telegram。
- 私聊 `/captcha` 在限制之前读这份记录。读失败时回复「参数无效」，不调用限制。检测在创建 `captcha` 动作之前读。读失败时记 `runtime_failed`，按 300 秒继续。
- 不改 `default.json`，不改验证题目、nonce 或按钮。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把秒数写进现有运行时文档 | 旧 Worker 看到多出来的字段会把开关和 dry-run 一起丢掉。 |
| 只改入群验证，让 `/captcha` 仍是 300 秒 | ADR 0450 要求这两处共用一段时长。分开之后，补验证的人和新人不一样久。 |
| 让 `/mute` 不写秒数时改用这份记录 | 禁言和验证是两件事。ADR 0365 已经把手动禁言和自动处罚分开。 |
| 接受 1 到 29 秒 | Telegram 会把这段限制当成永久。回复里的秒数会短于实际限制。 |

## 后果

- `/verifyfor -100 120` 之后，这个群的入群验证和私聊 `/captcha` 都限制 120 秒。别的群仍是 300 秒。
- `/mute -100 77` 仍限制 3600 秒。
- 菜单多一条 `/verifyfor`，一共 97 条。
- 云额度的基础检测器名单没有改。30 天保留期没有改。
- 验证失败后的处置后来可以按群改。见 ADR 0465。没改过仍是留下。
