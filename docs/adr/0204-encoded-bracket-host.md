# ADR 0204：编码括号点不再贴出下一条主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

Android 不把 `%5B.%5D` 收成点。`%5B.%5Dbit.ly/…` 打开的是 `5Dbit.ly`。`%28.%29bit.ly/…` 打开的是 `29bit.ly`。`%7B.%7Dbit.ly/…` 打开的是 `7Dbit.ly`。中间的点写成 `%2E` 或句号 `。` 也一样。`see%5B.%5Dbit.ly/…` 和 `www%5B.%5Dbit.ly/…` 打开的是 `5Dbit.ly`。

`%5B.%5Dhttp://bit.ly/…` 什么都不打开。`%5B.%5D203.0.113.171/…` 不会打开这个地址。`%5B.%5D203.0.113.171/http://t.co/…` 会打开后面的 `t.co`。`%5B.%5Dbit.ly/http://…` 把后面的网址吞进 `5Dbit.ly`。

`%5B.%5Dwww.bit.ly/…` 打开的是 `5Dwww.bit.ly`。这个主机名仍以 `.bit.ly` 结尾。`%5B.%5D.bit.ly/…` 打开的是 `5D.bit.ly`。`http://%5B.%5Dbit.ly/…` 打开的是 `5Dbit.ly`。`http://bit.ly%5B.%5Devil.com/…` 仍先打开 `bit.ly`。

字面闭合括号不一样。`%5B.]bit.ly/…` 和 `[.]bit.ly/…` 会打开 `bit.ly`。换行、空格或制表符隔开之后也会打开。`bit%5B.%5Dly` 和 `bit[.]ly` 仍按短链删除。`t%5B.%5Dme/+…` 仍按邀请删除。第二层 `%255B.%255D` 仍留下。路径里的 `%5B.%5D` 仍收成点，不另开一条短链。公开的 `foldBracketDots` 仍把每一对收成点。

主机名扫描如果先把贴在前面的 `%5B.%5D` 收成点，`%5B.%5Dbit.ly` 会变成 `bit.ly`，`%5B.%5D203.0.113.171` 会变成一条裸 IP，`%5B.%5Dhttp://bit.ly` 会变成 `http://bit.ly`。

## 决策

- 只改主机名扫描。公开的 `foldBracketDots` 仍把 `[.]`、`(.)`、`{.}` 和一层编码收成点。
- 闭合括号是 `%5D`、`%29` 或 `%7D`，并且紧挨着已经写完的主机名、`.` 加主机名，或 `http://` / `https://` 时，把这一对换成闭合括号的两位十六进制。大小写保留原样，比较时再收成小写。
- 字面闭合括号仍收成点。`bit%5B.%5Dly` 后面接不上主机名，仍收成点。
- `://` 后面的这一对算主机名开头。路径里的 `/` 或 `%2F` 后面仍收成点。
- 换行、空格和制表符仍先按原规则处理，所以隔开之后的网址仍会打开。
- 每段仍走现有的短链、裸 IP、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 编码括号点一律不再收成点 | `bit%5B.%5Dly` 和 `t%5B.%5Dme/+…` 会漏掉。 |
| 公开的 `foldBracketDots` 一起改 | 结构化网址和已有调用仍要把这一对收成点。 |
| 字面闭合括号也换成十六进制 | `%5B.]bit.ly` 会漏掉 Android 打开的短链。 |

## 后果

- `%5B.%5Dbit.ly/…`、`%28.%29bit.ly/…`、`%7B.%7Dbit.ly/…` 和 `%5B.%5D203.0.113.171/…` 留着。
- `%5B.%5Dhttp://bit.ly/…` 和 `%5B.%5Dbit.ly/http://…` 留着。
- `%5B.%5D203.0.113.171/http://…` 按后面的短链删除。
- `bit%5B.%5Dly`、`bit[.]ly`、`[.]bit.ly` 和 `%5B.]bit.ly` 仍按短链删除。换行、空格或制表符后面的网址仍按短链删除。
- `%5B.%5Dwww.bit.ly/…` 和 `%5B.%5D.bit.ly/…` 仍按短链删除。证据是 `5dwww.bit.ly` 和 `5d.bit.ly`。
- `http://bit.ly%5B.%5D…` 仍按 `bit.ly` 删除。`t%5B.%5Dme/+…` 仍按邀请删除。第二层 `%255B` 仍留下。路径不进证据。
