# ADR 0064：匹配前去掉变体选择符

- 状态：已接受
- 日期：2026-11-01

## 背景

ADR 0054 和 ADR 0060 在比较前去掉格式字符和非常规空白，并保留普通空格。变体选择符插在两个字中间时几乎看不见，关键词和正则仍然匹配不到。把正文改掉会改变 `textSha256`。同形字仍要另做，而且不能为此加一套对照表。

## 决策

- `foldMatchText` 继续放在 core。比较前再去掉 Unicode 的 `Variation_Selector`：`U+180B`–`U+180D`、`U+FE00`–`U+FE0F` 和 `U+E0100`–`U+E01EF`。
- `U+0020` 保留。`免 费领取` 仍然不命中 `免费领取`。
- 事件里的正文和 `textSha256` 不变。正则模式本身不改写。只含这些字符的关键词在折叠后是空字符串，不匹配任何消息。
- 不新增检测器，也不改 ADR 0026 的基础检测器名单。不引入同形字库。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 在归一化时删掉变体选择符 | 哈希变了，同一句话的重复计数会拆开。 |
| 连普通空格和间隔号一起删掉 | 正常间隔会被当成关键词。这一项只处理不可见的选择符。 |
| 引入同形字库 | ADR 0054 已经拒绝。新依赖，而且会折进可见的多语言字母。 |

## 后果

- `免\uFE0F费领取` 和 `加\uFE0F微信` 会命中现有关键词和默认正则。
- 普通空格仍挡住关键词。同形字、间隔号仍按原样比较。
- 重复计数仍按原文哈希，所以只差一个变体选择符的两条消息仍算不同正文。
- 链接检测后来由 ADR 0065 在抽主机名之前做同一层折叠。正文和哈希仍不变。
