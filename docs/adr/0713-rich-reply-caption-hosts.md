# ADR 0713：富文本回复的引用条也只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

Android 把富文本消息画成普通文章气泡，和文字消息同一块。这条气泡上的引用条仍画出被回复消息的说明或正文，只取前 150 个 UTF-16 码元。

Bot API 的富文本写在 `rich_message`，常常没有 `text` 和 `caption`。ADR 0711 只在有正文、说明或普通媒体时读这行，所以只有富文本的回复会漏掉引用条上的短链。

服务公告仍走另一块，不画这行。

## 决策

- `rich_message` 是对象时，当前消息按普通气泡处理。前面的引用条都没有占住时，仍按 ADR 0711 从被回复的说明或正文前 150 个码元留主机名。
- 说明和正文仍不进事件，也不改内容哈希。关键词因此不命中。
- 服务公告仍不读这行。有引用、投票或更早的标题时仍不改读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。短链仍走已有的 `links`。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 只有富文本时不读引用条 | 文章气泡和文字气泡画的是同一行。 |
| 把富文本收成服务公告 | 客户端把它和文字消息放在同一块。 |
| 富文本上的引用读整段正文 | 这行仍只画前 150 个码元。 |

## 后果

- 只有富文本的回复，引用条上前 150 个码元里的短链会删除这条回复。证据只有主机名。
- 第 151 个码元起仍不读。原文不进事件。关键词不命中这行。内容哈希仍按富文本自己的正文。
- 服务公告仍不因被回复的正文删掉。被回复的富文本预览后来由 ADR 0717 也只留主机名。有说明时仍先读说明。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
