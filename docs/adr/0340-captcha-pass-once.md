# ADR 0340：验证按钮只放行一次

- 状态：已接受
- 日期：2026-11-04

## 背景

成员点「我不是机器人」时，`resolveChallenge` 先读出挑战，再解除限制、删掉挑战、写入 `captcha_passed`。两次投递可以在删除之前都读到同一份 nonce。隔离里的两次请求会交错，配了 D1 时两个 isolate 也会同时读到这一行。成员会被解除两次，审计也会写下两行。

ADR 0009 要求 nonce 匹配且未过期才解除限制。按钮文案和 `until_date` 不动。

## 决策

- `CaptchaStore.take` 只在 nonce 仍然一致时删掉这一行，并返回被取走的挑战。对不上或已经没有这一行时返回 `null`。
- 内存实现在同一次调用里比较并删除。D1 用一条 `DELETE ... AND nonce = ? RETURNING`。
- `resolveChallenge` 在确认未过期、nonce 匹配之后取走挑战。只有取到的那一次才 `releaseActor` 并写入 `captcha_passed`。
- 解除限制失败时，如果这个位置还空着，就把刚取走的挑战放回去。已经有新挑战时不覆盖。
- 过期仍走原来的删除和 `captcha_expired`。nonce 不对仍记 `captcha_mismatch`，不取走挑战。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 只按事件 id 占审计 | 连点两次是两个 update，事件 id 不同，审计占不住这一份 nonce。 |
| 先解除限制再取走 | 取走失败时，新的入群挑战可能已经被这次解除掉。 |
| 把按钮结果写进 KV | 挑战已经在内存或 D1。再写一份存储不增加正确性。 |

## 后果

- 同一次点击的重试，以及交错到来的第二次点击，不会再解除第二次，也不会再写一行 `captcha_passed`。
- 取走之后、解除限制之前如果进程停了，这次重试看不到挑战。成员仍受原来的 `until_date` 约束，到期后 Telegram 自己放开。
- 到期清理和按钮仍可能各写一行。这一轮不把两件事合成一次占用。
- 30 天保留期不动。
