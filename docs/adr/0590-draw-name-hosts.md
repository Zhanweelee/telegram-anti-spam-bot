# ADR 0590：创建抽奖的人，名字只留主机名

- 状态：已接受
- 日期：2026-11-05

## 背景

预约抽奖时，客户端把创建的人的名字画在公告上。没有公开中奖者时，私下结束也画出这个人。名字写在 `from`。星星数量和中奖人数当时留在事件外面。见 ADR 0483。奖品原文在可选的 `giveaway_message` 里，那是另一条消息。公开中奖者已经只留主机名。见 ADR 0580。这两条提示通常没有别的正文。短链可以只写在创建的人的名字里。

把 `from` 收成正文会让普通发言者的姓名也进检测。`giveaway_notice` 默认关闭，干净的提示仍留下。这次不取消抽奖，也不退回星星。进行中的卡片仍不读发送者。

## 决策

- 只在已经会标成 `giveawayNotice` 的提示上，从 `from` 的可见名字留主机名。`giveaway_created` 是对象时读，空对象也读。私下结束的中奖人数是大于等于 0 的安全整数时读，0 也读。两条同时出现时仍先认创建。
- `first_name` 的长度大于 0 时只读名。空白也算有名。名缺失或正好是空字符串时改读姓。用户名不读。抽出之前不截断。
- 空的结束对象、负数、小数和字符串不读发送者。进行中的卡片因此仍不读 `from`。普通消息因此仍不读 `from`。
- 名字不进正文，也不改内容哈希。关键词因此不命中。星星数量、中奖人数、未领数量和是否星星抽奖不读。嵌套的抽奖原文、名字和消息号不读。本群群名不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`giveaway_notice` 仍默认关闭。8 个主机名的上限不变。不取消抽奖，也不退回星星。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把名字整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0483。 |
| 从嵌套的 `giveaway_message` 抽主机名 | 那是另一条消息。奖品原文里的短链会误删这条结束公告。 |
| 进行中的卡片也读 `from` | 卡片已经能从举办频道标题抽主机名。发送者会再计一次。 |
| 新命令 `/drawname` | 菜单只剩一个空位。现有 `links` 已经能删短链。 |

## 后果

- 创建抽奖或私下结束的人，名字里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。抽奖本身不取消。星星不退回。
- 名字原文、路径和用户名不进事件，内容哈希不变。名字里的关键词不命中。
- 名的长度大于 0 时，姓和用户名不进事件。星星数量、中奖人数和嵌套原文不进事件。
- `example.com` 和公开的 `t.me/名字` 留着。付费帖仍不删除。见 ADR 0356。
- 空的结束、负数和小数仍不读发送者。进行中的卡片仍不读发送者。公开中奖者仍按 ADR 0580。干净的提示在 `giveaway_notice` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
- 创建公告上画出的群名后来由 ADR 0656 只留主机名。发送者仍只读名。用户名仍不读。
