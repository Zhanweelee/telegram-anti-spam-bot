# ADR 0646：视频聊天邀请名单上画出的全名成为正文

- 状态：已接受
- 日期：2026-11-06

## 背景

有人被邀请进视频聊天时，Android 的 `MessageObject` 在 `TL_messageActionInviteToGroupCall` 上用 `replaceWithLink` 画出被邀请的人。这就是 `UserObject.getUserName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。几个人之间是逗号加空格。

见 ADR 0119。当时正文还收了用户名，几个人也用空格接在一起。短链可以只写在姓上，也可以只写在用户名上。用户名上的词并没有画出来。

邀请的人另外画在句子里。这个人的主机名已经按全名抽取，名字本身不进正文。见 ADR 0634。通话时长不进事件。

没有更前面的正文时，被邀请的人的名字就是正文。已有正文时，名字另留在 `memberName`。见 ADR 0554。入群名单已经按同一套全名。见 ADR 0645。换群主仍跟在这段后面，而且仍含用户名。

## 决策

- `video_chat_participants_invited.users` 里每个人按会画出来的全名成为正文。名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读这个人。空格不截断。用户名不读。
- 几个人按出现顺序用逗号加空格接成一段。没有画出全名的人跳过，不留空位。
- 没有更前面的正文时，这段全名就是正文。已有正文时，拼起来的整段自己不是正文，就跟入群、换群主和靠近提醒一起另留前 4096 字在 `memberName`。主机名仍从这段全名抽取。
- 不读取用户编号、`language_code`、`is_bot` 和通话时长。邀请的人仍只留主机名，名字不进正文。
- 换群主仍按原来的可见名字，含用户名。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。短链仍走已有的 `links`。`member_name_regex` 和 `service_name_regex` 仍看这段正文。`call_invite` 仍默认关闭。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续把用户名收进正文 | 这行服务文字不画用户名。用户名上的短链和关键词会删掉看不见的字。 |
| 几个人仍用空格接起来 | 客户端在两个人之间画的是逗号加空格。 |
| 连换群主一起去掉用户名 | 这一轮只改视频聊天邀请。 |
| 自己被邀请时改成不读名字 | 客户端有时只画邀请者。Bot API 的名单仍是这行看得见的人，先按名单读。 |

## 后果

- 邀请名单全名里的短链、邀请或裸 IP 会删除这条服务消息。证据只有主机名。
- 全名里的关键词仍命中这段正文。用户名里的关键词不命中。用户名不进事件。
- 空白名不挡住姓。空格后面的网址仍读。两个人之间的逗号留在正文里。
- 已有别的正文时，证据仍先记正文的主机名。这段全名另留在 `memberName`。和正文相同的全名不重复留。
- 邀请的人仍只留主机名。通话时长仍不进事件。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 换群主的可见名字仍含用户名。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
