# ADR 0036：接入目录放进已有的 KV

- 状态：已接受
- 日期：2026-11-01

## 背景

ADR 0027 把拉进群后的操作者记在 isolate 内存里。Worker 一重启，`/chats` 变空，群主要等下一次管理员变更才能再操作。ADR 0035 已经用 `POLICY_KV` 保住规则开关。目录也是读多写少的配置，而且不能调用 `list`：免费计划每天大约 1,000 次 list。

## 决策

- 不新增绑定，也不改 `ChatDirectory`。配了 `POLICY_KV` 时用 `createKvChatDirectory`。每个租户一个 JSON，键前缀是 `chats`。里面只有群 id 和用户 id，最多 256 个群，每群最多 32 人。
- 没配 `POLICY_KV` 时仍用内存，上限相同。
- `list` 和 `chatsFor` 只读这一份文档，不扫描 KV。本 isolate 缓存 60 秒。成员变更写入后立刻更新这份缓存。其它 isolate 最多晚 60 秒看见。
- 文档没变不写。第 257 个群返回 `full`，日志仍是 `chat_directory_full`。第 33 个人不写入，结果仍是 `ok`，和内存实现一样。
- 坏文档当成空目录。热路径不为了修复去写。群名、用户名不进文档。
- bot 离开群时删掉这一群。某人不再是管理员时只去掉这个人，群还在。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 每个群一个 KV 键 | `/chats` 和每次私聊鉴权都要 `list`。每天 1,000 次 list 不够用。 |
| 新的绑定 | 操作者已经为白名单建过 `POLICY_KV`。目录和它一样，都是按租户记住的配置。 |
| 写进 D1 | 成员变更很少，但私聊鉴权会变成热路径上的 D1 读。 |

## 后果

- 配了 `POLICY_KV` 之后，重启仍记得谁可以把这个群管起来。
- 没配时行为和 ADR 0027 一样。
- 当时已经是管理员、之后状态没变的人，仍然要等下一次升降级才会进入目录。
- 提交的 `wrangler.jsonc` 仍不写 KV id。
- 私聊可以按群列出已经记下的人，顺序与写入相同。不新增键，第 33 个人仍不写入。见 ADR 0528。
