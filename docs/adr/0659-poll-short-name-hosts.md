# ADR 0659：加选项或删选项的人画出的短名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

有人给投票加上选项，或删掉一个选项时，Android 的 `TL_messageActionPollAppendAnswer` 和 `TL_messageActionPollDeleteAnswer` 把操作者画进服务消息。别人看到的名字来自 `DialogObject.getShortName`，也就是 `UserObject.getForcedFirstName`。名为空时改用姓。空白不算空。从下标 2 起找第一个空格，找到就把后面丢掉。下标 0 或 1 上的空格不截断。用户名不在这行里。自己操作时这行写“你”，不写名字。Bot 站在群里，读的是别人会看到的短名。

选项文字仍画在同一行，并按原来的方式成为正文。见 ADR 0089 和 ADR 0494。选项旁边的添加者是投票对象上的另一个名字，仍按 ADR 0577，空格不截断。

Bot API 把新选项放在 `poll_option_added`，被删选项放在 `poll_option_deleted`。文字在 `option_text`。同时出现时仍先认新加。空字符串落到另一种。

短链可以只写在空格后面。先前按整段名读取，会删掉客户端没有画出的后半段。

## 决策

- 已经会标成 `pollNotice` 的 `added` 或 `deleted` 时，从 `from` 会画出来的短名留主机名。`option_text` 长度大于 0 才读。空白也算有文字。`first_name` 的长度大于 0 时用名，不读姓。名缺失或正好是空字符串，且 `last_name` 是非空字符串时，改用姓。空白名挡住姓。
- 从下标 2 起的第一个空格后面不读。这个空格之前的前缀才抽主机名。没有这样的空格时，整段名字都读。下标 0 或 1 上的空格不截断。
- 主机名仍进消息已有的 `hosts`。邀请仍进 `invites`。选项文字里已有短链时，证据仍先记那段文字的主机名。被删选项的主机名仍排在这个人前面。短名不进正文，也不改内容哈希。关键词因此不命中。
- 用户名、选项编号、嵌套原投票和本群群名不读。没有 `from` 对象时不读。空对象、空字符串和布尔值不读发送者。普通消息不读 `from`。选项旁边的添加者仍按 ADR 0577。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`poll_notice` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不调用 `stopPoll`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续读空格后面 | 客户端的短名不画这段。会删掉没有出现在这行里的网址。 |
| 选项旁边的添加者也截断 | 那一行用的是可见名，不是这条服务消息的短名。见 ADR 0577。 |
| 空白名也改去读姓 | `TextUtils.isEmpty` 只把 null 和长度为 0 当成空。空白名仍挡住姓。 |
| 新命令 `/pollname` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 加选项或删选项的人，短名里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。投票还在。
- 从下标 2 起被空格截掉的后半段不读。下标 0 或 1 上的空格后面仍读。空白名挡住姓。
- 短名原文、路径和用户名不进事件。内容哈希不变。关键词不命中短名。选项文字仍按原来的正文。
- 选项文字里已有短链时，证据仍先记那段文字的主机名。被删选项的主机名仍排在前面。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 没有 `from` 对象、空对象、空字符串、布尔值和普通消息仍不读发送者。管理员仍豁免。干净的选项在 `poll_notice` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
- 选项菜单上的添加者后来按短名，从下标 2 起的第一个空格后面不读。群标题仍不截断。见 ADR 0662。
- 发送者是聊天时后来不读占位名字，也不读这个聊天的标题。用户仍按短名。见 ADR 0690。
