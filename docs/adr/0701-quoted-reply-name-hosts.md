# ADR 0701：带引用的回复补上另一边的名字

- 状态：已接受
- 日期：2026-11-06

## 背景

回复里带了摘录时，Android 的引用条不再走 `getForwardedName`，改走 `getReplyQuoteNameWithIcon`。转发来源只占一边：用户和隐藏显示名占人，群和频道占聊天。空着的那一边用这条被回复的消息自己的发送者补上。人在前，聊天在后。没有摘录时，仍只画转发来源，不画转发者。

摘录正文画在名字下面。自动摘录不进这条消息的正文。来源签名和用户名不在这个名字里。有外部回复时，这行仍画外部来源，不画本条回复。

Bot API 把摘录放在 `quote.text`。`is_manual` 只决定摘录正文进不进事件，不决定抬头画谁。ADR 0699 在能画出转发来源时只读那一边。带摘录时，空着的一边仍会留下短链。

## 决策

- `quote` 是对象，且 `text` 是字符串，并且没有 `external_reply` 对象时，按两边补名字。没有 `text` 字符串时，仍按 ADR 0699 只读转发来源。
- 转发来源是 `user` 或 `hidden_user`，以及旧的 `forward_sender_name`、`forward_from` 时，人这一边已经画了。`sender_chat` 是对象时再读标题。不读 `from`。
- 转发来源是 `chat` 或 `channel`，以及旧的 `forward_from_chat` 时，聊天这一边已经画了。没有 `sender_chat` 时，从 `from` 读全名。有 `sender_chat` 时不读 `from`，也不再读一遍标题。
- 没有转发来源时，仍只画发送者。`sender_chat` 是对象就读标题，不读 `from`。没有这个对象时，`from` 读全名。两边都没有时，只有 `chat.type` 正好是 `channel` 才读频道标题。
- 名和姓都去掉两端空白，名在前。空白名不挡住姓。空格不截断。标题不截断。先留下人，再留下聊天。用户名和来源签名不读。
- 自动引用的正文不读。手动引用的正文仍按 ADR 0547。有 `external_reply` 时不读本条 `reply_to_message`。
- 主机名仍进消息已有的 `hosts`。邀请仍进 `invites`。名字不进正文，也不改内容哈希。关键词因此不命中。正文里已有短链时，证据仍先记正文的主机名。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。短链仍走已有的 `links`。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 有摘录时仍只读转发来源 | `getReplyQuoteNameWithIcon` 会把空着的一边补上。只读一边会漏掉画出的短链。 |
| 没有摘录时也补上转发者 | 没有摘录时引用条走 `getForwardedName`，不画转发者。 |
| 来源签名也读 | 签名不在这个名字里。 |
| 新命令 | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 带摘录时，空着的一边出现短链、邀请或裸 IP，会删掉这一条。证据只有主机名。
- 没有摘录时仍只读转发来源。自动引用的原文、签名、用户名和外部回复的预览仍不进事件。画出来的自动引用后来由 ADR 0712 只留主机名。名字不改内容哈希。关键词不命中这个名字。
- 正文里已有短链时，证据仍先记正文的主机名。手动引用的正文仍排在名字前面。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 没有回复时不读。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
