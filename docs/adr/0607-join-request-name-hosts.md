# ADR 0607：入群申请的名字只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

群打开入群申请后，管理员看见的是申请人的名字。这个名字写在 `chat_join_request.from`。简介已经会拒绝短链。见 ADR 0116。名字里可以只有一条短链，简介仍然是干净的，或者根本没有简介。

ADR 0116 和 ADR 0117 当时不读这份姓名，是因为不能把名字收成简介。人还没进群，关键词也不该因为人名拒绝。这次只留主机名，名字本身仍不进事件。

真正入群后的昵称仍按 ADR 0117。邀请链接仍是管理员发出的正常邀请。

## 决策

- 只在 `kind: "join_request"` 上，从 `from` 的可见名字留主机名。名的长度大于 0 时只读名。空白也算有名。名缺失或正好是空字符串时改读姓。用户名不读。抽出之前不截断。
- 主机名记在 `nameHosts`。邀请记在 `nameInvites`。没有主机名就不设这两个字段。简介仍只来自 `bio`。名字不进 `profile`，也不改简介的哈希。
- 已有链接检测器先看简介，再看这份主机名。简介里已有短链时，证据仍先记简介的主机名。关键词和默认正则仍只看简介，不命中这个名字。
- 群名、邀请链接、`user_chat_id` 和查询号原文不读。布尔值的 `from` 仍让这条更新被忽略。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`join_request` 仍默认打开，动作仍是拒绝。8 个主机名的上限不变。不调用 `approveChatJoinRequest`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把名字拼进简介 | 关键词会命中人名，简介哈希也会变。见 ADR 0116。 |
| 等真正入群再看 | 申请阶段已经能看见这条短链。人还没进群，拒绝就够。 |
| 连邀请链接一起读 | 正常的 `t.me` 邀请会被拒绝。见 ADR 0116。 |
| 新命令 `/requestname` | 菜单只剩一个空位。现有 `links` 已经能拒绝短链。 |

## 后果

- 申请人的名字里出现短链、邀请或裸 IP 时，这条申请会被拒绝。证据只有主机名。人还没进群。
- 这个人的名字原文、路径和用户名不进事件。简介哈希不变。名字里的关键词不命中。
- 名的长度大于 0 时，姓和用户名不进事件。简介里已有短链时，证据仍先记简介的主机名。
- `example.com` 和公开的 `t.me/名字` 留着。没有短链的姓名仍留给管理员。带查询号时仍按原来的方式答复。
- 群名、邀请链接和用户编号仍不读。布尔值的 `from` 仍忽略。真正入群后的昵称仍按 ADR 0117。云额度的基础检测器名单没有改。30 天保留期没有改。
- 申请人后来按全名只留主机名。名和姓都去掉两端空白，名在前。空白名不挡住姓。空格不截断。见 ADR 0638。用户名、群名和邀请链接仍不读。
