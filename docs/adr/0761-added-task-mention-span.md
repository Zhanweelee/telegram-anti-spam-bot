# ADR 0761：后加任务上的按标识提及必须从这条任务里开始

- 状态：已接受
- 日期：2026-11-07

## 背景

按标识提及可以按群删除。用户编号不进事件。见 ADR 0514。清单任务上的按标识提及必须从这条任务里开始。见 ADR 0760。

新加任务的服务消息最多画出前三条。三条及以内全部画出。第四条起的提及不在这行里。

Android 的 `addEntitiesToText` 会跳过长度小于或等于 0、起点小于 0，或起点已经到达这条任务末尾的实体。起点落在任务里、长度越过末尾时，客户端把长度收到任务末尾，这段提及仍会画出来。

已有别的正文时，事件里的后加任务把画出的任务拼在一起，只留前 3029 字。提及仍按每一条画出的任务自己的整段文字判断。

现在前三条会读全部 `text_entities`。一个起点已经越过这条任务的按标识提及仍会带上 `asTextMention`。打开这条规则后，没画出来的提及也会删掉这条服务消息。

礼物和游戏不在这条里。

## 决策

- `checklist_tasks_added` 只看前三条。三条及以内全部看。
- 画出的任务文字是字符串时，`text_entities` 里的按标识提及，起点必须大于或等于 0 且小于这条任务的长度，长度必须大于 0。
- 起点落在这条任务里、长度越过末尾时，仍带 `asTextMention`。
- 任务文字不是字符串时，仍按原来的方式读取。
- 第四条起的按标识提及不读。
- 拼在一起超过 3029 字时，只要起点仍落在这条画出的任务里，就继续带 `asTextMention`。事件里的后加任务仍只留前 3029 字。
- 礼物附言上的按标识提及不在这条里。
- 仍落在任务里的提及继续带 `asTextMention`。用户编号和名字仍不进事件。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。规则仍默认关闭。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续读全部实体 | 没画出来的提及会在打开规则后删掉这条服务消息。 |
| 也要求长度落在任务里 | 起点在任务里时，客户端会把越过末尾的长度收回来再画。 |
| 也读第四条 | 客户端的服务消息只画出前三条。 |
| 也按 3029 字丢掉后面的提及 | 3029 只是拼在一起之后的上限。单条更长时，后面的提及仍落在这条任务里。 |
| 礼物附言也一起收 | 附言是另一段文字，这条只改后加任务。 |
| 默认打开 | 有的群会点名。打开之前不改现有群。 |

## 后果

- 起点已经到达或越过这条后加任务末尾的按标识提及不再带 `asTextMention`。空任务、长度为 0 和负起点也不带。第四条起也不带。
- 起点落在画出的任务里的提及，打开 `text_mention` 后删除。证据仍是 `entity:text_mention`。用户编号不进事件。长度越过末尾的提及也删除。起点已经超过 3029、但仍落在这条任务里的提及也删除。
- 规则关闭时留下。付费帖仍不删除。见 ADR 0356。
- 任务文字不是字符串时，按标识提及后来由 ADR 0805 不再读取。
- 礼物附言上的按标识提及后来由 ADR 0762 要求起点落在附言里。附言不是字符串时仍按原来的方式读取。长度越过末尾时仍算画出来。
- 管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
