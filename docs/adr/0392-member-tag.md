# ADR 0392：私聊可以设置一个成员的标签

- 状态：已接受
- 日期：2026-11-04

## 背景

管理员想给普通成员标一个短标签，或把已有标签清掉。官方有一次只改标签的调用。

`setChatMemberTag` 给群或超级群里的普通成员设置标签。bot 必须是管理员，并且有 `can_manage_tags`。成功时返回 True。参数是 `chat_id`、`user_id`，以及可选的 `tag`。`tag` 是 0–16 个字符，不能用 emoji。

文档没有说明省略 `tag` 和送出空字符串是否同一件事。空字符串落在写明的 0–16 里。

这条调用不改名字，也不读取成员资料。

没有 token 时，内存适配器可以把这次请求记下来。私聊如果复用这次成功，回复会写成标签已经设置。标签文本不能进回复或日志。

## 决策

- 私聊命令 `/tag <chatId> <userId> [tag]`。群 id 和成员 id 匹配 `^-?\d{1,20}$`。标签是剩下的参数，按空白折叠成一段。少一个编号不发出请求。群聊里的同样文本不执行。
- 折叠后的长度要落在 0 到 16。超过 16 个字符不发出请求。
- 不写标签时送出空字符串。请求里始终带 `tag`。
- 配置中的管理员可以操作任意群。接入目录里的人只能操作自己的群。
- 调用 `ModerationPort.setMemberTag`。适配器调用 `setChatMemberTag`，带 `chat_id`、`user_id` 和 `tag`。
- 不调用 `getChatMember`。不读取名字。
- 回复写明标签被请求设置或清掉，名字还在。回复不重复标签。
- 没有 token、没有这个方法，编号不合法，或调用失败时回复「参数无效」。日志只写 `operator_rejected`，带上 eventId、chatId 和命令名。不写异常文本、token、标签或原文。
- 没有 token 的 Worker 不把内存里的记录回复成已经成功。
- 不修改黑名单、白名单、封禁或禁言。不读取消息正文。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 省略 `tag` 表示清掉 | 文档没有写省略和空字符串的差别。空字符串已经在 0–16 里。 |
| 先用 `getChatMember` 读出名字再设置 | 多一次子请求，还会带回名字。设置本身不需要名字。 |
| 在本地判断 emoji | 文档只说不能用 emoji，没有给出码位表。超出范围或含 emoji 时，由 Telegram 返回失败。 |
| 回复里重复标签 | 标签可能是姓名或原文。管理员刚输入过它。 |

## 后果

- 成功只表示 Telegram 接受了这一次设置。缺少 `can_manage_tags`、目标不是普通成员，或标签含 emoji 时，回复是「参数无效」。
- 名字还在。
- 一次设置是一次 Telegram 子请求。封禁、禁言和黑名单都不变。
- 30 天保留期不动。
