# ADR 0045：`/chats` 带上每群已用次数

- 状态：已接受
- 日期：2026-11-01

## 背景

ADR 0027 的 `/chats` 只列出群 id。管理员要看每个群用了多少免费额度，只能再对每个群发一次 `/quota`。

## 决策

- 额度打开且快照有效时，`/chats` 的每一行是 `{chatId} {used}/{limit}`。中英文用同一组数字。
- 每个列出来的群只调用 `QuotaReader.read` 一次，不计数。顺序跟目录一致。
- 没有额度读数、额度关闭，或这一行读取失败时，这一行只留群 id。失败记 `quota_failed`，不写异常文本，其它行照常。
- 整份回复超过私聊长度时，保留前面的行，末尾写 `+{count}`。被省略的群也已经读过。
- 不在这一行写周期、结束时间或基础检测器。那些仍在 `/quota` 和超额后的 `/rules`。
- 不改 ADR 0026 的默认次数、周期和基础检测器名单，也不把计数写进 KV 或 D1。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 仍只列群 id | 对照额度要按群再发命令。 |
| 超长就整份改回只有群 id | 群一多，次数反而看不到。 |
| 每个群都写 `until` | 一行里再放时间，私聊更快超长。 |

## 后果

- 云上打开额度后，`/chats` 能同时看到这些群的已用次数和上限。
- 自定义的 `QuotaReader` 缺失或关闭时，列表仍只有群 id。
- 全局管理员列出很多群时，回复可能以 `+` 结尾。重启后内存计数归零，行上的已用次数也回到 0。
- 目录满 256 个群时，第一页后来盖不住后面的群。`/chats` 由 ADR 0525 接受 `skip`，从指定个数继续列。不写 `skip` 时仍是这一页。跳过的群不再读额度。
