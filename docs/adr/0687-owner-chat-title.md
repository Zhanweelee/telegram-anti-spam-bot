# ADR 0687：交群的发送者是聊天时只读聊天标题

- 状态：已接受
- 日期：2026-11-06

## 背景

群主换人时，Android 的 `TL_messageActionChangeCreator` 用 `replaceWithLink` 先画操作的人，再画新群主。待确认交群的 `TL_messageActionNewCreatorPending` 先画新群主，再画操作的人。操作的人是 `fromObject`。发送者是聊天时，画出这个聊天的标题。标题不截断。这两条都没有跳过自己。

Bot API 把换人放在 `chat_owner_changed`，把离开放在 `chat_owner_left`。发送者是聊天时，`sender_chat` 是那个聊天，`from` 是占位用户。见 `telegram-bot-api` 的 `messageSenderChat`。

ADR 0633 仍从 `from` 的全名留主机名。占位用户的名字不是这行画出的字。编号和本群相同时，通用代发规则也不读标题。这份 Android 源码里没有名叫 `chat_owner_left` 的动作。离开对象仍按同一行处理。

## 决策

- 已经会标成 `ownerNotice` 的提示上，`sender_chat` 是对象时，只从 `sender_chat.title` 留主机名，不从 `from` 留主机名。标题不截断。用户名不读。频道、群和超级群都一样。编号和本群相同时也读。
- 没有 `sender_chat` 时，仍从 `from` 的全名留主机名。名和姓都去掉两端空白，名在前。空白名不挡住姓。空格不截断。
- 不从 `chat.title` 另读。
- 编号不同时，标题由通用代发规则先读，排在新群主的名字前面。编号相同时，新群主的名字排在前面。没有下一位时只留标题。
- 新群主的名字仍按原来的正文。换人仍要有新群主对象。离开的空对象仍读。空的换人对象和布尔值仍不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`owner_notice` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不改群主。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续读 `from` | 占位用户的名字不在这行里。短链会删掉一条没有这个名字的提示，标题上的短链又会留下。 |
| 本群匿名不读群名 | Android 画的就是这个聊天的标题。通用代发规则在编号相同时不读它。 |
| 离开不读标题 | 离开对象上这行同样画出操作的人。空对象时正文是空的，短链可以只写在标题上。 |
| 新命令 | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 聊天交群或离开时，标题里的短链、邀请或裸 IP 会留下主机名。证据只有主机名。群主本身不变。
- 本群自己操作时，默认仍因管理员豁免而留下。关掉豁免后会删。别的聊天发到这个群时不豁免。
- 占位用户的名字不再留下主机名。用户仍按全名。
- 空的换人对象和布尔值仍不读发送者。`example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。
- 30 天保留期没有改。
