# ADR 0010：洪泛与重复的内存窗口

- 状态：已接受
- 日期：2026-11-01

## 背景

P1-02 要认出短时间里的发言洪泛，以及同一条内容的重复。计数在热路径上。`docs/limits.md` 写明：KV 每天只有 1,000 次写，而且最终一致，不适合强计数；每条消息叫醒一个 Durable Object 会把 Worker 请求和 DO 请求各算一笔，免费计划不能假设这份预算无限。额度文档要求洪泛计数可降级，DO 不可用时跳过该检测器。

## 决策

- 默认窗口是当前 isolate 的内存，接口是 `RateWindow`。实现放在 `packages/detectors-rate`，不进 core。
- `flood` 按 tenant + chat + actor 计数，默认 10 秒内 5 条。`repeat` 按 tenant + chat + `textSha256` 计数，默认 60 秒内 3 条。空正文不参与重复判断。证据摘要只有 `flood:N` 或 `repeat:N`。
- 每个窗口最多 256 个 key、每个 key 最多 32 个时间戳。新 key 放不下，而且扫过期 key 之后仍然放不下时，`observe` 返回 `null`。检测器记 `rate_window_skipped` 并返回未命中，不抛错。窗口抛错时记 `rate_window_failed`，同样返回未命中，日志不带异常文本。
- 时间用事件的 `occurredAt`，方便回放。dry-run 仍会推进窗口。
- 默认规则对这两种命中执行 delete。`chats.json` 整份替换的群不会自动带上这两条规则。
- 以后如果要跨 isolate 的强一致计数，用同一个 `RateWindow` 接 Durable Object。那一层必须在失败时返回 `null`，不能把请求拖住。这一项不绑定 DO。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 每条消息写 KV | 写预算是每天 1,000 次，而且同一 key 一秒只能写一次。计数会丢，也会把白名单的写预算挤掉。 |
| 默认绑定 Durable Object | 每条群消息都是一次 DO 请求。免费计划每天 100,000 次，和 Worker 请求叠在一起。强一致可以以后再加，默认路径用近似计数。 |
| 窗口放进 D1 | 每条消息多一次行写。行写预算要留给审计。洪泛判断不该排在数据库后面。 |

## 后果

- isolate 重启或多 isolate 会少计，方向是漏报，不会因为计数丢失而误罚。
- 没有正文的文件后来由 ADR 0052 用 `mediaSha256` 参加同一条 `repeat`。空正文且没有这份摘要时仍然跳过。
- 跨 isolate 的可选计数后来由 ADR 0050 接在同一个 `RateWindow` 上。提交的配置不绑定它。
- 窗口满了之后，新的 actor 或新的哈希会被跳过，已经在窗口里的 key 继续计数。
- 管理员和白名单在预过滤阶段就返回，不进入计数。
- 同一组数字相册在未编辑时只占一次洪泛名额。编辑后的消息仍逐条计。见 ADR 0438。
- 未编辑的定时消息在没有相册编号时共用一个洪泛名额。见 ADR 0442。
- 条数和秒数后来可以按群改。没改过仍是 10 秒 5 条。见 ADR 0460。
