# ADR 0688：社区的发送者是聊天时只读聊天标题

- 状态：已接受
- 日期：2026-11-06

## 背景

自己加入社区时，Android 的 `TL_messageActionChatJoinedViaCommunity` 用 `replaceWithLink` 画操作的人。发送者是聊天时，画出这个聊天的标题。标题不截断。

群被移入或移出社区时，`TL_messageActionChangeCommunity` 用 `DialogObject.getShortName`。这个人是用户时，短名从下标 2 起的空格后面不画。这个人是聊天时，短名就是聊天标题，空格不截断。

Bot API 把加入放在 `community_chat_joined`，移入放在 `community_chat_added`，移出放在 `community_chat_removed`。发送者是聊天时，`sender_chat` 是那个聊天，`from` 是占位用户。见 `telegram-bot-api` 的 `messageSenderChat`。

ADR 0636 和 ADR 0658 仍从 `from` 留主机名。占位用户的名字不是这行画出的字。编号和本群相同时，通用代发规则也不读标题。

## 决策

- 已经会标成 `community` 的提示上，`sender_chat` 是对象时，只从 `sender_chat.title` 留主机名，不从 `from` 留主机名。标题不截断。用户名不读。加入、移入和移出都一样。频道、群和超级群都一样。编号和本群相同时也读。
- 没有 `sender_chat` 时，加入仍按全名。移入和移出仍按短名，从下标 2 起的第一个空格后面不读。
- 不从 `chat.title` 另读。
- 编号不同时，标题由通用代发规则先读，排在社区名字前面。编号相同时，社区名字排在前面。移出没有社区名字时只留标题。
- 移入和加入仍要有社区对象。移出的空对象仍读。没有社区对象的移入或加入仍不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`community_notice` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不把群移出社区。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续读 `from` | 占位用户的名字不在这行里。短链会删掉一条没有这个名字的提示，标题上的短链又会留下。 |
| 移入和移出的聊天标题也按短名截断 | 聊天的 `getShortName` 是整段标题。空格后面的网址仍画在这行里。 |
| 本群匿名不读群名 | Android 画的就是这个聊天的标题。通用代发规则在编号相同时不读它。 |
| 新命令 | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 聊天加入、移入或移出社区时，标题里的短链、邀请或裸 IP 会留下主机名。证据只有主机名。群是否留在社区不变。
- 本群自己操作时，默认仍因管理员豁免而留下。关掉豁免后会删。别的聊天发到这个群时不豁免。
- 占位用户的名字不再留下主机名。用户加入仍按全名。用户移入或移出仍按短名。
- 没有社区对象的移入或加入仍不读。`example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。
- 30 天保留期没有改。
