# ADR 0051：入群挑战可以留在 D1

- 状态：已接受
- 日期：2026-11-01

## 背景

ADR 0009 把挑战放在 isolate 内存里，并写明跨 isolate 以后再单独立项。按钮回调可能落到另一个 isolate。那里没有 nonce，成员要等到 `until_date`。KV 是最终一致的，点击往往早于那份写入被看见。额度计数仍然不进持久存储。

## 决策

- 提交的 `wrangler.jsonc` 不新增绑定。没配 `DB` 时挑战仍在 isolate 内存。
- 配了 `DB` 之后，`captcha_challenges` 按租户、群和 actor 存一行。列是 nonce 和到期时间。只有主键，不建二级索引。
- 写入发生在挑战创建、替换、通过、超时和回滚。普通消息不写这张表。
- 另一个 isolate 用同一份 `DB` 读取。坏行读成没有挑战，并且不回写。
- Cron 仍是 `*/15 * * * *`。它删除已经到期的行并写审计，一次最多 64 条，不调用 `releaseActor`。
- 不改 ADR 0026 的默认额度。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把挑战放进 KV | 最终一致。按钮可能在写入可见之前到达，成员仍然被困住。每天 1,000 次写也更紧。 |
| 默认再绑一个 Durable Object | 对象被换掉时挑战还是会丢，并且每条入群和每次点击都是额外请求。D1 已经是可选的持久存储。 |
| 在对象或表里保住额度计数 | ADR 0026 拒绝为额度再写存储。 |

## 后果

- 自部署不配 `DB` 时，行为和 ADR 0009 一样。
- 配了 `DB` 之后，同一条挑战能跨 isolate 被按钮对上。
- 每次入群多一行写入，通过或删除再写一次。这不在每条消息的热路径上。
- 坏行留在表里，直到下一次 `put` 覆盖同一个 actor。
- 超过 64 条到期挑战时，剩下的等下一次 Cron。Telegram 的 `until_date` 仍会自己到期。
