# ADR 0157：内联查询只留高亮主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0111 从 `switch_inline_query`、`switch_inline_query_current_chat` 和 `switch_inline_query_chosen_chat.query` 抽出整段网址的主机名。Android 按下同一会话的按钮时，把 `@用户名` 和这段查询写进当前输入框；换聊天时把同一句存成草稿。发送预览对输入框调用 `MessageObject.addLinks`，走的是 `Linkify.WEB_URLS`。

点下去打开的是高亮那一段。整段解析会把 `∕` 后面的 `@` 认成新的主机。短链和裸 IP 可以只写在前面。按钮上看得见的字、已经写明的 `url`、复制文字和登录地址不经过这段高亮。

## 决策

- 这三处查询里的 `http` 或 `https` 再取 Android 高亮会打开的那一段主机名。只留主机名。内联键盘和富文本按钮同一条路径。
- 整段解析出的主机名仍然保留。两边都走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。最多 8 个。
- 查询不进入 `message.text`，也不参与内容哈希。按钮文字、`url`、`copy_text`、`login_url` 和 `web_app` 仍整段打开。
- 不读取 `callback_data`、`login_url.forward_text`、挑选聊天的允许范围，以及回复键盘。路径不进证据。没有新的主机名时不另记。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 只留整段解析出的主机名 | 发送预览打开的是高亮提前停住的那一段。短链可以只写在 `∕` 前面。 |
| 按钮文字也按高亮截断 | 按钮上的字被按钮自己吃掉，不走 `addLinks`。 |
| 把查询拼进正文 | 同一条消息的哈希会变。ADR 0111 拒绝的就是这个。 |

## 后果

- 查询是 `http://bit.ly∕@example.com/…` 时按短链删除。证据仍只有主机名。
- 同一段查询是 `http://example.com∕@bit.ly` 时，整段里的 `bit.ly` 仍删除。
- 小写 `%e2%88%95` 仍打开后面的主机。按钮文字里的同一段不另记前面的短链。
- 再套一层仍放行。路径和回调数据不进证据。
