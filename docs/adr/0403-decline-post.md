# ADR 0403：私聊可以拒绝一条建议帖

- 状态：已接受
- 日期：2026-11-04

## 背景

频道的私聊里会收到建议帖。垃圾建议帖不该被发出去。官方有一次只拒绝建议帖的调用。

`declineSuggestedPost` 拒绝一条建议帖。目标是对应频道的私聊。bot 必须在对应频道里有 `can_manage_direct_messages`。成功时返回 True。

必填参数是 `chat_id` 和 `message_id`。可选的 `comment` 是给投稿人的说明，长度 0 到 128。

这条调用不批准建议帖，也不处理加入申请。说明不能进回复或日志。没有 token 时不能把内存记录回复成已经拒绝。

## 决策

- 私聊命令 `/declinepost <chatId> <messageId> [comment]`。群 id 匹配 `^-?\d{1,20}$`。消息号是不带前导零的正安全整数，`1` 原样送出。说明是其余参数按空白折叠后拼起来的字符串。少一个编号不发出请求。群聊里的同样文本不执行。
- 不写说明时不送 `comment`。写出的说明长度要落在 1 到 128。超过 128 个字符不发出请求。
- 配置中的管理员可以操作任意群。接入目录里的人只能操作自己的群。
- 调用 `ModerationPort.declinePost`。适配器调用 `declineSuggestedPost`，带 `chat_id` 和 `message_id`。有说明时再带 `comment`。不送 `send_date`。
- 回复不重复说明，并写明这条不会发出、其它建议帖还在。
- 没有 token、没有这个方法，编号或说明不合法，或调用失败时回复「参数无效」。日志只写 `operator_rejected`，带上 eventId、chatId 和命令名。不写异常文本、token、说明或原文。
- 没有 token 的 Worker 不把内存记录回复成已经拒绝。
- 不调用 `approveSuggestedPost` 或 `declineChatJoinRequest`。不修改黑名单、白名单、封禁或禁言。不读取消息正文。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 不写说明时送出空字符串 | 空说明仍是给投稿人的一条说明。不写就表示没有说明。 |
| 同时提供批准命令 | 批准会把帖子发出去。拒绝才是拦住垃圾建议帖。 |
| 复用 `/decline` | `/decline` 已经用来拒绝加入申请。建议帖是另一条调用。 |
| 回复里重复说明 | 说明可能是管理员刚粘贴的原文。回复只确认这一次请求。 |

## 后果

- 成功只表示 Telegram 接受了这一次 `declineSuggestedPost`。缺少 `can_manage_direct_messages`、目标不是建议帖，或说明不被接受时，回复是「参数无效」。
- 这条建议帖不会发出。其它建议帖还在。加入申请还在。
- 一次拒绝是一次 Telegram 子请求。封禁、禁言和黑名单都不变。
- 30 天保留期不动。
