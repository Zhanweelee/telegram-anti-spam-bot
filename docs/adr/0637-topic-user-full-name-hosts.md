# ADR 0637：频道私信话题的用户画出的全名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

频道私信进一个话题。Android 在话题分隔上用 `DialogObject.getName` 把开话题的人画成标题。这就是 `UserObject.getUserName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行标题里。

Bot API 把这个人放在 `direct_messages_topic.user`。见 ADR 0608。当时名的长度大于 0 就丢掉姓。发言人不是这个用户时，标题仍是开话题的人，回复不该因为那个人的名字被删。短链可以只写在姓上。把整段收成正文会改变内容哈希，关键词也会命中名字。

## 决策

- 只在发言人编号和 `direct_messages_topic.user` 相同时，从这个用户会画出来的全名留主机名。`user` 必须是对象。
- 名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读。空格不截断。用户名不读。
- 名字不进正文，也不改内容哈希。关键词因此不命中。话题号和本群群名不读。发言人 `from` 上的名字不读。
- 发言人不是这个用户时不读。没有话题、布尔值、空对象和空的用户对象不读。普通消息因此仍不读 `from`。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。短链仍走已有的 `links`。8 个主机名的上限不变。不调用 `editForumTopic`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续只读名 | 话题标题把姓画在同一行里。姓上的短链会留在消息里。 |
| 把名字整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0606。 |
| 任何出现这个字段的消息都读 | 管理员在同一话题里的回复会被删。 |
| 新命令 `/topicname` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 开话题的人自己发言，全名里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。话题还在。
- 全名原文、路径和用户名不进事件。内容哈希不变。关键词不命中全名。
- 空白名不挡住姓。空格后面的网址仍读。
- 正文里已有短链时，证据仍先记正文的主机名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 发言人不是话题用户、没有话题、布尔值、空对象和空的用户对象仍不读。普通消息的 `from` 仍不读。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
- 付款失败和退款后来即使发言人不是话题用户，也读这个人画出的全名。通过和付款仍不读。见 ADR 0650。
