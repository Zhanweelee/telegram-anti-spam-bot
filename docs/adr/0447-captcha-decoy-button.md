# ADR 0447：验证消息带一颗不会通过的按钮

- 状态：已接受
- 日期：2026-11-04

## 背景

入群验证只有一颗「我不是机器人」。ADR 0009 记下问答验证还没有做，按钮是当时的唯一方式。问答要在 `captcha_challenges` 上另存答案，那是一次表结构变更。

客户端画出的两颗按钮里，先点到的那颗会先把回调送回来。只放一颗通过按钮时，脚本点第一颗就过。

## 决策

- 验证消息的正文改成「请点「我不是机器人」。点「我是机器人」不会通过。」
- 同一条消息先放「我是机器人」，`callback_data` 是 `n:` 加这一次挑战的 16 位 nonce。再放「我不是机器人」，仍是 `c:` 加同一段 nonce。
- `n:` 对不上现有的 `c:` 加 16 位十六进制，收成忽略。配了 token 时仍应答，清掉转圈。不读按钮所在消息的正文。
- 点对的那颗仍按原来的挑战放行一次。nonce、过期和陌生人点击的规则不动。
- 不改 `captcha_challenges`，不新增命令，不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 存一道算术题的答案 | 要给挑战表加一列。这一项不改表。 |
| 把 `n:` 收成一种新的失败事件 | 现有忽略路径已经应答。再写一行审计不增加拦住脚本的效果。 |
| 两颗按钮交换位置 | 脚本点第一颗就会点到通过按钮。 |

## 后果

- 点「我是机器人」不会放行，也不会删掉验证消息。点的时候会提示去点另一颗。见 ADR 0448。点「我不是机器人」仍只放行一次。
- 按钮原文和 nonce 不进忽略结果。挑战表的列没有增加。
- 云额度的基础检测器名单没有改。30 天保留期没有改。
