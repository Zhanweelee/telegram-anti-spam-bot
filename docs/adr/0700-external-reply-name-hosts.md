# ADR 0700：外部回复抬头只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

回复另一条聊天里的消息，而原文没有加载时，Android 的引用条走 `getReplyQuoteNameWithIcon`。名字来自外部来源：用户是 `UserObject.getUserName`，隐藏转发是 `from_name`，群和频道是标题。来源签名不在这个名字里。另一个聊天和本群不是同一个对话时，标题再画在来源名字后面。编号相同就不再画一遍。图标占位不是文字。

预览正文、链接预览和被引用的原文画在名字下面，不和名字拼成一段。有外部回复时，不再画本条已加载回复上的人。

Bot API 把这份预览放在 `external_reply`。来源是 `origin`。另一个聊天是 `chat`。ADR 0699 读本条回复的抬头，并在有外部回复时整段跳过。引用条上的外部来源仍会留下短链。

## 决策

- `external_reply` 是对象时，从引用条上会画出来的外部来源留主机名。本条 `reply_to_message` 不再读。
- `origin.type` 正好是 `user` 时，从 `sender_user` 读全名。名和姓都去掉两端空白，名在前。空白名不挡住姓。空格不截断。用户名不读。
- `origin.type` 正好是 `hidden_user`，且 `sender_user_name` 是字符串时，整段留下。
- `origin.type` 正好是 `chat` 时，只读 `sender_chat.title`。`origin.type` 正好是 `channel` 时，只读 `chat.title`。标题不截断。来源签名不读。
- `external_reply.chat.title` 在来源名字之后再读。`chat.id` 和本条 `message.chat.id` 都是编号，且相同，就不另读。缺了编号时仍读标题。用户名不读。
- 预览正文、链接预览、手动引用和媒体说明不读。
- 主机名仍进消息已有的 `hosts`。邀请仍进 `invites`。名字不进正文，也不改内容哈希。关键词因此不命中。正文里已有短链时，证据仍先记正文的主机名。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。短链仍走已有的 `links`。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 整份外部回复都当另一条消息来扫 | 预览正文属于另一条消息。引用条上画出的名字才在这一条里。 |
| 来源签名也读 | `peerNameWithIcon` 不把签名放进这个名字。 |
| 编号和本群相同的标题也再读一遍 | Android 只在 `reply_to_peer_id` 和当前对话不同时才加这段标题。 |
| 新命令 | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 外部来源或另一个聊天的标题出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。
- 预览正文、链接预览、来源签名、用户名和本条回复仍不进事件。名字不改内容哈希。关键词不命中这个名字。
- 正文里已有短链时，证据仍先记正文的主机名。转发来源和隐藏显示名仍按原来的规则排在前面。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 没有外部回复时不读。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
