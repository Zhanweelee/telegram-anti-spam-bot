# ADR 0096：乌克兰语 і 在比较前收成 i

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0095 留下了乌克兰语 `і`。`bіt.ly` 里的 `і` 不是 ASCII 单词字符，主机名扫描会从后面的 `t.ly` 开始。`t.ly` 不在短链名单里，整条消息放行。带协议时，URL 解析器把 `і` 收成 punycode，主机名也不是 `bit.ly`。

西里尔 `т` 仍不收。它在俄文里太常见。

## 决策

- `foldCyrillicLookalikes` 增加一对：`і/І`（`U+0456` / `U+0406`）收成 `i/I`。
- 关键词、正则、链接检测、`hostFromUrl` 和从正文里抽网址的扫描沿用同一层。
- 西里尔 `т/Т`、全角数字、`U+FF0B`、`U+3002` 和普通空格保留。
- 事件里的正文和 `textSha256` 不变。不新增检测器，也不改 ADR 0026 的基础检测器名单。不引入同形字库。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 连 `т` 一起收 | ADR 0095 已经拒绝。普通俄文句子会更容易被扫成主机名。 |
| 只在链接检测里收 | `vіp` 仍会绕过关键词 `vip`。三处比较走同一层。 |
| 在归一化时改掉正文 | 哈希变了，重复计数会拆开。 |

## 后果

- `bіt.ly/…` 和 `bІt.ly/…` 会走现有短链规则，不再被看成 `t.ly`。
- `vіp` 会命中关键词 `vip`。大小写敏感时 `vіp` 仍不命中 `VIP`。
- `привіт` 仍不命中 `免费领取`。`т.me/+…` 仍抽不出来。
- 重复计数仍按原文哈希。
