# ADR 0751：礼物附言上的自定义表情必须落在附言里

- 状态：已接受
- 日期：2026-11-07

## 背景

自定义表情可以按群删除。编号不进事件。见 ADR 0515。后加任务必须整段落在前三条里。见 ADR 0750。

普通礼物、唯一礼物和升级购买都可以带一段附言。Android 用 `addEntitiesToText` 把实体画到这段附言上。聊天列表的短预览、礼物卡片和详情表都走这一步。见 ADR 0734。自定义表情还要整段落在这段文字里：起点加长度越过附言时，表情不会画出来。

已有别的正文时，事件里的 `giftText` 只留前 128 字。表情仍按整段附言判断。

现在这三段会读全部 `entities`。一个越出附言的自定义表情仍会带上 `asCustomEmoji`。打开这条规则后，没画出来的表情也会删掉这条礼物消息。

游戏附加文字不在这条里。

## 决策

- `gift.text`、`unique_gift.text` 或 `gift_upgrade_sent.text` 是字符串时，这段 `entities` 里的自定义表情，起点必须大于或等于 0，长度必须大于 0，并且起点加长度不能越过这段附言。
- 附言不是字符串时，仍按原来的方式读取。
- 第 129 字起的表情，只要整段仍落在附言里，就继续带 `asCustomEmoji`。已有别的正文时，事件里的 `giftText` 仍只留前 128 字。
- 仍落在附言里的表情继续带 `asCustomEmoji`。编号仍不进事件。
- 游戏附加文字不在这条里。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。规则仍默认关闭。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续读全部实体 | 没画出来的表情会在打开规则后删掉这条礼物消息。 |
| 只要求起点小于附言 | 表情越过末尾时，客户端同样不会画。 |
| 也按 128 字丢掉后面的表情 | 128 只是旁路字段的上限。整段附言更长时，后面的表情仍落在附言里。 |
| 只改普通礼物 | 唯一礼物和升级购买的附言也用同一套实体画出来。 |
| 附言不是字符串时也不读 | 现有消息仍会带上这种实体。这条只改画出的附言。 |
| 游戏附加文字一起收 | 游戏说明是另一段文字。 |

## 后果

- 起点加长度越过礼物附言的自定义表情不再带 `asCustomEmoji`。空附言和长度为 0 的实体也不带。
- 仍落在附言里的表情，打开 `custom_emoji` 后删除。证据仍是 `entity:custom_emoji`。编号不进事件。起点已经超过 128、但仍整段落在附言里的表情也删除。
- 规则关闭时留下。付费帖仍不删除。见 ADR 0356。
- 游戏附加文字上的自定义表情后来由 ADR 0752 要求整段落在附加文字里。附加文字不是字符串时仍按原来的方式读取。已有别的正文时，事件里的附加文字仍只留前 4096 字。
- 管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
