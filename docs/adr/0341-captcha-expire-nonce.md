# ADR 0341：到期清理只取走原来的 nonce

- 状态：已接受
- 日期：2026-11-04

## 背景

ADR 0340 让按钮先按 nonce 取走挑战。到期清理仍先读出已到期的行，再按成员删除。成员又入群时，新挑战用同一个成员、另一份 nonce。清理会把这行新挑战删掉，并写下 `captcha_expired`。按钮和清理也可能各写一行。

D1 每次调用最多 50 条查询。`db.batch()` 算一条。到期列表最多 64 行。见 ADR 0328 和 `docs/limits.md`。

## 决策

- `takeMany` 只删除 nonce 仍然一致的行，并返回这些行。空列表不访问数据库。
- 内存实现在同一次调用里逐行比较并删除。D1 把这些 `DELETE ... AND nonce = ?` 打成一批。
- `expireChallenges` 先取走，再只为取到的行写 `captcha_expired`。没取到就不写、不记日志。
- 过期按钮同样先 `take` 这一份 nonce。取到才写 `captcha_expired` 并返回 `expired`。取不到返回 `ignored`，新挑战留着。
- 按成员整行删除仍只用于限制失败时的回滚。一次最多 64 条。不解除限制。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 每行单独 `take` | 64 行会超过一次调用 50 条查询。 |
| 先写审计再删除 | 按钮已经取走时，仍会留下一行 `captcha_expired`。 |
| 清理时按成员删除 | 新挑战和旧挑战是同一个成员。 |

## 后果

- 同一成员的新挑战不会被上一份 nonce 的清理删掉。
- 按钮和清理只有取到这一份 nonce 的那一次写审计。
- 取走之后审计写入失败时，下一轮清理看不到这行。成员仍受原来的 `until_date` 约束，到期后 Telegram 自己放开。
- 30 天保留期不动。
