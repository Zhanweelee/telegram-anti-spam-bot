# ADR 0060：匹配前去掉非常规空白

- 状态：已接受
- 日期：2026-11-01

## 背景

ADR 0054 去掉零宽字符和双向控制符，并保留空格。不间断空格、表意空格、窄空格和换行插在字与字之间，可见间隔几乎没有，关键词和正则仍然匹配不到。把正文改掉会改变 `textSha256`。

## 决策

- `foldMatchText` 继续放在 core。比较前再去掉这些字符：`U+0009`–`U+000D`、`U+00A0`、`U+1680`、`U+2000`–`U+200A`、`U+2028`、`U+2029`、`U+202F`、`U+205F`、`U+3000`。
- `U+0020` 保留。`免 费领取` 仍然不命中 `免费领取`。
- 事件里的正文和 `textSha256` 不变。关键词和正则的比较方式仍按 ADR 0054。
- 不新增检测器，也不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 连普通空格一起删掉 | ADR 0054 已经拒绝。正常间隔会被当成关键词。 |
| 在归一化时删掉这些空白 | 哈希变了，同一句话的重复计数会拆开。 |
| 引入同形字库 | ADR 0054 已经拒绝。这一项只处理空白，不处理可见的形近字。 |

## 后果

- `免\u00A0费领取`、`免\u3000费领取` 和 `免\n费领取` 会命中关键词 `免费领取`。
- `加\u00A0微信` 会命中默认正则 `加微[信xX]`。
- 普通空格仍挡住关键词。变体选择符和同形字仍按原样比较。
- 重复计数仍按原文哈希，所以插入空白的变体仍算不同正文。
