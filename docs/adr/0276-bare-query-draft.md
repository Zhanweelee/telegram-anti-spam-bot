# ADR 0276：裸域名的问号仍留在这一段

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 没有协议时，裸域名和点分 IPv4 可以接一到五位端口，以及以 `/` 或 `?` 开头的路径。问号里的网址仍属于这一段。

看得见的正文已经这样收。隐藏的分享 `text` 先按裸域名切开，问号不算进这一段，`example.com?http://bit.ly/…` 会把问号里的短链再记一次。`bit.ly?http://t.co/…` 也会多记 `t.co`。

端口后面如果不是路径，下一段仍会打开。六位数字不是端口。点号后面的斜杠不属于这一段。

## 决策

- 分享 `text`、分享 `url`、私聊预填 `tg://msg` 的 `text` 和用户名草稿的 `text`，裸域名和裸 IP 收下 1 到 5 位端口，以及以 `/` 或 `?` 开头的路径。
- 问号里的主机名不另记。
- 端口后面是标点，或六位数字后面还有网址时，下一段仍单独打开。
- 点号后面紧挨着 `/` 再写网址时，下一段仍单独打开。
- 第一段自己是短链、裸 IP 或邀请时，仍按现有规则读取。证据只留这一段的主机名。
- 路径和邀请码不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 问号继续切开 | `example.com?http://bit.ly` 会删掉 Android 留成一条普通链接的消息。 |
| 端口后面的标点也收进问号 | `example.com:80!http://bit.ly` 点得开的是后面的短链。 |
| 分享 `url` 里的裸域名不补协议 | `bit.ly?http://t.co` 会漏掉前面的短链。 |

## 后果

- `t.me/share/url?text=example.com?http://bit.ly/…` 和 `example.com:80?http://bit.ly/…` 留着。
- `bit.ly?http://t.co/…` 仍按短链删除。证据只有 `bit.ly`。
- `203.0.113.243?http://bit.ly/…` 仍按裸 IP 删除。证据只有这个地址。
- 分享 `url` 里的 `bit.ly?http://t.co/…` 同样只留 `bit.ly`。
- `example.com:80!http://bit.ly/…`、`example.com:123456-http://bit.ly/…` 和 `example.com./http://bit.ly/…` 仍删除后面的短链。
- `t.me/+…?http://bit.ly/…` 仍按邀请删除。邀请码和问号里的主机名不进证据。
- 没有两个斜杠的 `tg:` 后面的短链后来同样留下。见 ADR 0277。
