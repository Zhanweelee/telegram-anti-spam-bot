# ADR 0047：跨群黑名单在内容变化时写入已有的 KV

- 状态：已接受
- 日期：2026-11-01

## 背景

ADR 0012 把共享黑名单和每个群的开关放在 isolate 内存里。Worker 一重启，打开过的群和已经写入的 actor id、哈希都会消失。管理员要重新 `/blocklist`。

当时没有放进 KV，是因为热路径不该为名单付写入，也不能让「关掉」被 60 秒的白名单缓存拖住。

## 决策

- 不新增绑定，也不改 `BlocklistStore`。配了 `POLICY_KV` 时用 `createKvBlocklistStore`。每个租户一个 JSON，键前缀是 `blocklist`。里面是打开的群 id，加上 `actor` 或 `hash` 条目。没有原文。
- 没配 `POLICY_KV` 时仍用内存。上限仍是每个租户 128 个群、256 条。KV 使用同一上限。
- 只有开关或条目真的变化才写。相同的打开、关闭或重复添加不写。本 isolate 缓存 60 秒。发出写入的 isolate 立刻能读到新值，所以关掉之后的下一条消息不再把这个群当成打开。其它 isolate 最多晚 60 秒看见。
- 坏文档读成空名单、全部关闭。热路径不回写。
- 不改 ADR 0026 的默认额度，也不把额度计数写进 KV。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 每条消息读 KV | 忙的群会打满每天大约 100,000 次读。 |
| 新的 `BLOCKLIST_KV` | 操作者要多建一个命名空间。这份数据和白名单一样，都是读多写少的配置。 |
| 把名单写进 D1 | 检测热路径不该为了名单打 D1。审计已经占着每天的行写。 |

## 后果

- 配了 `POLICY_KV` 之后，重启仍记得打开的群和条目。
- 名单没变时，过期后的比较最多读一次 KV，不写。
- 坏文档会留到后来一次内容不同的成功写入。
- 提交的 `wrangler.jsonc` 仍不写 KV id。
- 验证、额度计数和频率窗口仍在内存。
