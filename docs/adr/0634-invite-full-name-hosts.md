# ADR 0634：拉进视频聊天的人画出的全名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

有人把别人拉进视频聊天时，Android 的 `MessageObject` 在 `TL_messageActionInviteToGroupCall` 上用 `replaceWithLink` 把这个人画进这行服务文字。这就是 `UserObject.getUserName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。自己拉人时这行不画自己，只画被邀请的人。别人拉人时，被邀请的人在前，拉人的人在后。

Bot API 把名单放在 `video_chat_participants_invited.users`。至少有一个用户对象时，这条提示成立。见 ADR 0596。当时名的长度大于 0 就丢掉姓。被邀请的名字仍按正文。见 ADR 0119。

靠近提醒这行仍只读名。开始、结束和预约仍只读名。短链可以只写在姓上。把整段收成正文会改变内容哈希，关键词也会命中名字。

## 决策

- 只在已经会标成 `asCallInvite` 的提示上，从 `from` 会画出来的全名留主机名。名单里至少有一个用户对象时读。空数组、空对象和布尔值不读。
- 名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读。空格不截断。用户名不读。
- 被邀请的名字仍按 ADR 0119 成为正文。已有别的正文时仍留在 `memberName`。被邀请名字里的主机名仍排在全名前面。拉人的人的全名不进正文，也不改内容哈希。关键词因此不命中。本群群名不读。正文里已有短链时，证据仍先记正文的主机名。
- 自己拉人时这行不画自己。现有条件仍读 `from`。这条只改名字怎么切。开始、结束和预约仍按原来的名。靠近提醒仍按原来的名。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`call_invite` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不改视频聊天。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续只读名 | 客户端把姓画在同一行里。姓上的短链会留在提示里。 |
| 把名字整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0119。 |
| 自己拉人时不读发送者 | 现有条件已经读 `from`。这条只改名字怎么切。 |
| 靠近提醒或通话开始也改成全名 | 靠近提醒这行用的是名。开始、结束和预约仍按原来的名。见 ADR 0597 与 ADR 0588。 |
| 新命令 `/invitename` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 拉进视频聊天的人，全名里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。视频聊天本身不变。
- 全名原文、路径和用户名不进事件。内容哈希不变。关键词不命中全名。
- 空白名不挡住姓。空格后面的网址仍读。被邀请的名字仍按原来的正文。发送者是聊天时后来由 ADR 0676 只读这个聊天的标题。用户仍按全名。频道也读标题。
- 被邀请名字里已有短链时，证据仍先记那段名字的主机名。正文里已有短链时，证据仍先记正文的主机名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 靠近提醒仍只读名。开始和结束后来按全名。见 ADR 0635。预约后来不读发送者。见 ADR 0663。空数组、空对象、布尔值和普通消息仍不读发送者。管理员仍豁免。干净的提示在 `call_invite` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
