# ADR 0631：换头像的人画出的全名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

群头像被换掉或拿掉时，Android 的 `MessageObject` 在 `TL_messageActionChatEditPhoto` 和 `TL_messageActionChatDeletePhoto` 上用 `replaceWithLink` 把这个人画进这行服务文字。这就是 `UserObject.getUserName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。自己换头像时这行不画名字。频道广播这行也不画这个人。

Bot API 把新头像放在 `new_chat_photo`，把删头像放在 `delete_chat_photo`。新头像里至少有一个尺寸对象，或删头像正好是 true 时，这条提示成立。见 ADR 0591。当时名的长度大于 0 就丢掉姓。

改群名这行仍只读名。短链可以只写在姓上。把整段收成正文会改变内容哈希，关键词也会命中名字。

## 决策

- 只在已经会标成 `photo` 的提示上，从 `from` 会画出来的全名留主机名。`new_chat_photo` 里至少有一个对象时读。否则 `delete_chat_photo` 正好是 true 时读。同时出现时仍先认换头像。
- 名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读。空格不截断。用户名不读。
- 全名不进正文，也不改内容哈希。关键词因此不命中。文件号、唯一号和尺寸不读。本群群名不读。正文里已有短链时，证据仍先记正文的主机名。
- 空数组和 false 不读发送者。普通图片的 `photo` 不读发送者。普通消息不读 `from`。改群名仍按原来的名。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`chat_photo` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不调用 `deleteChatPhoto` 或 `setChatPhoto`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续只读名 | 客户端把姓画在同一行里。姓上的短链会留在提示里。 |
| 把名字整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0479。 |
| 频道广播不读发送者 | 现有条件已经读 `from`。这条只改名字怎么切。频道仍按同一条提示读。 |
| 改群名也改成全名 | 改群名要另看频道是不是画出这个人。这一轮只改头像。 |
| 新命令 `/photoname` | 菜单只剩一个空位。现有 `links` 已经能删除短链。`/delphoto` 仍负责拿掉群头像。 |

## 后果

- 换头像或删头像的人，全名里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。群头像本身不变。
- 全名原文、路径和用户名不进事件。内容哈希不变。关键词不命中全名。
- 空白名不挡住姓。空格后面的网址仍读。文件号和尺寸仍不读。
- 正文里已有短链时，证据仍先记正文的主机名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 改群名后来按全名只留主机名。见 ADR 0632。频道换头像和删头像后来由 ADR 0666 不再读发送者。群和超级群仍按全名。空数组、false、普通图片和普通消息仍不读发送者。管理员仍豁免。干净的提示在 `chat_photo` 关闭时仍留下。拿掉群头像仍走 `/delphoto`。云额度的基础检测器名单没有改。30 天保留期没有改。
