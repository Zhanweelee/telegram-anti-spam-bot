# ADR 0440：删掉相册里其余的照片

- 状态：已接受
- 日期：2026-11-04

## 背景

Telegram 把一次发出的多张图片收成一个 `media_group_id`，webhook 仍是多条 `message`。洪泛已经把未编辑的这一组算成一条。见 ADR 0438。一条说明是广告时，删除动作只删这一条，其余照片留在群里。

## 决策

- 一条带 `albumId` 的未付费消息被真正删除之后，同一租户、同一群、同一相册里已经见过的其它未付费消息也删除。
- 这组被记下之后，后到的未付费消息即使自己的正文会放行，也删除。
- 付费帖不删除，也不能把这一组记成要删。见 ADR 0356。
- 试运行只记下消息编号，不删除，也不把这一组记成要删。
- 同一条事件再次投递、动作被标成 `duplicate` 时，不再次删除。
- 只保存匹配 `^[1-9][0-9]{0,19}$` 的消息编号，以及可选的接收者编号。正文、链接和相册编号都不进日志。删除失败记 `album_delete_failed`，只带事件 id 和群 id。
- 这份名单留在当前 isolate 的内存里，最多 256 组，每组 10 条。满了就不再记新的一组。不写入 D1。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 只删命中的那一条 | 同一组里的其它照片还留在群里。 |
| 连付费帖一起删 | ADR 0356 要求付费帖留下。 |
| 试运行也把这一组记成要删 | 试运行不该改变群里的消息。 |
| 把消息编号写进 D1 | 多一次子请求，也把编号留过重启。相册在这次请求里就能删。 |

## 后果

- 重启，或 256 组已经占满时，后到的照片可能留下。下一条命中的消息仍会删掉它自己。
- 某一条删除请求失败时，这条先留着。同组再来一条消息时再试。
- 洪泛和重复的计数不变。重复仍按正文或文件摘要，不按相册编号合并。
- 30 天保留期不动。
