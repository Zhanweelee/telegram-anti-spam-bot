# ADR 0199：编码连字符不再拼出裸主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

Android 不会在匹配前把 `%2D` 或 `%252D` 收成连字符。`%2Dbit.ly/…`、`see %2Dbit.ly/…` 和 `%252Dbit.ly/…` 打开的是 `2dbit.ly` 或 `252dbit.ly`，不是 `bit.ly`。`%2D203.0.113.166/…` 不会打开这个地址。`example.com%2Dbit.ly/…` 只打开前面的主机名，后面是 `2dbit.ly`。

真正的连字符仍然会拆开。`-bit.ly/…` 会打开短链。换行、空格、制表符或斜杠隔在 `%2D` 和主机名之间时，后面的短链也会打开。`bit%2Dly` 仍不是短链。`example.com-bit.ly/…` 仍是一整段。

`%2Dwww.bit.ly/…` 打开的是 `2dwww.bit.ly`。这个主机名仍以 `.bit.ly` 结尾。

粘连扫描如果先把 `%2D` 收成连字符，`%2Dbit.ly` 会变成 `-bit.ly`。短链被多出来的边界打开。`%252Dbit.ly` 同样会变成 `-bit.ly`。`%2D203.0.113.166` 会变成一条裸 IP。

## 决策

- 去掉换行之前，把紧挨在裸主机名或点分 IPv4 前面、而且不在路径里的 `%2D` 和 `%252D` 换掉。路径是前面已经有 `/` 或 `%2F`。
- 裸主机名保留标签和路径，最后一段换成 `arpa`，前面加 `!`。`!` 让前面的主机名结束。`arpa` 让短链后缀对不上，路径仍挂在这一段上。
- 点分 IPv4 换成 `!0.arpa`。路径仍挂在这一段上。
- 紧挨在 `http://` 或 `https://` 前面的 `%2D` 和 `%252D` 仍换成 `!x`。见 ADR 0194。
- 换行、空格、制表符或斜杠隔开的 `%2D` 和 `%252D` 仍收成连字符。`bit%2Dly` 仍收成 `bit-ly`。再套一层 `%25252D` 仍保留。
- 每段仍走现有的短链、裸 IP、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| `%2D` 一律不再收成连字符 | 换行隔开的 `%2D` 会漏掉后面的短链。 |
| 只改 `%2D`，不改 `%252D` | `%252Dbit.ly` 仍会收成 `-bit.ly`。 |
| 删掉这段编码和后面的主机名 | 路径会剩成一条新的短链。 |

## 后果

- `%2Dbit.ly/…`、`%252Dbit.ly/…`、`see%2Dbit.ly/…` 和 `example.com%2Dbit.ly/…` 留着。`%25252Dbit.ly/…` 留着。
- `%2D203.0.113.166/…` 留着。`203.0.113.166%2Dbit.ly/…` 仍按裸 IP 删除。证据是这个地址，不是后面的短链。
- `-bit.ly/…`、换行、空格、制表符或斜杠隔开的 `%2D`，以及换行隔开的 `%252D`，仍按短链删除。`example.com-bit.ly/…` 留着。`bit%2Dly` 留着。路径不进证据。
- `%2Dwww.bit.ly/…` 和 `example.com%2Dwww.bit.ly/…` 仍按短链删除。证据是 `2dwww.bit.ly`。
