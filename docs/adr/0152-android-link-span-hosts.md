# ADR 0152：Android 提前停住的链接只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

Android 用 `LinkifyPort.WEB_URL` 给正文加链接。协议后面先认用户信息，再认主机名。下一段不是 `/`、`?` 或 `#` 时，高亮就停在主机名。点下去打开的是这一段。

整段交给网址解析器时，主机名后面的 `∕`（U+2215）、`⁄`（U+2044）或 `%2F` 不会结束用户信息。再出现 `@` 时，解析器改认后面的主机。短链和裸 IP 可以只写在前面，后面接一个普通域名。

高亮段里的 `∕`、`⁄` 以及大写的 `%E2%88%95`、`%E2%81%84` 会先换成 `/`。小写的百分号编码不换。已经是合法用户信息的 `用户名@主机` 仍打开后面的主机。

## 决策

- 正文里的 `http` 或 `https` 再取 Android 高亮会打开的那一段主机名。只留主机名。
- 整段解析出的主机名仍然保留。两边都走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。最多 8 个。
- 已经写在 `text_link`、按钮或其它结构化字段里的地址整段打开，不按高亮截断。
- 路径不进证据。没有新的主机名时不另记。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 只留整段解析出的主机名 | Android 点前面的短链或裸 IP 时，证据里只剩后面的普通域名。 |
| 只留高亮段的主机名 | 桌面端仍按整段解析。`example.com∕@bit.ly` 会打开 `bit.ly`。 |
| 把小写 `%e2%88%95` 也换成斜杠 | Android 的替换只认那两种大写编码。 |

## 后果

- `http://bit.ly∕@example.com`、`http://bit.ly%E2%88%95@example.com` 和 `http://203.0.113.9∕@example.com` 按现有短链或裸 IP 规则删除。证据仍只有主机名。
- `http://example.com∕@bit.ly` 仍因整段里的 `bit.ly` 删除。
- `http://bit.ly@example.com` 和 `https://example.com/docs` 留着。
- 再套一层仍放行。路径不进证据。
