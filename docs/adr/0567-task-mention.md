# ADR 0567：清单任务上的按标识提及也走同一条规则

- 状态：已接受
- 日期：2026-11-05

## 背景

ADR 0514 在正文、说明、投票题干和清单标题上认出 `text_mention`。清单任务的 `text_entities` 可以带同一种实体。Bot API 写明投票选项只允许自定义表情，引用里也不保留这种提及。任务上可以点一个人，用户编号不在看得见的字里。

打开 `text_mention` 的群会删掉标题上的点名，任务上的同一处仍留下。后加任务是同一份 `ChecklistTask`。用户编号仍不能进事件。

## 决策

- `checklist.tasks` 和 `checklist_tasks_added.tasks` 的 `text_entities` 里，`type` 正好是 `text_mention`，并且 `user.id` 是大于 0 的安全整数时，事件同样带 `asTextMention: true`。
- 缺用户、布尔值、字符串编号和 0 仍不带这个标记。投票选项、手动引用、富文本按标识提及和用户名实体仍不带。
- 不读取嵌套的 `checklist_message`。原清单自己的消息已经按 ADR 0514 处理。
- 用户编号、名字和用户名不进事件，也不进证据。任务看得见的字仍留在原来的字段。正文和 `textSha256` 不变。
- 仍用检测器 `text_mention`。证据仍是 `entity:text_mention`。不新增规则，不新增命令。菜单仍是 99 条。
- 规则仍默认关闭。打开之后，任务和后加任务上的这种提及也删除。付费帖仍不删除。
- 不改 ADR 0026 的基础检测器名单。`text_mention` 仍不在里面。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 连投票选项一起认 | 官方只允许选项带自定义表情。那种点名不是入站消息。 |
| 连手动引用一起认 | 引用实体不保留 `text_mention`。ADR 0514 已经把引用留在外面。 |
| 另开一条规则 | 这是同一处隐藏的用户编号。分开开关会让群管开漏一处。 |
| 把用户编号写进证据 | 用户编号不进事件。 |

## 后果

- 规则关闭时，清单任务和后加任务上的按标识提及留下。看得见的字仍参与关键词。用户编号仍不进事件。
- 打开 `text_mention` 后，这种任务上的提及会删除。投票选项和手动引用仍留下。富文本提及仍由 `rich_text_mention` 决定。
- 付费帖仍留下。0 和缺用户不带这个标记。
- 自部署没有额度，打开后就会删除。云模式超过当月次数后，还要把 `text_mention` 写进 `QUOTA_BASIC`，否则超额时这条规则会停。
- `chats.json` 整份替换的群要自己加上 `text_mention`，否则 `/rule` 会拒绝。
- 30 天保留期没有改。
- 投票说明和描述上的按标识提及后来由 ADR 0568 也带上 `asTextMention`。投票选项和手动引用仍不带。用户编号仍不进事件。
- 新加任务四条起，后来由 ADR 0660 不把第四条起的按标识提及算进 `asTextMention`。前三条和清单自己的任务仍算。
