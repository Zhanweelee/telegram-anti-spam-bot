# ADR 0618：付款成功这行画出的名字和账单标题只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

有人付款成功时，Android 的 `MessageObject.generatePaymentSentMessageText` 用对话对方的 `UserObject.getFirstName` 拼进这行服务文字。名的长度大于 0 就用名，空白也算有名。名缺失或正好是空字符串时才改用姓。这里不按短名截断，空格后面仍画。用户名不在这行里。

被回复的消息是账单时，这行还会带上那张账单的标题。说明、回复正文和回复发送者的名字不画进这句付款文字。没有这张账单时，这行只剩金额和名字。

Bot API 把这次付款放在 `successful_payment`。布尔值不是对象。私聊对象上的 `first_name` 和 `last_name` 就是对话对方。群里的对话对方不是一个用户，这行名字是空的，群名不画。`invoice_payload`、收费编号和 `order_info` 不出现在这行里。退款服务消息画出的是另一侧的人，Bot API 的 `refunded_payment` 没有这个人，这次不读。

短链可以只写在这个名字或账单标题上。把整段收成正文会改变内容哈希，关键词也会命中名字。

## 决策

- `successful_payment` 是对象，且 `chat.type` 正好是 `private` 时，从私聊对方会画出来的名字留主机名。`first_name` 的长度大于 0 时用名，不读姓。名缺失或正好是空字符串，且 `last_name` 是非空字符串时，改用姓。空白名挡住姓。
- 同一条消息的 `reply_to_message.invoice` 是对象时，再从 `invoice.title` 留主机名。名字的主机名排在标题前面。没有账单时不读标题。
- 主机名仍进消息已有的 `hosts`。邀请仍进 `invites`。正文里已有短链时，证据仍先记正文的主机名。名字和标题不进正文，也不改内容哈希。关键词因此不命中。
- 用户名、私聊对象上的 `title`、发言人 `from`、群名、群对象上的 `first_name`、账单说明、被回复的正文、回复发送者、`invoice_payload`、收费编号和 `order_info` 不读。布尔值的 `successful_payment` 不读。没有这个对象时，私聊对方的名字仍不读。没有付款对象时，被回复账单的标题仍不读。`refunded_payment` 不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。短链仍走已有的 `links`。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 每条私聊都读对方名字 | 普通私聊的名字仍留在事件外面。只有付款成功这行把它画出来。 |
| 连被回复的正文和账单说明一起读 | 付款这行只画出账单标题。其余仍按 ADR 0085 留在外面。 |
| 读取载荷和订单资料 | 这行服务文字不画这些字段。 |
| 退款也读私聊对方 | 退款画出的人没有进 `refunded_payment`。 |
| 新命令 `/payment` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 付款成功这行里的短链、邀请或裸 IP 会删除这条消息。证据只有主机名。
- 名字原文、账单标题原文、路径和用户名不进事件。内容哈希不变。关键词不命中这些原文。
- 空白名挡住姓。空格后面的网址仍读。群里的私聊式名字不读。账单标题的主机名排在名字后面。
- 正文里已有短链时，证据仍先记正文的主机名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 没有付款对象时不读私聊对方，也不读被回复账单的标题。退款、载荷和订单仍不读。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
- 私聊退款后来按画出的全名只留主机名。名和姓都去掉两端空白，名在前。空白名不挡住姓。同一条上仍先认付款成功。见 ADR 0649。
- 护照提示上画出的私聊对方后来由 ADR 0657 只留主机名。没有护照对象时仍不读。证件、电话和邮箱仍不读。
- 回复抬头上画出的名字后来由 ADR 0699 只留主机名。这句付款文字仍不画回复发送者。账单标题仍按原来的规则。
