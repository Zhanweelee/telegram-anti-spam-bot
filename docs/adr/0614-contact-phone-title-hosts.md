# ADR 0614：名片没有姓名时，电话就是标题

- 状态：已接受
- 日期：2026-11-06

## 背景

分享的联系人会画出一张名片。标题来自 `ContactsController.formatName`，名和姓都会先去掉两端空白。两边都空时，标题改用原始的 `contact.phone_number`，不再做电话格式化。见 Android `ChatMessageCell` 的联系人布局。

已经有姓名时，副标题另算。没有 vCard 数据时，副标题走 `PhoneFormat.format`。这个函数先丢掉数字、`+`、`*`、`#` 以外的字符。结果以 `+` 开头，而且后面没有数字时，查不到国家码，函数退回原文，短链会留在气泡上。后面一旦有数字，就按电话排版，网址不再出现。vCard 去掉空白后还有字时，副标题改画 vCard，旁边这条电话不再出现。

可见名字和公司名已经只留主机名。见 ADR 0609 和 ADR 0613。短链仍可以只写在这行标题上。`shared_contact` 默认会删掉整张名片。关掉这条之后，标题里的短链仍会留下。

把电话收成正文会让关键词命中号码，也和原文默认不落盘冲突。

## 决策

- `contact` 是对象，且 `first_name` 与 `last_name` 去掉两端空白后都是空的时，从原始 `phone_number` 留主机名。空字符串不读。抽出之前不截断。这行就是名片标题。
- 已经有姓名，并且 `vcard` 去掉空白后是空的时，只在电话会原样画出时才读。判断方式和客户端一样：只保留 `0-9`、`+`、`*`、`#`，结果以 `+` 开头，且后面没有数字。带数字的电话不读。
- `vcard` 去掉空白后还有字时，已有姓名旁边的电话不读。没有姓名时，电话仍是标题，照读。
- 主机名仍进消息已有的 `hosts`。邀请仍进 `invites`。`URL` 行和可见名字的主机名仍排在前面。没有姓名时，电话标题排在公司名前面。正文里已有短链时，证据仍先记正文的主机名。电话不进正文，也不改内容哈希。关键词因此不命中电话。
- 不读取用户编号、邮箱、职务、备注和发送者姓名。布尔值的 `contact` 不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`shared_contact` 仍默认打开。关掉之后，短链仍走已有的 `links`。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把电话拼进正文 | 关键词会命中号码，电话也会落盘。见 ADR 0032。 |
| 只靠 `shared_contact` | 关掉名片规则后，标题里的短链仍留下。 |
| 有姓名时也读全部电话 | 多数电话会被格式化成数字，气泡上看不见网址。 |
| 连未闭合的 vCard 旁边的电话一起读 | 副标题何时改走 vCard，要再对一遍解析。这一轮只认空白后的 vCard 还有没有字。 |
| 新命令 `/contactphone` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 关掉 `shared_contact` 后，名片标题上的电话里的短链、邀请或裸 IP 仍会删除这条消息。证据只有主机名。
- 电话原文、路径和用户编号不进事件。内容哈希不变。电话里的关键词不命中。
- 空白名字会先被客户端去掉。这时标题就是电话。名的长度大于 0 时，姓仍按 ADR 0609，不因为这次改读电话。
- 已有姓名、电话里带数字，或旁边有 vCard 时，这条电话不读。`URL` 行、可见名字和公司名仍按原来的顺序。
- `example.com` 和公开的 `t.me/名字` 在名片规则关掉时留下。默认仍由 `shared_contact` 删除整张名片。付费帖仍不删除。见 ADR 0356。
- 发送者姓名和群名仍不读。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
