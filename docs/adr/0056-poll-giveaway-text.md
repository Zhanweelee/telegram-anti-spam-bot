# ADR 0056：投票题干和奖品说明进入正文

- 状态：已接受
- 日期：2026-11-01

## 背景

投票和抽奖消息往往没有 `text`，也没有 `caption`。关键词和正则只看归一化后的正文，题干和奖品说明就绕过去了。选项、说明、频道标题和中奖者名字如果一并写进事件，会把不是这条广告正文的字符串也哈希进去。

## 决策

- 没有 `text` 和 `caption` 时，正文按这个顺序取第一段非空字符串：`poll.question`、`giveaway.prize_description`、`giveaway_winners.prize_description`。截断到 4096，并以此计算 `textSha256`。
- 已有 `text` 或 `caption` 时仍用原来的正文，不把题干再拼上去。
- `poll.question_entities` 里的 `text_link` 走 ADR 0029 的同一套主机名规则，和隐藏链接、按钮合用 8 个主机名的上限。
- 选项文字、`explanation`、抽奖频道标题、中奖者名字和 id 不进事件。
- 不新增检测器，也不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把选项和中奖者名字拼进正文 | 正常投票的选项、频道标题和用户名会改变哈希，也可能进事件。 |
| 给投票单独做一个检测器 | 题干已经是正文。关键词和正则不用改。 |
| 有 caption 时仍把题干接在后面 | 同一条消息会变成两段正文，重复计数和关键词都会偏。 |

## 后果

- 题干或奖品说明里的「免费领取」会命中现有关键词。同一题干在重复窗口里按这段正文计次。抽奖卡片后来可以由这个群打开 `giveaway_card` 删除。奖品说明仍按原来的优先级成为正文。投票仍靠题干。见 ADR 0474。
- 后加选项和删除选项的服务消息可以另开 `poll_notice`。投票题干仍不因此带标记。见 ADR 0494。
- 选项或说明里的关键词仍然看不到。选项、说明和描述里的网址后来由 ADR 0077 只留下主机名。题干和奖品说明里的纯文本网址后来由 ADR 0083 只留下主机名。选项看得见的前 1211 字后来由 ADR 0537 交给关键词和默认正则。说明仍不进事件。选项仍不拼进题干。
- 题干上的隐藏短链只留下主机名。邀请码、查询、频道标题和中奖者名字不进事件。文字链接的起点后来由 ADR 0736 必须小于题干。题干不是字符串时仍按原来的方式读取。
- 清单标题后来由 ADR 0057 接在这些回退之后。任务文字仍不进事件。
