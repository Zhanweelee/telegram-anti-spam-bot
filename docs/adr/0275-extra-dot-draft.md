# ADR 0275：点号接不上标签时仍留下后面的主机名

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 读带协议的主机名时，点号只有在后面是标签字符时才开始下一个标签。再来一个点，或点号后面是连字符，当前匹配就停在前一个标签。后面如果还有网址，会再打开一次。点号后面是端口时，这个点留在当前网址里；端口后再遇标点，才另开后面的网址。下划线是单词字符，会挡住紧跟在后面的协议。

看得见的正文已经这样切。隐藏的分享 `text` 把 `http://example.com.:80!http://bit.ly/…` 整段交给地址解析，解析失败，短链留在后面。`http://example.com._http://bit.ly/…` 会被提前切开，短链被单独留下。末尾一个点的 `https://t.me./+…` 主机名收成 `t.me.`，邀请没有记上。

## 决策

- 分享 `text`、分享 `url`、私聊预填 `tg://msg` 的 `text` 和用户名草稿的 `text`，在点号接不上下一个标签时另抽后面的网址。
- 点号后面是 `/`、`?`、端口或 `_` 时，这个点留在当前这一条。
- 点号加一到五位端口之后，如果是主机名标点、连字符，或点号紧挨着协议，从那里另抽网址。
- 主机名末尾多出来的一个点去掉后再认主机名。`https://t.me./+…` 仍按邀请读取。两个点挡住的 `https://t.me../+…` 不改记成邀请。
- 路径和邀请码不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 整段交给地址解析 | `:80!` 后面的短链解析失败，末尾一个点的邀请记不上。 |
| 下划线后面也切开 | `example.com._http://bit.ly` 仍是一个主机名。 |
| 两个点后面的邀请也记上 | `t.me../+…` 不是邀请。 |

## 后果

- `t.me/share/url?text=http://example.com.:80!http://bit.ly/…` 删除。证据仍只有主机名。
- 分享 `url` 里的同样写法同样删除。
- `http://example.com._http://bit.ly/…` 留着。`http://example.com..http://bit.ly/…` 仍按短链删除。
- `https://t.me./+…` 按邀请删除。`https://t.me../+…` 不改记成邀请。路径不进证据。
