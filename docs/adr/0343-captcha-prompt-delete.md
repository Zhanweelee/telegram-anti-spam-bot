# ADR 0343：通过或到期后删掉验证按钮

- 状态：已接受
- 日期：2026-11-04

## 背景

验证按钮发出之后留在群里。成员通过、挑战到期，按钮都还在。ADR 0342 让同一条入群再投递时再发一次。第一次已经记下的那颗不删，群里就会有两颗同一份 nonce。

Bot API 不能按按钮文案搜自己发出的消息。要删掉，就得在 `sendMessage` 的响应里留下 `message_id`。

已有 D1 的 `captcha_challenges` 没有这一列。`CREATE TABLE IF NOT EXISTS` 不会给旧表加列。

## 决策

- 挑战可以带可选 `messageId`。它是正整数的十进制，最长 16 位。
- `attachPrompt` 只在 nonce 仍然一致时写下这个 id。对不上、行已经没了，或 id 不合法，就不改这一行。新的 `put` 不带 id 时清掉旧 id。
- `sendCaptchaButton` 从响应里读 `message_id`。HTTP 成功但读不到 id 时返回空，不当成发送失败。
- 通过和到期写完审计之后，有 id 就 `deleteMessage`。删除失败只记 `captcha_prompt_delete_failed`。日志只有事件 id 和群 id。通过、到期和限制都保持原样。
- 再发成功并记下新 id 之后，删掉上一颗。新 id 记不上时，删掉刚发出的这一颗。第一次发送失败仍解除限制并删掉挑战。
- 已有表在第一次存储调用时，列不存在才 `ALTER TABLE ... ADD COLUMN message_id TEXT`。新建表的 `CREATE TABLE` 直接带上这一列。可重复执行的 `0001_storage.sql` 不放这条 `ALTER`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 不存 id，之后再搜群消息 | Bot API 没有按按钮查找自己消息的方法。 |
| 把 id 写进审计 | 导出和日志会带上和处罚无关的字段。 |
| 重发失败也删掉旧按钮 | 成员会没有可以点的按钮。 |
| 把 `ALTER` 放进可重复执行的 SQL 文件 | 第二次执行会因为列已经存在而失败。 |

## 后果

- 没记下 id 的旧挑战，通过或到期后按钮还在。
- 删除发生在取走挑战之后。删不掉时按钮留在群里，成员已经通过或仍受原来的 `until_date` 约束。
- 每次成功记下 id 是一次额外的 D1 更新。没配 `DB` 时只改内存。
- 30 天保留期不动。
