# ADR 0334：审计摘要按词截断

- 状态：已接受
- 日期：2026-11-04

## 背景

私聊 `/logs` 最多列出最近 10 条审计。每一行把这条审计的全部规则和原因用逗号拼起来。单个词超过 80 个字符或含有换行时会换成 `redacted`。规则和原因的个数没有上限。一条消息命中很多规则时，这一行会超过 Telegram `sendMessage` 的 4096 字。适配器把文本切到 4096，最后一个规则或原因可能只剩一半。

## 决策

- 完整回复不超过 3500 字时，每一行保持现在的字段。
- 放不下时，先从最长的那一行丢掉后面的原因，再丢掉后面的规则。留下的都是原来顺序里的完整前缀。
- 没列完的规则个数和原因个数写在同一行。短审计不写这个个数。
- 最近 10 条、空范围 `no audits`，以及还有更早审计时指向 `/export`，都保持 ADR 0329。
- 不改审计记录。`/export` 仍带上全部规则和原因。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续交给适配器切到 4096 | 切口会落在一个规则或原因中间。 |
| 给每条审计的规则个数加上限 | 检测可以同时命中很多规则。回复长度不该少记审计。 |
| 整行只留时间和动作 | 短审计现在能看到是哪条规则。放不下时仍应留下前面的规则。 |

## 后果

- 私聊看到的是前缀和剩余个数。没写出来的规则仍在审计里。
- 这条命令的回复停在 3500 字以内。适配器对其他超长文本仍会切开。
- 额度和 30 天保留期不动。
