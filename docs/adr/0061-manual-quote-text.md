# ADR 0061：手动引用在没有正文时进入正文

- 状态：已接受
- 日期：2026-11-01

## 背景

一条消息可以只带 `quote`，自己的 `text` 和 `caption` 都是空的。手动选中的那段文字是用户发出的可见内容，关键词却看不到。自动引用和被回复的原消息是别人写的。把它们并进正文，回复一句「今天站会」也会因为原消息里的短链被删掉。

## 决策

- 没有更前面的正文时，`quote.is_manual === true` 且 `quote.text` 非空，才用这段文字当正文。截断到 4096，并以此计算 `textSha256`。
- 同一情况下，`quote.entities` 里的 `text_link` 走 ADR 0029 的主机名规则。
- 自动引用（没有 `is_manual: true`）、`reply_to_message`，以及自己已经有正文时的手动引用，文字和链接都不进事件。
- 不新增检测器，也不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 自动引用也当正文 | 回复别人的垃圾消息时，自己的空回复会被原消息拖下去。 |
| 有自己的正文时仍把引用接在后面 | 同一条消息变成两段正文，哈希和关键词都会偏。 |
| 读取 `reply_to_message` | 那是上一条消息，不是这一条要审的正文。 |

## 后果

- 只有手动引用、引用文字是「免费领取」时，会命中现有关键词。这段文字参加重复计数。
- 引用上的隐藏短链只在引用成为正文时留下主机名。
- 自动引用里的关键词和短链仍会放行。自己写了正文时，手动引用的关键词仍不参与比较。引用里的网址后来由 ADR 0085 只留下主机名。
- 动图、视频、音频和普通文件的名称后来由 ADR 0062 排在手动引用之前。有文件名时，引用原文仍不进正文。
- 按钮文字后来由 ADR 0063 也排在手动引用之前。有按钮文字时，引用原文仍不进正文。
- `pinned_message` 是另一条消息，仍然不读。某个群后来可以打开 `pin_notice` 删除这条服务消息。见 ADR 0482。置顶提示上画出的发送者名字后来由 ADR 0586 只留下主机名。被置顶的原文仍不读。
- 已有正文时，手动引用后来由 ADR 0547 另留旁路字段。自动引用和被回复的原消息仍不进事件。
