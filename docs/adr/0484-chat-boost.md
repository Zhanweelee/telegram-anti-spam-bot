# ADR 0484：助推提示按群删除

- 状态：已接受
- 日期：2026-11-05

## 背景

有人给聊天助推时，群里出现一条服务消息。次数在 `boost_added.boost_count`。发送者名字画在这条消息上，但那是 `from` 的名字，不进正文。次数也不进事件。见 ADR 0394。关键词看不到这条提示。

删掉这条服务消息不会取消已经加上的助推。查看一个人的次数仍走私聊 `/boosts`。

## 决策

- `boost_added.boost_count` 是大于 0 的安全整数时，事件带 `asBoost: true`。不写次数，也不写发送者名字。
- 空对象、0、负数、小数和字符串次数不带这个标记。已有正文时，正文仍按原来的优先级。
- 检测器在 `@tasb/detector-boost`，id 是 `chat_boost`。只在 `message.asBoost` 为 true 时返回 score 1。证据是 `boost:added`。
- 默认规则用同样的 id，关闭。某个群用现有的私聊 `/rule` 打开后，删除这条助推提示。没有新命令。菜单仍是 99 条。不调用 `getUserChatBoosts`。
- 付费帖仍不删除。见 ADR 0356。
- 不改 ADR 0026 的基础检测器名单。`chat_boost` 不在里面。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 默认删掉全部助推提示 | 有的群靠这条提示感谢助推。打开之前不改现有群。 |
| 把次数或发送者名字写进证据 | 次数不是广告。名字会进事件。都不能进证据。 |
| 把发送者名字收成正文 | `from` 的名字本来就不进正文。助推提示不能单独打开这扇门。 |
| 新命令 `/boost` | `t.me/boost` 已是另一件事。菜单只剩一个空位。现有 `/rule` 已经能打开这条规则。 |

## 后果

- 不打开这条规则的群，助推提示仍留下。次数和名字仍不进事件。
- 打开 `chat_boost` 后，这个群里的助推提示会删除。助推本身还在。`/boosts` 仍只回报次数。付费帖仍留下。
- 自部署没有额度，打开后就会删除。云模式超过当月次数后，还要把 `chat_boost` 写进 `QUOTA_BASIC`，否则超额时这条规则会停。
- `chats.json` 整份替换的群要自己加上这条规则，才会有这个开关。
- 30 天保留期不动。
- 助推的人后来由 ADR 0583 只留下主机名。名字本身仍不进事件。次数仍不读。没有真实助推次数时，发送者仍不读。
