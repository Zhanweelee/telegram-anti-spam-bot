# ADR 0602：清单完成提示上的人，名字只留主机名

- 状态：已接受
- 日期：2026-11-05

## 背景

清单里的任务被标成完成或取消完成时，客户端把这个人的名字画在服务消息上。名字写在 `from`。这两条提示的正文是空的。见 ADR 0489。短链可以只写在这个人的名字里。

把 `from` 收成正文会让普通发言者的姓名也进检测。`checklist_notice` 默认关闭，干净的提示仍留下。空对象、空数组、0、负数、小数和字符串仍然不是这两条提示。新加的任务仍按 ADR 0495，不因为这条读发送者。

## 决策

- 只在已经会标成 `checklistNotice` 的提示上，从 `from` 的可见名字留主机名。完成名单或取消完成名单是非空数组，且每一项都是大于 0 的安全整数时读。同时出现时仍先认完成。
- `first_name` 的长度大于 0 时只读名。空白也算有名。名缺失或正好是空字符串时改读姓。用户名不读。抽出之前不截断。
- 这个人的名字不进正文，也不改内容哈希。关键词因此不命中这个人的名字。任务号和嵌套的原清单不读。本群群名不读。
- 空对象、空数组、0、负数、小数、字符串和布尔值不读发送者。普通消息不读 `from`。新加的任务不读发送者。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`checklist_notice` 仍默认关闭。8 个主机名的上限不变。不调用 `editMessageChecklist`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把这个人整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0489。 |
| 并进 `checklist_notice` | 打开这两种提示的群并不一定要按名字里的短链删。任务完成状态仍不变。 |
| 连新加的任务一起读发送者 | 新加的文字已经是正文。完成者仍是另一条提示。见 ADR 0495。 |
| 新命令 `/taskname` | 菜单只剩一个空位。现有 `links` 已经能删短链。 |

## 后果

- 勾完或取消勾完清单的人，名字里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。任务完成状态不变。
- 这个人的名字原文、路径和用户名不进事件，内容哈希不变。名字里的关键词不命中。
- 名的长度大于 0 时，姓和用户名不进事件。任务号仍不进事件。嵌套原清单仍不进事件。
- `example.com` 和公开的 `t.me/名字` 留着。付费帖仍不删除。见 ADR 0356。
- 空对象、空数组、0、负数、小数、字符串、布尔值、新加的任务和普通消息仍不读发送者。本群群名仍不读。干净的提示在 `checklist_notice` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
