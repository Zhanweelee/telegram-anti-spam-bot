# ADR 0677：聊天拉人进群时只读聊天标题

- 状态：已接受
- 日期：2026-11-06

## 背景

有人把别人拉进群时，Android 的 `TL_messageActionChatAddUser` 用 `replaceWithLink` 画出发送者。发送者是用户时，画出全名。发送者是聊天时，画出这个聊天的标题。标题不截断。

自己加入广播频道时，这行是 “You joined this channel”，不画人，也不画标题。群和超级群自己加入仍画出发送者。别人拉进频道仍画出拉人的人。见 ADR 0670。

Bot API 把加入的人放在 `new_chat_members`。发送者是聊天时，`sender_chat` 是那个聊天，`from` 是占位用户。见 `telegram-bot-api` 的 `messageSenderChat`。

ADR 0622 仍从 `from` 的全名留主机名。占位用户的名字不是这行画出的字。加入的人的名字仍按正文。

## 决策

- 已经会标成 `notice: "join"`，不是频道自己加入，且 `sender_chat` 是对象时，只从 `sender_chat.title` 留主机名，不从 `from` 留主机名。标题不截断。用户名不读。频道、群和超级群代发都一样。
- 没有 `sender_chat` 时，仍从 `from` 的全名留主机名。名和姓都去掉两端空白，名在前。空白名不挡住姓。空格不截断。
- 频道自己加入仍不读发送者，也不读这份名单，也不读聊天标题。
- 名单里至少有一个用户对象时才读。空数组、非用户对象和布尔值不读。退群不读这条。
- 加入的人的名字仍按 ADR 0645 成为正文。不从 `chat.title` 另读。用户编号不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`service_notice` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不改入群。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续读 `from` | 占位用户的名字不在这行里。短链会删掉一条没有这个名字的提示。 |
| 频道自己加入也读标题 | 那一行不画人，也不画标题。 |
| 超级群自己加入不读 | 超级群这行仍画出发送者。发送者是聊天时画的是标题。 |
| 只读频道代发 | 群和超级群自己拉人时同样画标题。 |
| 新命令 | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 聊天把人拉进群时，标题里的短链、邀请或裸 IP 会留下主机名。证据只有主机名。入群本身不变。
- 占位用户的名字不再留下主机名。用户仍按全名。
- 频道自己加入仍不读发送者，也不读这份名单。
- 加入的人的名字仍按原来的正文。空数组、非用户对象、布尔值和退群仍不读发送者。
- 标题原文、路径、用户名和用户编号不进事件。内容哈希不变。关键词不命中标题和全名。
- 加入的人的名字里已有短链时，证据仍先记那个人的主机名。正文里已有短链时，证据仍先记正文的主机名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 管理员仍豁免。干净的提示在 `service_notice` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
