# ADR 0611：成员转发的频道签名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

成员把带签名的频道帖转到群里时，客户端在帖子下面画出原作者签名。签名写在 `forward_origin.type === "channel"` 的 `author_signature`。没有现代来源时，旧字段是 `forward_signature`。`channel_forward` 默认会删掉整条转发。见 ADR 0025。关掉这条之后，签名里的短链仍会留下。

讨论组里关联频道自动出现的原帖不再记成频道转发。见 ADR 0443。那种原帖的来源签名已经只留主机名，没有别的正文时签名本身成为正文。见 ADR 0445。成员转发的频道标题已经只留主机名。见 ADR 0610。

把签名收成正文会让关键词命中作者名，也和原文默认不落盘冲突。

## 决策

- `is_automatic_forward` 不是布尔值 `true` 时，频道来源的签名只留主机名。现代 `forward_origin.type === "channel"` 读 `author_signature`。没有现代来源、也没有隐藏显示名、也没有 `forward_from` 时，读 `forward_from_chat.type === "channel"` 旁边的 `forward_signature`。
- 签名长度大于 0 才读。空白也算有签名。空字符串不落到旧字段。用户名不读。频道标题仍按 ADR 0610。抽出之前不截断。
- 主机名仍进消息已有的 `hosts`。邀请仍进 `invites`。频道标题里已有短链时，证据仍先记标题的主机名。正文里已有短链时，证据仍先记正文的主机名。签名不进正文，也不改内容哈希。关键词因此不命中这个签名。
- `is_automatic_forward` 正好是 `true` 时不读这段签名，仍按 ADR 0445。群来源上的签名不读。外部回复不读。已有隐藏显示名时不读旧的频道签名。发送者姓名和本群群名不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`channel_forward` 仍默认打开。关掉之后，短链仍走已有的 `links`。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把签名拼进正文 | 关键词会命中作者名，签名也会改内容哈希。 |
| 只靠 `channel_forward` | 关掉频道转发后，签名里的短链仍留下。 |
| 连讨论组原帖再读一遍 | 原帖的签名已经按 ADR 0445 处理，没有别的正文时签名本身就是正文。 |
| 连群来源的签名一起读 | 群来源的签名仍按 ADR 0091 留在外面。 |
| 新命令 `/channelsign` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 关掉 `channel_forward` 后，成员转发的频道签名里的短链、邀请或裸 IP 仍会删除这条消息。证据只有主机名。
- 频道签名原文、路径和用户名不进事件。内容哈希不变。签名里的关键词不命中。
- 频道标题里已有短链时，证据仍先记标题的主机名。正文里已有短链时，证据仍先记正文的主机名。空白签名不落到用户名。
- `example.com` 和公开的 `t.me/名字` 在频道转发关掉时留下。默认仍由 `channel_forward` 删除整条转发。付费帖仍不删除。见 ADR 0356。
- 讨论组原帖的来源签名、群来源签名、外部回复、隐藏显示名旁边的旧频道签名、发送者姓名和本群群名仍不读。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
