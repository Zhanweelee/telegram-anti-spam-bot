# ADR 0265：超长分享草稿仍留下主机名

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 打开分享链接时，把 `url` 和 `text` 拼成草稿，再截到 `4096 * 4` 个字符。桌面端打开 Passport 的 `callback_url` 时没有 2048 的上限。

链接规则把分享 `url`、`tg://msg` 的 `url` 和 `callback_url` 停在 2048。一条能放进消息里的 `https://t.me/share/url?url=http://bit.ly/…%20` 后面再垫一长串字，解码后仍超过 2048，整段被丢掉，短链就漏了。

直接打开的 `text_link` 仍按 ADR 0029，长于 2048 就丢掉。

## 决策

- 分享 `url`、私聊预填 `url` 和 `callback_url` 先按现有规则解码，再截到 16384 个字符，然后抽出主机名。
- 16384 之后的字不再读。
- 隐藏链接、按钮和其它直接打开的地址仍停在 2048。只有外层是分享、私聊预填或 Passport 回调时，才放到 16384。
- 查询值不进入正文，也不参与关键词。路径不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续停在 2048 | 消息里就能放下更长的分享草稿，短链会漏。 |
| 所有链接都放到 16384 | 直接打开的长链接仍按 ADR 0029 丢掉。 |
| 超过 16384 整段丢掉 | 短链在截断点前面时，客户端仍会打开。 |

## 后果

- `t.me/share/url?url=http://bit.ly/…%20` 垫到超过 2048、`tg://msg_url?url=` 和 `callback_url` 里同样的短链删除。证据仍只有主机名。
- 16384 个字符之后的短链留着。
- 直接指向短链、长于 2048 的隐藏链接留着。
- 分享和私聊预填的 `text` 后来同样截到 16384。见 ADR 0266。用户名草稿的 `text` 仍停在 4096。
