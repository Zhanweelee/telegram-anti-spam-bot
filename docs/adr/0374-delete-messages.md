# ADR 0374：私聊可以一次删除多条消息

- 状态：已接受
- 日期：2026-11-04

## 背景

`/delete` 一次只删一条，每次都是一次 Telegram 子请求。免费计划一次调用的外部子请求很少。突发广告时逐条删除会把额度用完。

官方 `deleteMessages` 在一次请求里删除 1 到 100 条。`message_ids` 是 JSON 数组。找不到的消息会跳过，成功仍返回 True。能删哪些消息，限制与 `deleteMessage` 相同。

没有 token 时，内存适配器可以把这一批记下来。私聊如果复用这次成功，回复会写成这些消息已经不在。

## 决策

- 私聊命令 `/deletes <chatId> <messageId> [messageId...]`。群 id 匹配 `^-?\d{1,20}$`。每个消息号是没有前导零的正安全整数。群聊里的同样文本不执行。
- 一次 1 到 100 个消息号。重复或超过 100 个时回复「参数无效」，不发出请求。
- 配置中的管理员可以操作任意群。接入目录里的人只能操作自己的群。
- 命令调用 `ModerationPort.deleteMessages`，带 tenant、chat 和消息号列表。适配器调用 `deleteMessages`，只带 `chat_id` 和 `message_ids`。不循环调用 `deleteMessage`，也不带接收者。
- 列表长度不是 1 到 100 时，适配器在请求前失败。
- 回复写明条数，并写明找不到的会跳过。不逐个回显消息号。
- 没有 token、没有这个方法，或调用失败时回复「参数无效」。日志只写 `operator_rejected`，带上 eventId、chatId 和命令名。不写异常文本或 token。
- 没有 token 的 Worker 不把内存里的记录回复成已经成功。
- `/delete` 仍是单条 `deleteMessage`。
- 不修改黑名单、白名单、封禁或禁言。不读取消息正文。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 循环调用 `deleteMessage` | 100 条就要 100 次子请求。免费计划一次调用装不下。 |
| 回复写成每一条都已删除 | 官方会跳过找不到的消息，成功仍返回 True。 |
| 放进原来的 `/delete` | 单条命令的回复和调用已经固定。多条是另一次请求。 |
| 没有 token 时也回复「已删除」 | 群里的消息还在。管理员会以为已经删掉。 |

## 后果

- 成功只表示 Telegram 接受了这一次 `deleteMessages`。找不到的消息会留下。超过大约 48 小时、服务消息种类，或 bot 缺少删除权限时，回复是「参数无效」。
- 一次最多 100 条，只占一次 Telegram 子请求。作者仍留在群里。
- 30 天保留期不动。
