# ADR 0214：增补平面的标签字留在原主机名

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 的标签类收录增补平面里的字，一个码位算一个字。`http://bit.ly𠀀/…`、`http://bit.ly𠀀?…`、`http://bit.ly.𠀀/…`、`http://bit.ly-𠀀/…` 和 `http://bit.ly𠀀:80/…` 各是一条链接。点开的主机名不是 `bit.ly`。`http://t.co𠀀/…`、`http://www.bit.ly𠀀/…`、`http://203.0.113.10𠀀/…` 和 `http://t.me𠀀/+…` 也是。

高亮若把这个码位拆成两个代理项，就会在它前面停住，把整条链接收成短链或裸 IP。`http://bit.ly𠀀/http://t.co/…` 的路径仍属于这一条。空格后面的 `http://t.co/…` 会另外打开。

`@`、`#` 和空格仍让 Android 退回上一个单词边界，单独打开 `http://bit.ly`。`http://203.0.113.10𠀀@evil.com/…` 会单独打开这条裸 IP。没有协议的 `bit.ly𠀀/…` 和 `www.bit.ly𠀀/…` 也在这个字前面结束。

第一平面的 U+10140 不在标签类里。`http://bit.ly𐅀/…` 仍只打开 `bit.ly`。

## 决策

- 带协议的标签按完整码位读取。增补平面里 Android 收录的字，和基本平面的标签字用同一条结束规则。
- 一个增补字在 63 字的上限里只占一个位置。连字符和下划线后面的增补字仍留在标签里。
- `@`、`#` 和空格仍退回上一个单词。没有协议的主机名和 `www.` 仍在这个字前面结束。
- 第一平面和私用区仍不收进标签。组合附加符号仍透明。
- 每段仍走现有的短链、裸 IP、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 按 UTF-16 代理项停住 | `http://bit.ly𠀀/…` 会收成 `bit.ly`。Android 把这一整段当成一条链接。 |
| 第一平面也收进标签 | `http://bit.ly𐅀/…` 会漏掉。Android 的标签类没有这一面。 |
| 裸主机名也留下这个字 | `bit.ly𠀀/…` 会漏掉。Android 在这个字前面就结束了。 |

## 后果

- `http://bit.ly𠀀/…`、`http://bit.ly𠀀?…`、`http://bit.ly.𠀀/…`、`http://bit.ly-𠀀/…` 和 `http://bit.ly𠀀:80/…` 留着。
- `http://t.co𠀀/…`、`http://www.bit.ly𠀀/…`、`http://203.0.113.10𠀀/…` 和 `http://t.me𠀀/+…` 留着。邀请码不进证据。
- `http://bit.ly𠀀/http://t.co/…` 留着。空格后面的 `http://t.co/…` 仍删除，证据是 `t.co`。
- `http://bit.ly𠀀@evil.com/…`、`http://bit.ly𠀀#…` 和没有协议的 `bit.ly𠀀/…` 仍删除。
- `http://203.0.113.10𠀀@evil.com/…` 仍按裸 IP 删除。`http://bit.ly𐅀/…` 仍删除。路径不进证据。
- `http://bit.ly` 后面 61 个增补字仍留着。第 62 个让 `bit.ly` 单独打开。点号后面 63 个仍留着。
