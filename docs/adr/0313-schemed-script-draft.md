# ADR 0313：带协议的草稿主机名里，文字字母留在标签里

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 把带协议主机名后面的希腊文、西里尔文、亚美尼亚文和非 ASCII 拉丁字母留在同一个标签里。`http://bit.lyα/…`、`https://t.coα?…`、`http://203.0.113.10ա/…` 和 `http://bit.lyœ:80/…` 的主机名不是前面的短链或裸 IP。`http://bit.lyα/http://t.co/…` 的路径仍属于这一条。`http://bit.lyα.bit.ly/…` 收成 `x` 之后仍以 `bit.ly` 结尾。见 ADR 0224。

没有协议的 `bit.lyα/…` 只打开前面的短链。`#`、空格、过长的端口和放不下的第 62 个字母也退回短链。`bαit.ly` 仍是短链。

`http://bit.lyα@evil.com/…` 在看得见的正文里仍打开 `bit.ly`。隐藏草稿先把字母收掉，`@` 就变成用户信息，主机名记成 `evil.com`。

## 决策

- 分享 `text`、私聊预填 `tg://msg` 的 `text` 和用户名草稿的 `text`，在 `http://` 或 `https://` 的主机名后面遇到一段这类字母，而且紧接着是 `@` 时，先把这段字母换成空格。
- 主机名取最长的严格域名，不在中间的短链后缀停住。点分 IPv4 同样。用户信息仍可以放在主机名前面。
- 路径、问号、结尾、写完的端口和再接一个点时，字母仍交给主机名扫描。扫描已经会把它们留在标签里，或在点号后面收成 `x`。
- `#`、空格、过长端口和放不下的字母仍按原来的规则收掉。没有协议的主机名不改。
- 不改带协议网址的整段匹配。闭合分享链接里的网址不走这道切开。公开的折叠不改。
- 证据只留主机名。路径不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 字母一律收掉 | `http://bit.lyα/…` 会按短链删除。Android 打开的不是 `bit.ly`。 |
| `@` 前面的字母也留在标签里 | `http://bit.lyα@evil.com/…` 会漏掉已经打开的短链。 |
| 改公开折叠 | 看得见的正文已经按 ADR 0224 处理。隐藏草稿只需要在 `@` 前停住。 |

## 后果

- `t.me/share/url?text=http://bit.lyα/…`、`https://t.coα?…`、`http://203.0.113.10ա/…`、`http://bit.lyœ:80/…`、`http://bit.lyα/http://t.co/…` 和 `http://bit.lyα.evil.com/…` 留着。路径不进证据。
- `http://bit.lyα.bit.ly/…` 仍按短链删除。证据是 `bit.lyx.bit.ly`。
- `bit.lyα/…`、`www.bit.lyα/…`、`203.0.113.10α/…` 和 `bαit.ly` 仍按短链或裸 IP 删除。
- `http://bit.lyα@evil.com/…`、`http://bit.lyα#…` 和中间有空格的写法仍按短链删除。证据是 `bit.ly`。
- 第 62 个字母仍让短链单独打开。
- 点号后面新起的这类标签留在带协议的主机名里。见 ADR 0225。
