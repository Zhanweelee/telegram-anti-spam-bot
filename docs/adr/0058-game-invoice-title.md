# ADR 0058：游戏标题和账单标题进入正文

- 状态：已接受
- 日期：2026-11-01

## 背景

游戏和账单消息往往没有 `text`，也没有 `caption`。前面的回退只覆盖投票、抽奖和清单，标题仍绕过关键词。说明、附加文字、启动参数和封面文件 id 如果一并写进事件，会把不是标题的字符串也哈希进去。

## 决策

- 没有 `text`、`caption`、投票题干、奖品说明和清单标题时，正文按这个顺序取第一段非空字符串：`game.title`、`invoice.title`。截断到 4096，并以此计算 `textSha256`。
- 前面几项已经有非空字符串时，不把标题再拼上去。
- 不读取 `game.description`、`game.text`、`game.text_entities`、`game.photo`、`invoice.description`、`invoice.start_parameter`、币种和金额。
- 不新增检测器，也不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把说明和附加文字拼进正文 | 和投票选项、清单任务是同一类。说明会改变哈希。 |
| 把游戏封面上的文件 id 当成媒体 | 封面不是这条消息的附件。文件 id 不能进事件。 |
| 读取 `game.text_entities` 里的短链 | 那段文字本身不进入正文。只读实体会和「附加文字不进事件」拧着。 |

## 后果

- 游戏或账单标题里的「免费领取」会命中现有关键词。同一标题在重复窗口里按这段正文计次。
- 说明、附加文字和启动参数里的关键词仍然看不到。附加文字上的短链也不会变成主机名。
- 已有清单标题时，游戏标题不参与比较。
