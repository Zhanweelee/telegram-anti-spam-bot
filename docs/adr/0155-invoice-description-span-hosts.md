# ADR 0155：账单说明只留高亮主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

Android 把发票媒体的正文换成 `description`。消息没有实体时，`applyEntities` 对这段文字调用 `addLinks`，里面是 `Linkify.WEB_URLS`。点下去打开的是高亮那一段。

说明不进我们的正文。整段解析会把 `∕` 后面的 `@` 认成新的主机。短链和裸 IP 可以只写在前面。

预览卡片另起的说明被清掉。付款页把说明当普通文字，不做链接。已有实体时不再自动加链接，只打开实体里写明的地址。

## 决策

- 消息没有 `entities` 和 `caption_entities` 时，`invoice.description` 里的 `http` 或 `https` 再取 Android 高亮会打开的那一段主机名。只留主机名。
- 整段解析出的主机名仍然保留。两边都走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。最多 8 个。
- 已有实体时不按高亮截断。账单标题、币种、金额和 `start_parameter` 仍不进证据。
- 路径不进证据。没有新的主机名时不另记。说明仍不进入正文，也不参与内容哈希。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 已有实体时也截断 | 客户端这时不再自动加链接，只打开实体里的地址。 |
| 只在没有正文时截断 | 发票媒体的正文会被换成说明，旁边的 `text` 不是点开的那一段。 |
| 把说明拼进正文 | 哈希会变。ADR 0058 和 ADR 0078 拒绝的就是这个。 |

## 后果

- `invoice.description` 是 `http://bit.ly∕@example.com/…` 时按短链删除。证据仍只有主机名。
- 同一段说明是 `http://example.com∕@bit.ly` 时，整段里的 `bit.ly` 仍删除。
- 小写 `%e2%88%95` 仍打开后面的主机。带实体的消息不另记前面的短链。
- 再套一层仍放行。路径、币种和金额不进证据。
