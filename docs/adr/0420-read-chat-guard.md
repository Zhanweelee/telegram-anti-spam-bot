# ADR 0420：私聊可以查看群的反垃圾姿态

- 状态：已接受
- 日期：2026-11-04

## 背景

反垃圾要知道这个群现在怎么收人、怎么限速，以及 Telegram 自己的官方反垃圾有没有开。查看调用是 `getChat`。它返回 `ChatFullInfo`。

和这条命令有关的字段是：群类型、是否开了话题、是不是频道私聊、入群要不要审核、是不是入群才能发言、官方反垃圾、慢速秒数、自毁秒数、加速豁免所需的 boost 数、防转发、隐藏成员、可见历史、反应上限和关联群号。

同一份对象还带标题、简介、邀请链接、用户名和名字。那些不进这次回复。`/perms` 仍然单独看默认发言权限。

## 决策

- 私聊命令 `/guard <chatId>`。群 id 匹配 `^-?\d{1,20}$`。多出来的参数不发出请求。群聊里的同样文本不执行。
- 配置里的管理员可以看任意群。接入目录里的人只能看自己的群。
- 调用 `ModerationPort.readChatGuard`。适配器调用 `getChat`，只带 `chat_id`。
- 回复按固定顺序写上面这些字段。缺开关写未知。缺秒数、缺豁免或没有关联群写未知。显式的 0 写成 0。
- 类型不是 private、group、supergroup、channel，秒数或豁免或反应上限不是非负安全整数，关联群号不合规则，或返回的群号和请求不一致时，整份回复是「参数无效」，不露出已经读到的字段。
- 标题、简介、邀请链接、用户名、名字、贴纸包名和默认权限不进回复，也不进日志。
- 日志只写 `operator_rejected` 或命令名，带上 eventId、chatId 和命令名 `guard`。不写标题、邀请链接、异常文本或 token。
- 没有 token 的 Worker 不编一份状态。
- 不调用 `setChatPermissions`，也不改黑名单、封禁或禁言。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 缺开关当成关闭 | 这些字段经常只在为真时出现，也可能因为 bot 不是管理员而没返回。 |
| 把慢速 0 写成未知 | 显式的 0 和字段缺失不是同一件事。 |
| 连标题和邀请链接一起回复 | 标题可能是原文，邀请链接不该出现在私聊日志里。 |

## 后果

- 成功只表示 Telegram 返回了这个群的反垃圾姿态。标题和邀请链接仍留在 Telegram。
- 一次查看是一次 Telegram 子请求。`/perms` 仍是另一次 `getChat`。封禁、禁言和黑名单都不变。
- 删除改自动删除计时的服务消息不会改变秒数。秒数仍只由 `/guard` 读取。见 ADR 0486。
- 30 天保留期不动。
