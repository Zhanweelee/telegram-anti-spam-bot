# ADR 0147：更长的桌面端路径段仍只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0139 把帖子数字限制在 1 到 16 位。ADR 0145 和 ADR 0146 把 Passport 的附加段和应用名限制在 128 个字符。

桌面端 `TryConvertUrlToLocal` 用 `\d+` 和 `[A-Za-z0-9._-]+`，没有这些上限。用户名后的长应用名仍会收成 `appname`。对方不是 bot 时仍写入草稿。`用户名.t.me/` 后任意长度的数字会改写成同一条帖子链接，`text` 仍可能进输入框。`telegrampassport` 后更长的一段、两段更长的数字，以及 `telegrampassport.t.me/` 后更长的数字，仍会打开 Passport，`callback_url` 仍会在浏览器里打开。

子域上的长应用名桌面端不改写。讨论串仍是两段数字，不写草稿。邀请码仍按原来的长度判断。

## 决策

- 精确主机上的应用名改为 `[A-Za-z0-9._-]+`，不再设 128 的上限。全数字的第二段仍是帖子。
- 精确主机和 `用户名.t.me` 上的帖子数字改为一位以上，不再设 16 的上限。
- Passport 的附加段、`s/`、`a/`、`c/` 和两段数字同样不再设 16 或 128 的上限。`telegrampassport.t.me` 后的数字也一样。
- 这些链接仍只从原来的 `text` 或 `callback_url` 抽出主机名。只拆一层。路径不进证据。
- `用户名.t.me/长应用名`、讨论串、保留名和其它网站不读。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续停在 16 和 128 | 桌面端更长的一段仍会写草稿或打开回调。 |
| 邀请码也去掉 128 | 能用的邀请码比这短，放宽只会多记主机名。 |
| 子域上的长应用名也读 | 桌面端不把这段改写成带 `appname` 的 resolve。 |

## 后果

- `t.me/用户名/` 后 129 个字符的应用名、`用户名.t.me/` 后 17 位数字，以及 Passport 上同样更长的路径，里面的裸 IP、短链或邀请按现有链接规则删除。证据仍只有主机名。
- `用户名.t.me/长应用名` 和 `t.me/用户名/长数字/长数字` 留着。
- 再套一层仍放行。路径不进证据。
