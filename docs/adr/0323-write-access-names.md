# ADR 0323：允许发消息时的小程序名字命中就删除

- 状态：已接受
- 日期：2026-11-03

## 背景

Bot API 的 `write_access_allowed` 是用户允许这个 bot 给自己发消息。服务消息上看得见的是从小程序链接打开时带上的小程序名字。短链或关键词可以只放在这个名字里。这条消息通常没有 `text`。

`from_request` 和 `from_attachment_menu` 只说明来源，不是这行看得见的字。发送者的 `from` 姓名和所在聊天的标题也不是。

## 决策

- `write_access_allowed.web_app_name` 去掉首尾空白，最长 4096 字符。
- 没有更前面的正文时，这段名字成为正文。关键词和链接规则因此能删除这条服务消息。路径留在正文里。
- 已有正文时，名字只贡献主机名。路径和关键词不进事件。
- 不读取 `from_request`、`from_attachment_menu`、`from` 上的姓名和 `chat.title`。
- 入群名单、分享来的用户名单和新建受管 bot 的名字仍排在前面。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 名字永远只留主机名 | 关键词广告名会留在「允许发消息」这行上。 |
| 读取来源布尔值或发送者姓名 | 它们不是看得见的小程序名字。 |
| 读取每条消息的 `from` 姓名 | 会把普通发言者的姓名送进检测。 |

## 后果

- 没有正文时，小程序名字里的默认关键词、短链或邀请会删掉这条服务消息。证据仍只有关键词或主机名。路径留在正文里。
- 已有正文时，名字里的短链和邀请仍删除。正文和哈希不变。路径不进事件。
- `example.com` 和普通名字留着。来源布尔值、发送者姓名和所在聊天的标题不进事件。
- 云额度的基础检测器名单没有改。
