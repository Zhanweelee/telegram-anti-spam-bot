# ADR 0160：超长端口前只留高亮主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0152 按 Android `LinkifyPort.WEB_URL` 留下高亮提前停住的主机名。端口是一到五位数字。后面还是数字时，这五位不算端口，匹配停在主机名。

`http://bit.ly:999999/x` 打开的是 `bit.ly`。`http://203.0.113.9:999999/x` 打开的是 `203.0.113.9`。整段解析遇到大于 65535 的端口会失败，主机名拿不出来。只截前五位仍是打不开的端口，短链和裸 IP 都会漏掉。

一到五位、后面不是数字的端口仍留在原网址里。`http://bit.ly:80/x` 和 `http://bit.ly:65535/x` 整段就能解析出主机名。`https://t.me:999999/+邀请码` 停在没有路径的 `t.me`，不能把超长端口拿掉再读后面的邀请码。

## 决策

- 正文里的 `http` 或 `https` 再取这段高亮的主机名。冒号后面是一到五位数字，且下一位不是数字时，才把这段当成端口。否则主机名停在冒号前面。只留主机名。
- 整段解析出的主机名仍然保留。两边都走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。最多 8 个。
- 已经写在 `text_link`、按钮或其它结构化字段里的地址整段打开，不按高亮截断。
- 不把停住之后的路径再当成邀请。路径和端口数字不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 只留整段解析出的主机名 | 端口大于 65535 时整段解析失败，点下去打开的短链没有主机名。 |
| 端口只认到 65535 | Android 认的是位数。五位里大于 65535 的端口仍留在高亮里。 |
| 去掉超长端口后再读邀请路径 | `t.me:999999/+邀请码` 打开的是没有路径的 `t.me`。 |

## 后果

- `http://bit.ly:999999/…` 和 `http://203.0.113.9:999999/…` 按现有短链或裸 IP 规则删除。证据仍只有主机名。
- `http://bit.ly:80/…` 仍删除。`http://example.com:999999/…` 留着。
- `https://t.me:999999/+…` 不记成邀请。再套一层仍放行。路径和端口数字不进证据。
- 标签超过 63 个字符时，高亮停在前一个标签。见 ADR 0161。
