# ADR 0661：客座回复上召唤者画出的短名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

群里的客座 bot 替人回复时，Android 的 `ChatMessageCell` 在 `guestchat_via_from` 有值时重画名字行。这一行先放 bot 自己的短名，再放 “for”，最后放召唤者的短名。召唤者来自 `DialogObject.getShortName`。用户就是 `UserObject.getForcedFirstName`。名为空时改用姓。空白不算空。从下标 2 起找第一个空格，找到就把后面丢掉。下标 0 或 1 上的空格不截断。频道和群的短名是标题，空格不截断。

见 ADR 0446。当时按完整名读取。姓上的短链不在这行里。bot 自己的短名后来按 ADR 0616 截断。抬头上召唤者仍读完整名，空格后面的短链会删掉客户端没有画出的后半段。

Bot API 把召唤者放在 `guest_bot_caller_user`，频道放在 `guest_bot_caller_chat`。带非空 `guest_query_id` 的更新仍先被忽略。

## 决策

- `guest_bot_caller_user` 是对象时，从会画出来的短名留主机名。`first_name` 的长度大于 0 时用名，不读姓。名缺失或正好是空字符串，且 `last_name` 是非空字符串时，改用姓。空白名挡住姓。
- 从下标 2 起的第一个空格后面不读。这个空格之前的前缀才抽主机名。没有这样的空格时，整段名字都读。下标 0 或 1 上的空格不截断。
- 没有用户对象时，`guest_bot_caller_chat.title` 仍整段只留主机名。频道标题不按空格截断。频道用户名不读。用户和群同时存在时仍只读用户。
- 主机名仍进消息已有的 `hosts`。邀请仍进 `invites`。bot 自己的短名仍排在召唤者前面。正文里已有短链时，证据仍先记正文的主机名。短名不进正文，也不改内容哈希。关键词因此不命中。
- 用户名、用户 id 和本群群名不读。布尔值不读。没有客座召唤者对象时，普通 `from` 仍不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。短链仍走已有的 `links`。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续读空格后面 | 抬头上的短名不画这段。会删掉没有出现在这行里的网址。 |
| 频道标题也截断 | `getShortName` 对群和频道用的是标题，不从下标 2 起切空格。 |
| 空白名也改去读姓 | `TextUtils.isEmpty` 只把 null 和长度为 0 当成空。空白名仍挡住姓。 |
| 新命令 `/guestcaller` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 召唤者短名里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。
- 从下标 2 起被空格截掉的后半段不读。下标 0 或 1 上的空格后面仍读。空白名挡住姓。频道标题仍整段读。
- 短名原文、路径和用户名不进事件。内容哈希不变。关键词不命中短名。
- bot 自己的短名仍排在前面。正文里已有短链时，证据仍先记正文的主机名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 带 `guest_query_id` 的更新仍忽略。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
