# ADR 0647：新群主画出的全名成为正文

- 状态：已接受
- 日期：2026-11-06

## 背景

群主换人时，Android 的 `MessageObject` 在 `TL_messageActionChangeCreator` 上用 `replaceWithLink` 画出下一位群主。待接受时，`TL_messageActionNewCreatorPending` 同样画出这个人。这就是 `UserObject.getUserName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。

见 ADR 0120。当时正文还收了用户名。短链可以只写在姓上，也可以只写在用户名上。用户名上的词并没有画出来。

交出去的人另外画在句子里。这个人的主机名已经按全名抽取，名字本身不进正文。见 ADR 0633。没有下一位时不读新群主。

没有更前面的正文时，新群主的名字就是正文。已有正文时，名字另留在 `memberName`。见 ADR 0554。入群名单和视频聊天邀请已经按同一套全名。见 ADR 0645 与 ADR 0646。

## 决策

- `chat_owner_changed.new_owner` 和 `chat_owner_left.new_owner` 按会画出来的全名成为正文。名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读。空格不截断。用户名不读。
- 两条都带着新群主时，按换人再离开，用一个普通空格接起来。
- 没有更前面的正文时，这段全名就是正文。已有正文时，拼起来的整段自己不是正文，就跟入群、邀请和靠近提醒一起另留前 4096 字在 `memberName`。主机名仍从这段全名抽取。
- 不读取用户编号、`language_code` 和 `is_bot`。没有 `new_owner` 时不读名字。交群或离开的人仍只留主机名，名字不进正文。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。短链仍走已有的 `links`。`member_name_regex` 和 `service_name_regex` 仍看这段正文。`owner_notice` 仍默认关闭。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续把用户名收进正文 | 这行服务文字不画用户名。用户名上的短链和关键词会删掉看不见的字。 |
| 两条通知用逗号接起来 | 客户端一次只画一个新群主。两条同时出现时仍按原来的字段顺序用空格接。 |
| 没有下一位时改读发送者全名当正文 | 发送者已经只留主机名。没有下一位时这行看不见新群主。 |

## 后果

- 新群主全名里的短链、邀请或裸 IP 会删除这条服务消息。证据只有主机名。
- 全名里的关键词仍命中这段正文。用户名里的关键词不命中。用户名不进事件。
- 空白名不挡住姓。空格后面的网址仍读。
- 已有别的正文时，证据仍先记正文的主机名。这段全名另留在 `memberName`。和正文相同的全名不重复留。
- 交群或离开的人仍只留主机名。没有下一位时仍不读新群主。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
