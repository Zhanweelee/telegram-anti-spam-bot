# ADR 0596：拉人的人，名字只留主机名

- 状态：已接受
- 日期：2026-11-05

## 背景

有人把别人拉进视频聊天时，客户端把这个人的名字画在服务消息上。名字写在 `from`。被邀请的名字当时按正文处理。见 ADR 0119。开始、结束和预约已经从发送者留主机名。见 ADR 0588。只有邀请名单时，那一条仍不读邀请者。短链可以只写在拉人的人的名字里。

把 `from` 收成正文会让普通发言者的姓名也进检测。`call_invite` 默认关闭，干净的提示仍留下。用户编号仍不读。空数组、空对象和布尔值仍不是这条提示。

## 决策

- 只在已经会标成 `asCallInvite` 的提示上，从 `from` 的可见名字留主机名。`video_chat_participants_invited.users` 里至少有一个用户对象时读。
- `first_name` 的长度大于 0 时只读名。空白也算有名。名缺失或正好是空字符串时改读姓。用户名不读。抽出之前不截断。
- 被邀请的名字仍按 ADR 0119 成为正文。已有别的正文时仍留在 `memberName`。拉人的人的名字不进正文，也不改内容哈希。关键词因此不命中这个人的名字。用户编号不读。本群群名不读。
- 空数组、空对象和布尔值不读发送者。普通消息不读 `from`。开始、结束和预约仍按 ADR 0588，不因为这条改它们的条件。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`call_invite` 仍默认关闭。8 个主机名的上限不变。不改视频聊天。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把拉人的人整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0119。 |
| 并进 `call_notice` | 打开通话提示的群并不一定要删邀请。ADR 0588 把只有邀请名单留在外面。 |
| 把用户编号写进证据 | 编号不是这行看得见的字。见 ADR 0491。 |
| 新命令 `/invitename` | 菜单只剩一个空位。现有 `links` 已经能删短链。 |

## 后果

- 拉人的人，名字里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。视频聊天本身不变。
- 这个人的名字原文、路径和用户名不进事件，内容哈希不变。名字里的关键词不命中。
- 名的长度大于 0 时，姓和用户名不进事件。被邀请的名字仍按原来的正文。用户编号仍不进事件。
- `example.com` 和公开的 `t.me/名字` 留着。付费帖仍不删除。见 ADR 0356。
- 空数组、空对象、布尔值和普通消息仍不读发送者。本群群名仍不读。干净的提示在 `call_invite` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
