# ADR 0641：清单任务上画出的完成者全名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

清单任务标成完成时，任务旁边画出完成者。Android 的 `ChatMessageCell` 用 `DialogObject.getName` 画这行。用户就是 `UserObject.getUserName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。群或频道画出标题。用户名不在这行里。变音符号和从右到左的控制符不在这里复现。

见 ADR 0578。当时名的长度大于 0 就丢掉姓。空白也算有名。短链可以只写在姓上。任务文字已经交给链接规则。勾完和新加任务的发送者后来按全名。见 ADR 0627 和 ADR 0628。嵌套的 `checklist_message` 是另一条消息。

把名字收成正文会让关键词命中人名，也和原文默认不落盘冲突。

## 决策

- `checklist.tasks` 和 `checklist_tasks_added.tasks` 上，`completed_by_user` 是对象时，从会画出来的全名留主机名。名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读名字。空格不截断。
- 有用户对象时不读 `completed_by_chat`。没有用户对象时，群标题仍只留主机名。群用户名不读。
- 主机名仍进消息已有的 `hosts`。邀请仍进 `invites`。任务文字里的主机名仍排在完成者前面。8 个主机名的上限不变。
- 名字不进正文，也不改内容哈希。关键词因此不命中这个名字。用户名、用户 id、群 id、任务 id 和 `completion_date` 不读。
- 嵌套的 `checklist_message` 不读。`checklist_tasks_done` 上没有完成者字段。勾完和新加任务的发送者仍按各自的全名。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。短链仍走已有的 `links`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续只读名 | 任务旁边把姓画在同一行里。姓上的短链会留在消息里。 |
| 有用户对象时也读群标题 | 客户端画出的是这个用户。群标题不在这行里。 |
| 把名字拼进正文 | 关键词会命中人名，内容哈希也会变。见 ADR 0032。 |
| 新命令 `/completername` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 完成者全名里的短链、邀请或裸 IP 会删除这条消息。证据只有主机名。
- 全名原文、路径和用户名不进事件。内容哈希不变。关键词不命中全名。
- 空白名不挡住姓。空格后面的网址仍读。
- 任务文字或正文里已有短链时，证据仍先记那一边的主机名。
- 有用户对象时，群标题仍不读。没有用户时仍只读群标题。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 嵌套的 `checklist_message` 仍不读。勾完和新加任务的发送者仍按全名。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
