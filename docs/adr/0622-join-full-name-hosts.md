# ADR 0622：拉人进群的人画出的全名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

有人把别人拉进群时，Android 的 `MessageObject` 在 `TL_messageActionChatAddUser` 上用 `replaceWithLink` 把拉人的人画进这行服务文字。这里没有打开短名，所以名字是 `UserObject.getUserName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。

Bot API 把这个人放在 `from`。`new_chat_members` 里至少有一个用户对象时，这才是入群提示。空对象也算。加入的人的名字仍按原来的正文。见 ADR 0118。退群仍不读这个发送者。见 ADR 0582。

短链可以只写在姓上。名的长度大于 0 时如果丢掉姓，这条短链就留在提示里。把整段收成正文会改变内容哈希，关键词也会命中名字。

## 决策

- 只在已经会标成 `notice: "join"` 的提示上，从 `from` 会画出来的全名留主机名。名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读。空格不截断。
- 主机名仍进消息已有的 `hosts`。邀请仍进 `invites`。加入的人的名字里已有短链时，证据仍先记那个人的主机名。正文里已有短链时，证据仍先记正文的主机名。全名不进正文，也不改内容哈希。关键词因此不命中这个人的名字。
- 用户名不读。用户编号不读。本群群名不读。加入的人的名字仍按原来的正文。空数组、非用户对象和布尔值不读发送者。退群不读发送者。普通消息因此仍不读 `from`。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`service_notice` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不改入群。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续只读名 | 客户端把姓画在同一行里。姓上的短链会留在群里。 |
| 把拉人的人整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0118。 |
| 每条服务提示的发送者都改成全名 | 助推这行用的是名。付款成功这行也只读名。见 ADR 0583 与 ADR 0618。 |
| 新命令 `/joinname` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 拉人进群的人全名里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。入群本身不变。
- 全名原文、路径和用户名不进事件。内容哈希不变。关键词不命中全名。
- 空白名不挡住姓。空格后面的网址仍读。名的主机名排在姓前面。
- 加入的人的名字仍按原来的正文。那里已有短链时，证据仍先记那个人的主机名。正文里已有短链时，证据仍先记正文的主机名。
- 加入的人后来按画出的全名成为正文。名和姓都去掉两端空白，名在前。几个人用逗号分开。用户名不进。见 ADR 0645。拉人的人仍只留主机名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 空数组、非用户对象、布尔值、退群和普通消息仍不读发送者。管理员仍豁免。干净的提示在 `service_notice` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
