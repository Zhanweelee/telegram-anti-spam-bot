# ADR 0675：群里聊天开始或结束视频聊天时只读聊天标题

- 状态：已接受
- 日期：2026-11-06

## 背景

群或超级群开始、结束视频聊天时，Android 的 `TL_messageActionGroupCall` 用 `replaceWithLink` 画出发送者。发送者是用户时，画出全名。发送者是聊天时，画出这个聊天的标题。标题不截断。

所在聊天是频道时，这行是 “Live stream started” 或 “Live stream finished”，不画人。预约这行也只有开始时间，不画人。见 ADR 0669 与 ADR 0663。

Bot API 把开始放在 `video_chat_started`，把结束放在 `video_chat_ended.duration`。发送者是聊天时，`sender_chat` 是那个聊天，`from` 是占位用户。见 `telegram-bot-api` 的 `messageSenderChat`。

ADR 0635 在群和超级群上仍从 `from` 的全名留主机名。占位用户的名字不是这行画出的字。

## 决策

- 已经会标成 `call: "started"` 或 `call: "ended"`，并且所在聊天不是频道时，`sender_chat` 是对象就只从 `sender_chat.title` 留主机名，不从 `from` 留主机名。标题不截断。用户名不读。频道、群和超级群代发都一样。
- 没有 `sender_chat` 时，仍从 `from` 的全名留主机名。名和姓都去掉两端空白，名在前。空白名不挡住姓。空格不截断。
- 所在聊天是频道时仍不读发送者，也不读频道标题。预约仍不读发送者。
- 不从 `chat.title` 另读。时长和开始时间仍不进事件。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`call_notice` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不改视频聊天。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续读 `from` | 占位用户的名字不在这行里。短链会删掉一条没有这个名字的提示。 |
| 频道也读标题 | 频道这行不画人，也不画标题。 |
| 预约也读标题 | 预约这行不画人。 |
| 只读频道代发 | 群和超级群自己发起时同样画标题。 |
| 新命令 | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 群或超级群里，聊天开始或结束视频聊天时，标题里的短链、邀请或裸 IP 会留下主机名。证据只有主机名。视频聊天本身不变。
- 占位用户的名字不再留下主机名。用户仍按全名。
- 频道开始或结束仍不读发送者。预约仍不读发送者。
- 标题原文、路径、用户名、时长和开始时间不进事件。内容哈希不变。关键词不命中标题和全名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 空的结束、负数、非有限数字和普通消息仍不读发送者。管理员仍豁免。干净的提示在 `call_notice` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
