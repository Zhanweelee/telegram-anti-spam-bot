# ADR 0049：黑名单状态行带上共享条数

- 状态：已接受
- 日期：2026-11-01

## 背景

ADR 0047 把共享名单留在 KV 里，ADR 0048 让管理员能删一条。`/blocklist` 的回复仍只有 on 或 off。管理员看不到这份名单有多少条，也不知道离 256 条上限还有多远。把标识本身打出来会把 actor id 和哈希送进私聊。

## 决策

- `BlocklistStore` 增加 `size`。它返回当前租户的条目数，不返回标识，也不改开关。
- 私聊 `/blocklist` 的状态行变成 `blocklist {chatId} {state} shared {count}`。英文是 `Blocklist {chatId} is {state} shared {count}`。`shared` 表示这是整个租户的条目数，不是这个群自己的一份。
- 查看、开关、添加和删除都用这一行。添加和删除仍在下一行写 `added`、`removed` 或 `absent`。
- `size` 只读。配了 `POLICY_KV` 时走同一份 60 秒缓存，不因此写 KV。
- 读取失败时回复参数无效，日志是 `operator_rejected`，不写异常文本。
- 不改 ADR 0026 的默认额度。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 在回复里列出全部标识 | actor id 和哈希会进私聊。 |
| 只在单独的子命令里给条数 | 开关和增删之后仍不知道还剩多少。 |
| 把条数理解成这个群的名单 | 条目是按租户共享的。状态行用 `shared` 标出范围。 |

## 后果

- 管理员能看到共享名单的条数，看不到具体标识。
- 条数查询不增加 KV 写。
- 其它 isolate 最多晚 60 秒看见刚写入的条数。发出写入的 isolate 立刻数到新值。
