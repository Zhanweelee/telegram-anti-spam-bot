# ADR 0087：礼物附言里的网址只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

普通礼物、升级后的唯一礼物，以及事后购买的升级，都可以带一段附言。Bot API 里这是 `gift.text`、`unique_gift.text` 和 `gift_upgrade_sent.text`，并可以带 `text_link`。礼物服务消息通常没有 `text` 和 `caption`。关键词和链接都看不见这段附言时，短链可以只写在礼物上。

把附言拼进已有正文会改变 `textSha256`。礼物贴纸、星星数量、藏品名字和成交币种不是这段附言。

## 决策

- 从 `gift`、`unique_gift` 和 `gift_upgrade_sent` 的 `text` 抽出网址，并读取同一对象上的 `text_link`。只留主机名。长度、折叠、邀请判断和 8 个主机名的上限不变。顺序是普通礼物、唯一礼物、升级购买。
- 已有正文时，附言原文不进正文，也不改内容哈希。
- 没有更前面的正文时，第一段非空附言整段成为正文，并以此计算 `textSha256`。这条正文里的网址由链接规则从正文看见，同时也记在主机名列表里。`is_private` 不改变这一点。
- 不读取礼物贴纸、`file_id`、`set_name`、星星数量、`owned_gift_id`、唯一礼物的 `name`、成交币种和金额。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 已有正文时把附言拼进去 | 附言会改变哈希。短链只需要主机名。 |
| `is_private` 时跳过 | 更新里已经有这段文字，接收者看得到。 |
| 把藏品名字拼成 `t.me/nft` | 名字是平台标识，不是用户写下的网址。 |

## 后果

- 已有正文时，附言里的 `https://bit.ly/…` 会走现有短链删除。`https://t.me/+…` 和 `https://t.me/%2B…` 只留下 `t.me`，并记成邀请。
- 普通域名仍保留。附言原文、路径和邀请码在已有正文时不进事件。
- 附言成为正文时，整段附言仍参与关键词和内容哈希。
- 贴纸包名、星星数量、短名和成交币种里的网址仍然不读。某个群后来可以打开 `gift_card` 删除普通礼物、独特礼物和升级购买。星星不退回。见 ADR 0481。
- 卡片上看得见的收藏名后来由 ADR 0324 读取。有附言时型号、符号和背景仍不读。普通礼物的发布者用户名也只留主机名。
- 已有正文时，附言后来由 ADR 0548 另留旁路字段。贴纸、星星和收藏名仍不进这个字段。
