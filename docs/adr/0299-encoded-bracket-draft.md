# ADR 0299：编码括号点贴在草稿主机名后面时留下十六进制

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 不把 `%5B.%5D` 收成点。`%5B.%5Dbit.ly/…` 打开的是 `5Dbit.ly`。`%28.%29bit.ly/…` 打开的是 `29bit.ly`。`%7B.%7Dbit.ly/…` 打开的是 `7Dbit.ly`。中间写成 `%2E` 或句号 `。` 也一样。`%5B.%5Dwww.bit.ly/…` 打开的是 `5Dwww.bit.ly`。`%5B.%5D.bit.ly/…` 打开的是 `5D.bit.ly`。`http://bit.ly%5B.%5Devil.com/…` 仍先打开 `bit.ly`，下一段从 `5D` 开始。

字面闭合括号仍收成点。`bit[.]ly`、`[.]bit.ly` 和 `%5B.]bit.ly` 会打开 `bit.ly`。换行、空格或制表符隔开之后也会打开。`bit%5B.%5Dly` 和 `t%5B.%5Dme/+…` 仍按现有规则删除。第二层 `%255B.%255D` 仍留下。路径里的这一对仍收成点。

看得见的正文用停住扫描把百分号当成主机名边界，闭合括号的十六进制留给下一段。隐藏的分享 `text` 先按粘连扫描把这一对收成十六进制，`http://bit.ly%5B.%5Devil.com` 变成 `bit.ly5devil.com`。字面 `[.]` 又先被停住字符拆开，`bit[.]ly` 不再是 `bit.ly`。见 ADR 0204。

## 决策

- 分享 `text`、私聊预填 `tg://msg` 的 `text` 和用户名草稿的 `text`，已经结束的主机名或点分 IPv4 后面紧挨编码括号点时，改成空格加闭合括号的两位十六进制。`%5D`、`%29` 和 `%7D` 都算。大小写保留原样。
- 字面闭合括号在主机名还没结束时收成点。已经结束的主机名后面改成空格。
- 还没贴在已经结束的主机名上的编码括号点仍交给粘连扫描。路径里的这一对、第二层 `%255B`、换行、空格和制表符仍按原规则。
- 证据只留主机名。路径不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 编码括号点一律收成点 | `%5B.%5Dbit.ly` 会另开 `bit.ly`。 |
| 已经结束的主机名后面不再切开 | `http://bit.ly%5B.%5Devil.com` 会收成 `bit.ly5devil.com`，漏掉短链。 |
| 字面 `[.]` 继续交给停住字符 | `bit[.]ly` 会在点号收成之前被拆开。 |

## 后果

- `t.me/share/url?text=%5B.%5Dbit.ly/…`、`%5B.%5Dhttp://bit.ly/…`、`http://%5B.%5Dbit.ly/…` 和 `example.com%5B.%5Dbit.ly/…` 留着。`%5B.%5D203.0.113.171/…` 留着。
- `%5B.%5Dwww.bit.ly/…` 和 `http://%5B.%5Dwww.bit.ly/…` 按短链删除。证据是 `5dwww.bit.ly`。`%5B.%5D.bit.ly/…` 按短链删除。证据是 `5d.bit.ly`。`%28%2E%29www.bit.ly/…` 按短链删除。证据是 `29www.bit.ly`。路径不进证据。
- `http://bit.ly%5B.%5Devil.com/…` 和 `bit.ly%5B.%5Devil.com/…` 仍按短链删除。证据是 `bit.ly`。`203.0.113.171%5B.%5Devil.com/…` 仍按裸 IP 删除。
- `bit[.]ly`、`[.]bit.ly`、`%5B.]bit.ly`、`bit%5B.%5Dly`，以及换行、空格或制表符后面的网址，仍按短链删除。`t%5B.%5Dme/+…` 仍按邀请删除。`%5B.%5D203.0.113.171/http://t.co/…` 按 `t.co` 删除。
- 第二层 `%255B.%255D` 仍留下。路径里的编码括号点不另开一条短链。
