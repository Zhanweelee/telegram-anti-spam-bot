# ADR 0066：结构化网址在解析前折叠

- 状态：已接受
- 日期：2026-11-01

## 背景

ADR 0065 在链接检测抽主机名前折叠正文。按钮 `url`、`text_link` 和整段就是一条网址的 `copy_text` 不走那段正文，它们在 `hostFromUrl` 里直接 `new URL`。URL 解析器会把主机名里的零宽字符清掉，所以 `https://bit\u200b.ly/x` 已经是短链。邀请码里的零宽字符、变体选择符和不间断空格会被百分号编码进路径，`/+IN%E2%80%8BVITE` 对不上邀请正则，这条按钮就只剩普通的 `t.me`。

## 决策

- `hostFromUrl` 在长度检查之后、`new URL` 之前对原始字符串做 `foldMatchText`。
- 长度仍按折叠前的字符串判断，上限 2048。折叠只会变短。
- `U+0020` 保留。`https://bit. ly/x` 仍然解析失败，不留下主机名。
- 事件里仍只记主机名。邀请码、路径和查询不进事件。
- 不读 `login_url` 和 `web_app`。不改 ADR 0026 的基础检测器名单。不引入同形字库。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 解析后再折叠 `pathname` | 缺口已经变成 `%E2%80%8B` 这类编码，折叠函数对不上。 |
| 先 `decodeURIComponent` 再折叠路径 | 主机名和路径要各做一遍，和关键词用的是两套规则。 |
| 只在链接检测里折叠 `message.text` | 按钮地址不在正文里。归一化时邀请标志已经丢了，检测器只能看见普通主机名。 |

## 后果

- `https://t.me/+IN\u200b…`、`joinchat` 里的变体选择符、`addlist` 里的不间断空格，会记成对应主机的邀请。
- 不间断空格拆开的短链主机名，例如 `tinyurl\u00A0.com`，解析前会合成一个主机名。普通空格不会。
- 邀请码不进事件。正文和哈希不变。
- 同形字仍按原样比较。`login_url` 和 `web_app` 仍不读。
- 已经写成百分号编码的格式字符后来由 ADR 0067 再去掉一层。`%20` 和两层编码仍留下。
