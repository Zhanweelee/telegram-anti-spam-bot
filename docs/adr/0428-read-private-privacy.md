# ADR 0428：私聊可以查看对方的隐私开关

- 状态：已接受
- 日期：2026-11-04

## 背景

私聊对象可以限制别人用 `tg://user?id=` 指向自己，也可以限制语音和视频留言。反垃圾要知道对方把这两项开到哪一档，才不会把私聊里的转发和语音留言误判成群规则。这两个开关在 `getChat` 返回的 `ChatFullInfo` 里，字段是 `has_private_forwards` 和 `has_restricted_voice_and_video_messages`。文档把它们写成可选的 `True`。

名字、简介、用户名和邀请链接可能带原文，不进这次回复。`personal_chat` 和 `parent_chat` 是另外两条命令要看的字段。

## 决策

- 私聊命令 `/privacy <chatId>`。群 id 匹配 `^-?\d{1,20}$`。多出来的参数不发出请求。群聊里的同样文本不执行。
- 配置里的管理员可以看任意群。接入目录里的人只能看自己的群。
- 调用 `ModerationPort.readPrivatePrivacy`。适配器调用 `getChat`，只带 `chat_id`。
- 回复三行：群号、私密转发、语音视频。缺字段写未知。`true` 写 on，`false` 写 off。
- 不是布尔值，或返回的群号和请求不一致时，整份回复是「参数无效」，不露出已经读到的字段。
- 名字、简介、用户名和邀请链接不进回复，也不进日志。
- 日志只写 `operator_rejected` 或命令名，带上 eventId、chatId 和命令名 `privacy`。不写名字、异常文本或 token。
- 没有 token 的 Worker 不编一份开关。
- 不调用 `setChatPermissions`，也不改黑名单、封禁或禁言。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 缺字段写成 off | 文档把这两个字段写成可选的 `True`。缺字段不是明确关闭。 |
| 并进 `/perms` | `/perms` 看的是群发言权限。这两个开关是对方在私聊里的隐私设置。 |
| 并进 `/guard`、`/parent` 或 `/personal` | 那三条命令分别看群姿态、对应频道和个人频道。隐私开关是另一件事。 |
| 回复里带上名字或简介 | 名字和简介可能是原文。开关够用来判断转发和语音留言。 |

## 后果

- 成功只表示 Telegram 返回了这两个可选开关，或字段没有返回。
- 一次查看是一次 Telegram 子请求。`/perms` 仍单独回报群发言权限。封禁、禁言和黑名单都不变。
- 30 天保留期不动。
