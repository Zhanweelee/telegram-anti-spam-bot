# ADR 0208：多字节百分号编码不再收成短链

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 的主机名标签不含 `%`。`http://b%E2%85%A0t.ly/…` 被拆成 `http://b` 和 `A0t.ly/…`。`http://b%E2%84%B9t.ly/…` 拆成 `http://b` 和 `B9t.ly/…`。`http://bi%CD%8Ft.ly/…` 拆成 `http://bi` 和 `8Ft.ly/…`。这三段都不是短链。

抽主机名时，带协议的标签把 `%HH` 算进同一个地址。`new URL` 再把这段 UTF-8 解出来：`%E2%85%A0` 是罗马数字 `Ⅰ`，映成 `i`；`%E2%84%B9` 是 `ℹ`，也映成 `i`；`%CD%8F` 是字素连接符，解析时被忽略。三条都变成 `bit.ly`。

裸的 `b%E2%85%A0t.ly/…` 已经只读到 `a0t.ly`。`http://%E2%84%B9bit.ly/…` 读到的不是 `bit.ly`。`http://example.com/%E2%84%B9bit.ly/…` 的百分号在路径里，整段仍是一个地址，主机名是 `example.com`。

`http://b%69t.ly/…` Android 也会在 `%` 处停下，但单字节 ASCII 字母在扫描前已经收成字母，这条仍是短链。`https://bit.ly%2F…` 仍是一条链接。

## 决策

- 带协议的主机名标签不再包含 `%HH`。匹配在百分号前结束。后面的十六进制可以另成一条裸域名。
- 路径和用户信息里的 `%HH` 仍留在这条链接里。不在 `/` 上拆开。
- 单字节 ASCII 字母、数字、连字符和下划线的百分号编码仍由主机名扫描先收成字符。不停掉全部 `%HH`。
- 每段仍走现有的短链、裸 IP、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 在折叠里把多字节 UTF-8 解出来再做 IDNA 映射 | 映射结果仍是 `bit.ly`。误报还在。 |
| 扫描前停掉全部 `%HH` | `b%69t.ly` 和 `https://bit.ly%2F…` 会跟着变。 |
| 路径里的 `%HH` 也停掉 | `http://example.com/%E2%84%B9bit.ly` 可能再拆出短链。斜杠后面的路径仍属于这条链接。 |

## 后果

- `http://b%E2%85%A0t.ly/…`、`http://b%E2%84%B9t.ly/…` 和 `http://bi%CD%8Ft.ly/…` 留着。
- `http://b%69t.ly/…`、`b%69t.ly/…` 和 `https://bit.ly%2F…` 仍按短链删除。路径不进证据。
- `http://example.com/%E2%84%B9bit.ly/…` 和 `http://%E2%84%B9bit.ly/…` 留着。
- 亚美尼亚文、西里尔文、希腊文和拉丁文里的标点不再收成短链。见 ADR 0209。
