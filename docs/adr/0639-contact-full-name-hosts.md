# ADR 0639：名片上画出的全名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

分享的联系人画出一张名片。Android 的 `ChatMessageCell` 用 `ContactsController.formatName` 把 `contact.first_name` 和 `contact.last_name` 画成标题。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。两边去掉空白后都是空的，标题才改成原始电话。用户编号不在这行标题里。

见 ADR 0609。当时名的长度大于 0 就丢掉姓。空白也算有名。短链可以只写在姓上。`shared_contact` 默认会删掉整张名片。关掉这条之后，姓上的短链仍会留下。vCard 的 `URL` 行、没有姓名时的电话标题、公司名和会原样画出的电话邮箱已经只留主机名。见 ADR 0151、ADR 0613、ADR 0614 和 ADR 0615。

把名字收成正文会让关键词命中人名，也和原文默认不落盘冲突。

## 决策

- `contact` 是对象时，从会画出来的全名留主机名。名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读名字。空格不截断。
- 主机名仍进消息已有的 `hosts`。邀请仍进 `invites`。vCard 里 `URL` 行的主机名仍排在前面。名字不进正文，也不改内容哈希。关键词因此不命中这个名字。
- 两边去掉空白后都是空的时，标题仍是原始电话。已有姓名且没有 vCard 时，仍只在电话会原样画出时才读。公司名和副标题里会原样画出的电话、邮箱仍按原来的顺序排在名字后面。
- 用户编号、邮箱备注、职务和群名不读。布尔值的 `contact` 不读。发送者姓名不读。普通消息的 `from` 不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`shared_contact` 仍默认打开。关掉之后，短链仍走已有的 `links`。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续只读名 | 名片标题把姓画在同一行里。姓上的短链会留在消息里。 |
| 把名字拼进正文 | 关键词会命中人名，电话旁边的姓名也会落盘。见 ADR 0032。 |
| 有姓名时也读全部电话 | 多数电话会被格式化成数字，气泡上看不见网址。见 ADR 0614。 |
| 新命令 `/contactname` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 关掉 `shared_contact` 后，名片全名里的短链、邀请或裸 IP 仍会删除这条消息。证据只有主机名。
- 全名原文、路径、电话和用户编号不进事件。内容哈希不变。关键词不命中全名。
- 空白名不挡住姓。空格后面的网址仍读。
- vCard 里已有 `URL` 短链时，证据仍先记那一行的主机名。正文里已有短链时，证据仍先记正文的主机名。
- `example.com` 和公开的 `t.me/名字` 在名片规则关掉时留下。默认仍由 `shared_contact` 删除整张名片。付费帖仍不删除。见 ADR 0356。
- 没有姓名时的电话标题、公司名和副标题电话邮箱仍按原来的规则。布尔值的 `contact` 仍不读。发送者姓名和群名仍不读。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
