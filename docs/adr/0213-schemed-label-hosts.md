# ADR 0213：带协议的标签字留在原主机名

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 的单词边界只认 ASCII 字母、数字和下划线。汉字、全角逗号和同类标签字可以留在带协议的主机名里。`http://bit.ly一/…`、`http://bit.ly一?…`、`http://bit.ly一.evil.com/…` 和 `http://bit.ly一:80/…` 各是一条链接。点开的主机名不是 `bit.ly`。`http://t.co一/…`、`http://www.bit.ly一/…` 和 `http://203.0.113.10一/…` 也是。

高亮若在这个字前面停住，就会把整条链接收成短链或裸 IP。`http://bit.ly一/http://t.co/…` 的路径仍属于这一条，后面的短链不会再打开。

`@`、`#` 和空格后面没有路径。Android 会退回上一个单词边界，单独打开 `http://bit.ly`。`http://203.0.113.10一@evil.com/…` 会单独打开这条裸 IP。没有协议的 `bit.ly一/…` 和 `www.bit.ly一/…` 也在这个字前面结束。

非间距组合附加符号仍是透明的。`http://bit.ly` 后面紧挨这个符号再写路径，仍按短链删除。连字符和下划线仍不能结束标签。

## 决策

- 带协议的标签可以在 `/`、`?`、点号加下一个标签，或已经写完的端口处结束，即使这里没有 ASCII 单词边界。
- 非间距组合附加符号不使用这条规则。标签仍结束在它前面的字母上。
- 匹配在 `@`、`#` 或空格处被截断时，仍把下一个字符交给同一段判断，短链和裸 IP 继续删。
- 没有协议的主机名和 `www.` 仍在这个字前面结束。
- 连字符和下划线仍不能结束标签。
- 每段仍走现有的短链、裸 IP、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 任何非 ASCII 都留在主机名里 | `http://bit.ly一@evil.com` 会漏掉 Android 单独打开的短链。 |
| 组合附加符号也留在标签里 | `http://bit.lỳ/…` 会漏掉。ADR 0191 已经按短链删除。 |
| 裸主机名也把这个字留在标签里 | `bit.ly一/…` 会漏掉。Android 在这个字前面就结束了。 |

## 后果

- `http://bit.ly一/…`、`http://bit.ly一?…`、`http://bit.ly一.evil.com/…` 和 `http://bit.ly一:80/…` 留着。
- `http://t.co一/…`、`http://www.bit.ly一/…`、`http://203.0.113.10一/…` 和 `http://t.me一/+…` 留着。邀请码不进证据。
- `http://bit.ly一/http://t.co/…` 留着。
- `http://bit.ly一@evil.com/…`、`http://bit.ly一#…` 和 `http://bit.ly一 evil.com/…` 仍删除。
- `http://203.0.113.10一@evil.com/…` 仍按裸 IP 删除。没有协议的 `bit.ly一/…` 和 `www.bit.ly一/…` 仍删除。
- `http://bit.ly` 加组合附加符号再写路径仍删除。路径不进证据。
- 增补平面里的标签字同样留在带协议的主机名里。见 ADR 0214。
