# ADR 0467：入群和退群提示默认仍留下

- 状态：已接受
- 日期：2026-11-04

## 背景

人入群时，Telegram 除了 `chat_member`，还会发一条服务消息 `new_chat_members`。客户端把它显示成「某人加入了群组」。退群时另有一条 `left_chat_member`。ADR 0118 只在可见名字命中关键词或链接时删除入群那一行。干净的名字会留下。退群那一行正文是空的，也不会删。

入群验证走的是另一条 `chat_member` 更新。删掉服务消息不能取消验证。

## 决策

- `new_chat_members` 里至少有一个用户对象时，消息事件带 `notice: "join"`。没有这份名单、而 `left_chat_member` 是用户对象时，带 `notice: "leave"`。
- 视频聊天邀请、群主变更、靠近提醒和普通正文不带这个标记。
- 入群的可见名字仍留在正文里。退群的人、用户 id 和链接仍不进事件。证据只有 `notice:join` 或 `notice:leave`。
- 检测器 id 是 `notice`，放在 `@tasb/detector-notice`。只在 `kind: message` 且带这个标记时返回 score 1。入群和退群共用 reason `service_notice`。
- 默认规则 `service_notice` 存在，但是关闭的。某个群用现有的私聊 `/rule` 把它打开之后，两条服务消息一起删除。没有新命令。菜单仍是 99 条。
- 不改 ADR 0026 的基础检测器名单。`notice` 不在默认 `QUOTA_BASIC` 里。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 默认删掉全部入群和退群提示 | 现在干净的入群行会留下。打开开关之前不改现有群。 |
| 入群和退群各一条命令 | 菜单只剩一个空位。现有 `/rule` 已经能打开一条规则。分开开关以后再做。 |
| 另做 `/notice` | 同样要占掉最后一个菜单位。 |
| 把开关写进运行时文档 | 规则开关已经能按群记住。不需要新的 KV 键。 |

## 后果

- 不打开 `service_notice` 的群，干净的入群提示仍留下，退群提示仍不删。名字里的关键词或短链仍按 ADR 0118 删除。
- 打开之后，自部署会删除这两行。云模式超过当月次数后，还要把 `notice` 写进 `QUOTA_BASIC`，否则超额时这条规则会停。建群提示可以另开 `group_created`。打开 `service_notice` 仍不删除这种服务消息。见 ADR 0498。建群提示上画出的发送者名字后来由 ADR 0587 只留下主机名。名字本身仍不进事件。
- `chats.json` 整份替换的群要自己加上这条规则，才会有这个开关。
- 入群验证、验证时长和失败处置不变。30 天保留期不动。
- 退群名字里的短链后来由 ADR 0582 删除这条提示。名字仍不进事件。干净的退群提示在 `service_notice` 关闭时仍留下。
- 拉人进群的人后来由 ADR 0598 只留下主机名。名字本身仍不进事件。加入的人的名字仍按原来的正文。空数组、非用户对象和布尔值仍不读发送者。退群仍不读发送者。
