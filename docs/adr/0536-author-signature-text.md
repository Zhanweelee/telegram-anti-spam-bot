# ADR 0536：正文旁边的作者签名也走关键词和默认正则

- 状态：已接受
- 日期：2026-11-05

## 背景

ADR 0101 在已有正文时，只从这条消息自己的 `author_signature` 抽出主机名。「免费领取」和「加微x」留在帖子下面，正文哈希不变。

ADR 0445 对讨论组原帖来源上的 `forward_origin.author_signature` 做了同样的事。这种原帖的发送者是关联频道，不会被当成管理员放行。短链仍会删除，签名上的关键词会留下。

本群匿名管理员和频道自己发出的帖子仍是管理员。签名可以留在事件里，删除仍不会发生。

## 决策

- 已有别的正文，且这条消息自己的签名去掉两端空白后仍有字时，事件另留 `authorSignature`。只留前 256 字。签名自己就是正文时不设这个字段。正文和 `textSha256` 仍按 ADR 0101。
- `is_automatic_forward` 正好是 true，并且来源是频道时，来源签名同样另留 `mirrorSignature`，上限也是 256。来源签名自己就是正文时不设。成员转发、群来源和其它标记不读这段签名。
- Bot API 没有写这个字段的长度。匿名管理员头衔在客户端最多 16 字。频道上这行通常是作者的名和姓，各自最多 64。256 字放得下一整行。第 257 字起不进事件。主机名仍从整段签名抽取。
- 关键词和 `regex` 同时看正文、`senderTag`、`buttonText`、`authorSignature`、`mirrorSignature` 和 `profile`。证据仍是原来的摘要。签名原文不进证据，也不进日志。
- `regex` 命中时带上 `places`，只写命中的字段名。`senderTag`、`buttonText`、`authorSignature` 和 `mirrorSignature` 这几条规则，只在 `places` 含有自己的字段时算命中。检测器没有 `places` 时仍按分数。
- 规则条件增加 `authorSignature: true` 和 `mirrorSignature: true`。消息上有对应字段时为真。
- 新规则 `author_signature_regex` 和 `mirror_signature_regex` 默认打开。条件是对应字段，检测器是现有的 `regex`，命中后 `delete`。
- 「免费领取」和「加微信」仍走已经打开的关键词规则。
- `regex_hint` 仍默认关闭。正文里的「加微x」不会因为旁边有一条干净的签名、标签或按钮就被删掉。
- 不改 ADR 0026 的基础检测器名单。`keyword` 和 `regex` 已经在里面，超额后这几条仍会跑。
- `chats.json` 整份替换的群不会自动带上这两条规则。
- 不新增命令。菜单仍是 99 条。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 默认打开 `regex_hint` | 普通消息会被同一份模式删除。这次要读的是正文旁边的签名。 |
| 把签名拼进正文 | 会改变 `textSha256`。ADR 0101 和 ADR 0445 已经拒绝。 |
| 成员转发的来源签名也读 | 那种转发已经按频道转发删除。群来源的签名仍留在外面。 |
| 取消管理员放行 | 频道自己的帖和本群匿名管理员会开始被删。这次不改放行。 |

## 后果

- 不是管理员的消息上，自己的签名含「免费领取」或「加微信」时按关键词删除。含 `t.me/+`、「加微x」或「加微X」时按 `author_signature_regex` 删除。证据不含签名原文。
- 讨论组原帖的来源签名命中同一组模式时按关键词或 `mirror_signature_regex` 删除。
- 频道自己发出的帖子，以及本群匿名管理员的消息，仍按管理员放行。
- 签名干净时消息留下。签名自己就是正文时，「加微x」仍要打开 `regex_hint`。
- 第 257 个字符起不进事件。主机名仍从整段签名抽取。写在签名里的路径会留在对应字段，不进审计。
- 关掉这两条规则后，这种签名回到只看关键词和短链。
- 整份替换规则的群要自己加上这两条，才会删除签名上的「加微x」。
- 30 天保留期没有改。
- `places` 后来由 ADR 0537 加上 `pollOption`。投票选项的规则只认自己的字段。
- 成员转发的频道签名后来由 ADR 0611 只留下主机名。关键词和这两条正则仍不读这段签名。讨论组原帖仍按本决定。
- 群来源的签名后来由 ADR 0612 只留下主机名。关键词和这两条正则仍不读这段签名。讨论组原帖仍按本决定。
