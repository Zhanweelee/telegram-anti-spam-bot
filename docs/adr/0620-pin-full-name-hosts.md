# ADR 0620：置顶提示上画出的发送者全名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

管理员把一条消息置顶时，Android 的 `MessageObject.generatePinMessageText` 用 `replaceWithLink` 把发送者画进这行服务文字。这里没有打开短名，所以名字是 `UserObject.getUserName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。

Bot API 把这个人放在 `from`。`pinned_message.message_id` 是大于 0 的安全整数时，这才是置顶提示。被置顶的原文、里面的发送者和消息号不画进这个人的名字。付费媒体那一行同样用 `getUserName`，仍是同一个人。

短链可以只写在姓上。名的长度大于 0 时如果丢掉姓，这条短链就留在提示里。把整段收成正文会改变内容哈希，关键词也会命中名字。

## 决策

- 只在已经会标成 `asPin` 的提示上，从 `from` 会画出来的全名留主机名。名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读。空格不截断。
- 主机名仍进消息已有的 `hosts`。邀请仍进 `invites`。正文里已有短链时，证据仍先记正文的主机名。全名不进正文，也不改内容哈希。关键词因此不命中。
- 用户名不读。被置顶的原文、里面的发送者、消息号和本群群名不读。空对象、0、负数、小数、字符串和布尔值的 `pinned_message` 不读发送者。普通消息因此仍不读 `from`。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`pin_notice` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不调用 `unpinChatMessage`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续只读名 | 客户端把姓画在同一行里。姓上的短链会留在群里。 |
| 连被置顶的原文一起读 | 那是另一条消息。见 ADR 0482。 |
| 每条服务提示的发送者都改成全名 | 助推这行用的是名。付款成功这行也只读名。见 ADR 0583 与 ADR 0618。 |
| 新命令 `/pinname` | 菜单只剩一个空位。现有 `links` 已经能删除短链。`/pin` 已经是操作命令。 |

## 后果

- 置顶的人全名里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。置顶本身还在。
- 全名原文、路径和用户名不进事件。内容哈希不变。关键词不命中全名。
- 空白名不挡住姓。空格后面的网址仍读。名的主机名排在姓前面。
- 正文里已有短链时，证据仍先记正文的主机名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 文字预览的前 20 个码元和游戏标题后来由 ADR 0653 只留主机名。第 21 个码元起、说明、被置顶的人和消息号仍不读。不是真实置顶提示时，发送者仍不读。管理员仍豁免。干净的提示在 `pin_notice` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
