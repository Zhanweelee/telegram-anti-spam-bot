# ADR 0117：入群名字里的短链或邀请就封禁

- 状态：已接受
- 日期：2026-11-02

## 背景

人已经进群之后，可见名字会显示在成员列表里。ADR 0028 只让关键词检测器看这份名字。`https://bit.ly/…` 或 `https://t.me/+…` 不含默认关键词，于是只发验证按钮，广告名仍然留在群里。

链接检测器在没有消息正文时已经会读 `profile`。缺的是一条默认规则。

进群用的 `invite_link` 是管理员发出的正常邀请。读它会把每个经邀请加入的人封禁。入群申请上的姓名仍按 ADR 0116 不读，要等真正入群。

## 决策

- 默认规则 `join_link` 对 `chat_member` 启用，检测器是现有的 `link`，命中后 `ban`。
- 它和 `join_name` 分开。关掉其中一条不会关掉另一条。
- 只有从群外加入的人带 `profile`。升降级和已经在群里的成员不带这份名字，所以这条规则不会封禁他们。
- 不读取 `chat_member.invite_link`。不把姓名放进 `join_request`。
- 决策已经是 ban 时，验证按钮让路，不再限制或发按钮。普通名字仍走 `new_member`。
- 不新增检测器。不改 ADR 0026 的默认次数、周期和基础检测器名单。
- `chats.json` 整份替换的群不会自动带上 `join_link`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把 `link` 加进 `join_name` | 关键词和短链不能分别关闭。 |
| 读取进群邀请链接 | 正常的 `t.me` 邀请会把新人封禁。 |
| 在入群申请里检查姓名 | ADR 0116 把姓名留到真正入群。申请阶段仍只看简介。 |
| 公开的 `t.me/名字` 也封禁 | `t.me` 不是短链，公开用户名也不是邀请。 |

## 后果

- 可见名字里的默认短链或邀请会被封禁，不会收到验证按钮。路径和邀请码不进证据。
- `example.com`、公开的 `t.me/名字` 和普通名字仍只验证。
- 关掉 `join_link` 后，短链名字回到只验证。关键词名字仍由 `join_name` 封禁。
- 整份替换规则的群要自己加上这条，才会封禁短链名字。
- 入群服务消息是另一条更新。上面的可见名字后来由 ADR 0118 删除。
- 同一份名字上的默认正则后来由 ADR 0532 另开 `join_regex`。关掉链接规则不会关掉它。
