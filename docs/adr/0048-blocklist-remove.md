# ADR 0048：私聊可以删掉一条共享黑名单

- 状态：已接受
- 日期：2026-11-01

## 背景

ADR 0012 的 `/blocklist` 只能打开、关闭和添加。ADR 0047 把名单留在 `POLICY_KV` 之后，一条误加的 actor id 或哈希会一直占着名额，其它打开的群也会继续命中。

## 决策

- `BlocklistStore` 增加 `remove`。它删掉当前租户的一条 `actor` 或 `hash`，并返回这条是否存在。不存在就不写。不改这个群的开关，也不动其它租户。
- 私聊 `/blocklist <chatId> remove actor <id>` 和 `remove hash <sha256>` 走这个方法。回复只说 `removed` 或 `absent`，不回显标识。哈希大小写在校验前折成小写。
- 校验失败或存储抛错时回复参数无效，日志是 `operator_rejected`，不写异常文本。
- 配了 `POLICY_KV` 时，删除成功才写。本 isolate 立刻读到新名单。没配时仍是内存。
- 不改 ADR 0026 的默认额度。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 关掉开关就清空名单 | ADR 0012 已经让其它打开的群继续用同一份名单。 |
| 只提供清空整个租户 | 一条误判会带走其余标识。 |
| 在回复里重复标识 | 哈希和 actor id 不该出现在私聊文本里。 |

## 后果

- 删掉一条之后，空出来的名额可以再写入。上限仍是 256 条。
- 名单里没有这条时不写 KV。
- 回复不含被删的标识。
- 状态行上的共享条数后来由 ADR 0049 带上。`size` 只读，不写 KV。
