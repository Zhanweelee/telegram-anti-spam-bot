# ADR 0674：助推的发送者是聊天时只读聊天标题

- 状态：已接受
- 日期：2026-11-06

## 背景

有人给聊天助推时，Android 的 `TL_messageActionBoostApply` 先看发送者。发送者是用户时，用 `UserObject.getFirstName`。发送者是聊天时，画出这个聊天的标题。标题不截断。次数不画进名字。

Bot API 把次数放在 `boost_added.boost_count`。发送者是聊天时，`sender_chat` 是那个聊天，`from` 是占位用户。见 `telegram-bot-api` 的 `messageSenderChat`。

ADR 0583 仍从 `from` 的可见名字留主机名。占位用户的名字不是这行画出的字。聊天标题上的短链会留在提示里。

## 决策

- 已经会标成 `asBoost` 的提示上，`sender_chat` 是对象时只从 `sender_chat.title` 留主机名，不从 `from` 留主机名。标题不截断。用户名不读。频道、群和超级群都一样。
- 没有 `sender_chat` 时，仍从 `from` 的可见名字留主机名。名的长度大于 0 时只读名。空白也算有名。名缺失或正好是空字符串时改读姓。
- 不从 `chat.title` 另读。次数仍不进事件。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`chat_boost` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不调用 `getUserChatBoosts`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 聊天标题继续不读 | 这行把聊天标题画出来。标题上的短链会留在提示里。 |
| 聊天也读 `from` | 占位用户的名字不在这行里。 |
| 只读频道标题 | 群和超级群代发时同样画标题。 |
| 改读 `chat.title` | 画出的是发送者那个聊天的标题。本群群名不另收。 |
| 新命令 | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 聊天助推时，标题里的短链、邀请或裸 IP 会留下主机名。证据只有主机名。助推本身还在。
- 占位用户的名字不再留下主机名。用户仍按可见名字。
- 标题原文、路径、用户名和次数不进事件。内容哈希不变。关键词不命中标题和名字。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 空对象、0、负数、小数和普通消息仍不读发送者。干净的助推提示在 `chat_boost` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
