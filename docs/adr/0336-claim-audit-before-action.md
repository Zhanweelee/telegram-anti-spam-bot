# ADR 0336：先占住审计再处罚

- 状态：已接受
- 日期：2026-11-04

## 背景

ADR 0335 在处罚之前读审计。读到记录就跳过动作。两次投递同时读到空记录时，两边都会处罚。动作已经执行、审计还没写上就中断时，重试也读不到记录，验证会再换一次 nonce。

读和插入是两次查询。免费计划一次调用最多 50 次 D1 查询。

## 决策

- `Storage.claimAudit` 插入这一行。主键已经存在时返回 false，不覆盖原来的审计。
- 决策不是 allow，也不是 dry-run 时，流水线先占住审计。返回 true 才执行动作。返回 false 时动作结果是 `skipped`，细节是 `duplicate`。
- D1 用一条 `INSERT ... ON CONFLICT DO NOTHING`。`changes` 至少为 1 才算占住。内存适配器在同一次调用里检查并写入。
- 占住抛错时记 `audit_claim_failed`。隐私拒绝的代码是 `raw_content_rejected`，其它是 `storage_failed`。不写异常文本。这次仍执行动作。
- allow 和 dry-run 不占审计。`appendAudit` 仍是直接插入。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续先读再插入 | 挡不住同时到来的两次投递，也挡不住动作和插入之间的中断。 |
| 给审计加状态列 | 现有表要改结构。占住一行已经能分出谁先到。 |
| 占住失败就跳过处罚 | 第一次写入失败时垃圾会留下来。 |

## 后果

- 同一条事件只有先占住的那一次会处罚。
- 占住之后、动作之前中断时，重试看到记录就不再处罚。这次处罚可能没有发出。
- 处罚路径少一次读。放行仍不碰 D1。
- 额度和 30 天保留期不动。
