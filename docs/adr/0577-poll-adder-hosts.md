# ADR 0577：后加投票选项的人，名字只留主机名

- 状态：已接受
- 日期：2026-11-05

## 背景

一条投票可以在发出之后继续加人选项。客户端在选项旁边画出添加者的名字。用户画出名，名为空时画出姓。群或频道画出标题。

这个名字写在 `poll.options` 的 `added_by_user` 或 `added_by_chat`。选项文字已经交给链接规则。名字本身还没有。广告可以把短链写进这个名字。

后加和删除选项的服务消息只带选项文字。原投票在嵌套的 `poll_message` 里，那是另一条消息。

## 决策

- `added_by_user` 是对象，且 `first_name` 的长度大于 0 时，从这段名抽出网址，只留主机名。空白也算有名。长度、折叠、邀请判断和 8 个主机名的上限不变。抽出之前不截断。
- `first_name` 缺失或正好是空字符串，且 `last_name` 的长度大于 0 时，改从姓里留主机名。名是空白或不是字符串时不读姓。
- 没有用户对象时，`added_by_chat.title` 只留主机名。群用户名不读。
- 用户对象和群对象同时存在时只读用户。有名时不读姓，也不读群标题。
- 这段名字不进正文，也不改内容哈希。关键词因此不命中。
- 用户名、用户 id、群 id、选项 `persistent_id`、`voter_count` 和 `addition_date` 不读。
- 嵌套的 `poll_message` 不读。`poll_option_added` 和 `poll_option_deleted` 上没有添加者字段，仍只读选项文字。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把名字整段当成正文 | 会改变哈希，关键词也会命中人名。短链只需要主机名。客座回复画出的名字也只留主机名，见 ADR 0446。 |
| 连用户名一起抽 | 客户端画出的是名或标题，不是用户名。 |
| 姓只要存在就读 | 名为空时才画姓。空白也算有名。 |
| 连嵌套的原投票一起扫 | `poll_message` 是另一条消息。原消息发出时已经扫过。 |
| 新命令 `/adder` | 菜单只剩一个空位。现有 `links` 已经能删短链。 |

## 后果

- 画出的名字里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。
- 名字原文、路径和邀请码不进事件，内容哈希不变。名字里的关键词不命中。
- 名的长度大于 0 时，姓、用户名和群标题不进事件。
- `example.com` 和公开的 `t.me/名字` 留着。付费帖仍不删除。见 ADR 0356。
- 云额度的基础检测器名单没有改。30 天保留期没有改。
- 服务消息上加选项或删选项的人后来由 ADR 0604 只留下主机名。选项旁边的添加者仍按这条。名字本身仍不进事件。嵌套原投票仍不读。服务消息上的人后来按短名，从下标 2 起的第一个空格后面不读。见 ADR 0659。
- 菜单上的添加者后来按短名。从下标 2 起的第一个空格后面不读。群标题仍不截断。见 ADR 0662。
