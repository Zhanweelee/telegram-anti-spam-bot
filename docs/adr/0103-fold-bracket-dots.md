# ADR 0103：括号里的点在抽主机名前收成点

- 状态：已接受
- 日期：2026-11-02

## 背景

短链和邀请常写成 `bit[.]ly`、`bit(.)ly`、`t{.}me/+`。词法扫描只认 ASCII 点，这些括号会把主机名拆开。

句号 `。` 单独出现时仍是中文标点。ADR 0093 不把它收成点。括号里的 `。` 是在标明这个位置是点。

关键词比较如果删掉这对括号，`不是免费[.]领取` 会对上 `免费领取`。

## 决策

- 抽主机名之前，把 `[.]`、`(.)`、`{.}` 收成 ASCII 点。全角括号 `［］`、`（）`、`｛｝` 同样处理。
- 括号里的点可以是 ASCII 点，或句号 `。`。点状间隔号先按 ADR 0093 收成 ASCII 点，再走这一层。
- 括号里有普通空格时不收。百分号编码的 `%5B.%5D` 不收。
- 单独的句号 `。`、普通空格和全角加号保留。
- 关键词和正则不走这一层。
- 事件里的正文和 `textSha256` 不变。不新增检测器，也不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 在关键词里也删掉这对括号 | `不是免费[.]领取` 会对上 `免费领取`。 |
| 把 `%5B.%5D` 也解开 | 百分号编码的括号还不是这条规则。和 `%5B` 不在字母表里一致。 |
| 括号里的空格也收成点 | 普通空格仍把主机名拆开。ADR 0060 已经留下空格。 |

## 后果

- `bit[.]ly/…` 和 `bit[·]ly/…` 走现有短链规则。`t[.]me/+…` 走现有邀请规则。
- `example[.]com` 仍保留。`t[.]me/durov` 仍是公开用户名。
- `bit[ . ]ly` 仍抽不出来。一层 `%5B.%5D` 后来由 ADR 0104 收成点。第二层仍留下。
- 关键词 `免费领取` 不命中 `不是免费[.]领取`。
- 重复计数仍按原文哈希。
