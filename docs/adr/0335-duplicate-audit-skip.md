# ADR 0335：已有审计就不再处罚

- 状态：已接受
- 日期：2026-11-04

## 背景

事件 id 来自 Telegram 的 `update_id`。Webhook 没有在时限内返回时，Telegram 会把同一个 update 再送一次。流水线先执行动作，再 `appendAudit`。D1 的主键是租户、群和事件 id，第二次插入会失败，并记成 `storage_failed`。删除、禁言、封禁和验证在插入之前已经又跑了一遍。验证会写一个新的 nonce，用户已经点开的按钮对不上。

## 决策

- 决策不是 allow，也不是 dry-run 时，先 `getAudit`。已经有记录就不再调用动作，也不再插入。每个计划中的动作结果是 `skipped`，细节是 `duplicate`。
- 完成日志带 `duplicate: true`。`aggregateMetrics` 不把它算进 screened 或拦截率。
- 查找抛错时记 `audit_lookup_failed`，代码是 `storage_failed`，不写异常文本。这次仍按决策处罚。
- allow 和 dry-run 不读审计。检测器仍会跑。额度计数仍在处罚之前，这次不改。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 每条消息都先读审计 | 放行是热路径。免费计划不为了重试给每条普通消息加一次 D1 读。 |
| 只靠插入失败挡住第二次 | 动作已经执行完。主键冲突挡不住第二次验证或封禁。 |
| 查找失败就跳过处罚 | 第一次消息如果读失败，垃圾会留下来。读失败仍按 fail-open 处罚。 |

## 后果

- 审计已经写上之后的重试不再处罚，也不再插一行。
- 动作执行完、审计还没写上就中断时，重试仍会再处罚一次。这次没有先写占位行。
- 重试仍会再跑检测器。洪泛和重复的窗口可能多记一次。额度计数不改。
- 30 天保留期不动。
