# ADR 0462：每个群可以改重复窗口

- 状态：已接受
- 日期：2026-11-04

## 背景

ADR 0010 把重复固定成 60 秒 3 条。ADR 0460 让群管能改洪泛，并明确 `/flood` 不改重复。同一句话刷屏的群和正常复述的群仍共用这一档。

## 决策

- `RuntimeStore` 增加 `getRepeatPolicy`、`setRepeatPolicy`、`clearRepeatPolicy`。一个群一份 `{ threshold, windowSeconds }`。
- 条数是 2 到 32 的整数。秒数是 1 到 300 的整数。界限与洪泛相同，对齐窗口里每个 key 最多记住的时间戳。1 条会把每条相同内容都删掉，所以不接受。
- 没设置时仍是 60 秒 3 条。写成 3 和 60，或 `reset`，都删掉记录。
- 私聊 `/repeat <chatId>` 只读，回复当前条数和秒数。`/repeat <chatId> <count>` 只改条数，秒数保持现状。`/repeat <chatId> <count> <seconds>` 两个都改。
- 内存最多 256 个群，和洪泛、关键词、开关各用一份名额。已有的群可以改。新群放不下时回复「参数无效」，日志是 `repeat_policy_full`。
- 配了 `POLICY_KV` 时写在 `runtime-repeat` 键。原来的运行时文档、动作键、上报键、洪泛键和关键词键都不改。坏文档读成没设置。每个 isolate 缓存 60 秒。相同的值不写。
- 群聊里的同样文本不执行。接入目录里的人只能改自己的群。读或写失败回复「参数无效」，日志是 `operator_rejected`。不写姓名、消息原文或 token。这条命令不调用 Telegram。
- 检测在创建 `repeat` 检测器之前读这份记录。读失败时记 `runtime_failed`，按 60 秒 3 条继续。洪泛仍按 ADR 0460。
- 不改 `default.json`，不改重复计数的存放位置。空正文且没有媒体摘要时仍然跳过。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把窗口写进现有运行时文档 | 旧 Worker 看到多出来的字段会把开关和 dry-run 一起丢掉。 |
| 用 `/flood` 同时改重复 | ADR 0460 已经把两份窗口分开。群管要能单独放宽复述。 |
| 把默认改成别的数字 | 现在按 3 条删除的群会被另一套阈值重新计算。默认要另一次决定。 |
| 允许 1 条 | 每条相同内容都会命中删除。 |

## 后果

- `/repeat -100 2` 之后，这个群同一份摘要的第 2 条在 60 秒内按重复删除。别的群仍是 3 条。
- 菜单多一条 `/repeat`，一共 95 条。
- 云额度的基础检测器名单没有改。30 天保留期没有改。
