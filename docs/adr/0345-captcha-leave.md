# ADR 0345：成员离群时删掉验证按钮

- 状态：已接受
- 日期：2026-11-04

## 背景

验证按钮会留到成员通过，或挑战到期。成员在这之前离群或被移出时，挑战还在，按钮也还在。下一次入群会换掉它。没有下一次入群时，按钮要等到默认 300 秒再加 15 分钟的清理。

机器人刚限制成员时，Telegram 会再发一条 `chat_member`：旧状态是 `member`，新状态是 `restricted`。把所有非入群更新都当成离群，会删掉刚写下的挑战。

## 决策

- `membership` 增加 `leave`。人从 `member`、`restricted`、`administrator` 或 `creator` 变成 `left` 或 `kicked` 时带上它。旧状态缺失、已经是 `left` 或 `kicked`、以及 bot，都不带。
- 昵称只在 `membership === "join"` 时进入 `profile`。离群事件不带名字。
- `cancelChallenge` 只处理 `leave`。没有挑战就返回 false。有 `messageId` 时先删按钮。没有删除端口，或删除抛错，就留下这一行，并在抛错时记 `captcha_prompt_delete_failed`。删掉按钮之后，或这一行没有 `messageId`，就删掉挑战并记 `captcha_left`。
- 不解除限制，不写 `captcha_expired`。日志只有事件 id 和群 id。
- Worker 在同步群目录之后调用它，然后仍走原来的检测。删除挑战这一步抛错时记 `captcha_leave_failed`，检测继续。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 任何非入群的 `chat_member` 都清掉挑战 | 限制成员自己会发出 `member` 到 `restricted`，刚写的挑战会被删掉。 |
| 删不掉按钮也清掉这一行 | `messageId` 一丢，按钮就留在群里，到期清理也找不到它。 |
| 离群时写 `captcha_expired` 并解除限制 | 人已经不在群里。到期语义和放行都对不上。 |
| 更严重的处罚顺手清掉旧挑战 | 另一条路径。这次只处理离群和被移出。 |

## 后果

- 成员离群或被移出后，已经记下 id 的验证按钮会被删掉，挑战也不再留给下一次点击。
- 删除按钮失败时挑战还在。下一次离群可以再试。Cron 到期后仍会取走这一行；那次删除失败不会留下挑战。
- 按钮已经删掉、随后存储删除失败时，重试会再删一次已经不在的消息。那一次失败会把行留到到期清理。
- 没记下 id 的按钮还会留在群里。
- 成员被限制、bot 离群、以及已经不在群里的状态变化，都不删按钮。
- 30 天保留期不动。
