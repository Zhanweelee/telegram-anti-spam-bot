# ADR 0388：私聊可以撤下一条消息的置顶

- 状态：已接受
- 日期：2026-11-04

## 背景

置顶列表里只想拿下一条消息时，`/unpin` 会把全部置顶一起撤掉。官方有一次只撤一条的调用。

`unpinChatMessage` 从置顶列表里拿下一条消息。参数是必须的 `chat_id`，以及可选的 `message_id`。不带消息号时，官方撤下最近发出的那一条置顶。私聊和频道私聊里，消息都可以撤下。群里 bot 要有 `can_pin_messages`，频道里要有 `can_edit_messages`。成功时返回 True。

这条调用不删除消息，也不动其它置顶。清空全部置顶仍走 `/unpin`。

没有 token 时，内存适配器可以把这次请求记下来。私聊如果复用这次成功，回复会写成置顶已经撤下。

## 决策

- 私聊命令 `/unpinmsg <chatId> <messageId>`。群 id 匹配 `^-?\d{1,20}$`。消息号和 `/delete` 使用同一条规则：`/^[1-9]\d{0,15}$/`，并且是安全整数。少一个参数或多出来的参数都不发出请求。群聊里的同样文本不执行。
- 配置中的管理员可以操作任意群。接入目录里的人只能操作自己的群。
- 调用 `ModerationPort.unpinMessage`。目标带 `chatId` 和 `messageId`。适配器调用 `unpinChatMessage`，两个字段都带上。消息号 `1` 原样送出。
- 不省略 `message_id`。不传 `business_connection_id`。不调用 `unpinAllChatMessages`、`pinChatMessage` 或 `deleteMessage`。
- 回复写明这条消息的置顶被撤下，消息还在，其它置顶还在。
- 没有 token、没有这个方法，群号或消息号不合法，或调用失败时回复「参数无效」。日志只写 `operator_rejected`，带上 eventId、chatId 和命令名。不写异常文本、token 或原文。
- 没有 token 的 Worker 不把内存里的记录回复成已经成功。
- 不修改黑名单、白名单、封禁或禁言。不读取消息正文。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 不带消息号时撤下最近一条 | 最近一条可能不是管理员想拿下的那条。必须写明消息号。 |
| 复用 `/unpin` 并在有消息号时改走这一次 | `/unpin` 已经表示清空全部置顶。两条命令的范围不同。 |
| 先拉出置顶列表再挑选 | 一次 `unpinChatMessage` 已经指向这一条。多一次读取会多花子请求。 |
| 没有 token 时也回复「已撤下」 | 置顶还在。管理员会以为已经拿下。 |

## 后果

- 成功只表示 Telegram 接受了这一次撤下。这条消息本来就没有置顶，或缺少置顶或编辑权限时，回复是「参数无效」。
- 其它置顶还在。这条消息还在。
- 一次撤下是一次 Telegram 子请求。封禁、禁言和黑名单都不变。
- 删除置顶服务消息不会调用 `unpinChatMessage`。置顶仍在，直到 `/unpinmsg`。见 ADR 0482。
- 30 天保留期不动。
