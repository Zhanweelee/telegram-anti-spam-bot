# ADR 0111：内联查询只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

内联按钮可以在按下后把一段查询插进输入框。这段字可以是短链或邀请，按钮上看得见的字却是另一句普通的话。`copy_text` 已经抽出主机名。`switch_inline_query`、`switch_inline_query_current_chat` 和 `switch_inline_query_chosen_chat.query` 还没有。

富文本按钮使用同一组字段。`callback_data` 仍是回调数据。登录按钮在转发后替换的文字、用户名和回复键盘仍不是这条消息上打开的网址。

## 决策

- 从内联键盘和富文本按钮的这三处查询抽出网址，只留主机名。折叠、长度、邀请判断和 8 个主机名的上限与旁路纯文本相同。
- 查询不进入 `message.text`，也不参与内容哈希。没有更前面的正文时，按钮上看得见的字仍是正文。
- 不读取 `callback_data`、`login_url.forward_text`、`login_url.bot_username`、挑选聊天的允许范围，以及回复键盘。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把查询拼进正文 | 同一条消息的哈希会变，路径也会进事件。 |
| 只读会打开的 `url` | 查询会插进输入框，短链可以只写在这里。 |
| 连 `callback_data` 和回复键盘一起读 | 回调数据不是打开的网址。入站消息上的回复键盘仍不读。 |

## 后果

- 已有正文时，查询里的短链、邀请或裸 IP 按现有链接规则命中。路径和邀请码不进事件。高亮提前停住的主机名后来由 ADR 0157 留下。
- 按钮文字仍按原规则成为正文。查询里的关键词仍然看不到。
- `callback_data`、转发后的按钮文字和回复键盘不进事件。这段替换文字里的网址后来由 ADR 0444 只留下主机名。句子和用户名仍不进事件。
- 非空的内联查询后来由 ADR 0517 另开 `switch_query`。查询仍不进事件。看得见的按钮文字仍是正文。
