# ADR 0128：代码实体的语言标签只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

普通消息、图片说明、投票说明和其它已经在扫的实体列表里，`pre` 实体可以带 `language`。这是语法高亮用的语言标签，发送者能写成一条网址。代码正文已经在 `text` 或 `caption` 里。标签本身不在这段正文里。

ADR 0127 只读了富文本块 `pre.language`。同一条短链改放到实体的 `language` 上，链接规则仍放行。

把标签拼进正文会改变 `textSha256`。`python` 这种普通语言名不该成为正文，也不该进事件。加粗实体上的 `language` 和自定义表情 id 不是语言标签。

## 决策

- 从已经读取的实体列表里，抽出 `type` 为 `pre` 的 `language` 网址，只留主机名。折叠、长度、邀请判断和 8 个主机名的上限与旁路纯文本相同。
- 语言标签不进入 `message.text`，也不参与内容哈希。代码正文仍按原来的规则成为正文。
- 不把语言标签里的关键词交给关键词检测器。
- 不读取加粗等其它实体上的 `language`，也不读取 `custom_emoji_id`。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 实体上的语言标签整段都不读 | 短链可以只写在代码实体的语言标签上。 |
| 没有别的正文时让标签成为正文 | 普通语言名会改掉内容哈希。 |
| 任何实体上的 `language` 都读 | 这个字段只属于 `pre`。 |

## 后果

- 代码实体语言标签里的默认短链或邀请会删掉这条消息。证据仍只有主机名。
- `example.com` 留着。语言标签里的关键词留着。代码正文里的关键词仍会命中。
- 标签原文、路径和邀请码不进事件。
