# ADR 0013：命令回复走消息目录

- 状态：已接受
- 日期：2026-11-01

## 背景

P1-05 要求命令回复走字典，至少中文和英文。缺键时回退到 key，不能抛错。现在这些句子写在 `runOperatorCommand` 里面，中英混在同一批返回值里。

## 决策

- core 里放两份静态目录，`zh` 和 `en`。`translate(locale, key, vars)` 做替换。
- 未知 locale 使用中文。目录里没有的 key 原样返回这个 key。缺占位符时留下 `{name}`。这三条路径都不抛错。
- `runOperatorCommand` 的可选 `locale` 缺省是 `zh`，所以现有中文回复不变。导出的审计 JSON 仍是数据，不翻译。
- Worker 读可选变量 `LOCALE`，只接受 `zh` 或 `en`。别的值当成没写。不放进提交的 `wrangler.jsonc`，绑定保持原来的两个。
- 这一轮只覆盖私聊命令。验证按钮的文案仍在 `platform-telegram`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 读 Telegram 的 `language_code`，再按人记住 | 要新的存储，也多一份个人信息。命令目录先按部署选一种语言。 |
| 把文案放进 KV，让管理员热改 | 每次私聊都多一次 KV 读。目录很小，打进包里就够。热改可以以后再加。 |

## 后果

- 自部署要英文回复时，在 `vars` 里加 `LOCALE=en` 再部署。不改 core 的运行模式。
- 新增一句回复要同时写进两份目录。类型会在缺其中一份时失败。
- 运行时拼出来的未知 key 会直接出现在私聊里，而不是把请求打成 500。
