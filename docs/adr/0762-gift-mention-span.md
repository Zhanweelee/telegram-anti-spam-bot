# ADR 0762：礼物附言上的按标识提及必须从附言里开始

- 状态：已接受
- 日期：2026-11-07

## 背景

按标识提及可以按群删除。用户编号不进事件。见 ADR 0514。后加任务上的按标识提及必须从这条画出的任务里开始。见 ADR 0761。

普通礼物、独特礼物和升级礼物的附言都走这一条。Android 的 `addEntitiesToText` 会跳过长度小于或等于 0、起点小于 0，或起点已经到达附言末尾的实体。起点落在附言里、长度越过末尾时，客户端把长度收到附言末尾，这段提及仍会画出来。

已有别的正文时，事件里的附言只留前 128 字。附言自己就是正文时，事件正文只留前 4096 字，不再另留附言。提及仍按整段附言判断。

现在附言会读全部 `entities`。一个起点已经越过附言的按标识提及仍会带上 `asTextMention`。打开这条规则后，没画出来的提及也会删掉这条礼物。

游戏附加文字不在这条里。

## 决策

- `gift`、`unique_gift` 和 `gift_upgrade_sent` 的 `text` 是字符串时，`entities` 里的按标识提及，起点必须大于或等于 0 且小于附言长度，长度必须大于 0。
- 起点落在附言里、长度越过末尾时，仍带 `asTextMention`。
- 附言不是字符串时，仍按原来的方式读取。
- 已有别的正文时，第 129 字上的提及，只要起点仍落在附言里，就继续带 `asTextMention`。事件里的附言仍只留前 128 字。
- 附言自己就是正文时，第 4097 字上的提及，只要起点仍落在附言里，就继续带 `asTextMention`。事件正文仍只留前 4096 字。这时不再另留附言。
- 游戏附加文字上的按标识提及不在这条里。
- 仍落在附言里的提及继续带 `asTextMention`。用户编号和名字仍不进事件。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。规则仍默认关闭。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续读全部实体 | 没画出来的提及会在打开规则后删掉这条礼物。 |
| 也要求长度落在附言里 | 起点在附言里时，客户端会把越过末尾的长度收回来再画。 |
| 也按 128 字丢掉后面的提及 | 128 只是旁边附言的上限。整段附言更长时，后面的提及仍落在附言里。 |
| 只改普通礼物 | 独特礼物和升级礼物的附言用同一套画法。 |
| 游戏附加文字也一起收 | 附加文字是另一段文字，这条只改礼物附言。 |
| 默认打开 | 有的群会点名。打开之前不改现有群。 |

## 后果

- 起点已经到达或越过礼物附言末尾的按标识提及不再带 `asTextMention`。空附言、长度为 0 和负起点也不带。
- 起点落在附言里的提及，打开 `text_mention` 后删除。证据仍是 `entity:text_mention`。用户编号不进事件。长度越过末尾的提及也删除。起点已经超过 128 或 4096、但仍落在附言里的提及也删除。
- 规则关闭时留下。付费帖仍不删除。见 ADR 0356。
- 附言不是字符串时，按标识提及后来由 ADR 0806 不再读取。
- 游戏附加文字上的按标识提及后来由 ADR 0763 要求起点落在附加文字里。附加文字不是字符串时，按标识提及后来由 ADR 0807 不再读取。长度越过末尾时仍算画出来。
- 管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
