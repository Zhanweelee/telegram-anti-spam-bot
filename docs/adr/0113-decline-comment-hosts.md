# ADR 0113：拒绝建议帖的说明只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

拒绝一条建议帖时，服务消息可以带 `suggested_post_declined.comment`。这是拒绝的人写的说明，成员看得见。说明里可以只放短链或邀请，外面的正文是另一句普通的话。

同一对象里的 `suggested_post_message` 是嵌套的原帖。原帖、被回复的消息和置顶的消息一样，不在这条服务消息上展开。

把说明拼进已有正文会改变 `textSha256`。

## 决策

- 从 `suggested_post_declined.comment` 抽出网址，只留主机名。折叠、长度、邀请判断和 8 个主机名的上限与旁路纯文本相同。
- 已有正文时，说明原文不进正文，也不改内容哈希。
- 没有更前面的正文时，说明整段成为正文，并以此计算 `textSha256`。话题名仍排在说明之前。已有作者签名或成员标签时，说明仍先成为正文，签名和标签只留主机名。
- 不读取 `suggested_post_message`，也不读取通过、失败、付款和退款对象里的原帖。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 已有正文时把说明拼进去 | 说明会改变哈希。短链只需要主机名。 |
| 把嵌套原帖也扫一遍 | 原帖是另一条消息。回复和置顶都没有展开。 |
| 说明整段都不读 | 短链可以只写在这句看得见的话里。 |

## 后果

- 已有正文时，说明里的短链、邀请或裸 IP 按现有链接规则命中。路径和邀请码不进事件。
- 说明成为正文时，整段说明仍参与关键词和内容哈希。路径留在正文里。
- 嵌套原帖里的网址不进事件。
- 通过、失败、付款和退款没有说明。某个群可以以后打开 `post_notice`，删除这四条提示。拒绝说明仍成为正文。见 ADR 0488。
- 说明干净的拒绝仍留下。某个群可以以后打开 `post_declined`，把这种服务消息删掉。没有说明时这行也会删除。原帖仍不进事件。打开 `post_notice` 仍不删除拒绝。见 ADR 0497。
- 已有别的正文时，拒绝说明后来由 ADR 0551 另留在 `declineComment`。关键词和默认正则可以删除。嵌套原帖仍不进事件。
