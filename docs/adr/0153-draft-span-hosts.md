# ADR 0153：草稿里提前停住的链接只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

点开用户名、分享或 `msg` 链接时，`text` 会写进输入框。发送预览对这段文字调用 `MessageObject.addLinks`，里面是 `Linkify.WEB_URLS`。高亮规则和正文相同：下一段不是 `/`、`?` 或 `#` 时停在主机名，点下去打开的是这一段。

这条链接若只写在按钮或 `text_link` 上，正文扫描看不到查询里的地址。整段解析会把 `∕` 后面的 `@` 认成新的主机，短链和裸 IP 就只留在前面。

## 决策

- 用户名草稿、分享 `text` 和 `msg` 的 `text` 里，`http` 或 `https` 再取 Android 高亮会打开的那一段主机名。只留主机名。
- 整段解析出的主机名仍然保留。两边都走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。最多 8 个。
- 按钮文字、复制文字和已经写在 `text_link`、按钮 `url` 上的地址整段打开，不按高亮截断。
- 路径不进证据。没有新的主机名时不另记。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 只扫正文 | 按钮上的草稿链接不在正文里，短链不会留下。 |
| 所有纯文本都按高亮截断 | 按钮文字点下去打开的是按钮自己的地址。 |
| 在结构化地址上也截断 | 客户端整段打开 `text_link` 和按钮 `url`。见 ADR 0152。 |

## 后果

- `https://t.me/durov?text=http://bit.ly∕@example.com/…` 按短链删除。证据仍只有主机名。
- `http://example.com∕@bit.ly` 写在同一段草稿里时，整段里的 `bit.ly` 仍删除。
- 小写 `%e2%88%95` 仍打开后面的主机。
- 再套一层仍放行。路径不进证据。
