# ADR 0606：把人移出群的人，名字只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

有人把别人移出群时，客户端把这个人的名字画在服务消息上。名字写在 `from`。离开的人写在 `left_chat_member`，当时已经只留主机名。见 ADR 0582。短链可以只写在操作的人的名字里。

自己离开时，画出的也是 `from` 上的可见名字。ADR 0582 读的是离开的人，没有读发送者。ADR 0598 当时把退群的发送者留在外面，是因为不能把名字收成正文。这次只留主机名，名字本身仍不进事件。

把 `from` 收成正文会让普通发言者的姓名也进检测。`service_notice` 默认关闭，干净的退群提示仍留下。用户编号仍不读。入群仍按 ADR 0598。

## 决策

- 只在已经会标成 `notice: "leave"` 的提示上，从 `from` 的可见名字留主机名。`left_chat_member` 是对象时读。空对象也读。同时出现入群名单时仍先认入群，发送者仍按 ADR 0598。
- `first_name` 的长度大于 0 时只读名。空白也算有名。名缺失或正好是空字符串时改读姓。用户名不读。抽出之前不截断。同一个人自己离开时也读。
- 离开的人仍按 ADR 0582 只留主机名，排在这个人前面。离开的人的名字不进正文，也不进 `memberName`。操作的人的名字不进正文，也不改内容哈希。关键词因此不命中这两个人。用户编号不读。本群群名不读。
- 布尔值不读发送者。普通消息不读 `from`。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`service_notice` 仍默认关闭。8 个主机名的上限不变。退群本身不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把这个人整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0118。 |
| 并进 `service_notice` | 打开退群提示的群并不一定要按名字里的短链删。入群也会被一起打开。 |
| 编号相同就不读发送者 | 自己离开时画出的仍是这个名字。短链可以只写在 `from` 上。 |
| 新命令 `/leavename` | 菜单只剩一个空位。现有 `links` 已经能删短链。 |

## 后果

- 把人移出群的人，名字里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。人还是离开了。
- 这个人的名字原文、路径和用户名不进事件，内容哈希不变。名字里的关键词不命中。
- 名的长度大于 0 时，姓和用户名不进事件。离开的人的主机名仍排在前面。离开的人的名字仍不进正文。
- `example.com` 和公开的 `t.me/名字` 留着。付费帖仍不删除。见 ADR 0356。
- 布尔值和普通消息仍不读发送者。空对象仍读。本群群名仍不读。干净的退群提示在 `service_notice` 关闭时仍留下。入群仍按 ADR 0598。离开的人仍按 ADR 0582。云额度的基础检测器名单没有改。30 天保留期没有改。
- 频道私信话题里，发言人就是话题用户时，后来由 ADR 0608 只留下那个人的主机名。名字本身仍不进事件。普通消息的 `from` 仍不读。发言人不是话题用户时仍不读。
