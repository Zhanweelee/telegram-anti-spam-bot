# ADR 0454：规则可以选用警告动作

- 状态：已接受
- 日期：2026-11-04

## 背景

ADR 0452 让管理员用 `/warn` 计数，满 3 次再封禁。它故意没把默认规则改成自动警告，因为那会把现在只删除的命中改成封禁。群里仍需要一种可选动作：删掉这一条，累计同一个人的次数，第三次再封禁。

## 决策

- 动作名单增加 `warn`，严重度在 `delete` 和 `mute` 之间。`mute` 仍比 `warn` 更重，`ban` 仍最重。
- `createWarnAction` 使用和 `/warn` 同一份 `WarnStore`。配了 `DB` 时是 D1，没配时是内存。
- 试运行不删消息，也不读次数。
- 没有 actor id 时记 `missing_actor`，不删消息。
- 付费帖记 `paid_post`，不删，也不计数。
- 有消息号时先 `deleteMessage`。带了 `audienceId` 就一并送出。删除失败时不计数。
- 没有消息号时仍计数。相册里的其它消息不在这一步删除。
- 次数未满 3 时只加一。加到 3 时调用 `banActor`，参数只有 tenant、chat、actor。封禁失败时把次数退回刚加上的这一次，流水线记 `action_failed`。
- 次数已经是 3 时不再加。这条人还在发，所以再调用一次 `banActor`。私聊 `/warn` 在已经满 3 次时仍不封禁。
- 成功结果不写次数。日志不写姓名或消息原文。
- `default.json` 仍使用 `delete`。要启用时把那条规则的 `actions` 写成 `["warn"]`。`/rule` 只开关规则，不改动作。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把默认关键词和链接改成 `warn` | 现在只删消息的人会被第三次命中封禁。默认行为要另一次决定。 |
| 警告不删当前消息 | 这条已经判定为垃圾。留下它，次数还在涨。 |
| 满 3 次之后不再封禁 | 私聊命令可以停。流水线面对的是还在发送的人，需要再送一次封禁。 |
| 同时跑 `delete` 和 `warn` | `warn` 已经删除当前消息。两条一起写会再删一次。 |

## 后果

- 一条规则写成 `warn` 后，前两次删除，第三次删除并封禁。封禁不撤回历史消息。
- 和 `/warn`、`/unwarn`、`/warns` 看的是同一次数。
- 指标里的拦截次数包含 `warn`。
- 云额度的基础检测器名单没有改。30 天保留期没有改。
