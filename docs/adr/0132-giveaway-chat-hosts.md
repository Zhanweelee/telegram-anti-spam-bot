# ADR 0132：抽奖频道名字只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

抽奖消息列出必须加入的频道，名字在 `giveaway.chats[].title`。抽奖结束时，举办频道的名字在 `giveaway_winners.chat.title`。这两处往往没有别的网址。频道名字里可以只放短链、裸 IP 或邀请。奖品说明已经会抽主机名，频道名字还没有。

`chat.title` 会附在每一条消息上。转发来源里的频道标题也不是这次抽奖要加入的频道。中奖者姓名、频道 id 和用户名不是这段名字。

## 决策

- 从 `giveaway.chats[].title` 和 `giveaway_winners.chat.title` 抽出网址，只留主机名。折叠、长度、邀请判断和 8 个主机名的上限与旁路纯文本相同。
- 频道名字不进入 `message.text`，也不参与关键词或内容哈希。
- 不读取 `chat.title`、转发来源里的频道标题、`username`、频道 id 和中奖者姓名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把频道名字当成正文 | 名字会进事件和哈希。短链只需要主机名。 |
| 每条消息都扫 `chat.title` | 群名会跟着每条消息重复计一次主机名。 |
| 抽奖频道名字整段都不读 | 短链可以只写在必须加入的频道名字里。 |

## 后果

- 抽奖频道名字里的短链、裸 IP 或邀请按现有链接规则删除这条消息。证据仍只有主机名。
- `example.com` 留着。频道名字里的关键词留着。
- 群名、转发来源里的频道标题、用户名、频道 id 和中奖者姓名不进事件。
- `t.me/share`、`t.me/msg/url`、`tg://share`、`tg://iv` 和私聊预填上的 `url` 后来由 ADR 0133 只留下主机名。用户名上的 `url` 仍不读。
