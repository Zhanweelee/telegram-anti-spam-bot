# ADR 0385：私聊可以删除一个论坛话题

- 状态：已接受
- 日期：2026-11-04

## 背景

一个话题整段都是诈骗时，逐条 `/delete` 会把免费套餐的子请求花光。官方有一次删掉整个话题的调用。

`deleteForumTopic` 删除一个论坛话题，并删掉这个话题里的全部消息。参数是 `chat_id` 和必须的 `message_thread_id`。超级群里，bot 必须是管理员，并且有 `can_delete_messages`。成功时返回 True。

没有单独删除通用话题的方法。通用话题仍走关闭、隐藏和撤置顶。

没有 token 时，内存适配器可以把这次请求记下来。私聊如果复用这次成功，回复会写成话题和消息已经删除。

## 决策

- 私聊命令 `/deltopic <chatId> <threadId>`。群 id 匹配 `^-?\d{1,20}$`。话题号和消息号使用同一条规则：`/^[1-9]\d{0,15}$/`，并且是安全整数。少一个参数或多出来的参数都不发出请求。群聊里的同样文本不执行。
- 配置中的管理员可以操作任意群。接入目录里的人只能操作自己的群。
- 调用 `ModerationPort.deleteTopic`。目标必须带 `threadId`。适配器调用 `deleteForumTopic`，带上这个 `message_thread_id`。话题号 `1` 原样送出。
- 不调用 `deleteMessage` 或 `deleteMessages`。不带消息号。
- 回复写明这个话题和里面的消息在这次里，其它话题不在这次里。
- 没有 token、没有这个方法，群号或话题号不合法，或调用失败时回复「参数无效」。日志只写 `operator_rejected`，带上 eventId、chatId 和命令名。不写异常文本、token 或原文。
- 没有 token 的 Worker 不把内存里的记录回复成已经成功。
- 不修改黑名单、白名单、封禁或禁言。不读取消息正文。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 不带话题号时删除通用话题 | 官方没有删除通用话题的方法。通用话题仍走 `/closetopic`、`/hidegeneral` 和 `/untopic`。 |
| 把话题号 `1` 改成别的方法 | 这条方法要求话题号。通用话题没有对应的删除接口。 |
| 先拉出消息号再逐条删除 | 一次 `deleteForumTopic` 已经包含这个话题里的消息。逐条删除会多花子请求。 |
| 回复写成消息还在 | 成功表示这个话题和里面的消息被删掉。其它话题的消息还在。 |
| 没有 token 时也回复「已删除」 | 话题和消息都还在。管理员会以为已经清掉。 |

## 后果

- 成功只表示 Telegram 接受了这一次删除。缺少 `can_delete_messages`，这个群不是论坛，或这个话题号删不掉时，回复是「参数无效」。
- 其它话题和里面的消息还在。聊天级置顶不在这次里。
- 一次删除是一次 Telegram 子请求。封禁、禁言和黑名单都不变。
- 30 天保留期不动。
