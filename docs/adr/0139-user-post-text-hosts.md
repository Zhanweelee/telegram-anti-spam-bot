# ADR 0139：用户帖子路径和用户名子域的 text 只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0137 认为 `t.me/用户名/123?text=` 不会把 `text` 放进输入框。

桌面端 `TryConvertUrlToLocal` 把 `t.me/用户名/数字`、`telegram.me/用户名/数字`、`telegram.dog/用户名/数字` 和 `用户名.t.me`、`用户名.t.me/数字` 收成 `tg://resolve`，查询原样保留。`showPeerByLinkResolved` 在对方是用户时调用 `SetChatLinkDraft`。频道不是用户，这条 `text` 不进输入框。Android 只在 `user_id` 分支写入 `start_text`，`ChatActivity` 再把它放进输入框；频道走 `chat_id`，不写 `start_text`。

链接本身看不出名字属于用户还是频道。用户名后面只有一段数字时，点开可能把短链放进私聊输入框。`用户名.t.me` 没有路径时也一样。

两条数字是讨论串，桌面端在草稿之前就返回。小程序路径走 Bot App。`proxy.t.me` 这类保留名走命令，不进私聊草稿。单字母子域桌面端不改写。

## 决策

- `t.me`、`telegram.me`、`telegram.dog` 以及 `www` 前缀上，路径是一个公开用户名再加 1 到 16 位数字时，从 `text` 抽出主机名。
- 公开用户名的 `name.t.me`，路径为空或只有 1 到 16 位数字时，同样从 `text` 抽出主机名。`www`、单字母和保留命令名除外。
- 这个主机名走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。`text` 不进入正文，也不参与关键词。
- 用户名、数字和路径不进证据。
- 两条及以上的数字路径、非数字的第二段、Passport、其它网站和保留子域不读。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 一段数字的路径继续不读 | 名字解析成用户时，客户端会把 `text` 放进输入框。 |
| 先解析用户名再决定读不读 | 热路径不能为了这条链接打 Telegram。 |
| 讨论串和小程序路径也读 | 桌面端这些分支不写草稿。 |

## 后果

- `t.me/用户名/123` 和 `用户名.t.me` 的 `text` 是裸 IP、默认短链或邀请时，现有链接规则删除这条消息。证据仍只有主机名。
- 频道帖子如果带了同样的 `text`，也会被删。客户端对频道不写这段草稿。
- `example.com` 留着。`t.me/用户名/12/34` 和 `proxy.t.me` 仍放行。
- 再套一层预填链接仍放行。正文就是这条链接时，链接原文仍在 `message.text`。按钮和隐藏链接只留下主机名。
- Passport 的 `callback_url` 后来由 ADR 0145 只留主机名。这里的 `text` 仍不读。
- `t.me/用户名/app` 后来由 ADR 0146 只留 `text` 里的主机名。子域上的应用名和讨论串仍不读。
- 帖子数字后来由 ADR 0147 不再停在 16 位。`用户名.t.me/` 后更长的数字同样只留 `text` 里的主机名。
- 查询名正好是 `profile`、值不是 `0` 或 `false` 时，后来由 ADR 0232 不读 `text`。`profile=0` 和 `Profile` 仍读。
- `tg://resolve` 上的非零 `story`、`album` 和 `collection` 后来由 ADR 0233 不读 `text`。网页上的 `story` 查询仍读。
- `t.me/c?text=` 后来由 ADR 0256 按用户名读取。小写 `c/数字` 仍不读 `text`。
