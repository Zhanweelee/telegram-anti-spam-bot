# ADR 0280：除号接不上边界时仍留下前面的主机名

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 的放松标签可以接上标签类里的字符。`http://bit.ly，广告`、`http://bit.ly` 加 U+200B 再接 `foo`，以及 `http://bit.ly点击`，都是一条链接，主机名不再是 `bit.ly`。除号 U+2215 后面没有单词边界时，匹配会退回 `bit.ly`，后面的 `example.com` 仍单独打开。夹在 `bit` 和 `.ly` 中间的 U+200B 仍由整段折叠收成 `bit.ly`。

看得见的正文和隐藏的分享 `text` 已经这样切。分享 `url` 把除号收进用户信息，主机名停在后面的域名上，前面的短链就漏了。

## 决策

- 分享 `text`、分享 `url`、私聊预填 `tg://msg` 的 `url` 和 Passport 的 `callback_url`，带协议的标签继续吃进 Android 标签类里的字符。这段的主机名按整段计算，前缀不另记。
- 除号后面接不上单词边界时，仍留下前面的主机名，并打开后面的网址。
- 整段折叠仍去掉 U+200B，所以 `bit` 加 U+200B 再接 `.ly` 仍按短链删除。
- 证据只留主机名。路径不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 非 ASCII 一律从标签上截断 | `http://bit.ly，广告` 会删掉 Android 留成一条普通链接的消息。 |
| 除号也留在用户信息里 | 分享 `url` 里的 `bit.ly` 会漏掉。 |
| 整段折叠不再去掉 U+200B | `bit` 加 U+200B 再接 `.ly` 就不再按短链删除。 |

## 后果

- `t.me/share/url?text=http://bit.ly，广告`、U+200B 再接 `foo`，以及 `http://bit.ly点击`，留着。
- 分享 `url` 里的 `http://bit.ly` 加 U+2215 再接 `@example.com/…` 按短链删除。证据有 `bit.ly`。后面的 `example.com` 仍留下。路径不进证据。
- `http://bit` 加 U+200B 再接 `.ly/…` 仍按短链删除。
