# ADR 0466：每个群可以放行指定主机

- 状态：已接受
- 日期：2026-11-04

## 背景

链接规则会删除短链、裸 IP、拒绝名单上的主机和邀请。`github.com` 这类普通主机本来就会留下。群里自己要用的短链、状态页 IP 或本群邀请仍会被删。关掉整条链接规则会把其它短链也放进来。

## 决策

- `RuntimeStore` 增加 `listAllowHosts`、`addAllowHost`、`removeAllowHost`、`clearAllowHosts`。一个群一份主机名单。没有记录表示不放行。
- 私聊 `/allowhost <chatId>` 只读。`add` 追加一台主机，`remove` 删掉一台，`reset` 清空。
- 写入前按链接检测器的主机折叠。带协议、路径、端口、用户信息或空白的值不写入。主机名至少两段，每段 1 到 63。IPv4 是四段 0 到 255，只按整段相等放行，`1.2.3` 不会放行 `1.2.3.4`。其它主机沿用检测器已有的后缀匹配，所以放行 `t.me` 也会放行 `evil.t.me`。
- 一个群最多 32 个主机。内存最多 256 个群，和关键词、验证、禁言、重复、洪泛、开关各用一份名额。已有的群可以改。新群放不下时回复「参数无效」，日志是 `allow_host_full`，日志里没有主机名。
- 配了 `POLICY_KV` 时写在 `runtime-allow-host` 键。原来的运行时文档和其它运行时键都不改。坏文档读成空名单。每个 isolate 缓存 60 秒。相同的主机不写。
- 群聊里的同样文本不执行。接入目录里的人只能改自己的群。读或写失败回复「参数无效」，日志是 `operator_rejected`。不写姓名、消息原文或 token。这条命令不调用 Telegram。
- 检测在链接规则上读这份名单。名单里的主机跳过邀请、短链、裸 IP、拒绝名单和信誉查询。其它主机仍删除。名单为空时和现在一样。读失败记 `runtime_failed`，仍按默认规则删除。
- 不改 `default.json`，不改验证时长、失败处置、题目、nonce 或按钮。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把名单写进现有运行时文档 | 旧 Worker 看到多出来的字段会把开关和 dry-run 一起丢掉。 |
| 放进链接检测器的 config | schema 不认识多余字段，检测器起不来。名单是每个群的运行时数据。 |
| 拒绝放行 `t.me` | 后缀匹配是检测器已经用来认邀请主机的办法。放行 `t.me` 连同子域，是群管的选择。 |
| 读失败时放行全部链接 | 存储短暂失败会把短链放进来。读失败仍删除。 |

## 后果

- `/allowhost -100 add bit.ly` 之后，这个群的 `bit.ly` 留下，`tinyurl.com` 仍删除。别的群仍删除 `bit.ly`。
- 放行 `t.me` 时，`evil.t.me` 也不再记成邀请。
- 菜单多一条 `/allowhost`，一共 99 条。
- 云额度的基础检测器名单没有改。30 天保留期没有改。
- 32 台最长主机名后来会超过一条私聊回复。`/allowhost` 由 ADR 0524 接受 `skip`，从指定台数继续列，并且不把主机名从中间切开。不写 `skip` 时仍从第一台开始。
