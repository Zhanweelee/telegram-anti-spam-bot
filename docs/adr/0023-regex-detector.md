# ADR 0023：正则检测器默认关闭，并且只接受安全子集

- 状态：已接受
- 日期：2026-11-01

## 背景

关键词检测器做的是子串包含。它表达不了字符类，也表达不了 `t.me/+` 这种邀请链接。目录规划里本来就有正则检测器。

JavaScript 的 `RegExp` 是同步的。流水线给检测器的 50 ms 超时打断不了正在执行的 `test`。一份嵌套量词可以占满免费计划 10 ms 的 CPU，并让 Telegram 重试。见 `docs/limits.md`。

## 决策

- 新包 `@tasb/detector-regex`。配置是 1 到 8 条模式，每条 1 到 64 个字符，只用 `u` 标志。
- 创建时拒绝：连续的 `+` 或 `*`、反向引用、`(?` 断言、Unicode 属性、任何 `{`、量词修饰的分组，以及分组内部再带量词。通不过 `new RegExp(source, "u")` 的也拒绝。
- 默认模式是 `t\.me/\+` 和 `加微[信xX]`。Worker 和评测共用这份列表。
- 命中只记一条证据：`kind: "feature"`，`summary` 固定为 `regex:hit`。reason 是 `regex_match`。分数是 1。不记录匹配片段，也不记录模式。模式有可能等于用户原文。
- `test` 抛错时记 `regex_failed`，字段只有 `detectorId`、`eventId`、`chatId`、`tenantId`，然后返回未命中。
- 默认规则 `regex_hint` 的 `enabled` 是 false。不改现有删除行为。某个群要打开时，把这条规则改成启用。`chats.json` 整份替换的群不会自动带上它。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 接受任意 `RegExp` | 同步匹配不会被 50 ms 超时打断，会打满 10 ms CPU。 |
| 引入 RE2 或原生模块 | 需要新依赖。Workers 跑不了原生扩展，也没有对应 ADR。 |
| 默认打开 | 误伤普通句子就会删除。和 `llm_hint` 一样，先关掉，由规则显式打开。 |

## 后果

- `{n}` 和分组上的量词写不进去。`https?://`、`t\.me/\+`、`加微[信xX]` 和 `(a|b)` 可以。
- 检查器漏过的同步正则仍可能占满 CPU。模式列表保持很短，是为了把这个窗口留小。
- 整份替换默认规则的群要自己写 `regex_hint`，否则没有这项检测。
