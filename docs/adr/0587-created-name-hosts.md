# ADR 0587：建群的人，名字只留主机名

- 状态：已接受
- 日期：2026-11-05

## 背景

普通群刚建好时，客户端把建群的人的名字画在服务消息上。名字写在 `from`。`group_chat_created` 正好是 `true` 时才会标成建群提示。见 ADR 0498。这行通常没有别的正文。短链可以只写在名字里。

把 `from` 收成正文会让普通发言者的姓名也进检测。`group_created` 默认关闭，干净的提示仍留下。超级群和频道的创建字段不能从更新里收到。这次不新建群。

## 决策

- 只在已经会标成 `asGroupCreated` 的提示上，从 `from` 的可见名字留主机名。`group_chat_created` 正好是 `true` 时读。
- `first_name` 的长度大于 0 时只读名。空白也算有名。名缺失或正好是空字符串时改读姓。用户名不读。抽出之前不截断。
- `false`、字符串、超级群创建和频道创建不读发送者。普通消息因此仍不读 `from`。
- 名字不进正文，也不改内容哈希。关键词因此不命中。本群群名不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`group_created` 仍默认关闭。8 个主机名的上限不变。不调用建群方法。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把名字整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0498。 |
| 连超级群和频道创建一起读 | 这两条不能从更新里收到。回复里的原消息不展开。 |
| 每条消息都读 `from` | 发言人的名字会跟着每条消息重复计一次。 |
| 新命令 `/createdname` | 菜单只剩一个空位。现有 `links` 已经能删短链。 |

## 后果

- 建群的人名字里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。群还在。
- 名字原文、路径和用户名不进事件，内容哈希不变。名字里的关键词不命中。
- 名的长度大于 0 时，姓和用户名不进事件。
- `example.com` 和公开的 `t.me/名字` 留着。付费帖仍不删除。见 ADR 0356。
- `false`、超级群创建和频道创建仍不读发送者。干净的提示在 `group_created` 关闭时仍留下。打开 `service_notice` 仍不删除建群提示。云额度的基础检测器名单没有改。30 天保留期没有改。
