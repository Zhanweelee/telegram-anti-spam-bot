# ADR 0012：跨群黑名单默认关闭，只放在内存里

- 状态：已接受
- 日期：2026-11-01

## 背景

P1-04 要让多个群自愿共享一份黑名单。验收是：默认关闭；打开后只共享哈希或标识，不共享原文；关闭后立即停止读取共享名单。

`docs/limits.md` 里 KV 每天只有 1,000 次写，而且是最终一致的。D1 的写预算要留给审计。白名单已经用了 60 秒缓存。如果把「这个群关了没有」放进同一份缓存，关闭后最多还要再读几十秒共享名单，验收过不了。

## 决策

- 新增端口 `BlocklistStore`。条目只有两种：`actor`（`[A-Za-z0-9_-]{1,128}`）和 `hash`（64 位小写十六进制）。schema 是 strict object，多出来的 `text` 字段会被拒绝。
- 共享范围是同一个 `tenantId`。Self-host 只有一个租户。群 A 写入的 id，群 B 只有在自己 opt-in 打开时才会读到。
- 每个群的开关默认关闭。检测器先读开关。关闭时返回未命中，并且不调用 `has`。开关不进 `PolicyStore` 的 60 秒缓存，下一条消息立刻生效。关掉开关不删除条目，其它仍然打开的群还能用。
- 内存实现放在 core，因为命令和检测器都要同一份行为，而且它没有 I/O。`adapters-memory` 再导出它。Worker 在 isolate 里放一个单例。每个租户最多 128 个打开的群、256 条条目，满了就拒绝新的写入。
- 默认规则 `shared_blocklist` 对命中执行 delete。检测器在关闭时是空操作，所以规则可以一直启用。`chats.json` 整份替换的群不会自动带上这条规则。
- 私聊命令 `/blocklist` 只给配置中的管理员。回复只说 on/off 和是否写入，不回显哈希或原文。存储抛错时回复「参数无效」，日志是 `operator_rejected`。
- 存储抛错时检测器记 `blocklist_failed` 并返回未命中。日志只有 `eventId`、`chatId`、`detectorId`。
- 证据摘要是 `actor:` 加截断后的 id，或 `hash:` 加 8 位前缀。不放消息原文。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把共享名单塞进 `PrefilterPolicy`，用现有 KV 和 60 秒缓存 | 白名单是按群的，共享名单是按租户的。缓存会让「关掉后立刻不读」做不到。每条消息读 KV 也会把读额度打在热路径上。 |
| 默认打开，而且跨租户共用一份名单 | 标识会漏到别的租户。验收要求默认关闭。 |
| 用 D1 或 KV 持久化这份名单 | 热路径不该为名单付写入。持久化留到以后，而且仍然不能把原文写进去。 |

## 后果

- isolate 重启会丢掉名单和开关，和验证、洪泛窗口一样。
- 管理员豁免和白名单仍然先于检测器。被豁免的人即使在名单上也不会被这条规则删掉。
- 满 256 条或 128 个群之后，新的写入失败，已经打开的群继续按现有名单检测。
- 不新增 npm 依赖，也不占用 KV、D1 或第二个 Cron。
