# ADR 0011：链接信誉默认不访问网络

- 状态：已接受
- 日期：2026-11-01

## 背景

P1-03 要认出短链接、裸 IP 和信誉很差的域名。`docs/limits.md` 写明免费计划每次请求只有 50 次外部子请求，热路径还要留出 Telegram 的处罚调用。每条消息都去查一次远程信誉，会把子请求预算打在检测上，超时还会占住这 10 ms 以外的等待。验收要求默认不在热路径上做远程查询，远程失败时 fail-open。

## 决策

- `link` 检测器先在本地判断：内置短链域名、调用方给出的 denylist、IPv4 主机。证据摘要只有原因和主机名，不带路径和查询串。
- `ReputationSource.lookup(host)` 是可选端口。Worker 默认不传入，因此不会发网络请求。
- 本地已经命中时，不再调用信誉源。
- 信誉源抛错或超过 `sourceTimeoutMs`（默认 20 ms，上限 40 ms）时，检测器记 `reputation_failed` 并返回未命中。日志只有 `eventId`、`chatId` 和 `detectorId`。
- 默认规则 `links` 对本地命中执行 delete。`chats.json` 整份替换的群不会自动带上这条规则。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 每条带链接的消息都请求 Safe Browsing 或类似服务 | 外部子请求要省给处罚。而且这会引入需要密钥、可能付费的第三方，超出这一项。 |
| 把每条链接放进队列再查 | 免费计划队列大约每天 3,000 条完整投递。链接检测不该占这条预算。队列适合以后单独的异步信誉，而且失败时仍然必须 fail-open。 |

## 后果

- 没配信誉源时，普通 `https://example.com/...` 不会被删。短链和裸 IP 会被删。
- 配了信誉源之后，超时和异常都放过这条消息，不把 Worker 打成 500。
- 主机名会出现在证据摘要里。路径、查询串和消息原文不会。
