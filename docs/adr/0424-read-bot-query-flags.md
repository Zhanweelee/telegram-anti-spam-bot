# ADR 0424：私聊可以查看 bot 的查询能力

- 状态：已接受
- 日期：2026-11-04

## 背景

反垃圾要知道这个 bot 能不能处理入群申请查询，以及能不能在自己没加入的群里接收访客消息。这两件事都写在 `getMe` 返回的 `User` 上：`supports_join_request_queries` 和 `supports_guest_queries`。两个字段都只在 `getMe` 返回，而且是可选布尔值。

`/who` 已经回报编号、用户名、能否入群和是否看得到全部群消息。见 ADR 0418。查询能力是同一份身份里的另外两个开关，不另开命令。

## 决策

- 私聊 `/who` 的回复在原有四行之后再加两行：能否做访客查询，能否处理入群查询。
- 缺字段写未知。`true` 写 on，`false` 写 off。其它值让整份回复变成「参数无效」，不露出已经读到的字段。
- 名字和其它用户字段仍不进回复，也不进日志。
- 只有配置里的管理员可以看。没有 token 的 Worker 不编一份身份。
- 不调用 `logOut` 或 `close`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 另开一条命令 | 这两个开关和编号、用户名来自同一次 `getMe`。再请求一次没有新信息。 |
| 缺字段写成 off | 文档把它们标成可选。没返回和明确关闭不是同一件事。 |
| 一并回报内联查询、Web App 和商业连接 | 那些开关不决定这个 bot 能不能做反垃圾。 |

## 后果

- 成功只表示 Telegram 返回了这个 token 对应 bot 的当前身份，包括这两项查询能力。
- 一次查看仍是一次 `getMe`。入群、封禁和黑名单都不变。
- 30 天保留期不动。
