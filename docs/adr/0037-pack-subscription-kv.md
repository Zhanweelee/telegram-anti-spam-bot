# ADR 0037：规则包订阅指针放进已有的 KV

- 状态：已接受
- 日期：2026-11-01

## 背景

ADR 0019 把订阅和上一份通过 schema 的规则都放在 isolate 内存里。Worker 一重启，管理员要重新 `/packs`。上一份规则每次刷新成功都会写一次。如果连同归档一起进 KV，60 秒规则缓存会让每个已订阅的群、每个 isolate 大约每分钟写一次，免费计划每天大约 1,000 次写会被打满。

## 决策

- 不新增绑定，也不改 `RuleSubscriptionStore`。配了 `POLICY_KV` 时用 `createKvRuleSubscriptionStore`。每个群一个 JSON，键前缀是 `pack`，值只有 `{ packId }`。`off` 写成 `{ "packId": null }`，因为这份 KV 封装没有删除。
- 没配 `POLICY_KV` 时仍用内存。内存每个租户最多 128 个群，满了抛 `pack_full`。KV 不扫描键，所以不执行这 128 的上限。
- 本 isolate 缓存 60 秒。同一条命令写入后立刻更新这份缓存，下一条消息就看见。其它 isolate 最多晚 60 秒。这不是 ADR 0019 拒绝过的规则缓存：规则缓存不能拿来存订阅，否则 `off` 会继续用社区规则。
- 值没变不写。坏文档读成未订阅，热路径不回写。
- 上一份成功的 `RuleSet` 仍在内存。重启后下一次成功读取 `packs.json` 再补上。包 id 暂时找不到时，订阅还在，检测回到本地规则。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 订阅和上一份规则一起进 KV | 刷新成功就会写。忙群会打满每天 1,000 次写。 |
| 一个租户一份文档 | 这个端口按群读，不需要列出全部订阅。按群一个键就不用 `list`。 |
| 写进 60 秒规则缓存 | ADR 0019 已经拒绝。关掉之后还会继续用社区规则。 |

## 后果

- 配了 `POLICY_KV` 之后，重启仍记得这个群订阅了哪一份包。上一份规则要等下一次成功读取才回来。
- 没配时行为和 ADR 0019 一样。
- 其它 isolate 最多晚 60 秒看见 `/packs off`。发出命令的那一个 isolate 立刻生效。
- 提交的 `wrangler.jsonc` 仍不写 KV id。
