# ADR 0683：群里聊天改名时只读聊天标题

- 状态：已接受
- 日期：2026-11-06

## 背景

群或超级群改名时，Android 的 `TL_messageActionChatEditTitle` 用 `replaceWithLink` 画出发送者，新名字放在 `un2`。发送者是用户时，画出全名。发送者是聊天时，画出这个聊天的标题。标题不截断。自己改名的那条不画名字。Bot 不区分是不是自己发出。

所在聊天是频道且不是超级群时，这行是 “Channel name changed to un2”。这行不画人。见 ADR 0667。新名字仍只留主机名。

Bot API 把新名字放在 `new_chat_title`。发送者是聊天时，`sender_chat` 是那个聊天，`from` 是占位用户。见 `telegram-bot-api` 的 `messageSenderChat`。

ADR 0632 在群和超级群上仍从 `from` 的全名留主机名。占位用户的名字不是这行画出的字。编号和本群相同时，通用的代发规则也不读标题。

## 决策

- 已经会标成 `asTitle` 的提示上，所在聊天不是频道，且 `sender_chat` 是对象时，只从 `sender_chat.title` 留主机名，不从 `from` 留主机名。标题不截断。用户名不读。频道、群和超级群代发都一样。编号和本群相同时也读。
- 没有 `sender_chat` 时，仍从 `from` 的全名留主机名。名和姓都去掉两端空白，名在前。空白名不挡住姓。空格不截断。
- 所在聊天是频道时仍不读发送者，也不读频道标题。新名字仍只留主机名。
- 不从 `chat.title` 另读。发送者是用户时，本群群名仍不读。
- 新群名仍只留主机名。同一条上发送聊天和本群编号不同时，通用代发先记下这个标题，新群名排在它后面。编号相同时，新群名排在前面。
- 空字符串不读。编号和本群相同时仍按已有的管理员豁免。关掉豁免后，标题里的短链会删除这条提示。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`chat_title` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不调用 `setChatTitle`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 群和超级群继续读 `from` | 占位用户的名字不在这行里。短链会删掉一条没有这个名字的提示，标题上的短链又会留下。 |
| 频道也读标题 | 频道这行不画人，也不画发送者的标题。新名字已经单独留下主机名。 |
| 用户改名也读本群群名 | 这行画的是这个人的全名，不画本群群名。 |
| 新命令 | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 群或超级群里，聊天改名时，标题里的短链、邀请或裸 IP 会留下主机名。证据只有主机名。群名本身还在。
- 本群自己改名的这条提示，默认仍因管理员豁免而留下。关掉豁免后会删。别的聊天发到这个群时不豁免。
- 占位用户的名字不再留下主机名。用户仍按全名。
- 频道改名仍不读发送者。新名字仍只留主机名。
- 标题原文、路径、用户名和新群名原文不进事件。内容哈希不变。关键词不命中标题和全名。
- 新群名里已有短链时仍留下主机名。正文里已有短链时，证据仍先记正文的主机名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 空字符串和普通消息仍不读发送者。换背景仍只读名。管理员仍豁免。干净的提示在 `chat_title` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
