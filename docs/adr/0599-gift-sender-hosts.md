# ADR 0599：送礼的人，名字只留主机名

- 状态：已接受
- 日期：2026-11-05

## 背景

有人送出普通礼物、独特礼物或升级购买时，客户端把这个人的名字画在服务消息上。名字写在 `from`。附言、收藏名和发布者用户名当时已经按原来的方式处理。见 ADR 0087 和 ADR 0324。短链可以只写在送礼的人的名字里。

把 `from` 收成正文会让普通发言者的姓名也进检测。`gift_card` 默认关闭，干净的卡片仍留下。星星数量、礼物编号和短名仍不读。空的外层对象和只有附言的对象仍不是这张卡片。

## 决策

- 只在已经会标成 `gift` 的提示上，从 `from` 的可见名字留主机名。`gift.gift`、`unique_gift.gift` 或 `gift_upgrade_sent.gift` 是对象时读。空的嵌套对象也读。几种同时出现时仍先认普通礼物，再认独特礼物，再认升级购买。
- `first_name` 的长度大于 0 时只读名。空白也算有名。名缺失或正好是空字符串时改读姓。用户名不读。抽出之前不截断。
- 附言、收藏名和发布者用户名仍按 ADR 0087 和 ADR 0324。送礼的人的名字不进正文，也不改内容哈希。关键词因此不命中这个人的名字。短名、编号、星星数量、发布者标题和本群群名不读。
- 空的外层对象、布尔值和只有附言的对象不读发送者。普通消息不读 `from`。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`gift_card` 仍默认关闭。8 个主机名的上限不变。不退回星星。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把送礼的人整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0324。 |
| 并进 `gift_card` | 打开礼物卡片的群并不一定要按名字里的短链删。星星仍不退回。 |
| 读取短名或星星数量 | 短名和星星都不是这行看得见的人名。见 ADR 0481。 |
| 新命令 `/giftname` | 菜单只剩一个空位。现有 `links` 已经能删短链。 |

## 后果

- 送礼的人，名字里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。礼物本身不变，星星不退回。
- 这个人的名字原文、路径和用户名不进事件，内容哈希不变。名字里的关键词不命中。
- 名的长度大于 0 时，姓和用户名不进事件。附言、收藏名和发布者用户名仍按原来的方式。短名、编号和星星数量仍不进事件。
- 送礼的人后来按画出的全名只留主机名。名和姓都去掉两端空白，名在前。空白名不挡住姓。用户名不进。见 ADR 0648。
- 发送者是聊天时后来只读这个聊天的标题，不读 `from`。标题不截断。用户仍按全名。见 ADR 0691。
- 独特礼物的来源正好是 `offer` 时后来不读发送者，也不读本群标题。别的聊天的标题仍由通用代发规则读取。见 ADR 0693。
- 来源是 `upgrade` 或 `gifted_upgrade` 时后来只读私聊对方的全名。群和频道不读群名。见 ADR 0694。
- `example.com` 和公开的 `t.me/名字` 留着。付费帖仍不删除。见 ADR 0356。
- 空的外层对象、布尔值、只有附言的对象和普通消息仍不读发送者。本群群名仍不读。干净的卡片在 `gift_card` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
