# ADR 0043：`/quota` 带上窗口结束时间

- 状态：已接受
- 日期：2026-11-01

## 背景

ADR 0026 的 `/quota` 给出已用次数、上限和周期名。管理员看到 `calendar_month` 或 `rolling_30d` 时，仍不知道这组次数何时恢复全量检测。

## 决策

- 额度打开时，内存计数的快照带上可选的 `resetsAt`。它是 UTC 时间，形式与 `Date.toISOString()` 相同。
- 自然月的结束时间是下一次 UTC 月初，按这次读取的时间计算。还没有计数时也带上。
- `rolling_30d` 从第一次计数起 30 天。还没有计数时不带 `resetsAt`。
- `/quota` 在状态行末尾加上 `until {resetsAt}`。中英文用同一个词。超额时基础检测器 id 仍在下一行。
- 快照没有这个字段，或字段不是合法时间时，状态行保持原样；非法时间整份快照视为没打开，回复 quota off，不回写这个值。
- 不改 ADR 0026 的默认次数、周期和基础检测器名单。查看不计数，也不把计数写进 KV 或 D1。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 只写周期名 | 管理员还是要自己算月末或 30 天。 |
| 在 core 里从周期名推算 | 30 天窗口的起点在计数器里，core 拿不到。 |
| 滚动窗口在第一次计数前也写一个预计时间 | 起点要等第一次检测。提前写会在下一次查看时对不上。 |

## 后果

- 云上打开额度后，`/quota` 状态行末尾是当前窗口的结束时间。
- 自定义的 `QuotaReader` 可以不带 `resetsAt`，回复和以前一样。
- 重启后内存计数归零。自然月的结束时间还在；30 天窗口要等下一次计数才重新出现。
