# ADR 0588：开视频聊天的人，名字只留主机名

- 状态：已接受
- 日期：2026-11-05

## 背景

视频聊天开始、结束或预约时，客户端把这个人的名字画在服务消息上。名字写在 `from`。时长和开始时间当时留在事件外面。见 ADR 0475。邀请名单仍按可见名字成为正文。见 ADR 0119。开始、结束和预约通常没有别的正文。短链可以只写在操作的人的名字里。

把 `from` 收成正文会让普通发言者的姓名也进检测。`call_notice` 默认关闭，干净的提示仍留下。这次不改时长，也不改开始时间。只有邀请名单时仍不读邀请者。

## 决策

- 只在已经会标成 `call` 的提示上，从 `from` 的可见名字留主机名。`video_chat_started` 是对象时读。结束的时长是有限且不小于 0 的数字时读，0 也读。预约的开始时间同样。几种同时出现时仍先认开始，再认结束，再认预约。
- `first_name` 的长度大于 0 时只读名。空白也算有名。名缺失或正好是空字符串时改读姓。用户名不读。抽出之前不截断。
- 空的结束或预约、负数、非有限数字、字符串，以及只有邀请名单的消息不读发送者。普通消息因此仍不读 `from`。
- 名字不进正文，也不改内容哈希。关键词因此不命中。时长和开始时间不读。邀请名单仍按原来的规则。本群群名不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`call_notice` 仍默认关闭。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把名字整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0119。 |
| 把时长或开始时间收成正文 | 时长不是广告。见 ADR 0475。 |
| 只有邀请名单时也读邀请者 | 那不是开始、结束或预约。邀请者的姓名仍留在外面。 |
| 新命令 `/callname` | 菜单只剩一个空位。现有 `links` 已经能删短链。 |

## 后果

- 开视频聊天、结束或预约的人，名字里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。时长和开始时间不变。
- 名字原文、路径和用户名不进事件，内容哈希不变。名字里的关键词不命中。
- 名的长度大于 0 时，姓和用户名不进事件。时长和开始时间不进事件。
- `example.com` 和公开的 `t.me/名字` 留着。付费帖仍不删除。见 ADR 0356。
- 空的结束或预约、以及只有邀请名单时，这条通话规则仍不读发送者。干净的提示在 `call_notice` 关闭时仍留下。邀请名单仍按 ADR 0119。邀请名单里至少有一个用户对象时，邀请者后来由 ADR 0596 只留下主机名。名字本身仍不进事件。云额度的基础检测器名单没有改。30 天保留期没有改。
