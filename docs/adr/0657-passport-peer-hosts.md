# ADR 0657：护照提示上画出的私聊对方只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

用户把 Telegram Passport 交给 bot 时，Android 的 `TL_messageActionSecureValuesSent` 用对话对方的 `UserObject.getFirstName` 拼进 “%1$s received the following documents: %2$s”。名的长度大于 0 就用名，空白也算有名。名缺失或正好是空字符串时才改用姓。这里不按短名截断，空格后面仍画。用户名不在这行里。

后面的证件种类是固定说法，例如电话、邮箱、护照。加密内容、电话号码和邮箱地址不画进这句。

Bot API 把这份资料放在 `passport_data`。布尔值不是对象。私聊对象上的 `first_name` 和 `last_name` 就是对话对方。群里的对话对方不是一个用户，这行名字是空的，群名不画。`data`、`phone_number`、`email` 和 `credentials` 不出现在这行里。

短链可以只写在这个名字上。把整段收成正文会改变内容哈希，关键词也会命中名字。证件号和邮箱不进事件。

## 决策

- `passport_data` 是对象，且 `chat.type` 正好是 `private` 时，从私聊对方会画出来的名字留主机名。空对象也读。`first_name` 的长度大于 0 时用名，不读姓。名缺失或正好是空字符串，且 `last_name` 是非空字符串时，改用姓。空白名挡住姓。
- 主机名仍进消息已有的 `hosts`。邀请仍进 `invites`。正文里已有短链时，证据仍先记正文的主机名。名字不进正文，也不改内容哈希。关键词因此不命中。
- 用户名、私聊对象上的 `title`、发言人 `from`、群名、群对象上的 `first_name`、`data`、`phone_number`、`email` 和 `credentials` 不读。布尔值的 `passport_data` 不读。没有这个对象时，私聊对方的名字仍不读。
- 不解密证件。不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。短链仍走已有的 `links`。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 每条私聊都读对方名字 | 普通私聊的名字仍留在事件外面。只有护照这行把它画出来。 |
| 读取电话、邮箱和加密内容 | 这行服务文字不画这些字段。证件号不进事件。 |
| 群里也读群名 | 群里这行没有用户名。群名不画。 |
| 新命令 `/passport` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 护照这行里的短链、邀请或裸 IP 会删除这条消息。证据只有主机名。证件不解密，电话和邮箱不进事件。
- 名字原文、路径和用户名不进事件。内容哈希不变。关键词不命中名字。
- 空白名挡住姓。空格后面的网址仍读。群里不读。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 没有护照对象时不读私聊对方。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
