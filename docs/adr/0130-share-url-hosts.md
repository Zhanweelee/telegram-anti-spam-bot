# ADR 0130：分享链接里的 url 只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

`https://t.me/share/url`、`https://t.me/iv` 和 `tg://msg_url` 把真正要打开的地址放在 `url` 参数里。外层主机名是 `t.me`。`/share/url` 和 `/iv` 不是邀请路径，链接规则看到的是 `t.me`，短链、裸 IP 和邀请可以藏在参数里。

`text` 是分享时附带的句子。`rhash` 是即时预览的校验值。证据里只该有主机名。

再套一层分享链接仍停在外层。公开用户名 `t.me/durov?url=` 不是分享链接。

## 决策

- `t.me`、`telegram.me`、`telegram.dog` 及其子域上的 `/share/url` 和 `/iv`，以及 `tg://msg_url` 和 `tg:msg_url`，从 `url` 抽出一条链接。主机名和邀请判断与普通链接相同。
- 同一条链接的 `text` 里再抽出网址，只留主机名或邀请。`text` 不进入 `message.text`，也不参与关键词。
- 只拆一层。里层如果还是分享链接，不再往下拆。
- 其它网站路径里的 `url` 不读。`t.me/名字?url=` 不读。
- 路径、邀请码和 `rhash` 不进证据，也不进隐藏链接的事件字段。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 分享链接整段都不读 | 短链和邀请可以只写在 `url` 上。 |
| 任何网址的 `url` 参数都读 | 普通网站的查询参数不是 Telegram 分享。 |
| 一直往下拆 | 第二层百分号编码也停住。一层够拦住直接转发的分享链接。 |

## 后果

- 分享或即时预览的 `url` 是裸 IP、默认短链或邀请时，现有链接规则删除这条消息。证据仍只有主机名。
- `example.com` 留着。`t.me/durov?url=` 和其它网站的 `url` 参数仍按外层主机名判断。
- 按钮上的 `text` 里的关键词留着。正文就是这条链接时，链接原文仍在 `message.text`。
- 私聊预填 `tg://msg` 的 `text` 后来由 ADR 0131 按普通链接处理。路径和收件人用户名仍不进证据。
