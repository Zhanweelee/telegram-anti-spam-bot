# ADR 0303：带协议的标签字留在草稿主机名

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 的单词边界只认 ASCII 字母、数字和下划线。汉字可以留在带协议的主机名里。`http://bit.ly一/…`、`http://bit.ly一.evil.com/…`、`http://bit.ly.一/…` 和 `http://bit.ly一:80/…` 各是一条链接。点开的主机名不是 `bit.ly`。`http://t.co一/…`、`http://www.bit.ly一/…`、`http://203.0.113.10一/…` 和 `http://t.me一/+…` 也是。全角逗号同样留在这条链接里。

`@`、`#` 和空格让 Android 退回上一个单词，单独打开 `http://bit.ly`。`http://203.0.113.10一@evil.com/…` 单独打开这条裸 IP。没有协议的 `bit.ly一/…` 和 `www.bit.ly一/…` 也在这个字前面结束。见 ADR 0213。

隐藏的分享 `text` 把 `http://bit.ly.一/…` 收成 `bit.ly`。点号后面的标签字被当成这一段的结束。空格又留在下一段，`http://bit.ly一 evil.com/…` 的主机名变成带这个字的编码，不再是 `bit.ly`。`www.bit.ly一/…` 也把这个字留在主机名里。

## 决策

- 分享 `text`、私聊预填 `tg://msg` 的 `text` 和用户名草稿的 `text`，在带协议的主机名后面遇到点号，点号后是 Android 收进标签的字时，不在这个点号前切开。
- 这段网址后面如果还有普通空格，空格仍交给同一段。`@` 和 `#` 仍按原来的规则退回上一个单词。
- 没有协议的主机名和 `www.` 在这个字前面结束。
- 不改带协议网址的整段匹配。闭合分享链接里的网址不走这道切开。
- 证据只留主机名。路径和邀请码不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 任何点号后面的字都留在主机名里 | 点号后面不是标签字时，后面的短链会留在这一条里。 |
| 带协议的网址也在这个字前面切开 | `http://bit.ly一/…` 会删掉 Android 留成一条链接的消息。 |
| 改掉带协议网址的整段匹配 | 其它已经收进同一条的字符会跟着拆开。 |

## 后果

- `t.me/share/url?text=http://bit.ly一/…`、`https://t.co一?…`、`http://bit.ly一.evil.com/…`、`http://bit.ly.一/…`、`http://bit.ly一:80/…`、`http://bit.ly一:80@evil.com/…`、`http://www.bit.ly一/…`、`http://203.0.113.10一/…`、`http://t.me一/+…` 和 `http://bit.ly，/…` 留着。`http://bit.ly一/http://t.co/…` 留着。
- `http://bit.ly一@evil.com/…`、`https://t.co一@evil.com/…`、`http://bit.ly一#…`、`http://bit.ly一 evil.com/…` 和 `http://bit.ly一. evil.com/…` 按短链删除。证据是 `bit.ly`。路径不进证据。
- `http://203.0.113.10一@evil.com/…` 按裸 IP 删除。没有协议的 `bit.ly一/…` 和 `www.bit.ly一/…` 按短链删除。`https://t.me/+…` 仍按邀请删除。邀请码不进证据。
- 空格后面的 `http://t.co/…` 仍删除。证据是 `t.co`。
- 增补平面里的标签字仍可能把带协议的短链单独打开。见 ADR 0214。
- 连字符后面的增补字仍可能把前面的短链单独打开。`http://bit.ly-𠀀` 留着。见 ADR 0304。
