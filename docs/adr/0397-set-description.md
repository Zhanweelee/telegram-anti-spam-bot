# ADR 0397：私聊可以修改一个聊天的简介

- 状态：已接受
- 日期：2026-11-04

## 背景

管理员想改一个群、超级群或频道的简介。官方有一次只改简介的调用。

`setChatDescription` 修改一个群、超级群或频道的简介。bot 必须是这个聊天的管理员，并有相应的管理权限。成功时返回 True。

参数是 `chat_id` 和可选的 `description`。`description` 长度 0 到 255 个字符。文档没有写省略这个字段和空字符串的差别。

标题和头像是另外的调用。没有 token 时不能把内存记录回复成已经修改。简介本身不能进回复或日志。

## 决策

- 私聊命令 `/desc <chatId> [description]`。群 id 匹配 `^-?\d{1,20}$`。简介是其余参数按空白折叠后拼起来的字符串。不写简介时送出空字符串。长度超过 255 时不发出请求。群聊里的同样文本不执行。
- 正数编号也原样送出。不能改简介时，由 Telegram 拒绝。
- 配置中的管理员可以操作任意群。接入目录里的人只能操作自己的群。
- 调用 `ModerationPort.setDescription`。适配器调用 `setChatDescription`，始终带 `chat_id` 和 `description`。
- 回复不重复简介。有简介时写明已请求修改，空字符串时写明已请求清掉。两种回复都写明标题和头像还在。
- 没有 token、没有这个方法，编号或简介不合法，或调用失败时回复「参数无效」。日志只写 `operator_rejected`，带上 eventId、chatId 和命令名。不写异常文本、token、简介或原文。
- 没有 token 的 Worker 不把内存记录回复成已经修改。
- 不调用 `setChatTitle`、`setChatPhoto` 或 `getChat`。不修改黑名单、白名单、封禁或禁言。不读取消息正文。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 省略 `description` 来清掉简介 | 文档没有写省略和空字符串的差别。空字符串的长度是 0，落在 0 到 255 里。 |
| 回复里重复新简介 | 简介可能是管理员刚粘贴的原文。回复只确认这一次请求。 |
| 先调用 `getChat` 读出现有简介 | 多一次子请求，还会把标题和邀请链接读回来。 |

## 后果

- 成功只表示 Telegram 接受了这一次 `setChatDescription`。不是群、超级群或频道，或缺少权限时，回复是「参数无效」。
- 标题和头像还在。
- 一次修改是一次 Telegram 子请求。封禁、禁言和黑名单都不变。
- 30 天保留期不动。
