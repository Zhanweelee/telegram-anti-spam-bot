# ADR 0175：没有协议的点分 IPv4 也留下

- 状态：已接受
- 日期：2026-11-02

## 背景

Android `LinkifyPort.WEB_URL` 会打开没有协议的点分 IPv4。第一段不能是 `0`，每一段都按它的数字写法匹配，末尾不能再粘着字母或数字。`203.0.113.142/…`、`1.2.3.4` 和放不下的标签后面的 `203.0.113.142` 都会打开。`0.0.0.0`、`1.2.3.00` 和 `256.1.1.1` 不会。后面还有域名标签时，整段是域名，不是裸 IP。写在路径里的地址仍属于前一个网址。写在 `tg:` 链接里面的地址仍属于那一条链接。

## 决策

- 裸域名同一处增加 Android 的点分 IPv4。没有协议时，它和裸域名一样可以作为一段网址。
- 第一段用 Android 的写法，不收单独的 `0`。中间两段可以是 `0`。最后一段可以是一位数字。`%HH` 不在这里展开。
- 裸域名优先。`203.0.113.142.example.com` 仍是一个域名。
- 落在 `tg:` 链接内部的这段地址不单独抽主机名。`text`、`url` 和代理参数仍按原来的规则读。
- 每段仍走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。前导零按 WHATWG 收成十进制。
- 已经写在 `text_link`、按钮或其它结构化字段里的地址整段打开。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 只认带 `http://` 的 IP | `203.0.113.142` 和放不下的标签后面的同一地址点得开。 |
| 四段数字都从 0 收到 255 | `0.0.0.0` 和 `1.2.3.00` 在 Android 里不是链接。 |
| `tg:` 链接里面的 IP 也切开 | `to=198.51.100.20` 属于这一条 `tg:` 链接，不是单独打开的地址。 |

## 后果

- `203.0.113.142/…`、`1.2.3.4`，以及 60 个 `a` 再接 `-203.0.113.142/…`，按现有裸 IP 规则删除。证据仍只有主机名。
- `010.0.0.1` 按 `8.0.0.1` 删除。原文里的前导零不进证据。
- `0.0.0.0`、`1.2.3.00`、`203.0.113.142.example.com` 和 `v203.0.113.142` 留着。放得下的标签仍是一个主机名。路径里的 IP 留着。
- `tg://msg?…&to=198.51.100.20` 不因为这个参数删除。`https://t.me/+…` 仍按邀请删除。路径不进证据。
