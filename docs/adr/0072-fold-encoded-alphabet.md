# ADR 0072：比较前把字母 %HH 收成字符

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0071 把 `%2B` 收成加号。邀请码里的字母仍可以写成 `%45`。`https://t.me/+OFF%45…` 能解析，路径仍是 `/+OFF%45…`，邀请正则认不出百分号。没有协议的 `b%69t.ly` 会被 `%` 拆开，短链名单对不上。带协议的 `https://b%69t.ly` 已经由 URL 解析器收成 `bit.ly`。

## 决策

- 新增 `foldEncodedAlphabet`。它只把一层 `%HH` 收成字母、数字、连字符或下划线。
- 链接检测在抽主机名前调用它，顺序在 `foldEncodedSeparators` 之后。`hostFromUrl` 在 `new URL` 之前也调用它。
- `%20`、`%2E`、`%00` 和 `%25` 不在这组字符里，仍原样留下。因此 `%2545` 和 `b%2569t.ly` 仍留下。
- 只影响这次比较。正文和哈希不变。证据仍只留主机名。
- `example%41.com` 仍是普通域名。`bit%2Dly` 收成 `bit-ly`，仍不是短链。邀请码里的 `%2E` 先收成点，路径因此对不上邀请正则。
- 关键词和正则仍只用 `foldMatchText`。
- 不改 ADR 0026 的基础检测器名单。不引入同形字库。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 只改邀请路径 | 没有协议的 `b%69t.ly` 仍被拆开，短链名单对不上。 |
| 整段 `decodeURIComponent` | `%20` 和 `%2E` 会一起展开。这和 ADR 0067 的边界冲突。 |
| 放进关键词折叠 | 这些字节不是格式字符。关键词不该因为 `%45` 改变比较。 |

## 后果

- `b%69t.ly` 会记成短链。`t.me/+OFF%45…`、`joinchat` 里的 `%65` 和按钮上的 `https://t.me/+OFF%45…` 会记成邀请。
- `example%41.com`、`bit%2Dly`、`t.me/+OFF%2E…`、`b%2569t.ly` 和 `t.me/+OFF%2545…` 仍放过。
- 邀请码不进事件。直接调用 `extractHosts` 的代码仍扫描原字符串。
- `%25HH` 后来由 ADR 0073 再收一层，并且只收字母表里的字节。`%252E` 和第三层仍留下。
