# ADR 0465：每个群可以决定验证失败后怎么处理

- 状态：已接受
- 日期：2026-11-04

## 背景

ADR 0009 让验证到期后删掉按钮并写下 `captcha_expired`，不解除限制，也不把人移出。`until_date` 到点后，这个人可以发言。ADR 0464 让群管缩短这段等待。时间变短之后，没点按钮的人仍会留下。

## 决策

- `RuntimeStore` 增加 `getCaptchaFail`、`setCaptchaFail`、`clearCaptchaFail`。一个群一个处置：`kick` 或 `ban`。没有记录表示留下。
- 私聊 `/verifyfail <chatId>` 只读。`/verifyfail <chatId> kick` 到期后移出。`ban` 封禁。`stay` 或 `reset` 回到留下，并删掉记录。
- 定时清理和过期后点按钮读同一份记录。点对仍只放行，不移出，也不封禁。
- 移出走现有的 `kickActor`。封禁走现有的 `banActor`。不改这两条命令自己的规则。
- 内存最多 256 个群，和验证时长、禁言、重复、洪泛、关键词、开关各用一份名额。已有的群可以改。新群放不下时回复「参数无效」，日志是 `captcha_fail_full`。
- 配了 `POLICY_KV` 时写在 `runtime-captcha-fail` 键。原来的运行时文档、验证时长键和其它运行时键都不改。坏文档读成留下。每个 isolate 缓存 60 秒。相同的值不写。
- 群聊里的同样文本不执行。接入目录里的人只能改自己的群。读或写失败回复「参数无效」，日志是 `operator_rejected`。不写姓名、消息原文或 token。这条命令不调用 Telegram。
- 到期时先读这份记录。读失败记 `runtime_failed`，成员留下，挑战仍清掉。移出或封禁失败记 `captcha_expire_action_failed`，不写异常文本，挑战仍清掉。
- 不改 `default.json`，不改验证时长、题目、nonce 或按钮。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把处置写进现有运行时文档 | 旧 Worker 看到多出来的字段会把开关和 dry-run 一起丢掉。 |
| 默认改成移出 | 现在靠 `until_date` 放行的群会开始把人移出。默认要另一次决定。 |
| 只在定时清理时移出 | 过期后点按钮也会清掉挑战。两条路径不一致时，点晚的人会留下。 |
| 点错按钮就移出 | 点错现在只提示正确得数。那是另一件事。 |

## 后果

- `/verifyfail -100 kick` 之后，这个群里没在时限内点对的人会被移出。别的群仍留下。
- `/verifyfail -100 ban` 之后，同一种人会被封禁。
- 菜单多一条 `/verifyfail`，一共 98 条。
- 云额度的基础检测器名单没有改。30 天保留期没有改。
