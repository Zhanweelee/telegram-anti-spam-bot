# ADR 0626：改名话题的人画出的全名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

有人改论坛话题的名字，或只换图标时，Android 的 `MessageObject` 在 `TL_messageActionTopicEdit` 上用 `ContactsController.formatName` 把这个人画进这行服务文字。这和 `UserObject.getUserName` 是同一种全名。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。

Bot API 把这行放在 `forum_topic_edited`。名字长度大于 0，或 `icon_custom_emoji_id` 是字符串时，这条提示成立。见 ADR 0605。当时名的长度大于 0 就丢掉姓。关掉、重开、隐藏和重新显示已经按全名只留主机名。见 ADR 0625。

新建话题这行不画这个人。同时出现时仍先认新建，姓仍不读。

短链可以只写在姓上。把整段收成正文会改变内容哈希，关键词也会命中名字。

## 决策

- 只在已经会标成 `topicNotice: "edited"` 的提示上，从 `from` 会画出来的全名留主机名。`forum_topic_edited.name` 长度大于 0 时读。空白也算有文字。否则 `icon_custom_emoji_id` 是字符串时读，空字符串也算。
- 名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读。空格不截断。用户名不读。
- 全名不进正文，也不改内容哈希。关键词因此不命中。话题名仍按 ADR 0088 成为正文。已有别的正文时仍留在 `topicName`。话题名里已有短链时，证据仍先记那段名字的主机名。正文里已有短链时，证据仍先记正文的主机名。图标颜色和自定义表情编号不读。本群群名不读。
- `topicNotice: "created"` 仍按 ADR 0605 只读名。空白名仍挡住姓。同时出现时仍先认新建。空的新建名字仍落到改名。空对象和布尔值不读发送者。普通消息不读 `from`。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`topic_notice` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不调用 `editForumTopic`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续只读名 | 客户端把姓画在同一行里。姓上的短链会留在提示里。 |
| 把名字整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0496。 |
| 新建也改成全名 | 新建这行不画这个人。姓上的短链并没有出现在那一行。 |
| 每条服务提示的人都改成全名 | 助推这行用的是名。付款成功这行也只读名。见 ADR 0583 与 ADR 0618。 |
| 新命令 `/topicname` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 改名或只换图标的人，全名里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。话题还在。
- 全名原文、路径和用户名不进事件。内容哈希不变。关键词不命中全名。
- 空白名不挡住姓。空格后面的网址仍读。话题名仍按原来的正文。
- 话题名或正文里已有短链时，证据仍先记那一边的主机名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 新建仍只读名。同时出现时仍先认新建，姓仍不读。空对象、布尔值和普通消息仍不读发送者。管理员仍豁免。干净的话题名在 `topic_notice` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
