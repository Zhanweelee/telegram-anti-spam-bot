# ADR 0460：每个群可以改洪泛窗口

- 状态：已接受
- 日期：2026-11-04

## 背景

ADR 0010 把洪泛固定成 10 秒 5 条。云上的群管没有检测器配置。安静的群会漏掉短时刷屏，忙的群会把正常对话删掉。重复窗口仍是 60 秒 3 条，这一轮不动它。

## 决策

- `RuntimeStore` 增加 `getFloodPolicy`、`setFloodPolicy`、`clearFloodPolicy`。一个群一份 `{ threshold, windowSeconds }`。
- 条数是 2 到 32 的整数。秒数是 1 到 300 的整数。32 对齐窗口里每个 key 最多记住的时间戳。1 条会把每条消息都删掉，所以不接受。
- 没设置时仍是 10 秒 5 条。写成 5 和 10，或 `reset`，都删掉记录。
- 私聊 `/flood <chatId>` 只读，回复当前条数和秒数。`/flood <chatId> <count>` 只改条数，秒数保持现状。`/flood <chatId> <count> <seconds>` 两个都改。
- 内存最多 256 个群。已有的群可以改。新群放不下时回复「参数无效」，日志是 `flood_policy_full`。
- 配了 `POLICY_KV` 时写在 `runtime-flood` 键。原来的运行时文档、动作键和上报键都不改。坏文档读成没设置。每个 isolate 缓存 60 秒。相同的值不写。
- 群聊里的同样文本不执行。接入目录里的人只能改自己的群。读或写失败回复「参数无效」，日志是 `operator_rejected`。不写姓名、消息原文或 token。这条命令不调用 Telegram。
- 检测在创建 `flood` 检测器之前读这份记录。读失败时记 `runtime_failed`，按 10 秒 5 条继续。`repeat` 仍是 60 秒 3 条。
- 不改 `default.json`，不改洪泛计数的存放位置。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把窗口写进现有运行时文档 | 旧 Worker 看到多出来的字段会把开关和 dry-run 一起丢掉。 |
| 用 KV 记每条消息的时间戳 | ADR 0010 已经拒绝。写预算不够，而且同一 key 一秒只能写一次。 |
| 把默认改成别的数字 | 现在按 5 条删除的群会被另一套阈值重新计算。默认要另一次决定。 |
| 同一条命令也改 `repeat` | 重复是另一份窗口。先让群管能改最常碰到的洪泛。 |
| 允许 1 条 | 每条消息都会命中删除。 |

## 后果

- `/flood -100 2` 之后，这个群同一个人 10 秒内的第 2 条消息按洪泛删除。别的群仍是 5 条。
- 菜单多一条 `/flood`，一共 93 条。
- 云额度的基础检测器名单没有改。30 天保留期没有改。
