# ADR 0342：同一条入群再投递时重发验证按钮

- 状态：已接受
- 日期：2026-11-04

## 背景

入群验证先限制成员、写入挑战，再发按钮。流水线在执行动作之前占住审计。同一条入群再投递时，`captcha` 是 `skipped` / `duplicate`，Worker 不再发按钮。

第一次处理如果已经限制了成员，却在 `sendMessage` 之前停住，成员会一直不能发言，群里也没有按钮。挑战还在，nonce 也还是这一份。

第一次发送已经成功时，再投递仍会再发一次同一份 nonce。发送失败不能解除限制，因为第一次按钮可能已经在群里，或者成员仍需要这份挑战。

## 决策

- 这一次入群自己执行了 `captcha`，或者这次动作因为 `duplicate` 被跳过，并且挑战还在，就再发一次按钮。nonce 用存储里的那一份。
- 自己这次执行的发送失败时，解除限制并删掉挑战，再记 `captcha_prompt_failed`。日志只有事件 id 和群 id。
- 重复投递这次发送失败时，只记同一条日志。不解除限制，不删除挑战。
- dry-run 的 `dry_run` 不重发。没有 `captcha` 动作的重复投递不读挑战。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 重复投递一律不发 | 第一次停在发按钮之前时，成员没有按钮。 |
| 重发失败也解除限制 | 第一次按钮可能已经发出。第二次失败会把还能用的挑战删掉。 |
| 记下按钮已经发出 | 要多一次存储写入。挑战还在就可以用同一份 nonce 再发。 |

## 后果

- 同一条入群再投递、挑战还在时，群里会再出现一次同一份 nonce 的按钮。
- 重发失败时成员保持原来的限制，下一轮投递还可以再发。
- 第一次就发不出去时，仍解除限制并删掉挑战。
- 另一个 isolate 上的重试看不到这份内存挑战，行为与现在的内存验证相同。
- 30 天保留期不动。
