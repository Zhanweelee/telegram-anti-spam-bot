# ADR 0151：联系人卡片的 URL 只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

分享的联系人可以带一段 vCard。Android 在对方不是 Telegram 用户时，把这段 vCard 打开成联系人卡片。属性名正好是 `URL` 的行会列出来，点一下就用浏览器打开。没有 `http` 开头时，客户端会补上 `http://`。

电话、邮箱和备注也会列在卡片上。电话去拨号，邮箱走 `mailto:`，备注只复制。它们不是要打开的网址。

外层消息没有这段 URL。短链、裸 IP 和邀请可以只写在 `URL` 行里。

## 决策

- 从 `contact.vcard` 里属性名正好是 `url` 的行抽出值。大小写不限。`URL;TYPE=...` 也算。
- 值用 `QUOTED-PRINTABLE` 时先解开，再按普通链接取主机名。没有 `http` 开头时补上 `http://`。
- 折行（下一行以空格或制表符开头，或 quoted-printable 以 `=` 结尾）先拼回去。
- 这个主机名走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。最多 8 个。
- 电话、姓名、邮箱、备注、`X-URL`、`item1.URL` 和路径不进证据。vCard 原文不进入正文，也不参与关键词。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 整段 vCard 当正文扫 | 电话和姓名会进事件，和「原文默认不落盘」冲突。 |
| 连邮箱和备注一起读 | 邮箱打开的是邮件，备注只复制，不是浏览器。 |
| 只认大写 `URL` | vCard 的属性名不区分大小写。 |

## 后果

- `URL` 是裸 IP、短链或邀请时，现有链接规则删除这条消息。证据仍只有主机名。
- 电话、邮箱、备注和其它属性留着。
- 再套一层分享链接仍停在外层。路径不进证据。
- 卡片上看得见的名字后来由 ADR 0609 只留下主机名。名字本身仍不进事件。`URL` 行的主机名仍排在前面。电话、邮箱和备注仍不读。
- 气泡副标题里的公司名后来由 ADR 0613 只留下主机名。公司名本身仍不进事件。电话、邮箱和备注仍不读。
- 没有姓名时，标题上的原始电话后来由 ADR 0614 只留下主机名。`URL` 行的主机名仍排在前面。
- 副标题里会原样画出的电话和邮箱后来由 ADR 0615 只留下主机名。`URL` 行的主机名仍排在前面。
