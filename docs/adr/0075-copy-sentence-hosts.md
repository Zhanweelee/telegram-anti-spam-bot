# ADR 0075：复制句子里的网址只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0055 只在 `copy_text.text` 整段能解析成一条网址时留下主机名。垃圾消息把短链或邀请夹在一句口令里，整段解析失败，链接规则看不到。把整句并进正文会改变 `textSha256`，路径和口令也会进事件。

## 决策

- 从 `copy_text.text` 里抽出和链接检测相同形状的片段：带 `http` 或 `https` 的网址、`www.` 开头的网址，以及裸主机名。
- 句末的 `)`、`,`、`.`、`;`、`!`、`?` 先去掉。没有协议的片段补上 `http://`，再走 `hostFromUrl`。长度、折叠、邀请判断和 8 个主机名、8 个邀请的上限都不变。
- 整段就是一条网址时，抽出的仍是这一条，行为和 ADR 0055 相同。
- 句子本身不进入 `message.text`，也不参与内容哈希。路径、查询和邀请码不进事件。
- `callback_data` 和回复键盘仍不读。
- 不新增检测器。默认规则 `links` 仍只删除短链、裸 IP、邀请和黑名单。普通网址保留。
- 不改 ADR 0026 的基础检测器名单。不引入同形字库。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把复制句子并进正文 | 原文会进事件，内容哈希也会变。ADR 0055 拒绝的就是这个。 |
| 只抽出已知短链 | 普通域名会被漏记。现有规则已经会放过普通域名。 |
| 连 `callback_data` 一起扫描 | 回调数据不是打开的网址。ADR 0053 已经把它留在事件外面。 |

## 后果

- 句子里的 `https://bit.ly/…` 会走现有短链删除。`https://t.me/+…` 和 `https://t.me/%2B…` 只留下 `t.me`，并记成邀请。
- 句子里的普通域名仍保留。句子、路径、查询和邀请码不进事件。
- 没有更前面的正文时，按钮上看得见的字仍是正文。复制句子不并进去。
- `callback_data` 里的网址仍不进事件。回复键盘仍不读。
