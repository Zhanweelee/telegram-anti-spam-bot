# ADR 0526：私聊可以接着看后面的豁免号

- 状态：已接受
- 日期：2026-11-05

## 背景

白名单最多 200 个 id，命令只接受最多 20 位的数字。200 个 20 位 id 大约 4200 字。`/whitelist` 放不下时留下前面的 id，末尾写 `还有 N 个`。后面的 id 仍免检，回复里只剩个数。`remove` 要先知道 id。

## 决策

- `/whitelist <chatId> [add|remove <actorId>|skip <count>]`。
- `count` 是 0 到 99999 的整数，不允许前导零。不写 `skip` 或 `count` 为 0 时，回复与原来相同。
- `count` 大于 0 时，先按存储顺序跳过前面的 `count` 个 id，再从下一个 id 开始列。放不下时仍保留完整 id，末尾写 `还有 N 个`。`N` 只数这一页没列出的 id。
- 跳过的个数已经不少于名单人数，或空名单写了大于 0 的 `count` 时，回复「参数无效」。缺数字、数字不合法也是「参数无效」。多出来的词回复用法。
- `add` 和 `remove` 不变。没有这个群权限时仍回复「没有权限」，不读名单。
- 不新增命令。菜单仍是 99 条。`/whitelist` 的菜单描述改为带上 `skip`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 在 `还有 N 个` 后面写下一页的命令 | 现有回复用这一行解析。下一页的起点就是已经看过的人数。 |
| 把上限降到一页放得下的个数 | 短 id 可以放进 200 个。降低上限会丢掉已经允许的名单。 |
| 只给全局管理员 | 只接入一个群的人用 `skip 0` 仍应看到原来的名单。 |

## 后果

- 200 个 20 位 id 时，`/whitelist -100 skip 164` 能看到后面的豁免号。不写 `skip` 时第一页不变。
- 菜单描述变长之后，`/commands` 第一页停在 `keyword`，末尾是 `+5`。`/commands skip 94` 从 `repeat` 继续。
- 已经设过命令菜单的部署，要再执行一次设置命令，菜单描述才会带上 `skip`。
- 没列出来的 id 仍在名单里。上限仍是 200。30 天保留期没有改。
