# ADR 0179：Android 留在标签里的空白仍属于这一段

- 状态：已接受
- 日期：2026-11-02

## 背景

Android 的标签类收进 U+1680、U+205F 和 U+FEFF。它们出现在路径、问号或带协议的标签里时，后面的网址不再单独打开。`http://example.com/` 加 U+1680 再接 `http://bit.ly/…`、`http://example.com` 加 U+1680 再接 `http://bit.ly/…`，以及 `http://bit.ly` 加 U+1680 再接 `foo`，都是一条链接。裸域名和 `www.` 不用这套放松标签，`example.com` 加 U+1680 再接 `http://bit.ly/…` 会再打开短链。不换行空格 U+00A0 会停住。夹在 `bit` 和 `.ly` 中间的 U+1680 仍由整段折叠收成 `bit.ly`。

## 决策

- U+1680、U+205F 和 U+FEFF 留在路径、问号和带协议的标签里。这段里面的另一个主机名不另记。
- 裸域名和 `www.` 仍在这三个字符前结束。后面的网址单独打开。
- U+00A0、U+2000–U+200A、U+2028、U+2029、U+202F 和 U+3000 仍结束这一段。
- 整段折叠仍去掉这三个字符，所以 `bit` 加 U+1680 再接 `.ly` 仍按短链删除。
- 证据只留主机名。只拆一层。最多 8 个。不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 这三个字符一律切开 | `http://example.com/` 加 U+1680 再接短链，会删掉 Android 留成一条普通链接的消息。 |
| 裸域名也把它们收进标签 | `example.com` 加 U+1680 再接 `http://bit.ly` 会漏掉后面打开的短链。 |
| 整段折叠也不再去掉它们 | `bit` 加 U+1680 再接 `.ly` 就不再按短链删除。 |

## 后果

- `http://example.com/` 加 U+1680、问号加 U+205F、裸路径加 U+FEFF，后面再接 `http://bit.ly/…`，都留着。
- `http://example.com` 加 U+1680 再接 `http://bit.ly/…`，以及 `http://bit.ly` 加 U+1680 再接 `foo`，留着。
- `example.com` 加 U+1680 再接 `http://bit.ly/…` 仍按短链删除。
- `http://example.com/` 加 U+00A0 再接 `http://bit.ly/…` 仍按短链删除。
- `http://bit` 加 U+1680 再接 `.ly/…` 仍按短链删除。证据只有 `bit.ly`。路径不进证据。
- Android 留在标签上的其它字符仍属于这一段主机名。见 ADR 0180。
