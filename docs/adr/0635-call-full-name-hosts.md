# ADR 0635：开始或结束视频聊天的人画出的全名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

视频聊天开始或结束时，Android 的 `MessageObject` 在 `TL_messageActionGroupCall` 上用 `replaceWithLink` 把这个人画进这行服务文字。这就是 `UserObject.getUserName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。时长不是 0 是结束，时长是 0 是开始。群和超级群里，别人开始或结束才画这个人。自己开始时这行不画名字。频道这行不画这个人。

`TL_messageActionGroupCallScheduled` 只画开始时间，不画人。

Bot API 把开始放在 `video_chat_started`，把结束放在 `video_chat_ended.duration`，把预约放在 `video_chat_scheduled.start_date`。见 ADR 0475。当时名的长度大于 0 就丢掉姓。见 ADR 0588。这三种通常没有别的正文。短链可以只写在姓上。把整段收成正文会改变内容哈希，关键词也会命中名字。

## 决策

- 只在已经会标成开始或结束的提示上，从 `from` 会画出来的全名留主机名。`video_chat_started` 是对象时读。结束的时长是有限且不小于 0 的数字时读，0 也读。几种同时出现时仍先认开始，再认结束，再认预约。
- 名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读。空格不截断。用户名不读。
- 预约仍只读名。名的长度大于 0 时不读姓。空白也算有名。空格不截断。预约这行不画人，不把姓收进来。
- 名字不进正文，也不改内容哈希。关键词因此不命中。时长和开始时间不读。本群群名不读。正文里已有短链时，证据仍先记正文的主机名。
- 自己开始时这行不画名字。频道这行不画这个人。现有条件仍读 `from`。这条只改开始和结束的名字怎么切。靠近提醒仍按原来的名。拉进视频聊天已按全名。见 ADR 0634。
- 空的结束、负数和非有限数字不读发送者。只有邀请名单时不读这条通话的发送者。普通消息因此仍不读 `from`。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`call_notice` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不改视频聊天。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 开始和结束继续只读名 | 客户端把姓画在同一行里。姓上的短链会留在提示里。 |
| 把名字整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0119。 |
| 预约也改成全名 | 预约这行不画人。姓上的短链不是这行里的字。 |
| 自己开始或频道时不读发送者 | 现有条件已经读 `from`。这条只改名字怎么切。 |
| 靠近提醒也改成全名 | 靠近提醒这行用的是名。见 ADR 0597。 |
| 新命令 `/callname` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 开始或结束视频聊天的人，全名里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。视频聊天本身不变。
- 全名原文、路径和用户名不进事件。内容哈希不变。关键词不命中全名。时长和开始时间不进事件。
- 空白名不挡住姓。空格后面的网址仍读。预约仍只读名，空白名仍挡住姓。
- 正文里已有短链时，证据仍先记正文的主机名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 靠近提醒仍只读名。空的结束、负数、非有限数字和普通消息仍不读发送者。管理员仍豁免。干净的提示在 `call_notice` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
