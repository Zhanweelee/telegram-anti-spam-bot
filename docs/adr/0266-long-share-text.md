# ADR 0266：超长分享附言仍留下主机名

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 把分享链接的 `url` 和 `text` 拼成同一段草稿，再截到 `4096 * 4`。ADR 0265 把 `url` 和 `callback_url` 放到 16384，`text` 仍在 4096 处整段丢掉。

`https://t.me/share/url?text=http://bit.ly/…%20` 后面垫过 4096 时，短链在草稿开头，客户端仍会打开。整段丢掉就会漏掉它。`tg://msg?text=` 同样写进这段草稿。

用户名上的 `text` 仍停在 4096。更长的用户名链接仍按 ADR 0029 丢掉。

## 决策

- 分享 `text` 和私聊预填 `tg://msg` 的 `text` 先按现有规则解码，再截到 16384 个字符，然后抽出主机名。
- 16384 之后的字不再读。
- 用户名草稿的 `text` 仍停在 4096。超过就整段不读。
- 查询值不进入正文，也不参与关键词。路径不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| `text` 继续停在 4096 | 分享附言和 `url` 在同一段草稿里，短链会漏。 |
| 用户名草稿也放到 16384 | 更长的用户名链接仍按 ADR 0029 丢掉。 |
| 超过 16384 整段丢掉 | 短链在截断点前面时，客户端仍会打开。 |

## 后果

- `t.me/share/url?text=http://bit.ly/…%20` 垫过 4096、以及 `tg://msg?text=` 里同样的短链删除。证据仍只有主机名。
- 16384 个字符之后的短链留着。
- `t.me/用户名?text=` 超过 4096 仍不读。
- 直接打开的长链接仍按 ADR 0029 丢掉。
