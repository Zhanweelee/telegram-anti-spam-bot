# ADR 0205：标签里的字不再拆出下一条主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

Android 的裸主机名把汉字、谚文、假名、希伯来文、阿拉伯文、泰文和同类标签字算进同一个标签。`example.com点bit.ly/…` 是一条主机名，不会打开 `bit.ly`。`bit.ly点evil.com/…` 也是一条，主机名不以 `.bit.ly` 结尾。`203.0.113.10点bit.ly/…` 既不是这条裸 IP，也不是短链。

主机名扫描只去掉西里尔、希腊、亚美尼亚文和非 ASCII 拉丁字母。汉字留下来以后，单词边界仍从它后面开始，于是又读出 `bit.ly`。

`点击bit.ly/…` 前面没有 ASCII。Android 从字符串开头把汉字算进标签，检测仍按短链删除。`example.com点http://bit.ly/…` 会另外打开后面的网址。换行、空格和斜杠也会打开。句号 `。` 会被地址解析器收成点，`example.com。bit.ly/…` 仍是短链。私用区和标签类没有的增补字母仍让后面的网址单独打开。

`example.com点www.bit.ly/…` 的整条主机名仍以 `.bit.ly` 结尾。

## 决策

- 只改主机名扫描。公开的 `foldHostInterrupters` 仍只去掉那四类字母。
- 一段 Android 标签字夹在 ASCII 字母或数字中间，而且后面不是 `http://` 或 `https://` 时，把这一段换成 `x`。
- 句号 `。` 不参与这段替换。变体选择符、间隔号和已经收成拉丁字母的字仍按原规则处理。
- 前面没有 ASCII 的 `点击bit.ly` 保持原样。换行、空格、斜杠和私用区仍让后面的网址单独打开。
- 停住扫描也做这一步，避免粘连扫描收成 `x` 之后又从原文读出短链。
- 每段仍走现有的短链、裸 IP、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 任何非 ASCII 后面都不再开始主机名 | `点击bit.ly` 会放行。ADR 0097 已经拒绝。 |
| 把汉字也从标签里删掉 | `点击bit.ly` 仍会命中，但 `b点it.ly` 会被粘成短链。Android 并不打开它。 |
| 连句号 `。` 一起换成 `x` | `example.com。bit.ly` 会漏掉。地址解析器已经把 `。` 收成点。 |

## 后果

- `example.com点bit.ly/…`、`bit.ly点evil.com/…`、`example.com가bit.ly/…` 和 `203.0.113.10点bit.ly/…` 留着。
- `点击bit.ly/…`、`example.com点http://bit.ly/…` 和换行、空格、斜杠后面的网址仍按短链删除。
- `example.com。bit.ly/…` 仍按短链删除。私用区和 U+10140 后面的短链仍删除。
- 写完的主机名和后面的域名之间的句号收成一个点。见 ADR 0216。
- `example.com点www.bit.ly/…` 仍按短链删除。证据是 `example.comxwww.bit.ly`。
- `bтit.ly` 和 `bit·ly` 仍按短链删除。路径不进证据。
- 写完的主机名后面接不上严格域名时，标签字不再收成 `x`。见 ADR 0219。
- IDNA 映射恰好是一个 ASCII 字母的字收成这个字母。见 ADR 0206。
