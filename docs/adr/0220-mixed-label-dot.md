# ADR 0220：写完的主机名和后面的严格域名之间的标签字收成 x

- 状态：已接受
- 日期：2026-11-03

## 背景

ADR 0205 把夹在 ASCII 中间的标签字收成 `x`。ADR 0219 在后面接不上严格域名时留下这些字。

点号夹在中间时，裸扫描仍会在标签字前面停住。`bit.ly点日本.com/…`、`www.bit.ly点日本.com/…`、`t.co点日本.com/…`、`203.0.113.10点日本.com/…`、`bit.ly가.com/…`、`bit.ly点日本.中国/…` 和 `bit.ly点日本.evil.com/…` 在 Android 上都是一条网址。带协议时，地址解析器给出的主机名不是前面的短链或裸 IP。

`bit.ly点日本.notarealtld/…` 仍只打开 `bit.ly`。`点日本.bit.ly/…` 前面没有 ASCII，仍打开这条短链。`example.com点.bit.ly/…` 的整条主机名仍以 `.bit.ly` 结尾。

## 决策

- 只改主机名扫描。公开的折叠不改。
- 一段 Android 标签字前面已经是写完的主机名，后面是点号加 Android 的严格域名时，把这一段换成 `x`。
- 点号后面不是严格域名时，留下这些标签字。`http://` 和 `https://` 前面的标签字仍留下。前面没有 ASCII 的标签字仍留下。
- 停住扫描也按这一步，避免粘连扫描收成 `x` 之后又从原文读出短链。
- 每段仍走现有的短链、裸 IP、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 只收紧贴顶级域的点，多一层标签仍拆开 | `bit.ly点日本.evil.com/…` 仍按短链删除。Android 只打开这一整条。 |
| 在抽主机名时跳过前缀，不收成 `x` | 旁路纯文本仍按原文读出 `bit.ly`。 |
| 点号后面一律收成 `x` | `bit.ly点日本.notarealtld/…` 会把已经打开的 `bit.ly` 粘没。 |

## 后果

- `bit.ly点日本.com/…`、`203.0.113.10点日本.com/…`、`bit.ly点日本.中国/…`、`bit.ly点日本.evil.com/…` 和 `http://bit.ly点日本.com/…` 留着。
- `bit.ly点日本.notarealtld/…` 按短链删除。证据是 `bit.ly`。
- `example.com点.bit.ly/…` 和 `bit.ly点日本.bit.ly/…` 仍按短链删除。证据是收成 `x` 之后的主机名。
- `点日本.bit.ly/…` 仍按短链删除。路径不进证据。
