# ADR 0162：下划线放不进标签时只留高亮主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0161 按 Android `LinkifyPort.WEB_URL` 把超过 63 个字符的标签留在高亮外面。标签中间还可以有下划线。Java 的 `\b` 只认 ASCII 单词字符，下划线也算一个，所以标签不能停在下划线前面。

`http://bit.ly.` 后面接 62 个字母再加 `_b` 时，下划线放不进这 63 个字符，整段标签都不成立，打开的是 `bit.ly`。63 个字母后面再加下划线也一样。`http://203.0.113.129.` 后面同样打开 `203.0.113.129`。整段解析把下划线留在主机名里，对不上短链，也不是四段数字。

下划线放得下时仍是标签的一部分。61 个字母加 `_b` 正好 63，打开的是整段主机名。`http://bit.ly_foo/x` 打开 `bit.ly_foo`。`http://bit.ly_/x` 打不开 `bit.ly`，打开的是 `bit`。

连字符不是单词字符。62 个字母后面接 `-foo` 时，高亮停在这 62 个字母。连字符已经放进标签、后面的字母又把标签撑过 63 时，高亮退到这个连字符前面，不退回再前一个标签。

## 决策

- 正文里的 `http` 或 `https` 再取这段高亮的主机名。下划线只有在补上之后仍不超过 63、并且后面还有字母或数字时才算进标签。否则这个标签不成立，句点留在前面。只留主机名。
- 标签停在单词中间时，退到最近一个还能停住的连字符前面。没有这种连字符，这个标签不成立。
- 整段解析出的主机名仍然保留。两边都走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。最多 8 个。
- 已经写在 `text_link`、按钮或其它结构化字段里的地址整段打开，不按高亮截断。
- 不把停住之后的路径再当成邀请。路径不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 只留整段解析出的主机名 | 点下去打开的是下划线前面的短链或裸 IP。 |
| 下划线一律截断并留下前缀 | `http://bit.ly_foo/x` 打开的是 `bit.ly_foo`，不是 `bit.ly`。 |
| 一遇到下划线就丢掉整个标签 | 放得下的下划线仍属于标签。连字符撑过 63 时应停在连字符前，而不是退回 `bit.ly`。 |

## 后果

- `http://bit.ly.` 加 62 个字母再加下划线，以及 `http://203.0.113.129.` 的同样写法，按现有短链或裸 IP 规则删除。证据仍只有主机名。
- 61 个字母加 `_b`、`http://bit.ly_foo/…` 和 `http://bit.ly_/…` 留着。60 个字母再加连字符和更多字母也不记成前面的短链。
- `https://t.me.` 加 62 个字母再加 `_/+…` 不记成邀请。再套一层仍放行。路径不进证据。
