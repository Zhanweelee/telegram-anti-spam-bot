# ADR 0098：一层 %C2%B7 在比较前收成间隔号

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0093 把间隔号 `·` 在抽主机名前收成 `.`，关键词比较前直接去掉。写成 `%C2%B7` 时，这两层都看不见。`bit%C2%B7ly` 因此对不上短链名单。

第二层 `%25C2%25B7` 仍按其它百分号编码的做法留下。其它间隔号的百分号形式不在这一项里。

## 决策

- 新增 `foldEncodedMiddleDot`。只把一层 `%C2%B7` 收成 `U+00B7`，大小写都认。`%25C2%25B7` 保留。
- 关键词和正则先做这一层，再按 ADR 0093 去掉间隔号。
- 链接检测、`hostFromUrl` 和从正文里抽网址的扫描也先做这一层，再把间隔号收成 `.`。
- 事件里的正文和 `textSha256` 不变。不新增检测器，也不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 连第二层一起收 | `%2E` 和格式字符的第二层都留下。这一项保持同一条线。 |
| 只在链接检测里收 | `加%C2%B7微信` 仍对不上关键词 `加微信`。 |
| 在归一化时改掉正文 | 哈希变了，重复计数会拆开。 |

## 后果

- `bit%C2%B7ly/…` 和 `t%C2%B7me/+…` 会走现有短链和邀请规则。`example%C2%B7com` 仍保留。
- `加%C2%B7微信` 会命中关键词 `加微信` 和默认正则。`不是免费。领取` 仍不命中。
- `bit%25C2%25B7ly` 仍抽不出来。
- 重复计数仍按原文哈希。
