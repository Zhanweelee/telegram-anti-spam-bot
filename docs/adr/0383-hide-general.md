# ADR 0383：私聊可以隐藏通用话题

- 状态：已接受
- 日期：2026-11-04

## 背景

论坛群的通用话题一直在话题列表里。诈骗集中在通用话题时，关掉它之后成员仍然看得到这个话题。官方还有一次把通用话题从列表里拿掉的调用。

`hideGeneralForumTopic` 隐藏通用话题。参数只有 `chat_id`。bot 必须是管理员，并且有 `can_manage_topics`。如果通用话题当时开着，这次会一起关掉。成功时返回 True。

它不接收话题号，也不删除消息。取消隐藏是另一条方法，而且不会重新打开。

没有 token 时，内存适配器可以把这次请求记下来。私聊如果复用这次成功，回复会写成通用话题已经隐藏。

## 决策

- 私聊命令 `/hidegeneral <chatId>`。群 id 匹配 `^-?\d{1,20}$`。多出来的参数不发出请求。群聊里的同样文本不执行。
- 配置中的管理员可以操作任意群。接入目录里的人只能操作自己的群。
- 调用 `ModerationPort.hideGeneral`。适配器调用 `hideGeneralForumTopic`，只带 `chat_id`。
- 不调用 `closeGeneralForumTopic`、`unhideGeneralForumTopic` 或 `deleteForumTopic`。不带话题号，也不带消息号。
- 回复写明原先开着的通用话题会一起关闭，消息还在，其它话题不在这次里。
- 没有 token、没有这个方法，群号不合法，或调用失败时回复「参数无效」。日志只写 `operator_rejected`，带上 eventId、chatId 和命令名。不写异常文本或 token。
- 没有 token 的 Worker 不把内存里的记录回复成已经成功。
- 不修改黑名单、白名单、封禁或禁言。不读取消息正文。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 隐藏时再调一次关闭 | `hideGeneralForumTopic` 已经会把开着的通用话题关掉。再调一次是第二次子请求。 |
| 接受话题号并隐藏指定话题 | 这条方法只作用于通用话题，不接收话题号。 |
| 隐藏时删除消息 | 这个方法不返回消息号，也不删除消息。删除仍走 `/delete` 和 `/deletes`。 |
| 回复不提自动关闭 | 开着的通用话题会一起关掉。管理员需要在回复里看到这个范围。 |
| 没有 token 时也回复「已隐藏」 | 通用话题还在列表里。管理员会以为成员已经看不到。 |

## 后果

- 成功只表示 Telegram 接受了这一次隐藏。缺少 `can_manage_topics`，或这个群不是论坛时，回复是「参数无效」。
- 其它话题保持原样。消息还在。置顶也不在这次里。
- 一次隐藏是一次 Telegram 子请求。封禁、禁言和黑名单都不变。
- 30 天保留期不动。
