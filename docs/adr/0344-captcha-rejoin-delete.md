# ADR 0344：再次入群时删掉上一颗验证按钮

- 状态：已接受
- 日期：2026-11-04

## 背景

ADR 0343 在通过、到期或同一条入群再发一颗时删掉已经记下的按钮。成员再次入群是另一条事件。`beginChallenge` 先写入新挑战，这一行不带 `messageId`，上一颗的 id 被清掉。新按钮发出之后，群里还留着点不中的旧按钮。

## 决策

- `beginChallenge` 先读出这一行。写入新挑战之后，如果旧行有 `messageId`，而且和新挑战的 id 不同，就删掉那条消息。
- 删除失败只记 `captcha_prompt_delete_failed`。新挑战和随后的限制照常进行。日志只有事件 id 和群 id。
- 限制失败时，新挑战仍按原来的方式回滚。旧按钮在写入新挑战之后已经删掉。
- `captcha` 动作把 `deleteMessage` 交给这次删除。dry-run 不读、不删。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 等新按钮记下 id 再删旧的 | 新 `put` 已经把旧 id 清掉，后面读不到。 |
| 删除失败就放弃新挑战 | 成员会留在没有按钮的限制里。 |
| 限制失败时把旧按钮放回去 | 旧 nonce 已经不在存储里，放回去也点不中。 |

## 后果

- 再次入群会留下新按钮，并去掉上一颗已经记下 id 的提示。
- 没记下 id 的旧按钮还会留在群里。
- 限制失败时，旧按钮已经删掉，新挑战也不留下。成员不会被这次失败卡住。
- 30 天保留期不动。
