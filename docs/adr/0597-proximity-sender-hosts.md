# ADR 0597：靠近的人，名字只留主机名

- 状态：已接受
- 日期：2026-11-05

## 背景

两个人共享实时位置并靠近时，客户端把操作的人的名字画在服务消息上。名字写在 `from`。触发者和设置者的名字当时按正文处理。见 ADR 0121。距离不进事件。短链可以只写在操作的人的名字里。

把 `from` 收成正文会让普通发言者的姓名也进检测。`proximity_notice` 默认关闭，干净的提示仍留下。用户编号和距离仍不读。负数、小数、字符串、布尔值和空对象仍不是这条提示。

## 决策

- 只在已经会标成 `asProximity` 的提示上，从 `from` 的可见名字留主机名。`proximity_alert_triggered.distance` 是大于等于 0 的安全整数时读。0 米也读。
- `first_name` 的长度大于 0 时只读名。空白也算有名。名缺失或正好是空字符串时改读姓。用户名不读。抽出之前不截断。
- 触发者和设置者的名字仍按 ADR 0121 成为正文。已有别的正文时仍留在 `memberName`。操作的人的名字不进正文，也不改内容哈希。关键词因此不命中这个人的名字。距离和用户编号不读。本群群名不读。这条提示不因此带 `asLocation`。
- 负数、小数、字符串、布尔值和空对象不读发送者。普通消息不读 `from`。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`proximity_notice` 仍默认关闭。8 个主机名的上限不变。不改实时位置。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把操作的人整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0121。 |
| 并进 `proximity_notice` | 打开靠近提示的群并不一定要按名字里的短链删。距离仍不是广告。 |
| 把距离或用户编号写进证据 | 距离和编号都不是这行看得见的字。见 ADR 0493。 |
| 新命令 `/nearname` | 菜单只剩一个空位。现有 `links` 已经能删短链。 |

## 后果

- 操作的人，名字里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。实时位置本身不变。
- 这个人的名字原文、路径和用户名不进事件，内容哈希不变。名字里的关键词不命中。
- 名的长度大于 0 时，姓和用户名不进事件。触发者和设置者的名字仍按原来的正文。距离和用户编号仍不进事件。
- 触发者和设置者后来按全名成为正文。名和姓都去掉两端空白，名在前。用户名不进。见 ADR 0642。操作的人仍只读名。
- `example.com` 和公开的 `t.me/名字` 留着。付费帖仍不删除。见 ADR 0356。
- 负数、小数、字符串、布尔值、空对象和普通消息仍不读发送者。本群群名仍不读。干净的提示在 `proximity_notice` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
