# ADR 0651：有价通过建议帖上画出的话题用户全名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

建议帖通过时，Android 的 `getActionSuggestionApprovalText` 第一行只画频道名，有发表时间时再画日期。金额大于 0 时，管理员看见的第二句 `SuggestionAgreementReachedAdmin2` 才把话题用户画进去。这个名字来自 `DialogObject.getName`，也就是 `UserObject.getUserName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这句里。

这个人是 `saved_peer_id`。Bot API 把它放在 `direct_messages_topic.user`。金额来自 `suggested_post_approved.price.amount`。`MessageSuggestionParams` 里金额是空的或 `isZero()` 时，这句不出现。投稿人自己看见的 `SuggestionAgreementReachedUser2` 只有金额，没有这个名字。付款到账那行只画频道名。见 ADR 0650。

名字本身不进正文。关键词不命中这段全名。

## 决策

- 已经会标成 `postNotice` 的 `approved`，并且 `suggested_post_approved.price` 是对象、`amount` 是大于 0 的安全整数时，从 `direct_messages_topic.user` 会画出来的全名留主机名。
- 名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读。空格不截断。用户名不读。发言人编号不同也读。
- 没标价、价格不是对象、金额不是安全整数、金额是 0 或更小的通过，不读这个人。付款仍不读。失败和退款仍按 ADR 0650 读。同时出现时仍先认通过。`from` 仍按 ADR 0601 只读名。普通消息的话题标题仍只在发言人就是这个用户时读。见 ADR 0637。
- 话题号、频道标题、嵌套原帖、币种和金额本身不读。没有话题、布尔值和空的用户对象不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`post_notice` 仍默认关闭。8 个主机名的上限不变。不调用 `approveSuggestedPost`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 所有通过都读 | 没标价时管理员那句也不画这个人。金额为 0 时同样不画。 |
| 付款也读 | 付款到账那行只画频道名。见 ADR 0650。 |
| 只在管理员会话里读 | 服务消息是同一条。管理员看见的那句已经画出全名。 |
| 把这个人整段当成正文 | 关键词会命中人名。普通话题标题的条件也会被打开。见 ADR 0637。 |

## 后果

- 有价通过这句的话题用户全名里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。稿子状态不变。
- 全名原文、路径、用户名、话题号、频道标题和金额不进事件。内容哈希不变。关键词不命中全名。
- 空白名不挡住姓。空格后面的网址仍读。发言人不是这个人时也读。
- `from` 仍只读名，空白名仍挡住姓。没标价或金额为 0 的通过，以及付款，仍不读话题用户。失败和退款仍读。普通消息的话题标题仍只在发言人就是这个用户时读。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 没有话题、布尔值、空的用户对象、字符串金额和小数金额不读。嵌套原帖仍不读。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
