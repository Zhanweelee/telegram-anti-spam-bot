# ADR 0483：抽奖创建和私下结束按群删除

- 状态：已接受
- 日期：2026-11-05

## 背景

预约抽奖时，群里先出现一条创建公告。`giveaway_created` 只有可选的星星数量，没有奖品说明。没有公开中奖者时，结束是 `giveaway_completed`。中奖人数在这条消息上，奖品原文在可选的 `giveaway_message` 里。那是另一条消息。见 ADR 0061 和 ADR 0482。

进行中的抽奖卡片和公开中奖者的结束公告已经可以由 `giveaway_card` 删除。见 ADR 0474。这两条服务消息的正文仍是空的。星星数量和中奖人数不进事件。关键词看不到它们。

## 决策

- `giveaway_created` 是对象时，事件带 `giveawayNotice: "created"`。不写星星数量。
- 否则，`giveaway_completed.winner_count` 是大于等于 0 的安全整数时，带 `completed`。不写中奖人数、未领数量和是否星星抽奖。不读 `giveaway_message` 里的原文、名字、消息号，也不从这条嵌套消息里抽主机名。
- 空的结束对象、负数和小数人数不带这个标记。已有正文时，正文仍按原来的优先级。进行中的卡片和公开中奖者仍只由 `asGiveaway` 表示。
- 检测器在 `@tasb/detector-giveaway-notice`，id 是 `giveaway_notice`。只在 `message.giveawayNotice` 是这两种之一时返回 score 1。证据是 `giveaway:created` 或 `giveaway:completed`。
- 默认规则用同样的 id，关闭。某个群用现有的私聊 `/rule` 打开后，删除这两种服务消息。没有新命令。菜单仍是 99 条。不取消抽奖，也不退回星星。
- 付费帖仍不删除。见 ADR 0356。
- 不改 ADR 0026 的基础检测器名单。`giveaway_notice` 不在里面。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 并进 `giveaway_card` | 已经打开卡片开关的群会突然多删两条公告。创建公告和私下结束要单独打开。 |
| 默认删掉这两条 | 有的群自己办抽奖，成员靠这条公告知道开始了。打开之前不改现有群。 |
| 把嵌套抽奖消息抄进正文 | 那是另一条消息。关键词会按奖品原文删除这条结束公告。 |
| 把星星数量或中奖人数写进证据 | 数量不是广告。不能进事件。 |
| 新命令 `/giveaway` | 菜单只剩一个空位。现有 `/rule` 已经能打开这条规则。 |

## 后果

- 不打开这条规则的群，创建公告和私下结束仍留下。这条更新仍然不读嵌套的抽奖消息。`giveaway_card` 仍只删进行中的卡片和公开中奖者。
- 打开 `giveaway_notice` 后，这个群里的创建公告和私下结束会删除。抽奖本身不取消。星星不退回。付费帖仍留下。
- 自部署没有额度，打开后就会删除。云模式超过当月次数后，还要把 `giveaway_notice` 写进 `QUOTA_BASIC`，否则超额时这条规则会停。
- `chats.json` 整份替换的群要自己加上这条规则，才会有这个开关。
- 30 天保留期不动。
- 创建抽奖或私下结束的人后来不再读。见 ADR 0664。星星数量、中奖人数和嵌套的抽奖原文仍不读。空的结束仍不读发送者。进行中卡片的发送者仍不读。
- 创建公告上画出的群名后来由 ADR 0656 只留主机名。用户名仍不读。私下结束仍不读所在聊天的名字。
