# ADR 0222：句号后面的标签字仍收成一个点

- 状态：已接受
- 日期：2026-11-03

## 背景

ADR 0216 和 ADR 0217 把写完的主机名后面的句号、点状间隔号收成一个 ASCII 点，但只认后面的 ASCII 域名。ADR 0220 在标签字和 ASCII 点之间收成 `x`。

`bit.ly。日本.com/…`、`bit.ly。点日本.com/…`、`203.0.113.10。日本.com/…` 和 `bit.ly点日本。evil.com/…` 在 Android 上都是一条网址。带协议时，地址解析器给出的主机名不是前面的短链或裸 IP。十个点状字符的边界相同。

`bit.ly。com/…`、`bit.ly。中国/…`、`bit.ly。/…` 和 `bit.ly。点日本.notarealtld/…` 仍只打开前面的短链或裸 IP。`bit.ly。com.日本/…` 也只打开 `bit.ly`。

## 决策

- 只改主机名扫描。公开的折叠不改。
- 写完的主机名后面，一段句号或点状间隔号在后面还有域名时收成一个 ASCII 点。这个域名可以含 Android 标签字，最后一个标签仍是严格顶级域，而且中间至少还有一个点。
- 单独的顶级域、路径、空标签和接不上严格域名的尾巴不收。
- 一段 Android 标签字夹在写完的主机名和这种间隔号中间，而且后面还有域名时，把标签字收成 `x`，间隔号收成一个点。
- 停住扫描也按这一步，避免粘连扫描收成点之后又从原文读出短链。
- 每段仍走现有的短链、裸 IP、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 只认 ASCII 域名 | `bit.ly。日本.com/…` 仍按短链删除。Android 只打开这一整条。 |
| 句号后面一律收成点 | `bit.ly。com/…` 和 `bit.ly。中国/…` 会把已经打开的短链粘没。 |
| 在抽主机名时跳过前缀，不收成点 | 旁路纯文本仍按原文读出 `bit.ly`。 |

## 后果

- `bit.ly。日本.com/…`、`203.0.113.10。日本.com/…`、`bit.ly点日本。evil.com/…` 和 `http://bit.ly。日本.com/…` 留着。
- `bit.ly。com/…`、`bit.ly。中国/…` 和 `bit.ly。点日本.notarealtld/…` 按短链删除。证据是 `bit.ly`。
- `example.com。日本.bit.ly/…` 仍按短链删除。证据是收成点之后的主机名。
- `bit.ly。/…` 仍按短链删除。路径不进证据。
