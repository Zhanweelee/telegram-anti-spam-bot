# ADR 0422：私聊可以查看允许的反应个数

- 状态：已接受
- 日期：2026-11-04

## 背景

群可以限制成员能用哪些反应。反垃圾要知道这份名单有多窄，才不会把正常反应当成异常。这个信息在 `getChat` 返回的 `ChatFullInfo.available_reactions` 里，类型是 `ReactionType` 数组。

文档写明：这个字段缺省时，全部表情反应都允许。数组里的每一项是 `emoji`、`custom_emoji` 或 `paid`。表情、自定义表情编号和付费标记都不进这次回复。`/react` 仍然是给一条消息设置一个官方表情，两件事不合并。

## 决策

- 私聊命令 `/reactions <chatId>`。群 id 匹配 `^-?\d{1,20}$`。多出来的参数不发出请求。群聊里的同样文本不执行。
- 配置里的管理员可以看任意群。接入目录里的人只能看自己的群。
- 调用 `ModerationPort.readReactions`。适配器调用 `getChat`，只带 `chat_id`。
- 回复两行：群号、允许的反应个数。没有 `available_reactions` 时写全部。空数组写 0。
- 不是对象、`type` 不是这三种、表情不是字符串、自定义表情编号是空字符串、或返回的群号和请求不一致时，整份回复是「参数无效」，不露出已经读到的字段。
- 表情、自定义表情编号、付费标记、标题和邀请链接不进回复，也不进日志。
- 日志只写 `operator_rejected` 或命令名，带上 eventId、chatId 和命令名 `reactions`。不写表情、编号、异常文本或 token。
- 没有 token 的 Worker 不编一个个数。
- 不调用 `setMessageReaction`，也不改黑名单、封禁或禁言。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 缺字段写成 0 | 文档把缺字段定义成全部表情反应都允许。0 只表示空数组。 |
| 回复里列出表情 | 表情和自定义编号可能是原文。个数够用来看这份名单有多窄。 |
| 并进 `/guard` 或 `/react` | `/guard` 已经有反应上限。`/react` 是给一条消息设置表情。允许名单是另一件事。 |

## 后果

- 成功只表示 Telegram 返回了这个群当前允许的反应个数，或这个字段没有返回。
- 一次查看是一次 Telegram 子请求。`/guard`、`/perms` 和 `/joinbot` 仍是各自的 `getChat`。`/react` 仍是 `setMessageReaction`。封禁、禁言和黑名单都不变。
- 30 天保留期不动。
