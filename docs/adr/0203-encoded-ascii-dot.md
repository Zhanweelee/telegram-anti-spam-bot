# ADR 0203：编码点不再贴出下一条主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

Android 不把 `%2E` 收成点。`%2Ebit.ly/…` 打开的是 `2Ebit.ly`。`see%2Ebit.ly/…`、`www%2Ebit.ly/…` 和 `example.com%2Ebit.ly/…` 也是 `2Ebit.ly`。`%2E203.0.113.170/…` 不会打开这个地址。`%2Ehttp://bit.ly/…` 什么都不打开。

`%2Ewww.bit.ly/…` 打开的是 `2Ewww.bit.ly`。这个主机名仍以 `.bit.ly` 结尾。`%2E.bit.ly/…` 打开的是 `2E.bit.ly`。`http://%2Ebit.ly/…` 打开的是 `2Ebit.ly`。`http://bit.ly%2Eevil.com/…` 仍先打开 `bit.ly`。

`%2E203.0.113.170/http://t.co/…` 会打开后面的 `t.co`。`%2Ebit.ly/http://…` 把后面的网址吞进 `2Ebit.ly`。

换行、空格或制表符隔开的 `%2E` 后面仍会打开短链。`bit%2Ely` 和 `t%2Eme/+…` 仍按现有规则删除。第二层 `%252E` 仍留下。路径里的 `%2E` 仍收成点，不另开一条短链。公开的 `foldEncodedSeparators` 仍把每一层 `%2E` 收成点。

主机名扫描如果先把贴在前面的 `%2E` 收成点，`%2Ebit.ly` 会变成 `bit.ly`，`http://%2Ebit.ly` 也会变成 `bit.ly`，`%2E203.0.113.170` 会变成一条裸 IP。

## 决策

- 只改主机名扫描。公开的 `foldEncodedSeparators` 仍把 `%2E` 收成点。
- `%2E` 紧挨在已经写完的主机名前面时，换成它自己的两位十六进制。主机名含裸域名和点分 IPv4。紧挨着 `.` 再加主机名时同样换。
- `://` 后面的 `%2E` 算主机名开头。路径里的 `/` 或 `%2F` 后面仍收成点。
- 换行、空格和制表符仍先按原规则处理，所以隔开之后的网址仍会打开。
- `%2E` 贴在 `http://` 或 `https://` 前面时仍收成 `!x`。`bit%2Ely` 和 `t%2Eme/+…` 仍收成点。
- 每段仍走现有的短链、裸 IP、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| `%2E` 一律不再收成点 | `bit%2Ely` 和 `t%2Eme/+…` 会漏掉。 |
| 公开的 `foldEncodedSeparators` 一起改 | 结构化网址仍要把路径里的 `%2E` 收成点。 |
| 贴在主机名前面时直接删掉 | `%2Ewww.bit.ly` 会漏成 `www.bit.ly`，Android 打开的是 `2Ewww.bit.ly`。 |

## 后果

- `%2Ebit.ly/…`、`see%2Ebit.ly/…`、`www%2Ebit.ly/…` 和 `%2E203.0.113.170/…` 留着。
- `http://%2Ebit.ly/…` 留着。`%2Ebit.ly/http://…` 留着。
- `%2E203.0.113.170/http://…` 按后面的短链删除。
- `bit%2Ely`、换行、空格或制表符后面的网址仍按短链删除。`t%2Eme/+…` 仍按邀请删除。
- `%2Ewww.bit.ly/…` 和 `%2E.bit.ly/…` 仍按短链删除。证据是 `2ewww.bit.ly` 和 `2e.bit.ly`。
- `http://bit.ly%2E…` 和 `203.0.113.170%2E…` 仍按原来的主机名删除。第二层 `%252E` 仍留下。路径不进证据。
