# ADR 0332：白名单回复按 id 截断

- 状态：已接受
- 日期：2026-11-04

## 背景

`/whitelist` 把这一群的 id 用逗号接在一条回复里。命令接受最多 200 个 id，每个是最多 20 位的数字。200 个 20 位 id 大约 4200 字。Telegram 的 `sendMessage` 只接受 4096 字。适配器会把更长的文本切到 4096，最后一个 id 可能只剩一半，回复里也看不出后面还有人。

上限本身是 ADR 0005 的决定。这一步只改回复。

## 决策

- 完整回复不超过 3500 字时，正文保持 `whitelist`、`exemptAdmins` 和 `allow`，不附加剩余个数。
- 放不下时，按存储里的顺序保留前面的若干个完整 id。最后一行写上没列出的个数。
- 不把一个 id 从中间切开，也不为了缩短回复去改名单。
- 英文目录用 `{count} more`。中文目录用 `还有 {count} 个`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续交给适配器切到 4096 | 切口会落在 id 中间，管理员以为名单到这里结束。 |
| 只回复个数 | 短名单现在能看到每个 id。放不下时仍应尽量列出前面的人。 |
| 把上限降到私聊一定放得下的个数 | 20 位只是上限。常见的短 id 可以放进 200 个。降低上限会丢掉已经允许的名单。 |

## 后果

- 私聊看到的是前缀和剩余个数。没列出来的 id 仍在名单里，`remove` 仍然按 id 删除。
- 适配器仍会把超过 4096 字的文本切开。这条命令的回复停在 3500 字以内。
- 白名单上限、豁免管理员和 30 天保留期不动。
