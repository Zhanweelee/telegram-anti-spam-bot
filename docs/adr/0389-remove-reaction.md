# ADR 0389：私聊可以撤下一条消息上的一个反应

- 状态：已接受
- 日期：2026-11-04

## 背景

一个人在一条消息上刷反应时，`/clearreact` 会清掉这个人最近大约一万条反应。官方有一次只撤这一条消息上的反应的调用。

`deleteMessageReaction` 撤下一条消息上的一个反应。参数是必须的 `chat_id` 和 `message_id`。反应来自用户时带 `user_id`，来自频道时带 `actor_chat_id`。方法不接收表情。群和超级群里，bot 要有 `can_delete_messages`。成功时返回 True。

这条调用不动别人的反应，也不动这个人在其它消息上的反应。清空最近反应仍走 `/clearreact`。

没有 token 时，内存适配器可以把这次请求记下来。私聊如果复用这次成功，回复会写成反应已经撤下。

## 决策

- 私聊命令 `/unreact <chatId> <messageId> <actorId>`。群 id 和成员号匹配 `^-?\d{1,20}$`。消息号和 `/delete` 使用同一条规则：`/^[1-9]\d{0,15}$/`，并且是安全整数。少一个参数或多出来的参数都不发出请求。群聊里的同样文本不执行。
- 配置中的管理员可以操作任意群。接入目录里的人只能操作自己的群。
- 调用 `ModerationPort.removeReaction`。正数编号是用户，请求只带 `user_id`。以 `-` 开头的编号是频道，请求只带 `actor_chat_id`。两个字段不同时出现。消息号 `1` 原样送出。
- 不传表情。不调用 `deleteAllMessageReactions`。
- 回复写明这个人在这条消息上的反应被撤下，别人的反应还在，其它消息上的反应还在。
- 没有 token、没有这个方法，群号、消息号或成员号不合法，或调用失败时回复「参数无效」。日志只写 `operator_rejected`，带上 eventId、chatId 和命令名。不写异常文本、token 或原文。
- 没有 token 的 Worker 不把内存里的记录回复成已经成功。
- 不修改黑名单、白名单、封禁或禁言。不读取消息正文。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 让管理员写表情 | 官方方法没有表情参数。表情写了也不会被送出。 |
| 两个编号字段一起传 | 一次只撤一个来源。一起传会让用户和频道分不清。 |
| 不带消息号时改走 `/clearreact` | 那一次会清掉最近大约一万条。范围比这一次大。 |
| 没有 token 时也回复「已撤下」 | 反应还在。管理员会以为已经拿下。 |

## 后果

- 成功只表示 Telegram 接受了这一次撤下。这条消息上没有这个人的反应，这个群不是群或超级群，或缺少 `can_delete_messages` 时，回复是「参数无效」。
- 别人的反应还在。这个人在其它消息上的反应还在。
- 一次撤下是一次 Telegram 子请求。封禁、禁言和黑名单都不变。
- 30 天保留期不动。
