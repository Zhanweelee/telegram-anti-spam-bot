# ADR 0628：新加清单任务的人画出的全名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

有人往清单里新加任务时，Android 的 `MessageObject` 在 `TL_messageActionTodoAppendTasks` 上用 `replaceWithLink` 把这个人画进这行服务文字。这就是 `UserObject.getUserName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。自己新加时这行不画名字。

Bot API 把这行放在 `checklist_tasks_added`。`tasks` 里至少有一条长度大于 0 的文字时，这条提示成立。见 ADR 0603。当时名的长度大于 0 就丢掉姓。勾完或取消勾完已经按全名只留主机名。见 ADR 0627。

任务上的完成者仍只读名。加选项或删选项的人仍只读名。短链可以只写在姓上。把整段收成正文会改变内容哈希，关键词也会命中名字。

## 决策

- 只在已经会标成 `asChecklistAdded` 的提示上，从 `from` 会画出来的全名留主机名。`tasks` 里至少有一条长度大于 0 的文字时读。空白也算有文字。空文字后面还有文字时仍读。
- 名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读。空格不截断。用户名不读。
- 全名不进正文，也不改内容哈希。关键词因此不命中。任务文字仍按 ADR 0089 成为正文。已有别的正文时仍留在 `addedText`。任务编号、完成时间和嵌套的原清单不读。任务文字里已有短链时，证据仍先记那段文字的主机名。正文里已有短链时，证据仍先记正文的主机名。完成者仍按原来的名，排在这个人前面。本群群名不读。
- 加选项或删选项的人仍按 ADR 0604 只读名。空字符串、空数组和布尔值不读发送者。普通消息不读 `from`。投票选项不读发送者。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`checklist_added` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不调用 `editMessageChecklist`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续只读名 | 客户端把姓画在同一行里。姓上的短链会留在提示里。 |
| 把名字整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0495。 |
| 任务上的完成者也改成全名 | 完成者这行仍只画名。姓上的短链并没有出现在那一行。 |
| 每条服务提示的人都改成全名 | 助推这行用的是名。付款成功这行也只读名。见 ADR 0583 与 ADR 0618。 |
| 新命令 `/addedname` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 新加清单任务的人，全名里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。任务还在。
- 全名原文、路径和用户名不进事件。内容哈希不变。关键词不命中全名。
- 空白名不挡住姓。空格后面的网址仍读。任务文字仍按原来的正文。
- 任务文字或正文里已有短链时，证据仍先记那一边的主机名。完成者的主机名仍排在这个人前面。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 任务上的完成者仍只读名。加选项或删选项的人仍只读名。空字符串、空数组、布尔值、投票选项和普通消息仍不读发送者。管理员仍豁免。干净的任务在 `checklist_added` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
- 任务上的完成者后来按全名只留主机名。名和姓都去掉两端空白，名在前。空白名不挡住姓。空格不截断。见 ADR 0641。主机名仍排在新加任务的人前面。加选项或删选项的人仍只读名。
- 发送者是聊天时后来只读聊天标题，不读 `from`。频道、群和超级群都一样。编号和本群相同时，任务文字排在前面。见 ADR 0686。
