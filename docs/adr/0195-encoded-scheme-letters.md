# ADR 0195：编码字母拼出的协议不再收成协议

- 状态：已接受
- 日期：2026-11-02

## 背景

Android 不会在匹配前把 `%68`、`%74`、`%70`、`%73` 收成字母。`%68ttp://bit.ly/…`、`ht%74p://bit.ly/…`、`htt%70://bit.ly/…`、`http%73://bit.ly/…` 和整段都写成编码的 `%68%74%74%70://bit.ly/…` 都不会打开。`%2568ttp://bit.ly/…` 和换行拆开的 `ht%74` 再写 `p://bit.ly/…` 也不会打开。`see %68ttp://bit.ly/…` 同样不会打开。

真正写出来的 `http://bit.ly/…` 和 `HTTP://bit.ly/…` 仍会打开。`b%69t.ly` 和 `http://b%69t.ly/…` 仍是短链。`t.me/+OFF%45` 仍是邀请。`example.com/%68ttp://bit.ly/…` 整段仍是前面的主机名。

粘连扫描如果先把这些字母收出来，`%68ttp://bit.ly` 会变成 `http://bit.ly`，短链被多出来的协议打开。

## 决策

- 去掉换行之后、把字母编码收成字符之前，把能拼成 `http://` 或 `https://` 的那一段换成 `!x`。这一段里至少有一个字母是 `%HH` 或 `%25HH`。
- 字面协议保持不动。协议以外的 `%69`、`%45` 仍收成字母。`:` 和 `/` 的百分号编码仍按原来的斜线规则处理。
- `!` 让前面的文字结束，`x` 让 `://` 后面的主机名不能另起一段。
- 每段仍走现有的短链、裸 IP、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 字母编码一律不再收成字符 | `b%69t.ly` 和 `t.me/+OFF%45` 会漏掉。 |
| 只改开头的 `%68` | `ht%74p://bit.ly` 和 `htt%70://bit.ly` 仍会收成协议。 |
| 直接删掉这段编码 | `%68ttp://bit.ly` 会变成 `ttp://bit.ly`，后面的 `bit.ly` 仍可能单独打开。Android 并不打开它。 |

## 后果

- `%68ttp://bit.ly/…`、`ht%74p://bit.ly/…`、`htt%70://bit.ly/…`、`http%73://bit.ly/…`、`%2568ttp://bit.ly/…` 和换行拆开的 `ht%74` 加 `p://bit.ly/…` 留着。`example.com/%68ttp://bit.ly/…` 留着。
- `http://bit.ly/…`、`http://b%69t.ly/…` 和 `b%69t.ly` 仍按短链删除。`t.me/+OFF%45` 仍按邀请删除。路径不进证据。
- `https://bit.ly/%68ttp://t.co/…` 仍按短链删除。证据是 `bit.ly`。
- 百分号编码的斜杠拼出 `://`，或紧挨在协议前面时，不再收成斜杠。见 ADR 0196。
