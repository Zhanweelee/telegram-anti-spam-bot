# ADR 0267：草稿停住之后仍留下主机名

- 状态：已接受
- 日期：2026-11-03

## 背景

看得见的正文用链接检测器切网址。Android 在 `|`、控制符和替换字符处停住，后面的短链另算一条。

隐藏的 `text_link` 把分享 `text`、`tg://msg` 的 `text` 和用户名草稿交给另一段抽取。这段会把停住字符吞进同一条网址，短链就漏了。

把每一个没写完的 `%` 换成空格，会把 `%2http://bit.ly` 拆开。`2` 仍是词字符，Android 不会在这里另开网址。裸域名分支会把 `bit.ly` 误报出来。

## 决策

- 分享 `text`、私聊预填 `tg://msg` 的 `text` 和用户名草稿的 `text`，在抽网址之前把 Android 停住、而这段抽取不停的字符换成空格。
- 紧挨着 `http://`、`https://` 或 `tg://` 的 `%` 也换成空格。
- `%` 后面不是两个十六进制数字，也不是协议时，留在原处。`%2http://bit.ly` 不拆开。
- 查询值不进入正文，也不参与关键词。路径不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续整段抽取 | 竖线和替换字符后面的短链会漏。 |
| 每个不完整的 `%` 都换成空格 | `%2http://bit.ly` 会被裸域名误报。 |
| 隐藏草稿改走可见正文的切分 | 这一轮只补停住字符，不搬整段切分规则。 |

## 后果

- `t.me/share/url?text=https://example.com/%7Chttp://bit.ly/…` 和 `tg://msg?text=` 里同样的短链删除。证据仍只有主机名。
- `%FF` 解码成替换字符后，后面的短链同样删除。
- `%2http://bit.ly` 留着。
- 看得见的正文本来就会停住，行为不变。
