# ADR 0380：私聊可以撤下话题置顶

- 状态：已接受
- 日期：2026-11-04

## 背景

`/unpin` 清空的是聊天的置顶列表。论坛群里，话题还有另一份置顶。诈骗消息钉在通用话题时，上一条命令不会动它。

官方 `unpinAllGeneralForumTopicMessages` 清空通用话题的置顶。参数只有 `chat_id`。`unpinAllForumTopicMessages` 清空一个指定话题，还要 `message_thread_id`。两边都要求 bot 是管理员，并且有 `can_pin_messages`。成功时返回 True。

这两次调用都不返回被撤下的消息号，也不删除消息。

没有 token 时，内存适配器可以把这次请求记下来。私聊如果复用这次成功，回复会写成置顶已经撤下。

## 决策

- 私聊命令 `/untopic <chatId> [threadId]`。群 id 匹配 `^-?\d{1,20}$`。话题号和消息号使用同一条规则：`/^[1-9]\d{0,15}$/`，并且是安全整数。群聊里的同样文本不执行。
- 配置中的管理员可以操作任意群。接入目录里的人只能操作自己的群。
- 不带话题号时调用 `ModerationPort.unpinTopic`，不带 `threadId`。适配器调用 `unpinAllGeneralForumTopicMessages`。
- 带话题号时，同一次请求调用 `unpinAllForumTopicMessages`，只带这个 `message_thread_id`。不把 `1` 改写成通用话题的方法。
- 不调用 `unpinAllChatMessages`，也不删消息。不带消息号。
- 回复写明消息还在。不带话题号时写明其它话题不在这次里。
- 没有 token、没有这个方法，话题号不合法，或调用失败时回复「参数无效」。日志只写 `operator_rejected`，带上 eventId、chatId 和命令名。不写异常文本或 token。
- 没有 token 的 Worker 不把内存里的记录回复成已经成功。
- 不修改黑名单、白名单、封禁或禁言。不读取消息正文。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把话题号 `1` 当成通用话题 | 通用话题有自己的方法，不接收话题号。两条接口的范围官方是分开写的。 |
| 只做通用话题 | 管理员已经知道其它话题的话题号时，仍然要逐条找消息号。 |
| 撤置顶时删除那些消息 | 这两个方法都不返回消息号。删除仍走 `/delete` 和 `/deletes`。 |
| 回复写成消息已经不在 | 成功只表示这一份置顶列表被清空。消息正文还在。 |
| 没有 token 时也回复「已撤下」 | 话题里的置顶还在。管理员会以为已经清掉。 |

## 后果

- 成功只表示 Telegram 接受了这一次话题撤置顶。缺少 `can_pin_messages`，或这个群不是论坛时，回复是「参数无效」。
- 不带话题号时，其它话题的置顶还在。带话题号时，通用话题和别的话题还在。聊天级置顶也不在这次里。
- 一次撤下是一次 Telegram 子请求。封禁、禁言和黑名单都不变。
- 30 天保留期不动。
