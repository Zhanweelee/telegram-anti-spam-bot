# ADR 0715：置顶文字预览上的文字链接只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

置顶一条文字消息时，Android 的 `generatePinMessageText` 先取 `messageText` 的前 20 个 UTF-16 码元，再调用 `addTextStyleRuns`。起点落在这 20 个码元里的 `text_link` 会画成可点的链接。链接地址可以和看得见的字不同。

正文比 20 个码元短时，截出来的就是整段正文。起点落在这段之后的实体不会画上。

Bot API 把这段文字放在 `pinned_message.text`，把链接放在 `pinned_message.entities`。ADR 0653 只从看得见的字里取主机名，所以「点这里」背后的短链会漏掉。

账单说明和清单标题是另一段文字。消息上的 `entities` 对不上这两段。游戏标题不走这段实体。见 ADR 0653、ADR 0654 与 ADR 0714。

这段预览不进正文。关键词不命中这 20 个字，也不命中链接地址。

## 决策

- 置顶预览来自 `text` 时，除了前 20 个码元里的普通网址，还读取 `entities` 里的 `text_link`。
- `offset` 必须是大于等于 0 的安全整数，并且小于实际画出的那段长度。正文更短时，这段长度就是正文长度。
- 只留链接地址里的主机名。看得见的字和路径不进事件。
- 代码块的语言不读。账单说明和清单标题不套用消息上的 `entities`。游戏仍只读标题。
- 富文本预览仍按 ADR 0714。没有文字链接时，普通网址仍按 ADR 0653。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`pin_notice` 仍默认关闭。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 整段正文上的文字链接都读 | 第 21 个码元起的链接没有画在这条提示上。 |
| 正文较短时仍按 20 个码元读 | 客户端只在截出来的那段上画链接。 |
| 把消息实体套到账单和清单上 | 这两段不是 `text`，实体的起点对不上。 |
| 把链接地址抄进正文 | 关键词会命中地址。内容哈希也会变。 |

## 后果

- 置顶文字预览前 20 个码元里的文字链接出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。置顶本身还在。
- 第 21 个码元起的链接、看得见的字和路径不进事件。内容哈希不变。关键词不命中预览。
- 账单、清单和游戏仍按原来的规则。富文本仍按 ADR 0714。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- `pin_notice` 仍默认关闭。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。清单标题上的文字链接后来由 ADR 0716 只留主机名。任务仍不读。文字和清单标题上的文字链接后来由 ADR 0785 要求长度大于 0。长度越过末尾时仍算画出来。代码块语言仍不读。
