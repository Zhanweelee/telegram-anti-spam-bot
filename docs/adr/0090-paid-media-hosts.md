# ADR 0090：付费视频文件名里的网址只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0084 从消息上的 `video.file_name` 抽出网址。付费媒体的视频不在那一层，而在 `paid_media.paid_media[].video.file_name`。说明文字通常在 `caption`。已有说明时，文件名留在事件外面，短链可以只写在文件名里。

把文件名拼进已有正文会改变 `textSha256`。星星数量、文件 id、mime、实况照片和预览尺寸不是文件名。

## 决策

- 从 `paid_media.paid_media` 里每个 `type` 为视频的对象的 `video.file_name` 抽出网址，只留主机名。长度、折叠、邀请判断和 8 个主机名的上限不变。顺序跟数组一致，排在消息本身的文件名之后。
- 已有正文时，文件名原文不进正文，也不改内容哈希。
- 没有更前面的正文时，第一段非空付费视频文件名整段成为正文，并以此计算 `textSha256`。这条正文里的网址由链接规则从正文看见，同时也记在主机名列表里。
- 不读取 `star_count`、`file_id`、`file_unique_id`、`mime_type`、照片、实况照片和预览。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 已有正文时把文件名拼进去 | 文件名会改变哈希。短链只需要主机名。 |
| 只抽最终成为正文的那一个文件名 | 一条付费消息可以带多段视频。后面的文件名里仍可能有短链。 |
| 连实况照片的文件 id 一起抽 | 文件 id 是平台标识。ADR 0084 已经把文件 id 留在事件外面。 |

## 后果

- 已有正文时，付费视频文件名里的 `https://bit.ly/…` 会走现有短链删除。`https://t.me/+…` 和 `https://t.me/%2B…` 只留下 `t.me`，并记成邀请。
- 普通域名仍保留。文件名原文、路径和邀请码在已有正文时不进事件。
- 文件名成为正文时，整段文件名仍参与关键词和内容哈希。
- 星星数量、文件 id、mime、实况照片和预览里的网址仍然不读。
