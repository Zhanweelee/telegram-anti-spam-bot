# ADR 0256：c 用户名仍读 text，私密帖不读

- 状态：已接受
- 日期：2026-11-03

## 背景

桌面端把小写 `c/` 后面的频道数字收成 `tg://privatepost`。查询会留在链接上，`ResolvePrivatePost` 不把 `text` 放进输入框。数字可以带一个负号。末尾斜杠仍对得上这道式子。不是数字的第二段落到用户名式子，收成应用名并写草稿。没有第二段时，`c` 和 `c/` 仍按用户名写草稿。

Android 在路径以小写 `c/` 开头时打开频道，不写聊天草稿。裸的 `c`、大写 `C/` 和不是这条前缀的路径仍按用户名读取 `text`。

`c.t.me` 是单字母子域。桌面端不改写单字母子域。空路径仍按 ADR 0139 不读。

## 决策

- 把 `c` 从保留用户名里拿掉。
- `t.me`、`telegram.me`、`telegram.dog` 以及一层 `www.` 上，`c`、末尾只有一条斜杠、末尾斜杠后面的查询、大写 `C` 后的短名，以及小写 `c/` 后面不是纯数字的短名，都从 `text` 抽主机名。
- 小写 `c/` 后面一段符合 `^-?\d+$` 时不读 `text`。末尾斜杠同样不读。`c.t.me/` 后面同样一段也不读。
- `c.t.me` 没有路径时不读。
- 再多一段路径不读。`c/数字/数字` 仍是讨论串，不读 `text`。
- `tg://resolve?domain=c` 仍读。`tg://privatepost` 不读 `text`。
- 这个主机名走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。`text` 不进入正文，也不参与关键词。
- 用户名、应用名和频道数字不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续把 `c` 放进保留名 | `t.me/c?text=` 会漏掉。两边都把它当成用户名。 |
| 小写 `c/数字` 也读 `text` | 桌面端收成 `tg://privatepost` 后丢掉 `text`。Android 打开频道，也不写聊天草稿。 |
| 大写 `C/数字` 不读 | Android 的 `startsWith("c/")` 区分大小写，仍按用户名写草稿。 |
| 小写 `c/带点的短名` 不读 | 桌面端对不上私密帖式子，仍收成应用名并写草稿。 |
| 空的 `c.t.me` 也读 | 单字母子域桌面端不改写。ADR 0139 已把这类子域留在外面。 |

## 后果

- `t.me/c`、`t.me/c/`、`tg://resolve?domain=c`、`t.me/C/slug.223`、`t.me/C/223`、`t.me/c/slug.223` 和 `t.me/c/slug223/` 的 `text` 是裸 IP、默认短链或邀请时删除。证据仍只有主机名。
- `t.me/c/223?text=`、`t.me/c/-100223?text=` 和 `t.me/c/223/?text=` 仍不读 `text`。
- `c.t.me` 没有路径时留着。`c.t.me/数字` 和 `c.t.me/短名` 留着。
- `t.me/c/223/456` 和 `t.me/c/短名/再一段` 留着。
- 用户名、应用名和频道数字不进证据。
