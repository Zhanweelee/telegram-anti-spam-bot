# ADR 0092：音频表演者里的网址只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0062 在没有更前面的正文时，用音频标题或文件名当正文，并明确 `audio.performer` 不进事件。ADR 0084 从标题和文件名抽主机名，同时把表演者和贴纸包名留在外面。播放器上的表演者是发送者或音频标签里的自由文字，短链可以只写在这里。

贴纸包名仍然不是这类文字。Telegram 要求包名只含英文字母、数字和下划线，并且以 `_by_<bot>` 结尾，放不进网址，也放不进中文关键词。

## 决策

- 从 `audio.performer` 抽出网址，只留主机名。长度、折叠、邀请判断和 8 个主机名的上限不变。顺序在音频标题和 `file_name` 之后。
- 已有正文时，表演者原文不进正文，也不改内容哈希。文件名或音频标题算已有正文。
- 没有更前面的正文时，表演者整段成为正文，并以此计算 `textSha256`。它排在媒体名称之后、按钮文字之前。
- 不读取贴纸的 `set_name` 和 `emoji`，也不读取 `file_id`、`file_unique_id`、`mime_type`、缩略图、语音和视频笔记。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 已有标题时把表演者拼进正文 | 表演者会改变哈希。短链只需要主机名。 |
| 连贴纸包名一起抽 | 包名是标识，字符集放不进网址。ADR 0052 和 ADR 0062 已经把它留在事件外面。 |
| 表演者继续完全不读 | 播放器上看得见这段字。短链写在这里就能绕过链接规则。 |

## 后果

- 已有正文时，表演者里的 `https://bit.ly/…` 会走现有短链删除。`https://t.me/+…` 和 `https://t.me/%2B…` 只留下 `t.me`，并记成邀请。
- 普通域名仍保留。表演者原文、路径和邀请码在已有正文时不进事件。
- 表演者成为正文时，整段文字仍参与关键词和内容哈希。
- 贴纸包名、文件 id 和 mime 里的网址仍然不读。有音频标题或文件名时，表演者里的关键词不参与比较。
