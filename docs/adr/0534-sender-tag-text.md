# ADR 0534：正文旁边的成员标签也走关键词和默认正则

- 状态：已接受
- 日期：2026-11-05

## 背景

ADR 0112 在已有正文时只从 `sender_tag` 抽出主机名。标签原文不进正文，也不改 `textSha256`。短链和邀请因此仍会删除，写在标签里的「免费领取」或「加微x」却看不见。

Telegram 的成员标签最多 16 个字符。标签自己成为正文时，现有关键词已经能读到整段。`regex_hint` 仍默认关闭，所以标签单独成文时「加微x」继续留下。

## 决策

- 已有别的正文，且标签去掉空白后仍有字时，事件另留 `senderTag`。只留去掉空白后的前 16 字。
- 标签自己就是正文时不设这个字段。正文和 `textSha256` 仍按 ADR 0112。
- 关键词和 `regex` 同时看正文、`senderTag` 和 `profile`。证据仍是原来的摘要。标签原文不进证据，也不进日志。
- 规则条件增加 `senderTag: true`。消息上有这个字段时为真。
- 新规则 `sender_tag_regex` 默认打开。条件是 `senderTag`，检测器是现有的 `regex`，命中后 `delete`。
- 「免费领取」和「加微信」仍走已经打开的关键词规则。
- `regex_hint` 仍默认关闭。关掉它不会关掉 `sender_tag_regex`。
- 不改 ADR 0026 的基础检测器名单。`keyword` 和 `regex` 已经在里面，超额后这两条仍会跑。
- `chats.json` 整份替换的群不会自动带上 `sender_tag_regex`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 默认打开 `regex_hint` | 普通消息会被同一份模式删除。这次要读的是正文旁边的标签。 |
| 把标签拼进正文 | 会改变 `textSha256`。ADR 0112 已经拒绝。 |
| 新增 `/regex` | 菜单只剩最后一格。按群追加模式这次不做。 |

## 后果

- 正文旁边的标签含「免费领取」或「加微信」时，按关键词删除。含 `t.me/+`、「加微x」或「加微X」时，按 `sender_tag_regex` 删除。证据不含标签原文。
- 标签干净时消息留下。标签自己就是正文时，「加微x」仍要打开 `regex_hint`。
- 第 17 个字符起不进事件。主机名仍从整段标签抽取。
- 关掉 `sender_tag_regex` 后，这种标签回到只看关键词和短链。
- 整份替换规则的群要自己加上这条，才会删除标签上的「加微x」。
- 30 天保留期没有改。
