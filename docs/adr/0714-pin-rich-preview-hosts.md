# ADR 0714：置顶富文本预览只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

置顶一条富文本时，Android 先用 `formatRichMessage` 拼出最多 1024 个码元的预览，再由 `generatePinMessageText` 画出前 20 个 UTF-16 码元。这条预览不是 `text`，也不是整篇文章。

段落、标题、预格式、页脚、可折叠引用、引语和思考画可见文字。折叠块只画摘要。普通引用画里面的块。列表按项拼接。表格只画标题，格子不画。音频画表演者与标题，两边都空时才画文件名。文件画文件名。按钮画按钮文字。图片、视频、动图、拼图、幻灯片、地图和公式是固定说法。

Bot API 把这篇文章放在 `pinned_message.rich_message`。ADR 0653 只读 `text`、账单说明、清单标题和游戏标题，所以富文本预览里的短链会漏掉。

这段预览不进正文。关键词不命中这 20 个字。

## 决策

- `pinned_message.rich_message` 是对象时，按上面的预览拼出文字，只读前 20 个 UTF-16 码元里的主机名。不再改读 `text`。
- 文字链接的可见文字从这 20 个码元里开始时，才读它的地址。按钮地址同样只在按钮文字画进这 20 个码元时才读。
- 表格只读标题。格子、引用署名、公式正文和地图说明不读。
- 音频同时有标题和表演者时不读文件名。两边都空时才读文件名。
- 图片、视频、动图、拼图、幻灯片、地图和公式是固定说法，占满剩下的 20 个码元，后面的块不读。
- 预览不进正文，内容哈希不变。没有富文本时，文字、账单、清单和游戏仍按 ADR 0653 与 ADR 0654。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`pin_notice` 仍默认关闭。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 整篇文章都读 | 置顶提示只画前 20 个码元。后面的短链没有画在这条提示上。 |
| 仍改读 `text` | 有富文本时客户端画的是预览，不是 `text`。 |
| 表格格子也读 | 预览只画表格标题。格子要打开表格才看得到。 |
| 固定说法后面的段落也读 | 固定说法的长度随语言变。少读比把没画出来的短链删掉更稳。 |
| 把预览抄进正文 | 关键词会命中这 20 个字。内容哈希也会变。 |

## 后果

- 置顶富文本预览的前 20 个码元里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。置顶本身还在。
- 第 21 个码元起的路径、表格格子、图片说明、音频文件名和被置顶的人不进事件。内容哈希不变。关键词不命中预览。
- 有富文本时不读旁边的 `text`。没有富文本时，文字、账单、清单和游戏仍按原来的规则。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- `pin_notice` 仍默认关闭。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
- 思考块后来由 ADR 0718 从这份预览里拿掉。气泡里的整篇文章仍读。
- 提及、日期和表情替代字后来由 ADR 0719 也从这份预览里拿掉。
