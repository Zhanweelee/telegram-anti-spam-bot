# ADR 0379：私聊可以查看管理员编号和权限

- 状态：已接受
- 日期：2026-11-04

## 背景

突袭之后，群里可能多出一个能删消息、能禁言或能继续拉人的管理员，也可能是另一个机器人。管理员要在私聊里看见这份名单，才能决定接下来封禁或调整权限。

官方 `getChatAdministrators` 返回一组 `ChatMember`。默认不带 `return_bots` 时，除了当前这个 bot，其它管理员机器人会被漏掉。

返回对象里有姓名、用户名和可选的自定义头衔。这些不能进回复或日志。`can_be_edited` 表示当前 bot 能不能改这个人的权限，不是这个人自己的权限。

创建者的对象写明拥有全部管理权限，但没有逐项 `can_*`。把缺省写成关闭，会让创建者看起来什么都不能做。

名单变长时，一条回复仍要落在 3500 个字符以内。

没有 token 时，内存适配器没有这份名单。私聊如果编一份，管理员会以为群里只有这些人。

## 决策

- 私聊命令 `/admins <chatId>`。群 id 匹配 `^-?\d{1,20}$`。群聊里的同样文本不执行。
- 配置中的管理员可以查看任意群。接入目录里的人只能查看自己的群。
- 命令调用 `ModerationPort.readAdministrators`。适配器调用 `getChatAdministrators`，`return_bots` 为 true。
- 每个管理员只保留编号、是否机器人、`creator` 或 `administrator`、是否匿名，以及值为 true 的权限。显式 false 和缺省都不进名单。创建者的权限列表为空。`can_be_edited`、姓名、用户名和自定义头衔丢掉。
- 回复按 Telegram 返回的顺序逐行写。一行放不下全部权限时仍写在同一行。全部行放不下时，按原顺序保留前面的若干人，并写上剩下的个数。没有管理员时，标题下面写 `none`。
- 权限顺序固定为：管理、删除、视频、限制、提升、资料、邀请、故事、改故事、删故事、发帖、编辑、置顶、话题、私信、标签、欢迎。
- 没有 token、没有这个方法，或调用失败时回复「参数无效」。日志只写 `operator_rejected`，带上 eventId、chatId 和命令名。不写异常文本或 token。
- 没有 token 的 Worker 不编造名单。
- 不修改黑名单、白名单、封禁、禁言或管理员。不读取消息正文。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 使用默认的 `getChatAdministrators` | 其它管理员机器人会被漏掉。突袭用的常常就是另一个 bot。 |
| 回复姓名和自定义头衔 | 这些字段能认出人，也会把对方的名字写进日志链路。编号已经够管理员对照。 |
| 把创建者的缺省权限全部写成打开 | 对象里没有这些字段。编出来的开关和 Telegram 实际返回的不是同一份。角色本身已经表示拥有全部权限。 |
| 把 false 也逐项写上 | 一个人一行就会超过回复长度。标成 true 的权限才是要看的能力。 |
| 没有 token 时回复空名单 | 空名单和「这个群没有管理员」分不清。应回复「参数无效」。 |

## 后果

- 成功只表示 Telegram 返回了一组管理员对象。bot 不在群里，或对方不是群和频道时，回复是「参数无效」。
- 创建者那一行没有权限词。这表示文档里的全部权限，不是一项都没有。
- 一个人的管理员身份另由 `/canadmin` 读取，见 ADR 0433。`/admins` 仍按 3500 个字符截断，创建者的权限列表仍为空，仍不写 `can_be_edited` 和自定义头衔。
- 私聊可以写 `skip <count>`，从后面的管理员继续列。不写 `skip` 时仍是这一页。见 ADR 0527。
- 一次查看是一次 Telegram 子请求。管理员、封禁和禁言都不变。
- 30 天保留期不动。
