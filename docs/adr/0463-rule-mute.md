# ADR 0463：每个群可以改规则禁言时长

- 状态：已接受
- 日期：2026-11-04

## 背景

ADR 0004 把规则命中后的禁言时长放在动作配置里。Worker 固定写成 3600 秒。云上的群管可以用 `/rule` 把一条规则换成 `mute`，却不能改这次自动禁言持续多久。ADR 0365 的私聊 `/mute` 可以给一个人指定秒数，并且明确不写秒数时不读动作配置。

## 决策

- `RuntimeStore` 增加 `getMuteDuration`、`setMuteDuration`、`clearMuteDuration`。一个群一个整数秒。
- 秒数是 30 到 366 天的整数，含两端。短于 30 秒或长于 366 天时 Telegram 会把成员当成永久限制，所以不接受。
- 没设置时仍是 3600 秒。写成 3600，或 `reset`，都删掉记录。
- 私聊 `/rulemute <chatId>` 只读。`/rulemute <chatId> <seconds>` 写入。`reset` 回到 3600 秒。
- 这条命令只改规则命中后的 `mute` 动作。私聊 `/mute` 不写秒数时仍是 3600 秒，写出的秒数仍只作用于那一个人。
- 内存最多 256 个群，和重复、洪泛、关键词、开关各用一份名额。已有的群可以改。新群放不下时回复「参数无效」，日志是 `mute_duration_full`。
- 配了 `POLICY_KV` 时写在 `runtime-mute` 键。原来的运行时文档、动作键、上报键、洪泛键、关键词键和重复键都不改。坏文档读成没设置。每个 isolate 缓存 60 秒。相同的值不写。
- 群聊里的同样文本不执行。接入目录里的人只能改自己的群。读或写失败回复「参数无效」，日志是 `operator_rejected`。不写姓名、消息原文或 token。这条命令不调用 Telegram。
- 检测在创建 `mute` 动作之前读这份记录。读失败时记 `runtime_failed`，按 3600 秒继续。
- 不改 `default.json`，不改验证时长。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把秒数写进现有运行时文档 | 旧 Worker 看到多出来的字段会把开关和 dry-run 一起丢掉。 |
| 让 `/mute` 不写秒数时改用这份记录 | ADR 0365 已经拒绝把一次手动禁言和自动处罚绑在一起。 |
| 把默认改成别的数字 | 现在禁言一小时的群会被另一段时长重新计算。默认要另一次决定。 |
| 接受 1 到 29 秒 | Telegram 会把这段限制当成永久。回复里的秒数会短于实际限制。 |

## 后果

- `/rulemute -100 120` 之后，这个群里规则命中的 `mute` 限制 120 秒。别的群仍是 3600 秒。
- `/mute -100 77` 仍限制 3600 秒。
- 菜单多一条 `/rulemute`，一共 96 条。
- 云额度的基础检测器名单没有改。30 天保留期没有改。
