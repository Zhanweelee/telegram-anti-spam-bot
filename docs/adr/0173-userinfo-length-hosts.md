# ADR 0173：放不下的用户信息后面打开的主机名也留下

- 状态：已接受
- 日期：2026-11-02

## 背景

Android `LinkifyPort.WEB_URL` 的用户信息最多 64 个字符，冒号后面的密码最多 25 个。超出之后，这一段不再算用户信息。后面如果还有网址，会再打开一次。

`http://` 加 65 个 `a` 再接 `@http://bit.ly/…` 因此会打开 `bit.ly`。整段仍当成用户信息时，主机名只剩 `@` 后面的 `http`。64 个字符刚好放得下，`@http` 仍是这一段的主机名，不会单独打开后面的短链。26 个字符的密码也一样。没有 `@`、直接粘上的长串不会给后面的协议留出单词边界。

## 决策

- 用户信息按 Android 的上限读取：用户名 1 到 64 个字符，密码 1 到 25 个字符。`%HH` 仍算一个字符。
- 放不下时不把这一段当成用户信息。后面的网址按自己的一段来抽主机名。
- 放得下、并且 `@` 后面接得上时，仍按整段用户信息和主机名判断。
- 每段仍走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。用户名和密码不进证据。
- 切开之后单独的邀请地址仍按邀请读取。超长密码挡住的 `/+…` 不改记成邀请。
- 已经写在 `text_link`、按钮或其它结构化字段里的地址整段打开。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 不限长度，整段只留 `@` 后面的主机名 | 放不下的用户信息后面，短链和裸 IP 点得开。 |
| 超长标签也在这里截断 | 没有 `@`、直接粘上的长串，后面的协议没有单词边界。 |
| 超长密码后面的路径改记成邀请 | `t.me:` 加超长密码再接 `/+…` 打开的是没有这段路径的主机名。 |

## 后果

- 65 个字符的用户名再接 `@http://bit.ly/…`，以及 26 个字符的密码再接 `@http://t.co/…` 或 `@http://203.0.113.140/…`，按现有短链或裸 IP 规则删除。证据仍只有主机名。
- 64 个字符的用户名或 25 个字符的密码再接 `@http://bit.ly/…` 留着。65 个字符直接粘上 `http://bit.ly/…` 留着。
- 放得下的 `user:pass@bit.ly/…` 和 64 个字符再接 `@bit.ly/…` 仍按短链删除。`http://bit.ly@example.com` 留着。
- `https://t.me:` 加 26 个字符再接 `@/+…` 不记成邀请。放不下的用户信息后面单独的 `https://t.me/+…` 按邀请删除。路径不进证据。
