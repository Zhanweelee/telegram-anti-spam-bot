# ADR 0384：私聊可以显示通用话题

- 状态：已接受
- 日期：2026-11-04

## 背景

`/hidegeneral` 把通用话题从列表里拿掉。误藏或者风波过去之后，管理员需要把它放回来。

官方 `unhideGeneralForumTopic` 显示通用话题。参数只有 `chat_id`。bot 必须是管理员，并且有 `can_manage_topics`。成功时返回 True。

这条方法不重新打开。通用话题当时关着，显示之后仍然关着。重新打开是 `reopenGeneralForumTopic`，那一次才会把隐藏的通用话题一起显示出来。

它不接收话题号，也不删除消息。

没有 token 时，内存适配器可以把这次请求记下来。私聊如果复用这次成功，回复会写成通用话题已经显示，也会让人以为它已经打开。

## 决策

- 私聊命令 `/showgeneral <chatId>`。群 id 匹配 `^-?\d{1,20}$`。多出来的参数不发出请求。群聊里的同样文本不执行。
- 配置中的管理员可以操作任意群。接入目录里的人只能操作自己的群。
- 调用 `ModerationPort.showGeneral`。适配器调用 `unhideGeneralForumTopic`，只带 `chat_id`。
- 不调用 `reopenGeneralForumTopic`、`hideGeneralForumTopic` 或 `deleteForumTopic`。不带话题号，也不带消息号。
- 回复写明原先关着的通用话题仍然关着，消息还在，其它话题不在这次里。
- 没有 token、没有这个方法，群号不合法，或调用失败时回复「参数无效」。日志只写 `operator_rejected`，带上 eventId、chatId 和命令名。不写异常文本或 token。
- 没有 token 的 Worker 不把内存里的记录回复成已经成功。
- 不修改黑名单、白名单、封禁或禁言。不读取消息正文。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 显示时再调一次重新打开 | 显示和打开是两条接口。重新打开会把隐藏的通用话题一起显示出来，范围比这一次更大。 |
| 接受话题号并显示指定话题 | 这条方法只作用于通用话题，不接收话题号。 |
| 回复写成话题已经打开 | 成功只表示通用话题重新出现在列表里。关着的话题仍然关着。 |
| 没有 token 时也回复「已显示」 | 通用话题还藏着。管理员会以为成员已经看得到。 |

## 后果

- 成功只表示 Telegram 接受了这一次显示。缺少 `can_manage_topics`，或这个群不是论坛时，回复是「参数无效」。
- 其它话题保持原样。消息还在。原先关着的通用话题仍然关着。
- 一次显示是一次 Telegram 子请求。封禁、禁言和黑名单都不变。
- 30 天保留期不动。
