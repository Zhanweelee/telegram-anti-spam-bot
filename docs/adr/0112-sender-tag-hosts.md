# ADR 0112：成员标签只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

超级群里，普通成员的消息可以带 `sender_tag`。这是显示在发送者旁边的标签，最多 16 个字符，足够放下一条短链或邀请。正文可以是另一句普通的话。

ADR 0101 只读这条消息自己的 `author_signature`。那是频道签名或匿名管理员的自定义头衔。成员标签是另一个字段。群名、真实姓名和转发来源上的签名仍不是这条消息的标签。

把标签拼进已有正文会改变 `textSha256`。

## 决策

- 从这条消息自己的 `sender_tag` 抽出网址，只留主机名。折叠、长度、邀请判断和 8 个主机名的上限与旁路纯文本相同。
- 已有正文时，标签原文不进正文，也不改内容哈希。
- 没有更前面的正文，且没有作者签名时，标签整段成为正文，并以此计算 `textSha256`。已有作者签名时，签名仍是正文，标签只留主机名。
- 不读取群名、用户姓名、用户名，以及 `forward_origin` 上的签名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 已有正文时把标签拼进去 | 标签会改变哈希。短链只需要主机名。 |
| 连群名和真实姓名一起抽 | 那不是这条消息上的标签。群名和姓名不进事件。 |
| 标签整段都不读 | 短链可以只写在这行看得见的字里。 |

## 后果

- 已有正文时，标签里的短链、邀请或裸 IP 按现有链接规则命中。路径和邀请码不进事件。
- 标签成为正文时，整段标签仍参与关键词和内容哈希。路径留在正文里。
- 已有作者签名时，签名仍是正文。群名和真实姓名不进事件。
