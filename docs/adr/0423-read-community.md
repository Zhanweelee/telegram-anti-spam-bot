# ADR 0423：私聊可以查看群所属社区

- 状态：已接受
- 日期：2026-11-04

## 背景

几个群可以挂在同一个社区下面。反垃圾要知道这个群是不是社区的一部分，才不会把跨群联动看成互不相关的入群。这个信息在 `getChat` 返回的 `ChatFullInfo.community` 里。值是一个 `Community`，有编号和名字。

文档没有把这个字段限制成只对管理员返回。缺字段表示这个群不属于社区。名字可能带链接，不进这次回复。

## 决策

- 私聊命令 `/community <chatId>`。群 id 匹配 `^-?\d{1,20}$`。多出来的参数不发出请求。群聊里的同样文本不执行。
- 配置里的管理员可以看任意群。接入目录里的人只能看自己的群。
- 调用 `ModerationPort.readCommunity`。适配器调用 `getChat`，只带 `chat_id`。
- 回复两行：群号、社区编号。没有 `community` 时写无。
- 名字不是字符串、编号不是正的安全整数、或返回的群号和请求不一致时，整份回复是「参数无效」，不露出已经读到的字段。
- 名字、标题和邀请链接不进回复，也不进日志。
- 日志只写 `operator_rejected` 或命令名，带上 eventId、chatId 和命令名 `community`。不写名字、异常文本或 token。
- 没有 token 的 Worker 不编一个编号。
- 不调用 `setChatPermissions`，也不改黑名单、封禁或禁言。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 缺字段写成未知 | 文档没有说这个字段只对管理员返回。缺字段就是不属于社区。 |
| 回复里带上名字 | 名字可能是原文。编号够用来对上同一个社区。 |
| 并进 `/guard` | `/guard` 已经是一长串开关。社区是另一件事。 |

## 后果

- 成功只表示 Telegram 返回了这个群当前的社区编号，或这个字段没有返回。
- 一次查看是一次 Telegram 子请求。`/guard`、`/perms`、`/joinbot` 和 `/reactions` 仍是各自的 `getChat`。封禁、禁言和黑名单都不变。
- 30 天保留期不动。
