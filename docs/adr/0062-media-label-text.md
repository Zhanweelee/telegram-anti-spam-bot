# ADR 0062：文件名和音频标题在没有正文时进入正文

- 状态：已接受
- 日期：2026-11-01

## 背景

动图、视频、音频和普通文件经常没有 `text` 和 `caption`。用户能看见的是文件名，音频播放器还会显示标题。关键词只看已经收成正文的字符串，所以「免费领取.pdf」会绕过去。ADR 0052 让同一份文件按摘要参加重复，并明确文件 id 和贴纸包名不进事件。文件名不是平台标识，它和标题是同一类可见文字。

## 决策

- 没有更前面的正文时，按 `animation`、`video`、`audio`、`document` 的顺序取第一个名称。音频先用 `title`，没有标题再用 `file_name`。其它三类只用 `file_name`。截断到 4096，并以此计算 `textSha256`。
- 这段名称排在场馆标题之后、手动引用之前。已有 caption 或更早的回退时，文件名不参与比较。
- `file_id`、`file_unique_id`、`mime_type`、缩略图、`audio.performer`、贴纸的 `set_name` 和 `emoji`、语音和视频笔记不进事件。`media` 和 `mediaSha256` 仍按 ADR 0052。
- 不新增检测器，也不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 另做文件名检测器并默认关闭 | 操作者要先打开它。关键词名单已经够用。 |
| 把文件名接在 caption 后面 | 同一条消息变成两段正文，哈希会偏。 |
| 贴纸包名也当正文 | 包名更像用户名。ADR 0052 已经把它留在事件外面。 |

## 后果

- 文件名或音频标题里的「免费领取」会命中现有关键词。链接检测也扫描这段正文，所以文件名里的短链会命中 `links`。`report.pdf` 这种普通后缀仍按普通主机名保留。
- 名称成为正文之后，重复按 `textSha256` 计次，不再按文件摘要。三份不同文件如果叫同一个名字，会算成同一次重复。
- 表演者、贴纸包名、文件 id 和 mime 里的关键词仍然看不到。
- 已有说明、标题或题干时，文件名不参与比较。有文件名时，手动引用上的短链也不参与比较。
- 按钮文字后来由 ADR 0063 排在文件名之后。有文件名时，按钮上的关键词不参与比较。
