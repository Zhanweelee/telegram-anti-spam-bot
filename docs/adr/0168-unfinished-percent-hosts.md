# ADR 0168：没写完的百分号后面打开的主机名也留下

- 状态：已接受
- 日期：2026-11-02

## 背景

Android `LinkifyPort.WEB_URL` 的路径只收完整的 `%` 加两位十六进制。写到一半的 `%` 会结束当前匹配。后面如果还有网址，会再打开一次。

`http://example.com%http://bit.ly/…` 和 `http://example.com/%http://bit.ly/…` 因此会打开 `bit.ly`。整段当成一个地址时，主机名只剩 `example.com`。`%20` 这种完整编码仍留在路径里，只打开前面的网站。`%2G` 不是两位十六进制，而且 `G` 是单词字符，后面的 `http://` 没有单词边界，不会再打开。斜杠本身仍属于路径。

## 决策

- 抽网址时，`%` 只有凑成两位十六进制才留在这一段里。没写完的 `%` 结束这段，后面的网址按自己的一段来抽主机名。
- 协议紧挨着 ASCII 单词字符（字母、数字、下划线）时不算下一段。`://` 后面的主机名也不再读一次。
- 每段仍走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 切开之后单独的邀请地址仍按邀请读取。同一段里被百分号挡住的路径不改记成邀请。
- 已经写在 `text_link`、按钮或其它结构化字段里的地址整段打开。完整的 `%HH` 仍留在分享链接的参数里。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 整段只留第一个主机名 | 没写完的百分号后面的短链和裸 IP 点得开。 |
| 每个 `%` 都切开 | `%20` 和 `%3A%2F%2F` 仍在路径或参数里，后面的地址不会单独打开。 |
| 被挡住的路径改记成邀请 | `t.me%/+邀请码` 打开的是没有这段路径的主机名。 |

## 后果

- `http://example.com%http://bit.ly/…`、`http://example.com/%http://bit.ly/…` 和 `http://news.example%http://203.0.113.135/…` 按现有短链或裸 IP 规则删除。证据仍只有主机名。
- `http://example.com/%20http://bit.ly/…`、`http://example.com%2Ghttp://bit.ly/…` 和 `http://example.com/http://bit.ly/…` 留着。
- 协议粘在字母或下划线上时不单独记成链接。`https://t.me%/+…` 不记成邀请。`http://example.com/%http://t.me/+…` 按邀请删除。路径不进证据。
