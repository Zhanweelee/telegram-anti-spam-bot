# ADR 0046：规则包归档在内容变化时写入已有的 KV

- 状态：已接受
- 日期：2026-11-01

## 背景

ADR 0037 把订阅指针放进 `POLICY_KV`，上一份通过 schema 的规则仍留在内存。Worker 重启后，包 id 还在，但刷新失败时没有上一份规则，检测回到本地规则，直到 `packs.json` 再次读成功。

当时没有把归档一起放进 KV，是因为成功刷新大约每 60 秒一次。如果每次都写，已订阅的群会打满免费计划每天大约 1,000 次写。

## 决策

- 不新增绑定。配了 `POLICY_KV` 时用 `createKvRulePackArchive`。每个群、每个 pack id 一个键，前缀是 `pack-rules`，值是 `RuleSet` 的 JSON。
- 没配 `POLICY_KV` 时仍用内存归档。
- 写入前先和本 isolate 缓存或 KV 里的 JSON 比较。相同就不写。缓存 60 秒。发出写入的 isolate 立刻能读到新值。
- JSON 超过 16384 个字符时不写，`put` 抛出 `pack_archive_too_large`。调用方已有的 `pack_archive_failed` 接住它，这次检测仍用刚读到的规则。
- 坏文档读成没有归档，热路径不回写。
- 不改 ADR 0026 的默认额度，也不把额度计数写进 KV。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 每次刷新成功都写 | ADR 0037 已经拒绝。忙群会打满每天的写额度。 |
| 和订阅指针放在同一个键 | 订阅值只有 pack id。规则文档变大之后，每次 `/packs` 都要带走整份规则。 |
| 不设字符上限 | 一份异常大的规则集会占满 KV 的值。 |

## 后果

- 配了 `POLICY_KV` 之后，重启仍记得上一份没超过上限的规则。刷新失败时可以继续用它。
- 规则没变时，过期后的比较最多读一次 KV，不写。
- 超过上限的规则包重启后仍要等下一次成功读取。
- 提交的 `wrangler.jsonc` 仍不写 KV id。
