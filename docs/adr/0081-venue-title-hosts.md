# ADR 0081：场馆标题里的网址只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0059 在没有更前面的正文时，用 `venue.title` 当正文。已有正文时，标题留在事件外面。ADR 0080 从地址抽出主机名，标题里的短链或邀请在已有正文时仍然看不到。

把标题拼进已有正文会改变 `textSha256`。地点类型字段仍不是标题。

## 决策

- 从 `venue.title` 里抽出网址，只留主机名。长度、折叠、邀请判断和 8 个主机名的上限不变。顺序在地址之前。
- 已有正文时，标题原文不进正文，也不改内容哈希。
- 没有更前面的正文时，标题仍整段成为正文。这条正文里的网址由链接规则从正文看见，同时也记在主机名列表里。
- 不读取坐标、地点 id 和地点类型。地址仍按 ADR 0080。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 已有正文时把标题拼进去 | 标题会改变哈希。短链只需要主机名。 |
| 只在标题不是正文时才抽 | 多一条分支。标题成为正文时，主机名列表仍应带上同一条网址。 |
| 连地点类型字段一起抽网址 | 那两个字段是类型标签。ADR 0080 已经把它们留在外面。 |

## 后果

- 已有正文时，标题里的 `https://bit.ly/…` 会走现有短链删除。`https://t.me/+…` 和 `https://t.me/%2B…` 只留下 `t.me`，并记成邀请。
- 普通域名仍保留。标题原文、路径和邀请码在已有正文时不进事件。
- 标题成为正文时，整段标题仍参与关键词和内容哈希。
- 地址里的关键词仍然看不到。地点类型字段里的网址仍然不读。
- 场馆标题原文后来由 ADR 0545 留在旁路字段。已有正文时，关键词和默认正则看这段标题。坐标和地点编号仍不进事件。
