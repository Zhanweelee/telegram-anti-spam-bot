# ADR 0176：没有斜杠的 tg: 后面打开的主机名也留下

- 状态：已接受
- 日期：2026-11-02

## 背景

Android `LinkifyPort.WEB_URL` 的协议是 `tg://`，两个斜杠不能少。`tg:http://bit.ly/…` 和 `tg:203.0.113.143/…` 因此打开的是后面的短链或裸 IP。`tg://http://bit.ly/…` 整段是一条 `tg://` 链接，主机名只到 `http`，后面的 `bit.ly` 不会再打开。`tg://msg?…&to=198.51.100.20` 也整段属于这一条链接。

## 决策

- 只有 `tg://` 盖住它内部的主机名。没有两个斜杠的 `tg:` 不盖住后面的网址。
- 后面的网址仍走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- `tg://` 里面的 `text`、`url` 和代理参数仍按原来的规则读。`to=` 不单独抽主机名。
- 没有斜杠的 `tg:join?invite=` 仍按邀请读取。`tg:https://t.me/+…` 按它自己的邀请读取。
- 已经写在 `text_link`、按钮或其它结构化字段里的地址整段打开。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 所有 `tg:` 都盖住内部地址 | `tg:http://bit.ly` 点得开的是 `bit.ly`。 |
| 把 `tg://` 的主机名也当成明网地址 | `tg://http://bit.ly` 打开的是 `tg://http`，不是后面的短链。 |
| 没有斜杠的 `tg:join` 不再记邀请 | 这条深链本来就会打开邀请。 |

## 后果

- `tg:http://bit.ly/…`、`see tg:http://t.co/…` 和 `tg:203.0.113.143/…` 按现有短链或裸 IP 规则删除。证据仍只有主机名。
- `tg://http://bit.ly/…` 和 `tg://203.0.113.143/…` 留着。`tg://msg?…&to=198.51.100.20` 不因为这个参数删除。
- `tg:join?invite=…` 和 `tg:https://t.me/+…` 仍按邀请删除。邀请码和路径不进证据。
- 裸域名和裸 IP 的问号仍属于这一段。见 ADR 0177。
