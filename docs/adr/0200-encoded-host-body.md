# ADR 0200：编码分隔符不再拼出编码主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

Android 不会在匹配前把主机名里的 `%HH` 收成字母，也不会把 `%2E` 收成点。`%2Bb%69t.ly/…`、`%2Fb%69t.ly/…`、`%2Db%69t.ly/…` 和 `%252Db%69t.ly/…` 打开的是 `69t.ly`。`%2Bbit%2Ely/…` 和 `%2B203%2E0%2E113%2E10/…` 什么都不打开。`%2Bb%2569t.ly/…` 打开的是 `2569t.ly`。

换行或制表符隔开时也一样。`example.com%2B\nb%69t.ly/…` 打开的是 `example.com` 和 `69t.ly`。字面短链隔着换行仍会打开。`example.com%2B\nbit.ly/…` 打开 `bit.ly`。

最后一个点是字面点时，Android 会把后面的路径挂在自己打开的主机名上。`%2Bb%69t.ly/http://t.co/…` 只打开 `69t.ly/http://t.co/…`。最后一个点是 `%2E` 时，前面没有主机名，后面的网址会打开。`%2Bbit%2Ely/http://t.co/…` 打开 `http://t.co/…`。

`%2B2b%77ww.bit.ly/…` 打开的是 `77ww.bit.ly`。这个主机名仍以 `.bit.ly` 结尾。单独的 `b%69t.ly`、`bit%2Ely` 和 `http://b%69t.ly/…` 仍按已有规则删除。路径里的 `t.me/%2B…` 仍是邀请。`%252B` 不是加号，`%252E` 不是点。

粘连扫描如果先把 `%69` 收成 `i`、把 `%2E` 收成点，`%2Bb%69t.ly` 会变成 `+bit.ly`，`%2Bbit%2Ely` 会变成 `+bit.ly`，`%2B203%2E0%2E113%2E10` 会变成一条裸 IP。

## 决策

- 紧挨在主机名前面、而且不在路径里的 `%2B`、`%2F`、`%2D` 和 `%252D`，在主机名本身还含有百分号时也换掉。百分号可以是字母或数字的 `%HH`、`%25HH`，或一层点 `%2E`。路径是前面已经有 `/` 或 `%2F`。`%2F` 仍在协议收完之后处理。
- 换行和制表符去掉之后，只处理主机名里还有百分号的那一种。字面主机名隔着这些间隔仍收成原来的字符。
- 最后一个点是字面点时，保留标签和路径，最后一段换成 `arpa`，前面加 `!`。点分 IPv4 仍换成 `!0.arpa`。
- 最后一个点是 `%2E` 时，整段换成 `!`。后面的 `/http://` 或 `/bit.ly` 仍会打开。`%252E` 仍不是点。
- 单独的 `b%69t.ly`、`bit%2Ely` 和 `http://b%69t.ly` 仍按原规则收成短链。`bit%2Dly` 仍收成 `bit-ly`。
- 每段仍走现有的短链、裸 IP、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 主机名里的 `%HH` 一律不再解码 | 单独的 `b%69t.ly` 会漏掉。 |
| 一律换成 `arpa` | `%2Bbit%2Ely/http://t.co/…` 会把后面的短链盖住。 |
| 只改 `%2B`，不改 `%2F` 和 `%2D` | `%2Fb%69t.ly` 和 `%2Db%69t.ly` 仍会收成 `bit.ly`。 |

## 后果

- `%2Bb%69t.ly/…`、`%2Bbit%2Ely/…`、`%2Fb%69t.ly/…`、`%2Fbit%2Ely/…`、`%2Db%69t.ly/…` 和 `%252Db%69t.ly/…` 留着。换行后面的 `b%69t.ly` 留着。
- `%2B203%2E0%2E113%2E167/…` 留着。`%2Bb%69t.ly/http://…` 留着。
- `b%69t.ly`、`bit%2Ely`、`http://b%69t.ly/…`、空格后面的 `b%69t.ly` 和换行后面的字面 `bit.ly` 仍按短链删除。
- `%2Bbit%2Ely/http://t.co/…` 按 `t.co` 删除。证据是这个主机名，不是前面没打开的那段。
- `%2B2b%77ww.bit.ly/…` 仍按短链删除。证据是 `77ww.bit.ly`。`t.me/%2B…` 仍按邀请删除。路径不进证据。
- 百分号编码的间隔贴在主机名或协议前面时不再删掉。见 ADR 0201。
