# ADR 0528：私聊可以列出一个群里记下的人

- 状态：已接受
- 日期：2026-11-05

## 背景

接入目录记下谁可以操作一个群，每个群最多 32 个用户 id。`/chats` 只列出群，不列出这些人。突袭之后，管理员要对照目录里还记着谁，才能决定谁还能改配置。

32 个 20 位 id 大约 700 字，放得进一页。

## 决策

- `/chats <chatId>` 列出这个群记下的人。顺序与写入相同：先记下的在前。
- 标题是 `chats {chatId}`。没有人时下一行是 `none`。
- 不读额度。不调用 `list`。
- 没有这个群权限时回复「没有权限」，不读这份名单。
- 没有接入目录时仍回复 `chats off`。
- 多出来的词回复用法。目录抛错时回复「参数无效」，原文不进回复和日志。
- 不新增 `skip`。32 个 id 放得下一页。
- 不新增命令。菜单仍是 99 条。菜单描述改成 `/chats [chatId|skip <count>]`。
- 第 33 个人仍不写入，结果仍是 `ok`。姓名和用户名仍不进目录，也不进回复。
- 不列出黑名单里的人。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 新命令 `/operators` | 菜单已经 99 条，Telegram 上限是 100。`/chats` 的群号原来空着。 |
| 给这份名单加 `skip` | 32 个 id 放得下 3500 字。跳过没有少读的数据。 |
| 列出黑名单编号 | ADR 0049 拒绝把这些编号写进私聊。 |
| 按编号排序 | 先记下的人是把 bot 设成管理员的人。排序会把这个人挪走。 |

## 后果

- `/chats -100` 列出这个群记下的人。不写群号时仍列出群。
- 已经设过命令菜单的部署，要再执行一次设置命令，菜单描述才会带上群号。
- 菜单描述变长之后，`/commands` 第一页停在 `flood`，末尾是 `+6`。`/commands skip 93` 从 `keyword` 继续。
- 30 天保留期没有改。目录仍是配置，不是消息原文。
