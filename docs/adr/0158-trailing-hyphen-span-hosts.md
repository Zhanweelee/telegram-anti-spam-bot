# ADR 0158：行尾连字符只留高亮主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0152 按 Android `LinkifyPort.WEB_URL` 留下高亮提前停住的主机名。标签的写法是先一个字母或数字，中间可以有连字符，结尾必须再是字母或数字。连字符不能收尾。

`http://bit.ly-/offer`、`http://bit.ly--/x` 和 `http://bit.ly-.com/x` 打开的是 `bit.ly`。`http://203.0.113.9-/x` 打开的是 `203.0.113.9`。整段解析把连字符留在主机名上，`bit.ly-` 对不上短链，`203.0.113.9-` 也不是四段数字。

连字符写在用户或密码里时，先认用户信息。`http://bit.ly-@example.com` 和 `http://bit.ly:x-@example.com` 打开的是 `example.com`。`http://bit.ly-foo` 和 `http://203.0.113.9-1` 仍是一整段主机名。`https://t.me-/+邀请码` 停在没有路径的 `t.me`，不能把连字符拿掉再读后面的邀请码。

## 决策

- 正文里的 `http` 或 `https` 再取这段高亮的主机名。连字符后面，跳过连续的连字符，仍是字母或数字时，连字符留在标签里。否则主机名停在连字符前面。只留主机名。
- 用户和密码都可以含连字符，和 Android 的用户信息字符集一致。带 `@` 时仍打开后面的主机。
- 整段解析出的主机名仍然保留。两边都走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。最多 8 个。
- 已经写在 `text_link`、按钮或其它结构化字段里的地址整段打开，不按高亮截断。
- 不把停住之后的路径再当成邀请。路径不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 只留整段解析出的主机名 | 点下去打开的是连字符前面的短链或裸 IP。 |
| 用户信息仍不含连字符 | `http://bit.ly-@example.com` 会被截成 `bit.ly`，Android 打开的是 `example.com`。 |
| 去掉连字符后再读邀请路径 | `t.me-/+邀请码` 打开的是没有路径的 `t.me`。 |

## 后果

- `http://bit.ly-/…`、`http://bit.ly--/…`、`http://bit.ly-.com/…` 和 `http://203.0.113.9-/…` 按现有短链或裸 IP 规则删除。证据仍只有主机名。
- `http://bit.ly-foo/…` 和 `http://203.0.113.9-1/…` 留着。
- `http://bit.ly-@example.com` 和 `http://bit.ly:x-@example.com` 留着。`http://example.com-@bit.ly` 仍因整段里的 `bit.ly` 删除。
- `https://t.me-/+…` 不记成邀请。再套一层仍放行。路径不进证据。
