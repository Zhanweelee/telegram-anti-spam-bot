# ADR 0525：私聊可以接着看后面的群

- 状态：已接受
- 日期：2026-11-05

## 背景

接入目录最多 256 个群。额度打开时，`/chats` 每一行是群号和已用次数。256 行放不进 3500 字，第一页留下前面的群，末尾写 `+N`。后面的群仍在目录里，回复里只剩个数。

## 决策

- `/chats [skip <count>]`。
- `count` 是 0 到 99999 的整数，不允许前导零。不写 `skip` 或 `count` 为 0 时，回复与原来相同。
- `count` 大于 0 时，先按目录顺序跳过前面的 `count` 个群，再从下一个群开始列。放不下时仍保留完整行，末尾写 `+N`。`+N` 只数这一页没列出的群。
- 跳过的群不再读额度。这一页列出来的群，包括随后被 `+N` 省略的群，仍各读一次，不计数。
- 跳过的个数已经不少于目录里的群数，或空目录写了大于 0 的 `count` 时，回复「参数无效」。缺数字、数字不合法也是「参数无效」。多出来的词回复用法。
- 没有接入目录时仍回复 `chats off`。配置里的管理员看全部群。接入目录里的人仍只看自己的群。
- 不新增命令。菜单仍是 99 条。`/chats` 的菜单描述改为带上 `skip`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 在 `+N` 后面写下一页的命令 | 现有回复用 `+N` 解析。下一页的起点就是已经看过的群数。 |
| 跳过的群也读额度 | 已经看过的次数不必再读一次。 |
| 只给全局管理员 | 只接入一个群的人用 `skip 0` 仍应看到原来的那一行。 |

## 后果

- 额度打开时，`/chats skip 166` 能看到目录后部的已用次数。不写 `skip` 时第一页不变。
- 已经设过命令菜单的部署，要再执行一次设置命令，菜单描述才会带上 `skip`。
- 没列出来的群仍在目录里。额度计数仍在内存。30 天保留期没有改。
