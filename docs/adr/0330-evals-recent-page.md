# ADR 0330：评测导出取最近的一页

- 状态：已接受
- 日期：2026-11-04

## 背景

ADR 0016 让 `/evals` 把申诉收成评测 JSON。超过 3500 字时整份丢掉，只回复条数。大约四十条普通样本就会超过这个长度。管理员看不到最近的误判和确认。

队列最多 256 条，一次 `list` 就能读完。限制来自私聊长度，不是 D1 的 50 次查询。

## 决策

- 完整 JSON 放得下时，文档仍是 `{ tenantId, chatId?, cases }`，不写 `omitted`。
- 放不下时，取最近的若干条，页内按原来的时间顺序，最新的一条在最后。文档增加正整数 `omitted`，表示这次没带上的更早样本数。`cases` 与 `omitted` 之和是这次列出的条数。
- 一条样本自己的 JSON 已经超过 3500 字时，仍只回复条数。
- 不改队列上限，不把原文写进文档，也不做文件下发。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续只回复条数 | 管理员无法把最近的申诉带出私聊。 |
| 从最早的一条开始截断 | 私聊里更有用的是刚标过的样本。更早的仍算在 `omitted` 里。 |
| 用多条消息或文件把 256 条一次发完 | 这一步只解决私聊长度。文件下发仍留到以后。 |

## 后果

- `feedbackEvalDocumentSchema` 接受可选的 `omitted`。完整导出的 JSON 与 ADR 0016 相同。
- 适配器不用改。`ReviewQueue.list` 仍返回范围内的全部样本。
- 一条超长样本仍走原来的条数回复。
