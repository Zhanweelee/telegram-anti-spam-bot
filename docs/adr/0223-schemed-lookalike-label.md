# ADR 0223：带协议的点状间隔号留在标签里

- 状态：已接受
- 日期：2026-11-03

## 背景

ADR 0217 把写完的主机名和后面的 ASCII 域名之间的点状间隔号收成一个点。斜杠前面的裸 `bit.ly·/…` 仍只打开 `bit.ly`。

`http://bit.ly·/…`、`https://t.co•?…`、`http://203.0.113.10∙/…` 和 `http://bit.ly·:80/…` 在 Android 上各是一条链接。地址解析器给出的主机名不是前面的短链或裸 IP。`http://bit.ly·/http://t.co/…` 的路径仍属于这一条。

`bit.ly·.com/…` 和 `203.0.113.10·.evil.com/…` 也是一条主机名。间隔号在标签里面，后面的 ASCII 点才分开下一个标签。`example.com·.bit.ly/…` 的主机名仍以 `bit.ly` 结尾。

`bit.ly·/…`、`http://bit.ly·@evil.com/…`、`http://bit.ly·#…` 和 `http://bit.ly。/…` 仍打开前面的短链。`bit.ly·.notarealtld/…` 也只打开 `bit.ly`。

## 决策

- 只改主机名扫描。公开的折叠不改。
- 带协议的主机名后面，一段点状间隔号在后面是路径、问号、结尾或已经写完的端口时留下。
- 这段间隔号后面紧接着 ASCII 点，而且后面是严格域名时，把间隔号收成 `x`。停住扫描也做这一步。
- 后面不是严格域名时，间隔号留下。没有协议、`@`、`#` 和空格仍按原来的短链或裸 IP 删除。
- 句号 `。` 仍按原来的规则收成点。它本身就是域名里的点。
- 每段仍走现有的短链、裸 IP、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 间隔号一律收成点 | `http://bit.ly·/…` 会按短链删除。Android 打开的不是 `bit.ly`。 |
| 裸主机名也把斜杠前的间隔号留下 | `bit.ly·/…` 会漏掉。Android 只打开 `bit.ly`。 |
| `#` 和 `@` 也留在标签里 | `http://bit.ly·#…` 和 `http://bit.ly·@evil.com/…` 会漏掉已经打开的短链。 |

## 后果

- `http://bit.ly·/…`、`https://t.co•?…`、`http://www.bit.ly‧/…` 和 `http://203.0.113.10∙/…` 留着。
- `http://bit.ly·/http://t.co/…` 留着。路径里的短链不另记。
- `bit.ly·.com/…`、`http://bit.ly·.evil.com/…` 和 `203.0.113.10·.evil.com/…` 留着。
- `bit.ly·/…`、`www.bit.ly•/…` 和 `203.0.113.10·/…` 仍删除。
- `http://bit.ly·@evil.com/…`、`http://bit.ly·#…` 和 `http://bit.ly。/…` 仍按短链删除。
- `example.com·.bit.ly/…` 仍按短链删除。证据是收成 `x` 之后的主机名。
- `bit.ly·.notarealtld/…` 仍按短链删除。路径不进证据。
- 带协议的主机名里，希腊文、西里尔文、亚美尼亚文和非 ASCII 拉丁字母留在标签里。见 ADR 0224。
