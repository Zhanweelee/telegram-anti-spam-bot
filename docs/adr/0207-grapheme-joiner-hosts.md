# ADR 0207：字素连接符不再挡住短链

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 把字素连接符 U+034F 留在主机名标签里。地址解析会忽略它。`bi͏t.ly/…`、`b͏it.ly/…` 和 `bit͏.ly/…` 都是一条链接，主机名是 `bit.ly`。`t͏.co/…` 的主机名是 `t.co`。连续两个连接符也一样。`t͏.me/+…` 仍是邀请。

这个字符落在 Android 的标签范围内。它夹在两个 ASCII 字母中间时，会被收成 `x`，短链变成 `bixt.ly`。它写在点号前面时，标签在点号前断开，抽出来的是 `.ly`。

点号后面的连接符不一样。裸的 `bit.͏ly/…` Android 不打开。带协议的 `http://bit.͏ly/…` 会打开，现有抽取已经能读到 `bit.ly`。`example.com͏http://bit.ly/…` Android 整段都不打开。删掉连接符以后也抽不出短链。开头的 `͏bit.ly/…` 已经能读到 `bit.ly`。

句号 `。` 仍不收成点。简写格式控制符会把主机名拆开，不在这里删。

## 决策

- 只改主机名扫描。公开的 `foldMatchText` 和 `foldHostInterrupters` 仍留下 U+034F。关键词比较不走这一层。
- 一段 U+034F 前面是 ASCII 字母或数字，后面是 ASCII 字母、数字或点号时，把这一段去掉。停住扫描也做这一步。
- 点号后面的连接符留下。前面没有 ASCII 的连接符留下。
- 每段仍走现有的短链、裸 IP、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 所有 U+034F 都删掉 | 裸的 `bit.͏ly` 会变成短链。Android 并不打开它。 |
| 把它继续收成 `x` | `bi͏t.ly` 会漏掉。地址解析打开的是 `bit.ly`。 |
| 和零宽字符一起从公开折叠里删掉 | 关键词比较会跟着变。这一轮只修主机名。 |

## 后果

- `bi͏t.ly/…`、`bit͏.ly/…`、`http://bi͏t.ly/…` 和 `t͏.co/…` 按短链删除。
- `t͏.me/+…` 按邀请删除。邀请码不进证据。
- 裸的 `bit.͏ly/…` 和 `example.com͏http://bit.ly/…` 留着。
- 开头的 `͏bit.ly/…` 和带协议的 `http://bit.͏ly/…` 仍按短链删除。路径不进证据。
- 带协议的主机名里，多字节百分号编码在主机名处停下。见 ADR 0208。
