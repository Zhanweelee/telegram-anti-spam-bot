# ADR 0537：投票选项也走关键词和默认正则

- 状态：已接受
- 日期：2026-11-05

## 背景

ADR 0056 让投票题干成为正文，并明确不把选项写进事件。ADR 0077 只从选项里抽出主机名。题干干净时，「免费领取」和「加微x」可以整段留在选项上。短链仍会删除，关键词看不见。

Bot API 把一次投票限制成 1 到 12 个选项，每个 1 到 100 字。用一个普通空格拼起来，最多 1211 字。

## 决策

- 已有别的正文，且选项去掉两端空白后仍有字时，事件另留 `pollOption`。几个选项用一个普通空格拼起来，只留前 1211 字。选项拼起来正好就是正文时不设这个字段。正文和 `textSha256` 仍按 ADR 0056，题干优先。
- 第 1212 字起不进事件。主机名仍从整段选项抽取，包括被截掉的尾巴。
- `explanation`、投票人数、选项上的媒体和后加选项的服务消息不进这个字段。后加选项仍按原来的规则成为正文。
- 关键词和 `regex` 同时看正文、`senderTag`、`buttonText`、`authorSignature`、`mirrorSignature`、`pollOption` 和 `profile`。证据仍是原来的摘要。选项原文不进证据，也不进日志。
- `regex` 命中时带上 `places`，只写命中的字段名。`pollOption` 加入这份名单。`poll_option_regex` 只在 `places` 含有 `pollOption` 时算命中。检测器没有 `places` 时仍按分数。
- 规则条件增加 `pollOption: true`。消息上有这个字段时为真。
- 新规则 `poll_option_regex` 默认打开。条件是这个字段，检测器是现有的 `regex`，命中后 `delete`。
- 「免费领取」和「加微信」仍走已经打开的关键词规则。
- `regex_hint` 仍默认关闭。正文里的「加微x」不会因为旁边有干净的选项就被删掉。
- 不改 ADR 0026 的基础检测器名单。`keyword` 和 `regex` 已经在里面，超额后这条仍会跑。
- `chats.json` 整份替换的群不会自动带上这条规则。
- 不新增命令。菜单仍是 99 条。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 默认打开 `regex_hint` | 普通消息会被同一份模式删除。这次要读的是题干旁边的选项。 |
| 把选项拼进题干 | 会改变 `textSha256`。ADR 0056 已经拒绝。 |
| 说明和选项放进同一个字段 | 测验说明不是选项。这一轮仍不读 `explanation`。 |
| 给选项单独做一个检测器 | 关键词和正则已经会扫旁路字段。名单不用再加一项。 |

## 后果

- 选项含「免费领取」或「加微信」时按关键词删除。含 `t.me/+`、「加微x」或「加微X」时按 `poll_option_regex` 删除。证据不含选项原文。
- 选项干净时消息留下。选项自己就是题干时，「加微x」仍要打开 `regex_hint`。
- 第 1212 个字符起不进事件。主机名仍从整段选项抽取。写在选项里的路径会留在 `pollOption`，不进审计。
- 说明、投票人数和选项媒体仍不进事件。
- 关掉这条规则后，选项回到只看关键词和短链。
- 整份替换规则的群要自己加上这条，才会删除选项上的「加微x」。
- 30 天保留期没有改。
