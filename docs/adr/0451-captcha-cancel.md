# ADR 0451：私聊取消尚未完成的验证

- 状态：已接受
- 日期：2026-11-04

## 背景

私聊 `/captcha` 会把一个人限制 300 秒，并在群里留下按钮。点错、点对，或者等到 `until_date`，才能结束。管理员如果发错了人，这段时间里既不能让他说话，也不能把按钮撤掉。

## 决策

- 私聊命令 `/uncaptcha <chatId> <actorId>`。两个 id 都要匹配 `^-?\d{1,20}$`。多出来的参数不发出请求。群聊里的同样文本不执行。
- 配置里的管理员可以取消任意群。接入目录里的人只能取消自己的群。
- 先按 tenant、chat、actor 读取挑战。没有记录时回复「没有待验证」，不调用 `restrictChatMember`，也不调用 `deleteMessage`。
- 有记录时先 `take` 取走。取不到就同样回复没有待验证。
- 取走之后调用 `releaseActor`，也就是 `restrictChatMember` 打开每一项权限，不带 `until_date`。
- 放行失败时把原挑战放回去，不删按钮。回复「参数无效」。
- 放行成功后，挑战里有消息号就 `deleteMessage`。删除失败只记 `captcha_prompt_delete_failed`，回复仍是已取消。人已经可以发言，按钮再点也不会通过。
- nonce 不进回复，也不进日志。没有 token 或缺少放行端口时回复「参数无效」，挑战留在原地。
- 不改 `/unmute`。`/unmute` 仍只打开权限，不读挑战表。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 让 `/unmute` 顺手删验证 | 禁言和验证是两件事。没有待验证的禁言不该去碰挑战表。 |
| 只删按钮，不放行 | 人还要等满 300 秒。取消应当马上能说话。 |
| 放行失败仍删掉挑战 | 按钮没了，限制还在，这个人无法再点通过。 |

## 后果

- 尚未完成的验证可以被取消。入群时自动发出的验证也同样可以取消。
- 打开的是全部权限，和验证通过时相同。群的默认权限更窄时，这个人可以超过默认。
- 云额度的基础检测器名单没有改。30 天保留期没有改。
