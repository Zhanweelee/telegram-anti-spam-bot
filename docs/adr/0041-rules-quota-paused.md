# ADR 0041：超额后 `/rules` 标出不会跑的规则

- 状态：已接受
- 日期：2026-11-01

## 背景

ADR 0026 在超额后只把基础检测器送进流水线。ADR 0040 的 `/rules` 仍列出全部规则。云上的管理员看到 `llm_hint file` 时，不知道这条规则此刻不会跑。

## 决策

- `/rules` 只读额度，不计数。快照里 `degraded` 为真，并且带有 `basicDetectorIds` 时，检测器不都在这组里的规则行末尾加上 `paused`。中英文用同一个词。
- 判断和 `degradeRules` 共用 core 里的 `ruleSurvivesQuota`。一条规则的每个检测器都在基础名单里才保留。
- 额度没打开、没有超额、没有这份名单，或读取失败时，行末不加 `paused`。失败记 `quota_failed`，不写异常文本，规则列表仍然返回。
- Worker 把当前策略的 `basicDetectorIds` 附在只读快照上。core 不知道部署模式。
- 不改 ADR 0026 的默认基础检测器名单，也不计数到 KV 或 D1。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 超额后从 `/rules` 里删掉这些行 | 管理员会以为规则不存在。标记表示这次检测不会跑，配置还在。 |
| `/rules` 也调用计数 | 看一眼规则就会消耗免费额度。 |

## 后果

- 自部署默认不打开额度，`/rules` 和以前一样。
- 云上超额之后，基础规则没有 `paused`，其余规则有。
- 自定义的 `QuotaReader` 要在降级快照里带上 `basicDetectorIds`，否则不加标记。
- 重启后内存计数归零，标记也一起消失。这和 ADR 0026 的计数一样。
