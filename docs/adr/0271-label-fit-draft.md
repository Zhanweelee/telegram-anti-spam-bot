# ADR 0271：放不下的标签后面仍留下主机名

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 的主机名标签最多 63 个字符。连字符只有在整段标签仍然放得下时才留在标签里。放不下时，高亮在这里停住，后面的网址另开一条。

看得见的正文已经这样切。隐藏的分享 `text` 和分享 `url` 把整段交给地址解析。59 个 `a` 再加 `-http://bit.ly` 时，主机名收成那段长标签，短链留在路径里。

放得下的标签仍是一条网址。下划线、直接粘住的词，以及写在另一条网址路径里的连字符，也不另开。

## 决策

- 分享 `text`、分享 `url`、私聊预填 `tg://msg` 的 `text` 和用户名草稿的 `text`，按 Android 的 63 个字符切 `http://` 和 `https://` 后面的标签。
- 连字符或点号让当前标签放不下，并且后面还有网址时，从这里另抽。
- 标签仍然放得下，包括后面紧接着 `://` 的，仍是一条。
- 下划线或直接粘住的词不另开。已经写进路径里的不另开。
- 放得下的长标签可以留下主机名。它不是短链。路径和邀请码不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 整段交给地址解析 | 短链留在路径里，主机名收成前面的长标签。 |
| 只要有连字符就拆开 | 58 个字符再加 `-http` 时，Android 仍把它当成一条。 |
| 路径里的同样连字符也拆 | 它仍属于前一条网址。 |

## 后果

- `t.me/share/url?text=http://` 接 59 个 `a` 再接 `-http://bit.ly/…` 删除。证据仍只有主机名。
- 60 个 `a` 后面的裸 `bit.ly`、64 个 `a` 后面的 `http://t.co`，以及分享 `url` 里的同样写法，同样删除。
- 58 个字符、63 个字符后面紧接 `://`、下划线、粘住的词，以及写在 `https://example.com/` 路径里的，留着。
- `@` 后面接不上用户信息时，前面的短链后来同样留下。见 ADR 0272。
