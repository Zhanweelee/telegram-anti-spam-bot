# ADR 0610：成员转发的频道标题只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

成员把频道帖转到群里时，客户端在抬头画出频道标题。标题写在 `forward_origin.type === "channel"` 的 `chat.title`，旧字段是 `forward_from_chat.title`。`channel_forward` 默认会删掉整条转发。见 ADR 0025。关掉这条之后，标题里的短链仍会留下。

讨论组里关联频道自动出现的原帖不再记成频道转发。见 ADR 0443。那种原帖的代发标题已经只留主机名。见 ADR 0581。来源签名也已经只留主机名。见 ADR 0445。

把标题收成正文会让关键词命中频道名，也和原文默认不落盘冲突。

## 决策

- `is_automatic_forward` 不是布尔值 `true` 时，频道来源的标题只留主机名。现代 `forward_origin.type === "channel"` 读 `chat.title`。没有现代来源、也没有隐藏显示名、也没有 `forward_from` 时，读 `forward_from_chat.type === "channel"` 的 `title`。
- 标题长度大于 0 才读。空白也算有标题。用户名不读。来源上的 `author_signature` 不读。抽出之前不截断。
- 主机名仍进消息已有的 `hosts`。邀请仍进 `invites`。正文里已有短链时，证据仍先记正文的主机名。标题不进正文，也不改内容哈希。关键词因此不命中这个标题。
- `is_automatic_forward` 正好是 `true` 时不读来源标题。外部回复不读。已有隐藏显示名时不读旧的频道标题。发送者姓名和本群群名不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`channel_forward` 仍默认打开。关掉之后，短链仍走已有的 `links`。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把标题拼进正文 | 关键词会命中频道名，标题也会改内容哈希。 |
| 只靠 `channel_forward` | 关掉频道转发后，标题里的短链仍留下。 |
| 连讨论组原帖的来源标题一起读 | 原帖画出的是代发标题，来源标题不是那一行。见 ADR 0581。 |
| 连来源签名和用户名一起读 | 成员转发的来源签名仍按 ADR 0445 留在外面。用户名不是画出的标题。 |
| 新命令 `/channeltitle` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 关掉 `channel_forward` 后，成员转发的频道标题里的短链、邀请或裸 IP 仍会删除这条消息。证据只有主机名。
- 频道标题原文、路径和用户名不进事件。内容哈希不变。标题里的关键词不命中。
- 正文里已有短链时，证据仍先记正文的主机名。空白标题不落到用户名。
- `example.com` 和公开的 `t.me/名字` 在频道转发关掉时留下。默认仍由 `channel_forward` 删除整条转发。付费帖仍不删除。见 ADR 0356。
- 讨论组原帖的来源标题、来源签名、外部回复、隐藏显示名旁边的旧频道标题、发送者姓名和本群群名仍不读。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
- 成员转发的频道签名后来由 ADR 0611 只留下主机名。签名本身仍不进事件。讨论组原帖的来源签名仍按 ADR 0445。群来源签名仍不读。
- 群来源的签名后来由 ADR 0612 只留下主机名。签名本身仍不进事件。用户来源的签名仍不读。
