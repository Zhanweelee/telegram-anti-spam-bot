# ADR 0444：登录按钮转发后的文字只留主机名

- 状态：已接受
- 日期：2026-11-04

## 背景

登录按钮可以带 `login_url.forward_text`。消息被转发之后，按钮上看得见的字换成这一段。短链或邀请可以只写在这里，按钮自己的字和 `login_url.url` 仍是普通句子和普通域名。ADR 0111 没有读它，因为那一轮只收会打开的网址和内联查询。

`bot_username` 是用来登录的用户名，不是这段替换文字。

## 决策

- 从内联键盘和富文本按钮的 `login_url.forward_text` 抽出网址，只留主机名。折叠、长度、邀请判断和 8 个主机名的上限与旁路纯文本相同。
- 顺序跟在同一条 `login_url.url` 之后。没有 `url` 时仍读这段文字。
- 这段文字不进入 `message.text`，也不参与内容哈希。
- 不是字符串的值不读，也不写进事件。
- 不读取 `bot_username`、`callback_data`、挑选聊天的允许范围，以及回复键盘。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把整段拼进正文 | 同一条消息的哈希会变，句子也会进事件。 |
| 只在已经是转发时才读 | 原消息里这段广告已经在。等到转发才删，来源群会留下。 |
| 连 `bot_username` 一起读 | 用户名不是打开的网址。 |

## 后果

- 这段文字里的短链、邀请或裸 IP 按现有链接规则命中。路径和邀请码不进事件。
- 普通域名仍保留。按钮上原来的字仍按原规则成为正文。这段替换文字里的关键词仍然看不到。
- 用户名不进事件。
- 30 天保留期不动。
- 非空的替换文字后来由 ADR 0518 另开 `login_forward`。句子仍不进事件。看得见的按钮文字仍是正文。
