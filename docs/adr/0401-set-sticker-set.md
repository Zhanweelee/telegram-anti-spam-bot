# ADR 0401：私聊可以设置一个群贴纸包

- 状态：已接受
- 日期：2026-11-04

## 背景

超级群的群贴纸包被换成垃圾贴纸时，管理员要能换上指定的包，同时留下消息。官方有一次只设置群贴纸包的调用。

`setChatStickerSet` 给一个超级群设置新的群贴纸包。bot 必须是管理员，并且有相应的管理权限。`getChat` 可能带有可选字段 `can_set_sticker_set`，用来判断 bot 能不能用这个方法。成功时返回 True。

必填参数是 `chat_id` 和 `sticker_set_name`。`sticker_set_name` 是贴纸包短名。`createNewStickerSet` 把这个短名写成：1 到 64 个字符，只能是英文字母、数字和下划线，以字母开头，不能有连续下划线，并且以 `_by_<bot_username>` 结尾。`<bot_username>` 大小写不敏感。

这次不读取贴纸对象。`getStickerSet` 会返回带文件号的贴纸。短名不能进回复或日志。没有 token 时不能把内存记录回复成已经设置。

## 决策

- 私聊命令 `/stickers <chatId> <name>`。群 id 匹配 `^-?\d{1,20}$`。短名必须是单独一个参数。多出来的参数不发出请求。群聊里的同样文本不执行。
- 短名长度 1 到 64。只能是英文字母、数字和下划线，以字母开头，不能有连续下划线。末尾的 `_by_` 后面是 5 到 32 个字符、以字母开头、以 `bot` 结尾的用户名。`bot` 大小写不敏感。不合这个形状时不发出请求。
- 配置中的管理员可以操作任意群。接入目录里的人只能操作自己的群。
- 调用 `ModerationPort.setStickerSet`。适配器调用 `setChatStickerSet`，带 `chat_id` 和 `sticker_set_name`。
- 回复不重复短名，并写明消息还在。
- 没有 token、没有这个方法，群号或短名不合法，或调用失败时回复「参数无效」。日志只写 `operator_rejected`，带上 eventId、chatId 和命令名。不写异常文本、token、短名或原文。
- 没有 token 的 Worker 不把内存记录回复成已经设置。
- 不调用 `deleteChatStickerSet`、`getChat` 或 `getStickerSet`。不修改黑名单、白名单、封禁或禁言。不读取消息正文。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 任意字符串都送出，交给 Telegram 拒绝 | 短名规则已经写明。不合规则的名字会多一次失败的子请求，还可能把原文送出去。 |
| 先用 `getChat` 看 `can_set_sticker_set` | 多一次子请求，还会带回标题、简介和邀请链接。设置本身不需要这些。 |
| 先用 `getStickerSet` 确认贴纸包存在 | 返回的贴纸带文件号。文件号不能进回复或日志。 |
| 回复里重复短名 | 短名可能是管理员刚粘贴的原文。回复只确认这一次请求。 |

## 后果

- 成功只表示 Telegram 接受了这一次 `setChatStickerSet`。不是超级群、贴纸包不存在，或缺少相应管理权限时，回复是「参数无效」。
- 消息还在。原来的群贴纸包被这次设置换掉，贴纸包本身还在。
- 一次设置是一次 Telegram 子请求。封禁、禁言和黑名单都不变。
- 30 天保留期不动。
