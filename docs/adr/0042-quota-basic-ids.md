# ADR 0042：超额后 `/quota` 列出基础检测器

- 状态：已接受
- 日期：2026-11-01

## 背景

ADR 0041 在 `/rules` 上用 `paused` 标出超额后不会跑的规则。`/quota` 超额时只回复 `basic`。管理员要对照那组 id，还得去看配置。

## 决策

- 快照里 `degraded` 为真，并且 `basicDetectorIds` 非空时，`/quota` 在状态行下面再加一行。id 用逗号拼接，不加空格，保持策略里的顺序。
- 中英文共用 `{status}\n{basic}`。id 不翻译。
- 没超额、名单缺失或为空时，仍是原来的一行。没打开或解析失败时仍是 quota off。
- Worker 已经把当前策略的名单附在只读快照上。core 不认识部署模式。查看不计数。
- 不改 ADR 0026 的默认基础检测器名单，也不把计数写进 KV 或 D1。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 只在 `/rules` 的 `paused` 上让管理员自己对照 | 超额回复仍然不说出停了哪些检测器。 |
| 按字母排序 | 和 `QUOTA_BASIC` 的顺序不一致。 |
| 没超额也列出名单 | 满额回复变长，和「只在降级时说明停了什么」不一致。 |

## 后果

- 云上超额之后，`/quota` 第二行是当前策略的基础检测器。默认仍是 `keyword,join,flood,repeat,link,blocklist,forward,regex`。
- 自定义的 `QuotaReader` 在降级快照里不带这份名单时，回复保持一行 `basic`。
- 重启后内存计数归零，回复回到 `full`，第二行也消失。
