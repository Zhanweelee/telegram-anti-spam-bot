# ADR 0191：组合附加符号不再拆开裸主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

Android 的单词边界会跳过非间距组合附加符号。`example.com`、`www.example.com` 或 `203.0.113.10` 后面紧挨这个符号，再写 `http://bit.ly/…`，整段都不是链接。`bit.ly` 后面紧挨这个符号再写斜杠，也不是链接。`example.com` 加这个符号再写 `https://t.me/+…`，邀请不会打开。

符号后面如果是斜杠，`example.com` 加符号再写 `/http://bit.ly/…`，后面的短链会单独打开。符号写在 `http://` 最前面，或者前面是空格、句号、`!`，短链仍会打开。希腊字母 `α` 和 `Ι` 不是这种符号，裸主机名仍在字母前结束。

带协议的 `http://example.com` 加符号再写短链，仍是一条链接。`example.com/` 或 `example.com?` 把符号留在路径或查询里，后面的短链不单独打开。

JavaScript 的 `\b` 把这个符号当成非单词字符，会从中间拆出短链。把符号删掉会让 `example.com` 加符号再写 `/http://bit.ly` 粘成一条路径，短链被盖住。

## 决策

- 网址边界把一串非间距组合附加符号当成透明的。裸主机名不在这种符号前面结束，符号后面的 `http://` 也不另起一段。
- 符号后面的斜杠仍开始下一条网址。
- 比较前把 U+0345 换成 U+0300。忽略大小写时，U+0345 会连带匹配希腊字母 `Ι`。
- 每段仍走现有的短链、裸 IP、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 删掉全部组合附加符号 | `example.com` 加符号再写 `/http://bit.ly` 会粘成一条路径，漏掉 Android 打开的短链。 |
| 任何非 ASCII 字符都按这个边界处理 | `见 例子.中国/http://bit.ly` 和 `a例.ly/http://bit.ly` 会改变。Android 只对非间距符号跳过边界。 |
| 让忽略大小写的字符类保留 U+0345 | 希腊字母 `Ι` 会被当成这个符号，`example.comΙhttp://bit.ly` 会漏掉。 |

## 后果

- `example.com`、`www.example.com` 和 `203.0.113.10` 加组合附加符号再写 `http://bit.ly/…` 留着。`bit.ly` 加符号再写斜杠也留着。证据里没有主机名。
- `example.com` 加符号再写 `https://t.me/+…` 不记成邀请。
- `example.com` 加符号再写 `/http://bit.ly/…`，以及符号开头的 `http://bit.ly/…`，按短链删除。路径不进证据。
- `http://bit.ly` 加符号再写路径仍按短链删除。`点击bit.ly`、`bіt.ly` 和希腊字母 `Ι` 后面的短链仍按短链删除。
- `http://example.com` 加符号再写短链，以及 `example.com/` 加符号再写短链，留着。
