# ADR 0302：不是一到五位的空端口另开草稿主机名

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 把 `http://` 后面的一到五位数字收成端口。`http://:80/bit.ly/…`、`https://:443?bit.ly/…`、`http://:8/bit.ly/…` 和 `http://:080/bit.ly/…` 是一条没有主机名的链接。路径和问号里的短链、裸 IP 和邀请不再打开。`http://example.com:80/bit.ly/…` 已经有主机名，端口留在这一条里。`http://:80bit.ly/…` 没有路径分隔，也不另开。

六位数字不是端口。`http://:999999/bit.ly/…`、`HTTP://:999999/bit.ly/…` 和 `http://:999999?bit.ly/…` 会单独打开 `bit.ly`。冒号后面没有数字时，`http://:/bit.ly/…` 同样另开。端口和路径之间的空格也切开下一条。`http://bit.ly:80/…` 和 `https://t.me/+…` 仍是短链或邀请。见 ADR 0212。

隐藏的分享 `text` 把 `http://:999999/bit.ly/…` 收成一条空主机名的网址。六位端口后面的短链不再另开。

## 决策

- 分享 `text`、私聊预填 `tg://msg` 的 `text` 和用户名草稿的 `text`，在 `http://` 或 `https://` 后面紧挨冒号、冒号后不是一到五位数字、并且下一个字符是 `/` 或 `?` 时，在这个空端口后面加一个空格。
- 一到五位端口仍留在这一条里。已经有主机名的端口不改。端口后面是字母时不另开。
- 不改带协议网址的整段匹配。闭合分享链接里的网址不走这道切开。
- 证据只留主机名。路径和邀请码不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 一到五位端口也另开 | `http://:80/bit.ly` 会删掉 Android 留成一条无主机名链接的消息。 |
| 六位数字也收进端口 | `http://:999999/bit.ly` 会漏掉单独打开的短链。 |
| 改掉带协议网址的整段匹配 | 其它已经收进同一条的字符会跟着拆开。 |

## 后果

- `t.me/share/url?text=http://:80/bit.ly/…`、`https://:443?bit.ly/…`、`http://:8/bit.ly/…`、`http://:080/bit.ly/…`、`http://:80/http://t.co/…`、`http://:80/203.0.113.10/…`、`http://:80/t.me/+…`、`http://example.com:80/bit.ly/…` 和 `http://:80bit.ly/…` 留着。
- `http://:999999/bit.ly/…`、`HTTP://:999999/bit.ly/…` 和 `http://:999999?bit.ly/…` 按短链删除。证据是 `bit.ly`。`http://:999999/http://t.co/…` 按短链删除。证据是 `t.co`。路径不进证据。
- `http://:/bit.ly/…` 和端口与路径之间有空格的 `http://:80 /bit.ly/…` 按短链删除。`http://bit.ly:80/…`、`http://@bit.ly/…` 和 `http://:@bit.ly/…` 仍按短链删除。`https://t.me/+…` 仍按邀请删除。邀请码不进证据。
- 带协议的主机名里，Android 留在标签中的字仍可能收成短链。见 ADR 0213。
- 带协议的点号后面如果是标签字，仍可能把前面的短链单独打开。`http://bit.ly.一` 留着。见 ADR 0303。
