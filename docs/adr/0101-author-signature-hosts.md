# ADR 0101：作者签名里的网址只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

频道帖子和匿名管理员的消息可以带 `author_signature`。这行字出现在帖子下面。正文可以是一句普通的话，短链只写在签名里。

ADR 0091 明确不读转发来源上的作者签名，也不读频道标题。那是被转发的原帖，不是这条消息自己的签名。

把签名拼进已有正文会改变 `textSha256`。

## 决策

- 从这条消息自己的 `author_signature` 抽出网址，只留主机名。长度、折叠、邀请判断和 8 个主机名的上限不变。
- 已有正文时，签名原文不进正文，也不改内容哈希。
- 没有更前面的正文时，签名整段成为正文，并以此计算 `textSha256`。更前面的正文包括题干、标题、文件名、表演者、按钮、引用、礼物附言、话题名、后加选项、清单任务、付费视频文件名和隐藏转发显示名。
- 不读取 `forward_origin.author_signature`、频道和群的标题、真实用户姓名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 已有正文时把签名拼进去 | 签名会改变哈希。短链只需要主机名。 |
| 连转发来源上的签名一起抽 | ADR 0091 已经把它留在事件外面。频道转发默认已经删除。 |
| 签名整段都不读 | 短链可以只写在这行看得见的字里。 |

## 后果

- 已有正文时，签名里的 `https://bit.ly/…` 会走现有短链删除。`https://t.me/+…` 只留下 `t.me`，并记成邀请。
- 普通域名仍保留。签名原文、路径和邀请码在已有正文时不进事件。
- 签名成为正文时，整段签名仍参与关键词和内容哈希。
- 成员转发的来源签名、频道标题和真实用户姓名里的网址仍然不读。讨论组原帖来源上的作者签名后来由 ADR 0445 只留下主机名。
- 成员标签里的网址后来由 ADR 0112 只留下主机名。群名和真实姓名仍不读。
- 已有正文时，签名看得见的前 256 字后来由 ADR 0536 交给关键词和默认正则。签名自己就是正文时仍不另留。频道自己的帖和本群匿名管理员仍放行。
