# ADR 0698：建议帖不读消息发送者

- 状态：已接受
- 日期：2026-11-06

## 背景

建议帖通过、余额不足、拒绝、付款到账或退款时，Android 画的是频道名和保存下来的话题用户。频道名来自这条消息所在对话的单论坛标题或关联聊天。话题用户来自 `saved_peer_id`，名字是 `DialogObject.getName`。这几行不用消息自己的 `fromObject`。

Bot API 把通过放在 `suggested_post_approved`，失败放在 `suggested_post_approval_failed`，付款放在 `suggested_post_paid`，退款放在 `suggested_post_refunded`，拒绝放在 `suggested_post_declined`。消息发送者另写在 `from`。发送者是聊天时，`sender_chat` 是那个聊天，`from` 是占位用户。

ADR 0600 和 ADR 0601 从 `from` 的可见名字留主机名。ADR 0692 只在发送者是聊天时停读。用户发送者的名字仍会留下主机名，但这几行并不画这个人。话题用户仍按 ADR 0650、ADR 0651 和 ADR 0652。频道名不在 `chat.title` 上，仍不另读。

## 决策

- 已经会标成 `postNotice` 或 `asPostDeclined` 的提示上，不从 `from` 留主机名，也不从 `sender_chat.title` 留主机名。
- 用户和聊天都一样。编号和本群相同也跳过。
- 编号不同的聊天标题仍由通用代发规则读取。不从 `chat.title` 另读。
- 付款失败、退款、有价通过和拒绝上画出的话题用户仍按原来的全名。拒绝说明仍按正文。
- 空对象、负数、其它币种、其它原因和布尔值仍不读发送者。拒绝的空对象仍算拒绝。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`post_notice` 和 `post_declined` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不调用 `approveSuggestedPost` 或 `declineSuggestedPost`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 用户仍只读名 | 这几行不画消息发送者。名上的短链会删掉一条没有这个名字的提示。 |
| 改读 `chat.title` 当频道名 | 频道名来自单论坛标题或关联聊天，不是这条消息的 `chat.title`。 |
| 新命令 | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 建议帖不再因为消息发送者的名字或本群标题留下主机名。话题用户的全名和拒绝说明仍按原来的规则删除短链。
- 别的聊天发到这个群时，标题仍由通用代发规则留下主机名。
- 名字原文、路径和用户名不进事件。内容哈希不变。关键词不命中消息发送者的名字。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 空对象、负数、其它币种、其它原因、布尔值和普通消息仍不读发送者。干净的提示在 `post_notice` 和 `post_declined` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
