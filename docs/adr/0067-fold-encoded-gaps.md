# ADR 0067：百分号编码的格式字符在解析前去掉

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0065 和 ADR 0066 会去掉原文里的零宽字符、非常规空白和变体选择符。邀请码如果已经写成 `%E2%80%8B` 这种百分号编码，路径里仍是这些 ASCII 字符，邀请正则对不上。没有协议的 `bit%E2%80%8B.ly` 也会被 `%` 从主机名扫描里拆开。

## 决策

- 新增 `foldEncodedGaps`。它只删掉那些 `foldMatchText` 会删掉的字符的一层 UTF-8 百分号编码。
- `%20`、`%2E` 和 `%25` 保留。不把整段地址做 `decodeURIComponent`。
- 链接检测在抽主机名前，对已经折叠过的正文再跑一遍。事件里的正文和哈希不变。
- `hostFromUrl` 在 `foldMatchText` 之前先跑一遍。长度仍按原始字符串判断。
- 关键词和正则仍只用 `foldMatchText`，不解释百分号编码。
- 不改 ADR 0026 的基础检测器名单。不引入同形字库。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 整段 `decodeURIComponent` 再折叠 | `%2E` 会变成点，`%2F` 会变成斜线。残缺的 `%` 还会让解析直接失败。 |
| 只解码路径 | 没有协议的 `bit%E2%80%8B.ly` 到不了路径这一步。 |
| 把同一规则放进关键词折叠 | `免%E2%80%8B费领取` 这种看得见的写法会和隐形字符混成一套规则。 |

## 后果

- `https://t.me/+IN%E2%80%8B…`、`%EF%B8%8F` 和 `%C2%A0` 会记成邀请。`bit%E2%80%8B.ly` 会记成短链。
- `%20` 仍让地址无效。`%2E` 仍原样留给 URL 解析器。
- 两层编码 `%25E2%2580%258B` 后来由 ADR 0068 去掉。`%252E` 和第三层仍留下。
- 邀请码不进事件。同形字仍按原样比较。
