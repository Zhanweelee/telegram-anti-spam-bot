# ADR 0615：名片副标题里原样画出的电话和邮箱只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

分享的联系人在气泡副标题里画出 vCard。Android 的 `MessageObject.VCardData.parse` 先画电话，再画邮箱，最后画公司名。没有 `END:VCARD` 时这段副标题不画。新的 `BEGIN:VCARD` 换一张名片。

电话含 `#` 或 `*` 时，原文直接画上。其余电话和全部邮箱先走 `PhoneFormat.format`。这个函数先丢掉数字、`+`、`*`、`#` 以外的字符。结果以 `+` 开头且后面没有数字时，查不到国家码，函数退回原文。后面一旦有数字，网址就不再出现。

电话和邮箱都不解开 `QUOTED-PRINTABLE`。只有公司名会解开。见 ADR 0613。`URL` 行、可见名字和没有姓名时的标题电话已经只留主机名。见 ADR 0151、ADR 0609 和 ADR 0614。

短链可以只写在这行原样画出的电话或邮箱上。`shared_contact` 默认会删掉整张名片。关掉这条之后，这行里的短链仍会留下。

把电话或邮箱收成正文会让关键词命中号码，也和原文默认不落盘冲突。

## 决策

- `contact` 是对象，且 vCard 里出现过成对的 `BEGIN:VCARD` 与 `END:VCARD` 时，从最后一张名片里会原样画出的电话和邮箱留主机名。属性名以 `TEL` 或 `EMAIL` 开头才算，大小写按客户端。`tel`、`email` 和 `item1.TEL` 不算。
- 电话的值含 `#` 或 `*` 时，用原文。其余电话，以及全部邮箱，只在格式化会退回原文时才读：只保留 `0-9`、`+`、`*`、`#`，结果以 `+` 开头，且后面没有数字。带数字、会被排成号码的值不读。空字符串不加入。抽出之前不截断，也不解开 `QUOTED-PRINTABLE`。以 `=` 结尾且带 `QUOTED-PRINTABLE` 的软折行仍拼上下一行，和客户端一样。
- 见到新的 `BEGIN:VCARD` 就丢掉上一张的电话和邮箱。没有 `END:VCARD` 时不读。
- 主机名仍进消息已有的 `hosts`。邀请仍进 `invites`。`URL` 行、可见名字和标题电话的主机名仍排在前面。这行排在公司名前面。正文里已有短链时，证据仍先记正文的主机名。电话和邮箱不进正文，也不改内容哈希。关键词因此不命中它们。
- 不读取用户编号、职务、备注和发送者姓名。布尔值的 `contact` 不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`shared_contact` 仍默认打开。关掉之后，短链仍走已有的 `links`。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把电话和邮箱拼进正文 | 关键词会命中号码，原文也会落盘。 |
| 只靠 `shared_contact` | 关掉名片规则后，副标题里的短链仍留下。 |
| 所有电话和邮箱都读 | 多数会被格式化成数字，气泡上看不见网址。 |
| 解开电话上的 `QUOTED-PRINTABLE` | 客户端画的是未解码的原文。 |
| 新命令 `/vcardphone` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 关掉 `shared_contact` 后，副标题里原样画出的电话或邮箱中的短链、邀请或裸 IP 仍会删除这条消息。证据只有主机名。
- 电话原文、邮箱原文、路径和用户编号不进事件。内容哈希不变。关键词不命中这些原文。
- 不含 `#` 或 `*`、格式化后只剩数字的电话不读。普通邮箱地址不读。小写属性和分组行不读。没有 `END:VCARD` 时不读。
- `URL` 行、可见名字和标题电话里已有短链时，证据仍先记那一边的主机名。公司名仍排在这行后面。
- `example.com` 和公开的 `t.me/名字` 在名片规则关掉时留下。默认仍由 `shared_contact` 删除整张名片。付费帖仍不删除。见 ADR 0356。
- 发送者姓名和群名仍不读。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
