# ADR 0080：场馆地址里的网址只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0059 用 `venue.title` 当正文，并明确不读 `venue.address`。短链或邀请可以只写在地址里。链接规则现在看不到。

把地址拼进正文会改变 `textSha256`，也会把街道和坐标旁边的原文写进事件。`foursquare_type` 和 `google_place_type` 是地点类型，不是地址。

## 决策

- 从 `venue.address` 里抽出网址，只留主机名。长度、折叠、邀请判断和 8 个主机名的上限不变。
- 地址原文不进正文，也不改内容哈希。坐标、`foursquare_id`、`google_place_id`、`foursquare_type` 和 `google_place_type` 不读。纯 `location` 的坐标仍不读。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把地址拼进正文 | 地址常是街道和门牌。它会改变哈希，也把位置写进事件。 |
| 连地点类型字段一起抽网址 | 那两个字段是类型标签。地址已经盖住用户能改的说明。 |
| 只抽已知短链 | 普通域名会被漏记。现有规则已经会放过普通域名。 |

## 后果

- 地址里的 `https://bit.ly/…` 会走现有短链删除。`https://t.me/+…` 和 `https://t.me/%2B…` 只留下 `t.me`，并记成邀请。
- 普通域名仍保留。地址原文、路径和邀请码不进事件。
- 场馆标题仍按原来的优先级成为正文。地址里的关键词仍然看不到。
- 已有正文时，标题不进事件。标题里的网址只在标题成为正文时，由链接规则从正文里看见。
