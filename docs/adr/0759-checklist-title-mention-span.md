# ADR 0759：清单标题上的按标识提及必须从标题里开始

- 状态：已接受
- 日期：2026-11-07

## 背景

按标识提及可以按群删除。用户编号不进事件。见 ADR 0514。投票描述上的按标识提及必须从描述里开始。见 ADR 0758。

Android 的 `addEntitiesToText` 会跳过长度小于或等于 0、起点小于 0，或起点已经到达清单标题末尾的实体。起点落在标题里、长度越过末尾时，客户端把长度收到标题末尾，这段提及仍会画出来。

已有别的正文时，事件里的清单标题只留前 255 字。标题自己就是正文时，事件正文只留前 4096 字。提及仍按整段标题判断。

现在标题会读全部 `title_entities`。一个起点已经越过标题的按标识提及仍会带上 `asTextMention`。打开这条规则后，没画出来的提及也会删掉这条清单。

清单任务、礼物和游戏不在这条里。

## 决策

- `checklist.title` 是字符串时，`title_entities` 里的按标识提及，起点必须大于或等于 0 且小于标题长度，长度必须大于 0。
- 起点落在标题里、长度越过末尾时，仍带 `asTextMention`。
- 标题不是字符串时，仍按原来的方式读取。
- 已有别的正文时，第 256 字上的提及，只要起点仍落在标题里，就继续带 `asTextMention`。事件里的标题仍只留前 255 字。
- 标题自己就是正文时，第 4097 字上的提及，只要起点仍落在标题里，就继续带 `asTextMention`。事件正文仍只留前 4096 字。这时不再另留标题。
- 清单任务上的按标识提及不在这条里。
- 仍落在标题里的提及继续带 `asTextMention`。用户编号和名字仍不进事件。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。规则仍默认关闭。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续读全部实体 | 没画出来的提及会在打开规则后删掉这条清单。 |
| 也要求长度落在标题里 | 起点在标题里时，客户端会把越过末尾的长度收回来再画。 |
| 也按 255 字丢掉后面的提及 | 255 只是旁边标题的上限。整段标题更长时，后面的提及仍落在标题里。 |
| 清单任务也一起收 | 任务是另一段文字，这条只改标题。 |
| 默认打开 | 有的群会点名。打开之前不改现有群。 |

## 后果

- 起点已经到达或越过清单标题末尾的按标识提及不再带 `asTextMention`。空标题、长度为 0 和负起点也不带。
- 起点落在标题里的提及，打开 `text_mention` 后删除。证据仍是 `entity:text_mention`。用户编号不进事件。长度越过末尾的提及也删除。起点已经超过 255 或 4096、但仍落在标题里的提及也删除。
- 规则关闭时留下。付费帖仍不删除。见 ADR 0356。
- 标题不是字符串时，按标识提及后来由 ADR 0803 不再读取。
- 清单任务上的按标识提及后来由 ADR 0760 要求起点落在这条任务里。任务文字不是字符串时，按标识提及后来由 ADR 0804 不再读取。长度越过末尾时仍算画出来。
- 管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
