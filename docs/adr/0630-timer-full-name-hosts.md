# ADR 0630：改自动删除计时的人画出的全名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

有人改自动删除计时，或把它关掉时，Android 的 `MessageObject` 在 `TL_messageActionSetMessagesTTL` 上用 `replaceWithLink` 把这个人画进这行服务文字。这就是 `UserObject.getUserName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。自己改计时时这行不画名字。频道广播这行也不画这个人。全局自动删除另画 `auto_setting_from` 指向的人。

Bot API 把秒数放在 `message_auto_delete_timer_changed.message_auto_delete_time`。大于等于 0 的安全整数时，这条提示成立。0 表示关掉。见 ADR 0584。当时名的长度大于 0 就丢掉姓。Bot API 的这个对象只有秒数，没有 `auto_setting_from`。

助推这行仍只读名。短链可以只写在姓上。把整段收成正文会改变内容哈希，关键词也会命中名字。

## 决策

- 只在已经会标成 `asAutoDelete` 的提示上，从 `from` 会画出来的全名留主机名。`message_auto_delete_time` 是大于等于 0 的安全整数时读。0 也读。
- 名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读。空格不截断。用户名不读。
- 全名不进正文，也不改内容哈希。关键词因此不命中。秒数不读。本群群名不读。正文里已有短链时，证据仍先记正文的主机名。
- 空对象、负数、小数、字符串和布尔值不读发送者。普通消息不读 `from`。助推仍按原来的名。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`autodelete_notice` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不调用 `setChatMessageAutoDeleteTime`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续只读名 | 客户端把姓画在同一行里。姓上的短链会留在提示里。 |
| 把名字整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0486。 |
| 频道广播不读发送者 | 现有条件已经读 `from`。这条只改名字怎么切。频道仍按同一条提示读。 |
| 助推也改成全名 | 助推这行用的是名。姓上的短链并没有出现在那一行。见 ADR 0583。 |
| 新命令 `/timername` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 改计时或关掉计时的人，全名里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。计时本身还在。
- 全名原文、路径和用户名不进事件。内容哈希不变。关键词不命中全名。
- 空白名不挡住姓。空格后面的网址仍读。秒数仍不读。
- 正文里已有短链时，证据仍先记正文的主机名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 助推仍只读名。频道改计时后来由 ADR 0668 不再读发送者。群和超级群仍按全名。发送者是聊天时后来由 ADR 0679 只读这个聊天的标题。空对象、负数、小数、字符串、布尔值和普通消息仍不读发送者。管理员仍豁免。干净的提示在 `autodelete_notice` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
