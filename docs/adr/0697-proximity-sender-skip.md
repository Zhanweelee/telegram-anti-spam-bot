# ADR 0697：靠近提醒不读消息发送者

- 状态：已接受
- 日期：2026-11-06

## 背景

两个人靠近时，Android 的 `TL_messageActionGeoProximityReached` 用 `replaceWithLink` 画动作里的 `from_id` 和 `to_id`。这两个人是触发者和设置者。用户画出全名，聊天画出标题。这行不用消息自己的 `fromObject`。

Bot API 把这两个人放在 `proximity_alert_triggered` 的 `traveler` 和 `watcher`。两个人都是用户。消息发送者另写在 `from`。发送者是聊天时，`sender_chat` 是那个聊天，`from` 是占位用户。

ADR 0597 从 `from` 的可见名字留主机名。ADR 0689 只在发送者是聊天时停读。用户发送者的名字仍会留下主机名，但这行并不画这个人。

## 决策

- `proximity_alert_triggered.distance` 是大于等于 0 的安全整数时，不从 `from` 留主机名，也不从 `sender_chat.title` 留主机名。
- 用户和聊天都一样。编号和本群相同也跳过。
- 编号不同的聊天标题仍由通用代发规则读取。不从 `chat.title` 另读。
- 触发者和设置者的全名仍按原来的正文。距离和用户编号仍不读。
- 负数、小数、字符串、布尔值和空对象仍不读发送者。普通消息不读 `from`。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`proximity_notice` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不改实时位置。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 用户仍只读名 | 这行不画消息发送者。名上的短链会删掉一条没有这个名字的提示。 |
| 改读发送者全名 | 全名同样不在这行里。 |
| 改读本群群名 | 靠近提醒不画所在群的群名。 |
| 新命令 | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 靠近提醒不再因为消息发送者的名字或本群标题留下主机名。触发者和设置者的全名仍按正文删除短链。
- 别的聊天发到这个群时，标题仍由通用代发规则留下主机名。
- 名字原文、路径和用户名不进事件。内容哈希不变。关键词不命中消息发送者的名字。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 负数、小数、字符串、布尔值、空对象和普通消息仍不读发送者。干净的提示在 `proximity_notice` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
