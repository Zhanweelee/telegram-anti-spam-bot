# ADR 0165：增补字母前停住的主机名也留下

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0097 在抽主机名前去掉西里尔、希腊、亚美尼亚文和非 ASCII 拉丁字母。`b` 和 `it.ly` 中间夹着这种字母时，粘连后仍是 `bit.ly`。

Android `LinkifyPort.UCS_CHAR_FIXED` 收录 BMP 里的这些字母，第一增补平面整段没有放进标签类。U+10140、U+10780 和 U+1E030 仍分别是希腊、拉丁和西里尔字母。`http://bit.ly` 或 `http://203.0.113.132` 后面紧跟这种字母时，高亮停在前面的主机名。字母被去掉之后，主机名粘成 `bit.lytail.example`，对不上短链或裸 IP。

## 决策

- 粘连扫描继续去掉这些字母。另外再用停住扫描抽一遍主机名：只去掉 Android 标签类里收录的字母，标签类没有的字母留下。
- 两边都走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 邀请仍只从粘连扫描读取。粘连结果里的邀请码保持原样。
- 已经写在 `text_link`、按钮或其它结构化字段里的地址整段打开。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 停住扫描不再去掉任何这类字母 | BMP 里的 `α` 会让前面的 `bit.ly` 被单独算中，Android 把这枚字母算进标签。 |
| 粘连扫描留下第一增补平面的字母 | `b` 和 `it.ly` 中间夹着这枚字母时，短链会漏掉。 |
| 停住之后的路径改记成邀请 | 邀请仍按粘连扫描读取。这枚字母去掉之后，原来的邀请码还在。 |

## 后果

- `http://bit.ly` 后接 U+10140 或 U+10780，以及 `http://203.0.113.132` 后接 U+10140，按现有短链或裸 IP 规则删除。证据仍只有主机名。
- `http://example.com` 后接 U+10140 留着。BMP 希腊字母 `α` 仍从两边去掉，不把前面的 `bit.ly` 单独算命中。
- `b` 和 `it.ly` 中间夹着 U+10140 仍删除。`https://t.me` 和这枚字母后面的邀请码仍按粘连结果记成邀请。路径和这枚字母不进证据。
