# ADR 0083：题干、奖品说明和清单标题里的网址只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0056 和 ADR 0057 在没有更前面的正文时，用投票题干、奖品说明或清单标题当正文。已有正文时，这三段留在事件外面。题干和标题上的 `text_link` 已经只留主机名。写在纯文本里的短链或邀请，在已有正文时仍然看不到。

把这三段拼进已有正文会改变 `textSha256`。选项、频道标题、中奖者名字和任务文字仍不能整段进事件。

## 决策

- 从 `poll.question`、`giveaway.prize_description`、`giveaway_winners.prize_description` 和 `checklist.title` 里抽出网址，只留主机名。长度、折叠、邀请判断和 8 个主机名的上限不变。
- 已有正文时，这四段原文不进正文，也不改内容哈希。
- 没有更前面的正文时，它们仍按原来的优先级整段成为正文。这条正文里的网址由链接规则从正文看见，同时也记在主机名列表里。
- `question_entities` 和 `title_entities` 里的 `text_link` 仍按原来的规则读取。投票人、频道、中奖者和完成者的名字与 id 不读。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 已有正文时把题干或标题拼进去 | 题干会改变哈希。短链只需要主机名。 |
| 只在它们不是正文时才抽 | 多一条分支。它们成为正文时，主机名列表仍应带上同一条网址。 |
| 连频道标题和中奖者名字一起抽 | 那是另一条消息上的名字，不是这条广告的网址。 |

## 后果

- 已有正文时，题干、奖品说明或清单标题里的 `https://bit.ly/…` 会走现有短链删除。`https://t.me/+…` 和 `https://t.me/%2B…` 只留下 `t.me`，并记成邀请。
- 普通域名仍保留。这四段原文、路径和邀请码在已有正文时不进事件。
- 它们成为正文时，整段仍参与关键词和内容哈希。
- 选项、任务、频道标题和中奖者名字里的关键词仍然看不到。这些字段里已经抽出的网址仍按 ADR 0077。
- 题干、奖品说明和清单标题的原文后来由 ADR 0544 留在旁路字段。已有正文时，关键词和默认正则看这三段。频道标题和中奖者名字仍不进事件。
