# ADR 0589：关话题的人，名字只留主机名

- 状态：已接受
- 日期：2026-11-05

## 背景

论坛话题被关掉、重新打开，或者通用话题被隐藏、重新显示时，客户端把这个人的名字画在服务消息上。名字写在 `from`。这四个对象本身没有字段。见 ADR 0485。话题名在新建和改名时已经是正文。见 ADR 0088。这四条提示通常没有别的正文。短链可以只写在操作的人的名字里。

把 `from` 收成正文会让普通发言者的姓名也进检测。`forum_notice` 默认关闭，干净的提示仍留下。这次不改话题开关，也不读话题名、图标和话题号。

## 决策

- 只在已经会标成 `forumNotice` 的提示上，从 `from` 的可见名字留主机名。关掉、重开、隐藏和重新显示都是对象时读。空对象也读，因为官方对象本身没有字段。几种同时出现时仍先认关掉，再认重开，再认隐藏，再认重新显示。
- `first_name` 的长度大于 0 时只读名。空白也算有名。名缺失或正好是空字符串时改读姓。用户名不读。抽出之前不截断。
- 布尔值不读发送者。新建和改名因此仍不读 `from`。普通消息因此仍不读 `from`。
- 名字不进正文，也不改内容哈希。关键词因此不命中。话题名、图标和话题号不读。本群群名不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`forum_notice` 仍默认关闭。8 个主机名的上限不变。不调用关闭、打开、隐藏或显示话题的方法。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把名字整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0485。 |
| 从关掉对象里的名字抽主机名 | 这四个对象没有字段。写在里面的句子仍是另一段文字。 |
| 新建和改名也读 `from` | 话题名已经是正文。发言人的名字会再计一次。 |
| 新命令 `/forumname` | 菜单只剩一个空位。现有 `links` 已经能删短链。 |

## 后果

- 关话题、重开、隐藏或重新显示的人，名字里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。话题开关不变。
- 名字原文、路径和用户名不进事件，内容哈希不变。名字里的关键词不命中。
- 名的长度大于 0 时，姓和用户名不进事件。话题名、图标和话题号不进事件。
- `example.com` 和公开的 `t.me/名字` 留着。付费帖仍不删除。见 ADR 0356。
- 布尔值、新建和改名仍不读发送者。干净的提示在 `forum_notice` 关闭时仍留下。新建和改名仍看 `topic_notice`。云额度的基础检测器名单没有改。30 天保留期没有改。
