# ADR 0069：没有协议的主机名把 %2E 收成点

- 状态：已接受
- 日期：2026-11-02

## 背景

带协议的 `https://bit%2Ely` 会被 URL 解析器收成 `bit.ly`。没有协议时，主机名扫描在 `%` 处断开，`bit%2Ely` 对不上短链规则。`t%2Eme/+` 同样对不上邀请。

## 决策

- 链接检测在抽主机名前，把比较文本里的 `%2E` 和 `%2e` 换成 `.`。
- 只影响这次比较。正文和哈希不变。证据仍只留主机名。
- `%252E` 不含 `%2E` 这段字符，仍原样留下。
- 不放进 `foldEncodedGaps`，也不放进关键词和正则。
- 普通空格仍拆开主机名。`example%2Ecom` 仍按普通域名保留。
- 不改 ADR 0026 的基础检测器名单。不引入同形字库。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把所有 `%25` 都还原后再看 `%2E` | `%252E` 会变成点，`bit%252Ely` 会被当成短链。ADR 0068 已经拒绝。 |
| 在 `hostFromUrl` 里替换 | 按钮和隐藏链接带协议，URL 解析器已经收成点。缺口在没有协议的正文。 |
| 放进关键词折叠 | 点号不是格式字符。关键词不该因为 `%2E` 改变比较。 |

## 后果

- `bit%2Ely` 和 `t%2Eme/+…` 会命中现有短链和邀请规则。
- `bit%252Ely` 仍放过。`example%2Ecom` 仍放过。
- 直接调用 `extractHosts` 的代码仍扫描传入的原字符串。检测器自己先替换。
