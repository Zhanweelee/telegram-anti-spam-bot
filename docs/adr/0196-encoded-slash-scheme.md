# ADR 0196：编码斜杠不再拼出协议

- 状态：已接受
- 日期：2026-11-02

## 背景

Android 不会在匹配前把 `%2F` 收成斜杠，也不会把 `%3A` 收成冒号。`%2Fhttp://bit.ly/…`、`http:%2F%2Fbit.ly/…`、`http:/%2Fbit.ly/…`、`https:%2F%2Fbit.ly/…` 和 `http%3A%2F%2Fbit.ly/…` 都不会打开 `bit.ly`。`http%253A%2F%2Fbit.ly/…` 同样不会。`example.com%2Fhttp://bit.ly/…` 整段仍是前面的主机名。

真正的斜杠仍然会拆开。`http:%2F/bit.ly/…` 会打开后面的短链。换行、空格或再写一个斜杠隔在 `%2F` 和网址之间时，后面的短链也会打开。`t.me%2F+…` 仍是邀请。`https://bit.ly%2F…` 仍是短链。

粘连扫描如果先把 `%2F` 收成斜杠，`%2Fhttp://bit.ly` 会变成 `/http://bit.ly`，`http:%2F%2Fbit.ly` 会变成 `http://bit.ly`。短链被多出来的协议打开。

## 决策

- 把字母编码收成字符之前，把能拼成 `http://` 或 `https://` 的那一段换成 `!x`。斜杠可以是字面 `/` 或 `%2F`，冒号可以是字面 `:`、`%3A` 或 `%253A`。这一段里至少有一个字符是百分号编码。
- 紧挨在已经写好的 `http://` 或 `https://` 前面的 `%2F` 也换成 `!x`。
- 其它位置的 `%2F` 仍收成斜杠。`%252F` 仍保留。
- `!` 让前面的文字结束，`x` 让后面的主机名不能另起一段。
- 每段仍走现有的短链、裸 IP、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| `%2F` 一律不再收成斜杠 | `t.me%2F+…` 和 `https://bit.ly%2F…` 会漏掉。 |
| 只改开头的 `%2Fhttp` | `http:%2F%2Fbit.ly` 仍会收成协议。 |
| 直接删掉这段 `%2F` | `%2Fhttp://bit.ly` 会变成一条短链。Android 并不打开它。 |

## 后果

- `%2Fhttp://bit.ly/…`、`http:%2F%2Fbit.ly/…`、`https:%2F%2Fbit.ly/…`、`http%3A%2F%2Fbit.ly/…` 和 `http%253A%2F%2Fbit.ly/…` 留着。`example.com%2Fhttp://bit.ly/…` 留着。
- `http:%2F/bit.ly/…`、换行或空格隔开的 `%2F`，以及 `https://bit.ly%2F…`，仍按短链删除。`t.me%2F+…` 仍按邀请删除。路径和邀请码不进证据。
- `https://bit.ly%2Fhttp://t.co/…` 仍按短链删除。证据是 `bit.ly`。
- `203.0.113.163%2Fhttp://bit.ly/…` 仍按裸 IP 删除。证据是这个地址，不是后面的短链。
- 百分号编码的加号紧挨着裸主机名时不再收成加号。见 ADR 0197。
