# ADR 0033：inline bot 默认保留

- 状态：已接受
- 日期：2026-11-01

## 背景

`via_bot` 表示这条消息是经 inline bot 发出的。垃圾广告常用它代发。动图、投票和查询也走同一条路径。

bot 的用户名和 id 不是正文，但这轮的证据不需要它们。

## 决策

- 消息可以带 `via: true`。只有更新里真有 `via_bot` 对象时才设置。用户名、显示名和 id 全部丢掉。
- 检测器 id 是 `via`，放在 `@tasb/detector-via`。只在 `kind: message` 且带这个标记时返回 score 1。证据是 `via:bot`。
- 默认规则 `via_inline` 存在，但是关闭的。某个群把 `enabled` 设为 true 之后才删除。
- 不改 ADR 0026 的基础检测器名单。`via` 不在默认 `QUOTA_BASIC` 里。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 默认删除全部 inline 消息 | 动图和投票会被删。私聊命令还不能只关一条规则。 |
| 保存 bot 用户名再做白名单 | 这轮没有白名单。用户名不该先进事件。 |
| 平台层看到 `via_bot` 就直接删 | 群规则关不掉，也没法保持默认放过。 |

## 后果

- 不改 `default.json` 的群，inline 消息继续保留。
- `via_bot` 的显示名仍不读。商业账号代发时画在时间戳旁的全名后来由 ADR 0617 只留主机名。那是 `sender_business_bot`。
- 打开 `via_inline` 后，自部署会删除。云模式超过当月次数后，还要把 `via` 写进 `QUOTA_BASIC`，否则超额时这条规则会停。
- `chats.json` 整份替换的群要自己加上这条规则，才会有这个开关。
