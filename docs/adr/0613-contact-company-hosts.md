# ADR 0613：名片上的公司名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

分享的联系人会在气泡里画出副标题。Android 的 `MessageObject.VCardData.parse` 把电话、邮箱和公司名拼成这段副标题。公司名来自属性名以 `ORG` 开头的最后一条。后写的盖住先写的，空值也盖住。新的 `BEGIN:VCARD` 换一张名片。没有 `END:VCARD` 时这段副标题不画。

`URL` 行和名片标题已经只留主机名。见 ADR 0151 和 ADR 0609。职务 `TITLE` 和 `ROLE` 只在打开名片时列出，点一下是复制。备注同样只复制。电话去拨号，邮箱走邮件。

短链可以只写在公司名上。`shared_contact` 默认会删掉整张名片。关掉这条之后，公司名里的短链仍会留下。

把公司名收成正文会让关键词命中单位名称，也和原文默认不落盘冲突。

## 决策

- `contact` 是对象，且 vCard 里出现过成对的 `BEGIN:VCARD` 与 `END:VCARD` 时，从最后一张名片的公司名留主机名。属性名以 `ORG` 开头才算，大小写按客户端。`ORG;CHARSET=...` 和 `ORGANIZATION` 都算。`org`、`item1.ORG`、`TITLE` 和 `ROLE` 不算。
- 后写的公司名盖住先写的。空字符串也盖住，这时不留主机名。见到新的 `BEGIN:VCARD` 就丢掉上一张的公司名。抽出之前不截断。分号先换成空格，和气泡上看到的字一样。`QUOTED-PRINTABLE` 先按 UTF-8 解开。以空格开头的折行不拼回公司名。
- 主机名仍进消息已有的 `hosts`。邀请仍进 `invites`。`URL` 行和可见名字的主机名仍排在前面。正文里已有短链时，证据仍先记正文的主机名。公司名不进正文，也不改内容哈希。关键词因此不命中公司名。
- 电话、邮箱、备注、职务、分组行和发送者姓名不读。布尔值的 `contact` 不读。本群群名不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`shared_contact` 仍默认打开。关掉之后，短链仍走已有的 `links`。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把公司名拼进正文 | 关键词会命中单位名称，公司名也会落盘。 |
| 只靠 `shared_contact` | 关掉名片规则后，公司名里的短链仍留下。 |
| 连 `TITLE` 和 `ROLE` 一起读 | 气泡副标题不画职务。打开名片时点一下只是复制。 |
| 连电话和邮箱一起读 | 电话去拨号，邮箱打开的是邮件。见 ADR 0151。 |
| 把折行拼回公司名 | 气泡解析不拼接以空格开头的下一行。 |
| 新命令 `/company` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 关掉 `shared_contact` 后，公司名里的短链、邀请或裸 IP 仍会删除这条消息。证据只有主机名。
- 公司名原文、路径、电话和用户编号不进事件。内容哈希不变。公司名里的关键词不命中。
- 后写的公司名盖住先写的。空的公司名不留主机名。没有 `END:VCARD` 时不读。`URL` 行和可见名字里已有短链时，证据仍先记那一边的主机名。正文里已有短链时，证据仍先记正文的主机名。
- `example.com` 和公开的 `t.me/名字` 在名片规则关掉时留下。默认仍由 `shared_contact` 删除整张名片。付费帖仍不删除。见 ADR 0356。
- 职务、备注、电话、邮箱、小写 `org`、分组行和折出来的下一行仍不读。发送者姓名和群名仍不读。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
- 没有姓名时，标题上的原始电话后来由 ADR 0614 只留下主机名。电话本身仍不进事件。这行排在公司名前面。已有姓名旁边的普通电话仍不读。
- 副标题里会原样画出的电话和邮箱后来由 ADR 0615 只留下主机名。它们排在公司名前面。原文仍不进事件。
