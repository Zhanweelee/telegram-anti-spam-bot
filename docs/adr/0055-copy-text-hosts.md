# ADR 0055：复制按钮只在整段是网址时留主机名

- 状态：已接受
- 日期：2026-11-01

## 背景

内联按钮可以带 `copy_text.text`，用户一点就把这段字符串放进剪贴板。垃圾消息把短链或邀请放在这里，正文和 `url` 都没有这段地址。ADR 0053 只读 `url`。剪贴板里的普通句子如果并进正文，会改变 `textSha256`，原文也会进事件。

## 决策

- `copy_text.text` 整段能解析成一条 `http` 或 `https` URL 时，走 ADR 0053 的同一套主机名规则：最长 2048，只留小写主机名。邀请路径仍只记主机名，并写入 `invites`。和隐藏链接、按钮 `url` 合用 8 个主机名、8 个邀请的上限。
- 整段不是一条 URL 时丢掉，不从句子里再搜网址。
- 不读取按钮文字、`callback_data`、`login_url` 和 `web_app`。
- 不新增检测器。默认规则 `links` 仍只删除短链、裸 IP、邀请和黑名单。普通网址保留。
- 不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 从复制文本里搜索任意 URL | 剪贴板常带口令或备注。只接受整段就是一条网址，和 `url` 字段一样。 |
| 把复制文本并进正文再跑关键词 | 原文会进事件，内容哈希也会变。 |
| 把 `login_url` 和 `web_app` 一起读进来 | ADR 0053 已经把这两处留在按钮里。它们不是用户要复制的网址。 |

## 后果

- 复制 `https://bit.ly/...` 会走现有短链删除。复制 `https://t.me/+邀请码` 只留下 `t.me`，并记成邀请。
- 「请领取 https://evil.example/hide」这种整段不是一条 URL 的文本不会变成主机名。
- 复制文本、查询和邀请码不进事件。
- 没有更前面的正文时，按钮上看得见的字后来由 ADR 0063 成为正文。复制到剪贴板的句子仍不进事件。
- 隐藏链接和按钮 `url` 已经占满 8 个主机名时，后面的复制网址不再写入。
