# ADR 0324：独特礼物卡片上的名字命中就删除

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 的独特礼物服务消息始终画出收藏名，形式是收藏名加编号。没有附言时，卡片表格还画出型号、符号和背景的名字。附言出现后，这三行不再画出。短链可以只放在这些看得见的名字里。

`name` 是 `t.me/nft` 用的短名，卡片副标题用的是 `base_name`。编号、发布者标题和发布者用户名不在这张独特礼物卡片上。普通礼物另有一行「由 @用户名 发布」，用的是 `publisher_chat.username`，不是标题。

礼物附言仍按 ADR 0087 处理，并且排在这些名字前面。

## 决策

- `unique_gift.gift.base_name` 去掉首尾空白。没有附言时，再按型号、符号、背景的顺序拼上各自的 `name`。几段用一个普通空格分开，最长 4096 字符。
- 没有更前面的正文时，这段名字成为正文。关键词和链接规则因此能删除这条服务消息。路径留在正文里。
- 已有正文或附言时，看得见的名字只贡献主机名。附言仍优先成为正文。
- 有附言时不读型号、符号和背景，因为客户端不画出这三行。
- 普通礼物和升级购买的 `gift.publisher_chat.username` 只留主机名，不进正文。
- 不读取独特礼物的 `name`、编号、`gift_id`、`publisher_chat`、`owned_gift_id`、成交币种和金额。不读取发布者标题、`from` 上的姓名和 `chat.title`。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 收藏名永远只留主机名 | 没有附言时，关键词会留在卡片副标题上。 |
| 把短名拼成 `t.me/nft` | 短名不是卡片上的那一行。ADR 0087 已经放弃。 |
| 有附言时仍读型号名字 | 客户端这时不画出型号、符号和背景。 |
| 读取发布者标题 | 普通礼物画出的是 `@用户名`，不是标题。 |

## 后果

- 没有正文和附言时，收藏名、型号、符号或背景里的默认关键词、短链或邀请会删掉这条服务消息。证据仍只有关键词或主机名。路径留在正文里。
- 已有正文或附言时，收藏名里的短链和邀请仍删除。正文和哈希不变。型号、符号和背景不进事件。
- 普通礼物的发布者用户名是短链时删除。标题不进事件。用户名不成为正文。某个群后来可以打开 `gift_card` 删除这张卡片。收藏名仍按本决定成为正文。见 ADR 0481。
- `example.com` 和普通名字留着。短名、编号、发布者标题、发送者姓名和所在聊天的标题不进事件。
- 云额度的基础检测器名单没有改。
