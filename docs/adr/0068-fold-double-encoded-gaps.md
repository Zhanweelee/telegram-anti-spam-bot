# ADR 0068：第二层百分号编码的格式字符也去掉

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0067 去掉 `%E2%80%8B` 这种一层编码。再编码一次时，只有百分号本身会变成 `%25`，十六进制仍是原文。`%25E2%2580%258B` 对不上邀请正则，也拆开没有协议的短链。

## 决策

- `foldEncodedGaps` 再识别 `%25HH` 这种第二层。还原后的字节仍必须是 `foldMatchText` 会删掉的字符，才把整段删掉。
- `%2520`、`%252E` 和 `%252F` 保留。不把所有 `%25` 都还原成 `%`。
- 第三层 `%2525E2%252580%25258B` 保留。
- 关键词和正则仍只用 `foldMatchText`。
- 不改 ADR 0026 的基础检测器名单。不引入同形字库。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把每个 `%25` 都换成 `%` | `%252E` 会变成 `%2E`，URL 解析器再把它收成点，`bit%252Ely` 会变成短链。 |
| 循环解到不能再解 | 第三层和更深的编码会把规则扩成通用解码。这一轮只补标准的第二次 `encodeURIComponent`。 |
| 只改邀请正则 | 没有协议的 `bit%25E2%2580%258B.ly` 仍然被 `%` 拆开。 |

## 后果

- `https://t.me/+IN%25E2%2580%258B…` 和 `bit%25E2%2580%258B.ly` 会命中现有规则。
- `%252E` 仍不会在这一层变成点。没有协议的 `%2E` 后来由 ADR 0069 在链接比较前收成点。
- 第三层编码仍留在路径里。邀请码不进事件。
