# ADR 0002：多租户模型

- 状态：已接受
- 日期：2026-11-01

## 背景

同一个核心要服务自部署和公共云 bot。如果自部署另写一套存储或规则，两条线会立刻分叉。

## 决策

- 持久化记录和事件从第一天带 `tenantId` 与 `chatId`。
- Self-host 是单个 `tenantId`、并且不加载计费模块的部署。Worker 的 `DEPLOYMENT_MODE` 只存在于 `apps/worker`。
- 云服务的租户目录、额度、付费入口只放在 `apps/cloud`。core 不引用这个包。
- 规则按 `(tenantId, chatId)` 存取。以后的「全局默认 + 群覆盖」是读规则的合并策略，不是另一套事件类型。
- 跨群黑名单必须显式 opt-in，默认关闭。那是 P1，不在本 ADR 里实现。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| Self-host 不写 tenantId | 以后把同一套数据模型搬到云上时要迁移所有表。 |
| 用 Cloudflare 账号 ID 充当租户 | 平台标识会漏进 core。租户是领域概念，账号是适配层细节。 |
| 每个群一个 Worker | 免费套餐的 Worker 数量和运维成本都不合适。隔离靠数据键，不靠进程。 |

## 后果

- 内存适配器和以后的 D1 适配器用同样的键：租户 + 群。
- 额度耗尽时的降级（退回基础规则，而不是停摆）发生在 cloud 模块调用流水线之前或之外。core 只看到自己被传入的规则集。
- 免费用量和周期的默认值在 ADR 0026。付费渠道仍然没有实现。
