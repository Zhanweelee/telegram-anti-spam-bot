# ADR 0678：聊天把人移出群时只读聊天标题

- 状态：已接受
- 日期：2026-11-06

## 背景

有人把别人移出群时，Android 的 `TL_messageActionChatDeleteUser` 用 `replaceWithLink` 画出发送者。发送者是用户时，画出全名。发送者是聊天时，画出这个聊天的标题。标题不截断。频道、群和超级群都画这个发送者。自己离开时，发送者是用户，仍画全名。

Bot API 把离开的人放在 `left_chat_member`。发送者是聊天时，`sender_chat` 是那个聊天，`from` 是占位用户。见 `telegram-bot-api` 的 `messageSenderChat`。

ADR 0623 仍从 `from` 的全名留主机名。占位用户的名字不是这行画出的字。离开的人的主机名仍排在前面，名字不进正文。

## 决策

- 已经会标成 `notice: "leave"`，且 `sender_chat` 是对象时，只从 `sender_chat.title` 留主机名，不从 `from` 留主机名。标题不截断。用户名不读。频道、群和超级群都一样。空对象也读。
- 没有 `sender_chat` 时，仍从 `from` 的全名留主机名。名和姓都去掉两端空白，名在前。空白名不挡住姓。空格不截断。自己离开时也读。
- 离开的人仍按 ADR 0624 只留主机名，排在标题前面。名字不进正文。
- 布尔值不读。同时出现入群名单时仍先认入群，不读这条移出的发送者。
- 不从 `chat.title` 另读。用户编号不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`service_notice` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。退群本身不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续读 `from` | 占位用户的名字不在这行里。短链会删掉一条没有这个名字的提示。 |
| 频道不读标题 | 移出这行在频道里也画出发送者。频道自己加入才不画人。 |
| 自己离开也不读 | 自己离开时发送者是用户，这行仍画全名。 |
| 只读频道代发 | 群和超级群自己移出人时同样画标题。 |
| 新命令 | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 聊天把人移出群时，标题里的短链、邀请或裸 IP 会留下主机名。证据只有主机名。人还是离开了。
- 占位用户的名字不再留下主机名。用户仍按全名。
- 离开的人的主机名仍排在前面。名字不进正文。布尔值仍不读。
- 标题原文、路径、用户名和用户编号不进事件。内容哈希不变。关键词不命中标题和全名。
- 离开的人的名字里已有短链时，证据仍先记那个人的主机名。正文里已有短链时，证据仍先记正文的主机名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 入群仍按 ADR 0677。管理员仍豁免。干净的退群提示在 `service_notice` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
