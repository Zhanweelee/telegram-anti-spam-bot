# ADR 0255：m 用户名仍读 text，短码不读

- 状态：已接受
- 日期：2026-11-03

## 背景

桌面端把 `m/短码` 收成 `tg://message?slug=`，查询里的 `text` 不进草稿。字符集是 `[A-Za-z0-9._-]`，没有长度上限，大小写不限。末尾斜杠对不上这道式子，会落到用户名式子并写草稿。没有短码时，`m` 和 `m/` 仍按用户名写草稿。

Android 只在路径以小写 `m/` 开头时打开业务聊天，不写聊天草稿。裸的 `m` 和大写 `M/短码` 仍按用户名读取 `text`。

小写 `m/` 后面 1 到 128 位字母、数字、`.`、`_` 或 `-` 已是邀请。超过 128 位的小写短码不是邀请，两边也都丢掉 `text`。带点的短码仍是邀请。

`m.t.me` 是单字母子域。桌面端不改写单字母子域。空路径仍按 ADR 0139 不读。

## 决策

- 把 `m` 从保留用户名里拿掉。
- `t.me`、`telegram.me`、`telegram.dog` 以及一层 `www.` 上，`m`、末尾只有一条斜杠、末尾斜杠后面的查询，以及大写 `M` 后的短码，都从 `text` 抽主机名。
- 小写 `m/` 后面一段符合 `[A-Za-z0-9._-]` 且路径不以斜杠结尾时不读 `text`。`m.t.me/` 后面同样一段也不读。
- `m.t.me` 没有路径时不读。
- 邀请仍按 ADR 0156 删除。
- 再多一段路径不读。
- `tg://resolve?domain=m` 仍读。`tg://message` 仍按邀请读取 `slug`，不读 `text`。
- 这个主机名走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。`text` 不进入正文，也不参与关键词。
- 用户名、应用名和短码不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续把 `m` 放进保留名 | `t.me/m?text=` 会漏掉。两边都把它当成用户名。 |
| 小写短码也读 `text` | 桌面端收成 `tg://message`。Android 打开业务聊天。两边都不写聊天草稿。ADR 0156 已拒绝。 |
| 大写 `M/短码` 不读 | Android 的 `startsWith("m/")` 区分大小写，仍按用户名写草稿。 |
| 末尾斜杠不读 | 桌面端的短码式子要求查询紧挨短码，斜杠会落回用户名草稿。 |
| 空的 `m.t.me` 也读 | 单字母子域桌面端不改写。ADR 0139 已把这类子域留在外面。 |

## 后果

- `t.me/m`、`t.me/m/`、`tg://resolve?domain=m`、`t.me/M/slug.222` 和 `t.me/m/slug222/` 的 `text` 是裸 IP、默认短链或邀请时删除。证据仍只有主机名。大写短码在 128 位以内时同时记邀请。
- `t.me/m/slug222?text=`、`t.me/m/slug.222?text=` 和超过 128 位的小写短码仍不读 `text`。短码本身仍按 ADR 0156 删除。
- 超过 128 位的大写 `M/短码` 仍读 `text`。它不是邀请。
- `m.t.me/数字?text=` 和 `m.t.me/短码?text=` 仍只记邀请。
- `m.t.me` 没有路径时留着。
- `t.me/m/短码/再一段` 留着。
- 用户名、应用名和短码不进证据。
