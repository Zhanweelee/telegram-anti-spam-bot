# ADR 0290：组合附加符号不再拆开草稿里的裸主机名

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 的单词边界会跳过非间距组合附加符号。`example.com`、`www.example.com` 或 `203.0.113.10` 后面紧挨这个符号，再写 `http://bit.ly/…`，整段都不是链接。`bit.ly` 后面紧挨这个符号再写斜杠，也不是链接。`example.com` 加这个符号再写 `https://t.me/+…`，邀请不会打开。

符号后面如果是斜杠，`example.com` 加符号再写 `/http://bit.ly/…`，后面的短链会单独打开。符号写在 `http://` 最前面，或者前面是空格、句号、`!`，短链仍会打开。希腊字母仍让裸主机名在字母前结束。

带协议的 `http://example.com` 加符号再写短链，仍是一条链接。`example.com/` 或 `example.com?` 把符号留在路径或查询里，后面的短链不单独打开。`http://bit.ly` 加符号再写路径，点开的主机名不是短链。

看得见的正文已经把这种符号当成透明的。隐藏的分享 `text` 把符号当成非 ASCII 字母，在它前面结束主机名，短链被单独打开。见 ADR 0191。

## 决策

- 分享 `text`、分享 `url`、私聊预填 `tg://msg` 的 `text` 和用户名草稿的 `text`，一串非间距组合附加符号是透明的。裸主机名不在这种符号前面结束，符号后面的 `http://` 也不另起一段。
- 符号后面的斜杠仍开始下一条网址。
- 比较前把 U+0345 换成 U+0300。希腊字母 `Ι` 仍让主机名结束。
- `bіt.ly`、变体选择符拆开的 `bit.ly` 和 `点击bit.ly` 仍收成短链。
- 证据只留主机名。路径和邀请码不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续把符号当成非 ASCII 字母 | `example.com` 加符号再写 `http://bit.ly` 会单独打开短链。 |
| 删掉全部组合附加符号 | `example.com` 加符号再写 `/http://bit.ly` 会粘成一条路径，漏掉短链。 |
| 让忽略大小写的字符类保留 U+0345 | 希腊字母 `Ι` 会被当成这个符号，后面的短链会漏掉。 |

## 后果

- `t.me/share/url?text=example.com` 加组合附加符号再写 `http://bit.ly/…` 留着。`bit.ly` 加符号再写斜杠也留着。证据里没有短链。
- 同一段再写 `https://t.me/+…` 不记成邀请。
- `example.com` 加符号再写 `/http://bit.ly/…`，以及符号开头的 `http://bit.ly/…`，按短链删除。路径不进证据。
- `http://example.com` 加符号再写短链，以及 `example.com/` 加符号再写短链，留着。
- 已经结束的主机名后面紧挨 `%2E` 时，隐藏草稿仍把这段收成点，短链不再是原来的主机名。见 ADR 0291。
