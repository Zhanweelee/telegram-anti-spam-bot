# ADR 0734：礼物附言上的文字链接不能越过正文

- 状态：已接受
- 日期：2026-11-07

## 背景

普通礼物、唯一礼物和升级购买都可以带一段附言。短链在各自的 `entities`。见 ADR 0087 与 ADR 0548。

Android 用 `addEntitiesToText` 把实体画到附言上。聊天列表的短预览、礼物卡片和详情表都走这一步。文字链接的起点大于或等于这段文字时，链接不会画上去。

现在这三段附言会读全部文字链接。起点已经越过附言的链接仍会留下主机名。

游戏附加文字已经要求起点落在附加文字里。见 ADR 0733。礼物附言是另一段文字。

## 决策

- `gift`、`unique_gift` 和 `gift_upgrade_sent` 上的文字链接，起点必须小于这段 `text` 的长度。附言不是字符串时，仍按原来的方式读取。
- 附言里的普通网址仍读。仍只留主机名。顺序仍是普通礼物、唯一礼物、升级购买。
- 投票描述不在这条里。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续读全部文字链接 | 没画上去的链接会删掉这条礼物消息。 |
| 只改普通礼物 | 唯一礼物和升级购买的附言也用同一套实体画出来。 |
| 投票描述也按正文长度丢掉链接 | 这份客户端还没有画出描述。这条只改礼物附言。 |

## 后果

- 起点越过附言的文字链接不再留下主机名。仍落在这段文字里的短链、邀请或裸 IP 会删除。证据只有主机名。
- 被截断的路径不进事件。写在附言里的路径仍留在正文或 `giftText`。关键词不命中没画上去的链接。内容哈希不变。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
- 外部回复清单标题上的文字链接后来由 ADR 0735 同样要求起点落在标题里。投票描述仍不在那条里。
- 礼物附言上的文字链接后来由 ADR 0769 要求长度大于 0。普通礼物、唯一礼物和升级购买都一样。长度越过末尾时仍算画出来。游戏附加文字不在那条里。
