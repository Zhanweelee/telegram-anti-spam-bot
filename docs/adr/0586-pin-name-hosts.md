# ADR 0586：置顶的人，名字只留主机名

- 状态：已接受
- 日期：2026-11-05

## 背景

管理员把一条消息置顶时，客户端把这个人的名字画在服务消息上。名字写在 `from`。被置顶的原文在 `pinned_message` 里，那是另一条消息。见 ADR 0482。这行通常没有别的正文。短链可以只写在置顶的人的名字里。

把 `from` 收成正文会让普通发言者的姓名也进检测。`pin_notice` 默认关闭，干净的提示仍留下。这次不撤下置顶，也不读被置顶的原文。

## 决策

- 只在已经会标成 `asPin` 的提示上，从 `from` 的可见名字留主机名。`pinned_message.message_id` 是大于 0 的安全整数时读。
- `first_name` 的长度大于 0 时只读名。空白也算有名。名缺失或正好是空字符串时改读姓。用户名不读。抽出之前不截断。
- 空对象、0、负数、小数和字符串不读发送者。普通消息因此仍不读 `from`。
- 名字不进正文，也不改内容哈希。关键词因此不命中。被置顶的原文、嵌套名字和消息号不读。本群群名不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`pin_notice` 仍默认关闭。8 个主机名的上限不变。不调用 `unpinChatMessage`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把名字整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0482。 |
| 从 `pinned_message` 抽主机名 | 那是另一条消息。原文里的短链会误删这条提示。 |
| 每条消息都读 `from` | 发言人的名字会跟着每条消息重复计一次。 |
| 新命令 `/pinname` | 菜单只剩一个空位。现有 `links` 已经能删短链。`/pin` 已经是操作命令。 |

## 后果

- 置顶的人名字里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。置顶本身还在。
- 名字原文、路径和用户名不进事件，内容哈希不变。名字里的关键词不命中。
- 名的长度大于 0 时，姓和用户名不进事件。被置顶的原文和消息号不进事件。
- `example.com` 和公开的 `t.me/名字` 留着。付费帖仍不删除。见 ADR 0356。
- 不是真实置顶提示时，发送者仍不读。干净的提示在 `pin_notice` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
- 置顶提示上的发送者后来按全名只留主机名。名和姓都去掉两端空白，名在前。空白名不挡住姓。空格不截断。见 ADR 0620。被置顶的原文和消息号仍不读。
