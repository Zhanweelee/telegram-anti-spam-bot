# ADR 0297：编码间隔贴在草稿主机名上时留下十六进制

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 不会在匹配前删掉百分号编码的换行、制表符、不换行空格或零宽字符。`%0Abit.ly/…` 打开的是 `0abit.ly`。`%09bit.ly/…`、`%C2%A0bit.ly/…`、`%E2%80%8Bbit.ly/…` 和 `%250Abit.ly/…` 也是把十六进制留在主机名开头。`%0A203.0.113.169/…` 不会打开这个地址。

`%09http://bit.ly/…`、`http%0A://bit.ly/…` 和 `ht%0Atp://bit.ly/…` 什么都不打开。`http:%0A//bit.ly/…` 会打开后面的 `bit.ly`。真正的换行后面仍会打开。

`%0Awww.bit.ly/…` 打开的是 `0awww.bit.ly`。这个主机名仍以 `.bit.ly` 结尾。`%0A.bit.ly/…` 打开的是 `0a.bit.ly`。`http://bit.ly%0Aevil.com/…` 仍先打开 `bit.ly`。`http://%0Abit.ly/…` 什么都不打开。

标签中间的编码仍要去掉。`bit%E2%80%8B.ly` 和 `b%0Ait.ly` 仍按短链删除。`t.me/+` 中间的 `%E2%80%8B` 仍是邀请。

看得见的正文已经这样切。隐藏的分享 `text` 抽出网址之后，又按公开规则把间隔整段删掉。`http://%0Abit.ly` 会收成 `bit.ly`。见 ADR 0201。

## 决策

- 分享 `text`、私聊预填 `tg://msg` 的 `text` 和用户名草稿的 `text`，协议正后面的编码间隔去掉百分号，十六进制留在主机名开头。
- 已经结束的主机名或点分 IPv4 后面的编码间隔改成空格，十六进制留给下一段。
- 标签中间的编码、真正的换行、`http:%0A//…` 和邀请码中间的零宽编码仍按原规则。
- 证据只留主机名。路径不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续按公开规则删掉每一段间隔 | `http://%0Abit.ly` 会收成 `bit.ly`。 |
| 编码间隔一律改成空格 | `bit%E2%80%8B.ly` 和邀请码中间的零宽编码会漏掉。 |
| 只改 `%0A` | `%09`、`%C2%A0` 和 `%E2%80%8B` 贴在协议后面时仍会收成短链。 |

## 后果

- `t.me/share/url?text=%0Abit.ly/…`、`%09http://bit.ly/…`、`http%0A://bit.ly/…` 和 `http://%0Abit.ly/…` 留着。`%0A203.0.113.169/…` 留着。
- `%0Awww.bit.ly/…` 按短链删除。证据是 `0awww.bit.ly`。`%0A.bit.ly/…` 按短链删除。证据是 `0a.bit.ly`。路径不进证据。
- `bit%E2%80%8B.ly`、`b%0Ait.ly`、真正的换行和 `http:%0A//bit.ly/…` 仍按短链删除。
- `http://bit.ly%0Aevil.com/…` 仍按短链删除。证据是 `bit.ly`。`http://203.0.113.169%0Aevil.com/…` 仍按裸 IP 删除。
- `t.me/+` 中间的零宽编码仍按邀请删除。
- 已经结束的主机名后面把 `%2E` 收成空格时，`example.com%2Ebit.ly` 会另开 `bit.ly`。见 ADR 0298。
