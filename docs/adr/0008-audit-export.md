# ADR 0008：审计导出与删除

- 状态：已接受
- 日期：2026-11-01

## 背景

ADR 0003 要求按租户导出和删除审计，并写明 30 天是初始保留期。自动清理要先问维护者。`listAudits` 最多 100 条，给 `/logs` 用，不能当成全量导出。

## 决策

- `Storage` 增加 `exportAudits` 和 `deleteAudits`。范围是 `tenantId`，可选 `chatId`。删除只删审计，不删规则文档，也不删白名单。
- 导出文档是 JSON：`tenantId`、可选 `chatId`、`audits`。每条记录再过一遍 `auditRecordSchema`。禁止原文键。
- D1 导出按 100 行一页，用 `rowid` 续读。删除按 1000 行一页，见 ADR 0361。这两条都不在消息热路径上。
- 私聊命令 `/export` 和 `/forget` 只给配置中的管理员。租户取事件上的 `tenantId`，不从参数里读。群聊里的同样文本不读、不删。
- 私聊回复有长度上限。超过 3500 字符时只回复条数，不发截断的 JSON。
- 不添加 30 天清理任务。保留期仍是 ADR 0003 的初始值，等维护者确认后再做。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把 `listAudits` 的上限放大来当导出 | `/logs` 和全量导出会共用一次可能很大的读。 |
| 现在就加 Cron 做 30 天删除 | 保留期还没有被维护者确认。 |
| `/forget` 同时删规则和白名单 | 验收只要求审计范围。规则和白名单是另一份配置。 |

## 后果

- 每个 `Storage` 都要实现这两个方法，并跑 `bindStorageContract`。
- 导出页和删除语句会计入 D1 行读、行写。消息检测路径不调用它们。
- 私聊里看不到超长导出的正文。调用方仍可通过 `exportAudits` 拿到全部记录。
- 同一租户的其它群、其它租户的审计，以及规则文档，在按群删除后还在。
