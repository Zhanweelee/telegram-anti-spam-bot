# ADR 0065：链接检测在抽主机名前折叠正文

- 状态：已接受
- 日期：2026-11-01

## 背景

ADR 0054、ADR 0060 和 ADR 0064 让关键词和正则在比较前去掉格式字符、非常规空白和变体选择符。链接检测仍把原文交给主机名扫描。`bit.ly` 中间插一个零宽字符或换行，短链规则就看不到。带协议的地址有时会被 URL 解析器自己清掉选择符，没有协议的 `bit.ly` 不会。

## 决策

- `createLinkDetector` 在调用主机名和邀请扫描之前，对 `message.text` 做 `foldMatchText`。
- `U+0020` 保留。`bit. ly` 仍然不是 `bit.ly`。
- 事件里的正文、`textSha256` 和已经抽出的 `hosts` / `invites` 不改。证据仍只写原因和主机名。
- 不新增检测器，也不改 ADR 0026 的基础检测器名单。不引入同形字库。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 在归一化时改掉正文 | 哈希变了，重复计数会拆开。 |
| 连普通空格一起删掉 | `bit. ly` 这种被空格拆开的写法会被当成短链。 |
| 只折叠变体选择符 | 零宽字符和换行是同一类缺口。折叠函数已经包含它们。 |

## 后果

- `bit\u200b.ly`、`bit\uFE0F.ly` 和 `https://bit.\nly` 会命中现有短链规则。邀请路径里的零宽字符不再挡住 `t.me/+`。
- 普通空格仍拆开主机名。同形字仍按原样比较。
- 换行被拿掉后，拆在两行里的主机名会合成一个。这只影响链接比较，不改哈希。
- 直接调用 `extractHosts` 的代码仍扫描传入的原字符串。检测器自己先折叠。
- 按钮 `url`、`text_link` 和整段网址的 `copy_text` 后来由 ADR 0066 在解析前做同一层折叠。解析后的路径已经百分号编码，再折叠看不到原来的字符。
