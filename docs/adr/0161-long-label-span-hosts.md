# ADR 0161：超长标签前只留高亮主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0152 按 Android `LinkifyPort.WEB_URL` 留下高亮提前停住的主机名。一个标签最多 63 个字符：开头一个字母或数字，中间最多 61 个字母、数字或连字符，结尾再是一个字母或数字。更长的一段配不上标签。

`http://bit.ly.` 后面接 64 个字母时，打开的是 `bit.ly`。`http://203.0.113.9.` 后面接 64 个字母时，打开的是 `203.0.113.9`。整段解析把这 64 个字母留在主机名里，`bit.ly.aaa…` 对不上短链，多出来的一段也不是四段数字。

正好 63 个字符的标签仍是主机名的一部分。62 个字母后面如果再接连字符会超过 63，高亮停在这 62 个字母，不把后面的连字符算进去，也不退回前一个标签。

## 决策

- 正文里的 `http` 或 `https` 再取这段高亮的主机名。标签超过 63 个字符时，这个标签不成立，句点留在前面。只留主机名。
- 连字符只有在补上之后仍不超过 63、并且后面还有字母或数字时才算进标签。否则标签停在连字符前面。
- 整段解析出的主机名仍然保留。两边都走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。最多 8 个。
- 已经写在 `text_link`、按钮或其它结构化字段里的地址整段打开，不按高亮截断。
- 不把停住之后的路径再当成邀请。路径不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 只留整段解析出的主机名 | 点下去打开的是超长标签前面的短链或裸 IP。 |
| 超长时改收前 63 个字符 | 第 64 个仍是字母，Android 整段标签都不成立，不会停在半截上。 |
| 连字符放不下时退回前一个标签 | `bit.ly.` 加 62 个字母再加 `-foo` 打开的是这 62 个字母，不是 `bit.ly`。 |

## 后果

- `http://bit.ly.` 加 64 个字母，以及 `http://203.0.113.9.` 加 64 个字母，按现有短链或裸 IP 规则删除。证据仍只有主机名。
- 正好 63 个字符、后面还有别的标签时留着。62 个字母再加 `-foo` 也不记成前面的短链。
- 再套一层仍放行。路径不进证据。
- 下划线放不进标签时，高亮退回前一个主机名。见 ADR 0162。
