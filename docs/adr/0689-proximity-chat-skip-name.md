# ADR 0689：靠近提醒的发送者是聊天时不读占位名字

- 状态：已接受
- 日期：2026-11-06

## 背景

两个人靠近时，Android 的 `TL_messageActionGeoProximityReached` 画的是动作里的 `from_id` 和 `to_id`。这两个人是触发者和设置者。聊天画出标题，用户画出全名。这行不用消息自己的 `fromObject`。

Bot API 把这两个人放在 `proximity_alert_triggered` 的 `traveler` 和 `watcher`。发送者是聊天时，`sender_chat` 是那个聊天，`from` 是占位用户。见 `telegram-bot-api` 的 `messageSenderChat`。

ADR 0597 仍从 `from` 的可见名字留主机名。占位用户的名字不在这行里。这行也不画 `sender_chat` 的标题。编号和本群相同时，通用代发规则本来就不读标题。

## 决策

- 已经会标成 `asProximity` 的提示上，`sender_chat` 是对象时，不从 `from` 留主机名，也不从 `sender_chat.title` 留主机名。频道、群和超级群都一样。编号和本群相同也跳过。
- 没有 `sender_chat` 时，仍从 `from` 的可见名字留主机名。名的长度大于 0 时不读姓。空白也算有名。
- 编号不同的聊天标题仍由通用代发规则读取。不从 `chat.title` 另读。
- 触发者和设置者的全名仍按原来的正文。距离和用户编号仍不读。
- 负数、小数、字符串、布尔值和空对象仍不读发送者。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`proximity_notice` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不改实时位置。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续读 `from` | 占位用户的名字不在这行里。短链会删掉一条没有这个名字的提示。 |
| 改读 `sender_chat.title` | Android 这行不画消息发送者。标题上的短链并没有出现在这行里。 |
| 本群群名也读 | 靠近提醒从一开始就不读本群群名。 |
| 新命令 | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 聊天发出的靠近提醒不再因为占位名字或本群标题留下主机名。触发者和设置者的名字仍按正文。
- 别的聊天发到这个群时，标题仍由通用代发规则留下主机名。
- 用户仍只读名。关掉管理员豁免也不会因为本群标题删除这条提示。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。
- 30 天保留期没有改。
