# ADR 0327：超长 `/export` 只计数

- 状态：已接受
- 日期：2026-11-04

## 背景

私聊 `/export` 先把范围内的审计全部读出，拼成 JSON。超过 3500 字时丢掉这份 JSON，只回复条数。D1 按 100 行一页读取。免费计划每次调用最多 50 个子请求、10 ms CPU。审计一多，回复条数之前请求就已经用完额度。

ADR 0326 让 `/forget` 不再为了计数去导出。导出命令仍然需要条数，也仍然需要在放得下时给出全文。

## 决策

- `Storage` 增加 `countAudits`。范围仍是 `tenantId`，可选 `chatId`。它只返回行数。
- D1 用一条 `SELECT COUNT(*)`。没有非负整数条数时抛出固定错误 `audit_count_missing`，不把数据库返回的文本写进日志。
- `/export` 先计数。用该范围内最短的合法审计估算 JSON 长度。这个长度已经超过 3500 时，回复「导出 N 条，超过私聊长度」，不再调用 `exportAudits`。
- 最短长度放得下时仍导出全文。实际 JSON 超过 3500 时，回复读到的条数。空范围直接返回空的 `audits` 数组。
- 规则、白名单和 30 天保留期不动。保留期仍是 ADR 0003。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续把每页读完再数长度 | 条数只是数组长度，免费额度会先被读请求用完。 |
| 读到第一页超长就停，回复「至少 100 条」 | 管理员看不到真实条数。 |
| 用平均长度估算 | 估短了会漏掉放不下的导出，估长了会丢掉本来放得下的 JSON。 |
| 条数缺失时回复 0 | 管理员会以为这个范围是空的。 |

## 后果

- 每个 `Storage` 都要实现 `countAudits`，并继续跑 `bindStorageContract`。
- 放不下的大范围在 D1 上是一条计数。放得下的小范围仍按页读出。大约二十几条最短记录就会超过 3500 字，所以还需要读出的行数停在一页以内。
- 计数和随后的导出之间如果有新审计写入，超长回复用的是计数，全文用的是实际读到的行。
- 驱动没有报告条数时，私聊回复「参数无效」。
