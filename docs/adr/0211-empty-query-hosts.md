# ADR 0211：空权威的问号不再另记主机名

- 状态：已接受
- 日期：2026-11-03

## 背景

`http://` 后面可以直接写 `?`。Android 把 `http://?bit.ly/…`、`https://?bit.ly/…` 和 `http:///?bit.ly/…` 收成一条链接。这条链接没有主机名，问号里的短链、裸 IP 和邀请不会再打开。

扫描若从问号里再认裸域名，就会把这条消息删掉。`http://example.com?bit.ly/…` 已经整段留下。`http:///bit.ly/…` 和 `http:////bit.ly/…` 仍会打开 `bit.ly`。`#` 仍结束前一段，后面的短链单独打开。

## 决策

- `://` 后面紧接着 `?` 或 `/`、并且还没有主机名时，这一段收到问号或路径结束。问号里的主机名不另记。
- 已经有主机名的网址仍按原尾巴收。`http://example.com?…` 和 `http://bit.ly?…` 不改。
- 解析器能读出主机名时仍记。`http:///bit.ly/…` 仍按短链删除。
- 空格后面的下一条网址仍单独打开。
- 每段仍走现有的短链、裸 IP、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 问号里的裸域名继续单记 | `http://?bit.ly` 会删掉 Android 留成一条无主机名链接的消息。 |
| `/` 开头的空权威一律不解析 | `http:///bit.ly` 会漏掉实际打开的短链。 |
| `#` 也收进这一段 | `http://#bit.ly` 仍会单独打开 `bit.ly`。 |

## 后果

- `http://?bit.ly/…`、`https://?bit.ly/…`、`http:///?bit.ly/…` 和 `http://?203.0.113.10/…` 留着。
- `http://?t.me/+…` 不记成邀请。`https://t.me/+…` 仍按邀请删除。邀请码不进证据。
- `http:///bit.ly/…`、`http:////bit.ly/…`、`http://bit.ly?…` 和 `http://#bit.ly/…` 仍删除。
- `http://example.com?bit.ly/…` 留着。空格后面的 `http://t.co/…` 仍删除。路径不进证据。
