# ADR 0164：百分号和括号前停住的主机名也留下

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0069、ADR 0072 和 ADR 0103 在抽主机名前把 `%2E`、`%65` 和 `[.]` 收成主机名里的字符。`b%69t.ly` 和 `bit[.]ly` 因此仍能对上短链。

Android `LinkifyPort.WEB_URL` 不会跨过 `%` 或 `[`。`http://bit.ly%2Eevil.com`、`http://bit.ly%65evil.com` 和 `http://bit.ly[.]evil.com` 打开的是 `bit.ly`。收成字符之后，主机名变成 `bit.ly.evil.com` 或 `bit.lyevil.com`，对不上短链。`http://203.0.113.131%2E…` 同样打开 `203.0.113.131`。

## 决策

- 粘连扫描继续收这些字符。另外再用留下 `%`、方括号和间隔的折叠抽一遍主机名，并入同一次判断。
- 两边都走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 邀请仍只从粘连扫描读取。百分号或括号后面的路径不改记成邀请。
- 已经写在 `text_link`、按钮或其它结构化字段里的地址整段打开。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 只留收成字符后的主机名 | 点下去打开的是百分号或括号前面的短链或裸 IP。 |
| 百分号和括号一律不再折叠 | `b%69t.ly` 和 `bit[.]ly` 会漏掉。 |
| 停住之后的路径改记成邀请 | `t.me%2E…/+邀请码` 打开的是没有这段路径的主机名。 |

## 后果

- `http://bit.ly%2E…`、`http://bit.ly%65…`、`http://bit.ly[.]…` 和 `http://203.0.113.131%2E…` 按现有短链或裸 IP 规则删除。证据仍只有主机名。
- `http://example.com%2E…` 留着。`b%69t.ly` 和 `bit[.]ly` 仍删除。
- `https://t.me%2E…/+…` 不改记成邀请。路径和百分号编码不进证据。
