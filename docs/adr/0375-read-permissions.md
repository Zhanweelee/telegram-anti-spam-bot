# ADR 0375：私聊可以查看群的默认发言权限

- 状态：已接受
- 日期：2026-11-04

## 背景

`/lock` 和 `/unlock` 会改全体成员的默认权限。管理员之后要确认现在是开还是关，只能回到 Telegram 客户端。

官方 `getChat` 返回 `ChatFullInfo`。其中 `permissions` 是群和超级群的默认成员权限，频道没有这项。`ChatPermissions` 的十六项都是可选布尔值。文档写明：没写 `can_react_to_messages` 时跟随 `can_send_messages`；没写 `can_edit_tag` 或 `can_manage_topics` 时跟随 `can_pin_messages`。

同一份对象里还有群标题、简介和邀请链接。这些不该进私聊回复。

没有 token 时，内存适配器不知道当前权限。把一次空记录回复成权限，会让管理员以为群已经锁上或打开。

## 决策

- 私聊命令 `/perms <chatId>`。群 id 匹配 `^-?\d{1,20}$`。群聊里的同样文本不执行。
- 配置中的管理员可以查看任意群。接入目录里的人只能查看自己的群。
- 命令调用 `ModerationPort.readPermissions`，只带 tenant 和 chat。适配器调用 `getChat`，只带 `chat_id`。
- 回复按固定顺序写出十六项。每一项是开、关或未知。
- 字段缺省时只套用文档写明的三项默认。其它缺省保持未知。显式的 true 或 false 保持原值。
- 没有 `permissions`，或某一项不是布尔值时，回复「参数无效」。
- 群标题、用户名、简介、邀请链接和姓名不进回复，也不进日志。
- 没有 token、没有这个方法，或调用失败时回复「参数无效」。日志只写 `operator_rejected`，带上 eventId、chatId 和命令名。不写异常文本或 token。
- 没有 token 的 Worker 不编造一份权限。
- 这条命令不调用 `setChatPermissions`，也不改黑名单、封禁或禁言。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把没写的权限都当成关闭 | 文档只给了三项缺省。其余项可能只是没返回。 |
| 用缺省覆盖显式的 false | 显式关闭反应时，不能因为发言开着就报成开。 |
| 连标题和简介一起回复 | 这些字段不是权限，也可能含原文。 |
| 没有 token 时回复一份全关 | 群的默认权限可能仍是开的。 |

## 后果

- 成功只表示 Telegram 返回了这份默认权限。频道，或 bot 不在群里时，回复是「参数无效」。
- 一次查看是一次 Telegram 子请求。默认权限、单人禁言和封禁都不变。
- 30 天保留期不动。
