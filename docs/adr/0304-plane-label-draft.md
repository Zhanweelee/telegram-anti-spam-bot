# ADR 0304：增补平面的标签字留在草稿主机名

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 把增补平面里的字收进标签，一个码位算一个字。`http://bit.ly𠀀/…`、`http://bit.ly.𠀀/…`、`http://bit.ly-𠀀/…` 和 `http://bit.ly𠀀:80/…` 各是一条链接。点开的主机名不是 `bit.ly`。连字符后面 31 个这样的字仍放得进 63 个字的标签。第 61 个放不下，`bit.ly` 单独打开。

`@`、`#` 和空格仍退回上一个单词。没有协议的 `bit.ly𠀀/…` 和 `www.bit.ly𠀀/…` 在这个字前面结束。第一平面的 U+10140 不在标签类里，`http://bit.ly𐅀/…` 仍只打开 `bit.ly`。见 ADR 0214。

隐藏的分享 `text` 在连字符处把 `http://bit.ly-𠀀/…` 收成 `bit.ly`。这个字还放得进标签。

## 决策

- 分享 `text`、私聊预填 `tg://msg` 的 `text` 和用户名草稿的 `text`，在带协议的主机名后面遇到连字符，后面的标签字仍放得进 63 个字时，不在连字符前切开。一个增补字只占一个位置。
- 放不下的连字符、62 个增补字，以及不在标签类里的第一平面字符，仍退回前面的主机名。
- 点号后面的增补字仍留在主机名里。`@`、`#` 和普通空格仍退回上一个单词。没有协议的主机名和 `www.` 在这个字前面结束。
- 不改带协议网址的整段匹配。闭合分享链接里的网址不走这道切开。
- 证据只留主机名。路径和邀请码不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 按 UTF-16 代理项停住 | `http://bit.ly𠀀/…` 会收成 `bit.ly`。Android 把这一整段当成一条链接。 |
| 连字符后面的字一律切开 | `http://bit.ly-𠀀/…` 会删掉 Android 留成一条链接的消息。 |
| 第一平面也收进标签 | `http://bit.ly𐅀/…` 会漏掉。Android 的标签类没有这一面。 |

## 后果

- `t.me/share/url?text=http://bit.ly𠀀/…`、`https://t.co𠀀?…`、`http://bit.ly.𠀀/…`、`http://bit.ly-𠀀/…`、`http://bit.ly𠀀:80/…`、`http://bit.ly𠀀:80@evil.com/…`、`http://www.bit.ly𠀀/…`、`http://203.0.113.10𠀀/…` 和 `http://t.me𠀀/+…` 留着。`http://bit.ly𠀀/http://t.co/…` 留着。后面 61 个增补字，以及连字符后面 31 个，仍留着。
- `http://bit.ly𠀀@evil.com/…`、`https://t.co𠀀@evil.com/…`、`http://bit.ly𠀀#…` 和 `http://bit.ly𠀀 evil.com/…` 按短链删除。证据是 `bit.ly`。路径不进证据。
- `http://203.0.113.10𠀀@evil.com/…` 按裸 IP 删除。没有协议的 `bit.ly𠀀/…` 和 `www.bit.ly𠀀/…` 按短链删除。`http://bit.ly𐅀/…` 仍按短链删除。后面 62 个增补字，以及连字符后面 61 个，仍按短链删除。
- 空格后面的 `http://t.co/…` 仍删除。证据是 `t.co`。`https://t.me/+…` 仍按邀请删除。邀请码不进证据。
- 写完的主机名后面的单字母仍可能粘上去。见 ADR 0215。
