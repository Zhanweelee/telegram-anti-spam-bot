# ADR 0644：分享给 bot 的用户画出的全名成为正文

- 状态：已接受
- 日期：2026-11-06

## 背景

用户通过按钮把若干用户分享给 bot 时，Android 的 `MessageObject` 在 `TL_messageActionRequestedPeer` 上用 `replaceWithLink` 画出每一个已经解析到的人。这就是 `UserObject.getUserName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。几个人之间是逗号加空格。

见 ADR 0321。当时正文还收了用户名，几个人也用空格接在一起。短链可以只写在姓上，也可以只写在用户名上。用户名上的词并没有画出来。

这行还会画正在对话的 bot。那个 bot 是客户端里的对话对象，不是这份 `users_shared` 名单。

没有更前面的正文时，这些人的名字就是正文。已有正文时，名字另留在 `sharedName`。见 ADR 0555。`chat_shared` 的标题仍只留主机名。

## 决策

- `users_shared.users` 里每个人按会画出来的全名成为正文。名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读这个人。空格不截断。用户名不读。
- 几个人按出现顺序用逗号加空格接起来。没有画出全名的人跳过，不留空位。
- 没有更前面的正文时，这段全名就是正文。已有正文时，拼起来的整段自己不是正文，就另留前 4096 字在 `sharedName`。主机名仍从这段全名抽取。
- 不读取 `request_id`、`user_id`、头像、`from` 上的姓名和 `chat` 的标题或名字。对话里的 bot 不在这份名单上。`chat_shared` 仍只留主机名。
- 入群名单、视频聊天邀请和换群主仍按原来的可见名字，含用户名。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。短链仍走已有的 `links`。`shared_name_regex` 仍只看这段画出的全名。`shared_chat` 仍默认关闭。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续把用户名收进正文 | 这行服务文字不画用户名。用户名上的短链和关键词会删掉看不见的字。 |
| 几个人仍用空格接起来 | 客户端在两个人之间画的是逗号加空格。 |
| 连对话里的 bot 一起读 | 客户端画的是正在对话的 bot。更新里没有这个人的名字。 |
| 连入群、邀请和换群主一起去掉用户名 | 这一轮只改分享来的用户。 |

## 后果

- 分享用户全名里的短链、邀请或裸 IP 会删除这条服务消息。证据只有主机名。
- 全名里的关键词仍命中这段正文。用户名里的关键词不命中。用户名不进事件。
- 空白名不挡住姓。空格后面的网址仍读。两个人之间的逗号留在正文里。
- 已有别的正文时，证据仍先记正文的主机名。这段全名另留在 `sharedName`。和正文相同的全名不重复留。
- 发送者的姓和用户名不进事件。请求编号、用户编号和头像仍不读。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 入群、邀请和换群主的可见名字仍含用户名。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
