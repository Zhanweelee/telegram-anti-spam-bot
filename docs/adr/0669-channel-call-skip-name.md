# ADR 0669：频道开始或结束视频聊天不再读发送者的名字

- 状态：已接受
- 日期：2026-11-06

## 背景

频道开始或结束视频聊天时，Android 的 `MessageObject` 在 `TL_messageActionGroupCall` 上，所在聊天不是普通群也不是超级群时，把这行设成 `ActionChannelCallJustStarted` 或 `ActionChannelCallEnded`。英文是 “Live stream started” 和 “Live stream finished (%s)”。两句都只写直播开始或结束的时间，不画操作的人。

群和超级群仍用 `replaceWithLink` 画出全名。见 ADR 0635。预约这行本来就不画人。见 ADR 0663。

Bot API 把频道放在 `chat.type === "channel"`。超级群是 `supergroup`，普通群是 `group`。ADR 0635 仍从 `from` 读名。名上的短链会删掉一条成员看不到这个名字的提示。时长不进事件。

## 决策

- `chat.type` 正好是 `channel`，并且已经标成开始或结束时，不从 `from` 抽主机名。`video_chat_started` 是对象时读这条规则。`video_chat_ended.duration` 是有限且不小于 0 的数字时也读，0 也算结束。名、姓和用户名都不读。
- 群和超级群仍按全名。没有 `chat`，或类型不是 `channel` 时仍按全名。
- 预约仍不读发送者。空的结束、负数和非有限数字仍不读。只有邀请名单时仍不读这条通话的发送者。时长和开始时间仍不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`call_notice` 仍默认关闭。8 个主机名的上限不变。不改视频聊天。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 频道继续按全名 | 这行不画人。名上的短链不是成员看到的字。 |
| 超级群也不读 | 超级群这行仍画全名。 |
| 0 秒仍读发送者 | 时长为 0 的结束对象仍是结束提示。频道句子同样不画人。 |
| 新命令 | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 频道开始或结束视频聊天时，发送者名字里的短链、邀请或裸 IP 不再删除这条消息。群和超级群仍会删。发送者是聊天时后来由 ADR 0675 只读这个聊天的标题。
- 名字不进事件。内容哈希不变。关键词不命中这些名字。
- 正文里的短链仍删除。`example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 预约仍不读发送者。靠近提醒仍只读名。空的结束、负数、非有限数字和普通消息仍不读发送者。管理员仍豁免。干净的提示在 `call_notice` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
