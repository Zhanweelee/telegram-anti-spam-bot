# ADR 0315：忽略标记后面的草稿文字字母留在带协议的主机名里

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 在带协议主机名和希腊文、西里尔文、亚美尼亚文或非 ASCII 拉丁字母之间，仍把地址解析会忽略的标记算进这条链接。`http://bit.ly​α/…`、`https://t.co​т?…`、`http://203.0.113.10​ա/…`、`http://bit.ly­α/…`、`http://bit.ly️α/…` 和 `http://bit.ly͏α/…` 的主机名不是前面的短链或裸 IP。`http://bit.ly​α.bit.ly/…` 的主机名仍以 `bit.ly` 结尾。见 ADR 0227。

没有协议的 `bit.ly​α/…` 只打开前面的短链。`#`、空格、换行和放不下的第 61 个字母也退回短链。

`http://bit.ly​α@evil.com/…` 在看得见的正文里仍打开 `bit.ly`。隐藏草稿先把标记和字母收掉，`@` 就变成用户信息，主机名记成 `evil.com`。

## 决策

- 分享 `text`、私聊预填 `tg://msg` 的 `text` 和用户名草稿的 `text`，在 `http://` 或 `https://` 的主机名后面先有一段这种标记，再是一段这类字母，而且紧接着是 `@` 时，先把标记和这段字母换成空格。
- 点号后面的同一段标记也一样。没有标记、字母直接贴在主机名或点号后面并且紧接着 `@` 时，仍按 ADR 0313 和 ADR 0314 换成空格。
- 这种标记是地址解析会忽略、并且 Android 标签类收得下的字符，包括 U+034F。制表符、换行和不换行空格不在里面。
- 主机名取最长的严格域名，不在中间的短链后缀停住。点分 IPv4 同样。
- 路径、问号、结尾、写完的端口和再接一个域名时，字母仍交给主机名扫描。
- `#`、空格、换行和放不下的字母仍按原来的规则收掉。没有协议的主机名不改。
- 不改带协议网址的整段匹配。闭合分享链接里的网址不走这道切开。公开的折叠不改。
- 证据只留主机名。路径不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 标记后面的字母一律收掉 | `http://bit.ly​α/…` 会按短链删除。Android 打开的不是 `bit.ly`。 |
| `@` 前面的字母也留在标签里 | `http://bit.ly​α@evil.com/…` 会漏掉已经打开的短链。 |
| 换行也当成这种标记 | `http://bit.ly` 换行再接 `α/…` 会漏掉。Android 只打开 `bit.ly`。 |

## 后果

- `t.me/share/url?text=http://bit.ly​α/…`、`https://t.co​т?…`、`http://203.0.113.10​ա/…`、`http://bit.ly­α/…`、`http://bit.ly️α/…`、`http://bit.ly͏α/…`、`http://bit.ly​α/http://t.co/…` 和 `http://bit.ly​α.evil.com/…` 留着。路径不进证据。
- `http://bit.ly​α.bit.ly/…` 仍按短链删除。证据是 `bit.lyx.bit.ly`。
- `bit.ly​α/…`、`www.bit.ly​α/…`、`203.0.113.10​α/…` 和 `bαit.ly` 仍按短链或裸 IP 删除。
- `http://bit.ly​α@evil.com/…`、`http://bit.ly​α#…`、换行和中间有空格的写法仍按短链删除。证据是 `bit.ly`。
- 第 61 个字母仍让短链单独打开。
- 标记写在主机名更前面时，这类字母也留在带协议的主机名里。见 ADR 0228。
- 主机名中间的忽略标记在隐藏草稿里也先拿掉。`http://bit​.lyα@evil.com/…` 仍按短链删除。见 ADR 0316。
