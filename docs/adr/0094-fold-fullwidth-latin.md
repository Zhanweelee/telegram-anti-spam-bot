# ADR 0094：全角拉丁字母在比较前收成半角

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0093 收了点状间隔号。`ｂｉｔ.ly` 和 `ｔ.ｍｅ/+…` 没有协议时，主机名扫描只认半角字母，短链和邀请都对不上。关键词和默认正则 `加微[信xX]`、`t.me/+` 也看不见全角字母。带协议的地址有时会被 URL 解析器自己收成半角。

全角数字写在没有协议的地址里，现有扫描本来就不把纯数字主机名当链接。带协议的 IP 已经由 URL 解析器收成数字。同形字库仍不引入。

## 决策

- 新增 `foldFullwidthLatin`。只把 `U+FF21`–`U+FF3A` 和 `U+FF41`–`U+FF5A` 收成 `A`–`Z` 和 `a`–`z`。
- 关键词和正则在 `foldMatchText` 之前做这一层。大小写开关仍先作用于原文，再收成半角。
- 链接检测、`hostFromUrl` 和从正文里抽网址的扫描，在点状间隔号之前做这一层。
- `U+FF10`–`U+FF19`、`U+FF0B`、`U+3002` 和普通空格保留。正则模式本身不改写。
- 事件里的正文和 `textSha256` 不变。不新增检测器，也不改 ADR 0026 的基础检测器名单。不引入同形字库。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 连全角数字一起收 | 没有协议的 IP 现在也抽不出来。带协议的 IP 解析器已经收成数字。 |
| 引入同形字库 | ADR 0054 已经拒绝。这一项只处理全角拉丁字母。 |
| 在归一化时改掉正文 | 哈希变了，重复计数会拆开。 |

## 后果

- `ｂｉｔ.ly/…` 和 `ｔ.ｍｅ/+…` 会走现有短链和邀请规则。`example.ｃｏｍ` 仍保留。
- `加微Ｘ` 和 `ｔ.ｍｅ/+…` 会命中默认正则。`ＶＩＰ` 会命中关键词 `VIP`。大小写敏感时 `ｖｉｐ` 仍不命中 `VIP`。
- `免Ａ费领取` 仍不命中 `免费领取`。全角数字、全角加号和句号 `。` 仍按原样比较。
- 重复计数仍按原文哈希。七个西里尔字母后来由 ADR 0095 收成拉丁字母。乌克兰语 `і` 后来由 ADR 0096 收成 `i`。西里尔 `т` 仍保留。
