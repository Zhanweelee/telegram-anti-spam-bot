# ADR 0616：客座回复抬头上 bot 自己的短名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

群里的客座 bot 替人回复时，Android 的 `ChatMessageCell` 在 `guestchat_via_from` 有值时重画名字行。这一行先放 `DialogObject.getShortName(from_id)`，再放本地化的 “for”，最后放召唤者的短名。

`getShortName` 对用户调用 `UserObject.getForcedFirstName`。名为空时改用姓。空白不算空。从下标 2 起找第一个空格，找到就把后面丢掉。下标 0 或 1 上的空格不截断。频道和群的短名是标题，这次不改召唤者那一侧。

Bot API 把召唤者放在 `guest_bot_caller_user` 或 `guest_bot_caller_chat`。布尔值不是对象。带非空 `guest_query_id` 的更新仍先被忽略。召唤者的完整名已经只留主机名。见 ADR 0446。桌面端画出的是召唤者全名，bot 自己的全名不在那条抬头里，所以这次只按 Android 的短名截断读取 `from`。

短链可以只写在 bot 自己的短名上。把整段名字收成正文会改变内容哈希，关键词也会命中名字。

## 决策

- `guest_bot_caller_user` 或 `guest_bot_caller_chat` 是对象，且 `from` 是对象时，从 bot 自己会画出来的短名留主机名。
- `from.first_name` 的长度大于 0 时用名，不读姓。名缺失或正好是空字符串，且 `last_name` 是非空字符串时，改用姓。空白名挡住姓。两边都没有可用名字时不读。
- 从下标 2 起的第一个空格后面不读。这个空格之前的前缀才抽主机名。没有这样的空格时，整段名字都读。抽出之前先截到正文长度上限。
- 主机名仍进消息已有的 `hosts`。邀请仍进 `invites`。bot 短名排在召唤者名字前面。正文里已有短链时，证据仍先记正文的主机名。短名不进正文，也不改内容哈希。关键词因此不命中。
- 用户名、用户 id、姓在有名时、本群群名，以及和本群编号相同的 `sender_chat.title` 不读。布尔值的召唤者对象不读。没有客座召唤者对象时，普通 `from` 仍不读。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。短链仍走已有的 `links`。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 每条消息的 `from.first_name` 都读 | 普通发言人的名字仍留在事件外面。 |
| 按桌面端读 bot 的完整名 | 这次补的是 Android 抬头上实际画出的短名。召唤者仍按 ADR 0446 读完整名。 |
| 把短名整段当成正文 | 会改变哈希，关键词也会命中名字。 |
| 连用户名一起抽 | 抬头画出的是短名，不是用户名。 |
| 新命令 `/guestbot` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 客座回复抬头上 bot 短名里的短链、邀请或裸 IP 会删除这条消息。证据只有主机名。
- 短名原文、路径和用户名不进事件。内容哈希不变。关键词不命中短名。
- 从下标 2 起被空格截掉的后半段不读。空白名挡住姓。没有客座召唤者对象时不读 `from`。
- 召唤者名字仍排在 bot 短名后面。正文里已有短链时，证据仍先记正文的主机名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 和本群编号相同的 `sender_chat` 仍按原有规则视为管理员并豁免。本群群名仍不读。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
