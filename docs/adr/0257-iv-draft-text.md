# ADR 0257：iv 用户名仍读 text，应用名也读

- 状态：已接受
- 日期：2026-11-03

## 背景

桌面端只在 `iv` 或 `iv/` 后面紧跟查询时返回原来的地址，用来打开即时预览页。`iv/短名` 和 `iv/数字` 对不上这道式子，落到用户名式子并写草稿。末尾斜杠也落在用户名式子里。

Android 没有单独的 `iv/` 分支。裸的 `iv`、应用名和数字都按用户名读取 `text`。

裸的 `t.me/iv?text=` 和 `t.me/iv/?text=` 已由 ADR 0130 按即时预览读取 `text`。`t.me/iv?url=` 仍从 `url` 抽主机名。

`iv.t.me` 有两个字符。没有路径时桌面端改写成 `t.me/iv`。后面是数字时改写成帖子。后面是短名时对不上这道改写。

## 决策

- 把 `iv` 从保留用户名里拿掉。
- `t.me`、`telegram.me`、`telegram.dog` 以及一层 `www.` 上，`iv`、后面一段应用名、后面一段数字，以及末尾斜杠，都从 `text` 抽主机名。
- `iv.t.me` 没有路径或后面是数字时同样读。后面是短名时不读。
- 再多一段路径不读。
- `tg://resolve?domain=iv` 仍读。`tg://iv` 仍按即时预览读取 `url`，并读取同一条上的 `text`。
- `t.me/iv/短名?url=` 不读 `url`。
- 这个主机名走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。`text` 不进入正文，也不参与关键词。
- 用户名和应用名不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续把 `iv` 放进保留名 | `t.me/iv/短名?text=` 和 `tg://resolve?domain=iv&text=` 会漏掉。两边都把它们当成用户名。 |
| 应用名不读 | 桌面端的即时预览式子只吃查询紧挨 `iv` 的写法。多出来的短名仍写草稿。 |
| 子域上的短名也读 | `iv.t.me/短名` 对不上桌面端子域改写。 |
| 应用名上的 `url` 也读 | 即时预览只认路径正好是 `/iv`。 |

## 后果

- `t.me/iv`、`t.me/iv/`、`iv.t.me`、`tg://resolve?domain=iv`、`t.me/Iv/slug.224`、`t.me/iv/slug224`、`t.me/iv/5` 和 `iv.t.me/数字` 的 `text` 是裸 IP、默认短链或邀请时删除。证据仍只有主机名。
- `t.me/iv/短名/再一段` 和 `iv.t.me/短名` 留着。
- `t.me/iv?url=` 仍按 ADR 0130 读取。`t.me/iv/短名?url=` 留着。
- 用户名和应用名不进证据。
