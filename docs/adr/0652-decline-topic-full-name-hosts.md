# ADR 0652：拒绝建议帖上画出的话题用户全名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

建议帖被拒绝时，Android 的 `getActionSuggestionApprovalText` 在 `rejected` 这一支里选一个名字。没有被回复的消息，或回复的发言人就是回复上的话题用户时，这行画频道名。回复的发言人不是这个话题用户时，这行画本条消息的话题用户。这个名字来自 `DialogObject.getName`，也就是 `UserObject.getUserName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。

这个人是本条的 `saved_peer_id`。Bot API 把它放在 `direct_messages_topic.user`。比较用的是 `reply_to_message` 上的 `from.id` 和 `direct_messages_topic.user.id`。两边都要能读成安全整数。缺一边时不猜。见 ADR 0600。`from` 仍只读名。频道标题仍不读。

名字本身不进正文。关键词不命中这段全名。

## 决策

- `suggested_post_declined` 是对象，并且 `reply_to_message.from.id` 与 `reply_to_message.direct_messages_topic.user.id` 都是安全整数且不相等时，从本条 `direct_messages_topic.user` 会画出来的全名留主机名。空的拒绝对象也算。
- 名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读。空格不截断。用户名不读。
- 没有回复、回复不是对象、任一边编号缺失或不是安全整数、两边编号相同，都不读这个人。那时客户端画频道名。频道标题仍不读。`from` 仍按 ADR 0600 只读名。
- 话题号、回复正文、嵌套原帖和拒绝说明以外的字段不因这一条改读。说明仍按原来的正文。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`post_declined` 仍默认关闭。8 个主机名的上限不变。不调用 `declineSuggestedPost`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 每次拒绝都读话题用户 | 发言人就是话题用户时，这行画的是频道名。 |
| 没有话题编号也当成不相同 | Bot API 没带这一边时无法对照客户端。缺一边就猜会删掉仍画频道名的提示。 |
| 改读频道标题 | 本群群名仍不读。见 ADR 0600。 |
| 把这个人整段当成正文 | 关键词会命中人名。说明仍按原来的正文。 |

## 后果

- 拒绝这行画出的话题用户全名里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。稿子状态不变。
- 全名原文、路径、用户名、话题号、回复正文和频道标题不进事件。内容哈希不变。关键词不命中全名。
- 空白名不挡住姓。空格后面的网址仍读。
- `from` 仍只读名，空白名仍挡住姓。没有回复或两边编号相同时不读话题用户。频道标题仍不读。说明仍按原来的正文。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 布尔值的拒绝对象、缺编号和嵌套原帖仍不读。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
