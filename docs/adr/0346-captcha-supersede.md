# ADR 0346：更重的入群处罚删掉上一颗验证按钮

- 状态：已接受
- 日期：2026-11-04

## 背景

昵称或链接命中时，入群的决策是封禁，验证动作返回 `superseded`。这次不会调用 `beginChallenge`。如果这个人还留着上一颗验证按钮，替换入群时的删除就不会发生。按钮留到到期，或者留到下一条离群更新。

离群更新能删掉按钮。封禁发生在这一条入群里，离群更新要等下一次投递。下一次没到时，群里还留着一颗已经点不中的按钮。

## 决策

- 入群事件的决策比 `captcha` 更重时，`captcha` 动作调用 `supersedeChallenge`。
- 有挑战就先删已经记下的按钮，再删这一行，并记 `captcha_superseded`。不解除限制，不写 `captcha_expired`。
- 没有删除端口，或删除抛错，就留下这一行，并在抛错时记 `captcha_prompt_delete_failed`。
- 删掉这一行本身抛错时记 `captcha_supersede_failed`。动作仍返回 `superseded`。日志只有事件 id 和群 id。
- 不是入群、没有挑战、以及 dry-run，都不碰这一行。
- 不调用 `releaseActor`。封禁之后的放行不会把人加回来。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 等随后的 `kicked` 更新再删 | 那条更新要晚一步，也可能没到。按钮在这一条入群里就已经没用了。 |
| 删不掉按钮也清掉这一行 | `messageId` 一丢，按钮就留在群里，到期清理也找不到它。 |
| 顺手解除刚才的限制 | 这次的决策是更重的处罚。放行会把人留在群里。 |

## 后果

- 再次入群被封禁、禁言或删除时，上一颗已经记下 id 的验证按钮会被删掉，挑战也不留给下一次点击。
- 第一次入群就被封禁、本来就没有挑战时，这一步什么都不做。
- 删除按钮失败时挑战还在。离群或到期清理可以再试。
- 按钮已经删掉、随后存储删除失败时，重试会再删一次已经不在的消息。那一次失败会把行留到到期清理。
- 没记下 id 的按钮还会留在群里。
- 30 天保留期不动。
