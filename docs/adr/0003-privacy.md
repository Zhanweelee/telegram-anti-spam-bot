# ADR 0003：隐私与保留

- 状态：已接受（初始策略）
- 日期：2026-11-01

## 背景

反垃圾需要在请求里看见消息文本，但文本本身是用户内容。日志、审计和评测如果默认落原文，自部署和公共 bot 都会变成内容仓库。

## 决策

- 处理请求时，`Event.message.text` 可以留在内存中。
- 存储的审计记录只有租户、群、事件 id、可选的消息 id、`textSha256`、动作、分数、原因、证据摘要、规则 id 和时间。schema 用 strict object，原文键会被拒绝。
- 证据摘要最长 120 字符。与整段原文完全相同的字符串在落盘前改写为 `redacted`。
- 日志只接受字符串、数字、布尔字段，并丢弃 `text`、`body`、`caption`、`raw`、`messageText`、`content`。检测器错误不记录 `Error.message`。
- Webhook 必须校验 `secret_token`。密钥只放在 Workers Secrets。这项在 Telegram 接入（P0）实现。
- 初始保留期：审计记录 30 天，到期删除。这是 founding default。改变保留期、或开始保存原文 / 更长的证据，必须先问维护者。
- 提供按租户导出和删除的能力。接口在 P0 交付，本 ADR 只定边界。
- 管理员把拦截标成误判或确认之后，样本默认只收哈希、特征和标签，不收原文。若评测集需要原文，那是另一次保留策略决定。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 默认保存原文，靠保留期补救 | 公共 bot 会集中存放群聊内容。删除任务失败时暴露面太大。 |
| 证据里附消息片段 | 片段经常等于原文。摘要只描述规则命中了什么。 |
| 不设保留期，只做手动删除 | 免费套餐的存储上限，以及「能删」不等于「会删」。 |

## 后果

- 关键词证据写成 `keyword:<配置里的词>`，不是消息摘录。
- 30 天是初始值，写在这里供维护者确认。生产部署前如果没有确认，实现保留任务的人要停下来问。
- 导出文件不得通过放宽 schema 把原文加回去。
