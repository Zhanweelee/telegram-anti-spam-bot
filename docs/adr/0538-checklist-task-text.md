# ADR 0538：清单任务也走关键词和默认正则

- 状态：已接受
- 日期：2026-11-05

## 背景

ADR 0057 让清单标题成为正文，并明确不把任务文字写进事件。ADR 0077 只从任务里抽出主机名。标题干净时，「免费领取」和「加微x」可以整段留在事项上。短链仍会删除，关键词看不见。

Bot API 把一份清单限制成 1 到 30 条任务，每条 1 到 100 字。用一个普通空格拼起来，最多 3029 字。

## 决策

- 已有别的正文，且任务去掉两端空白后仍有字时，事件另留 `checklistTask`。几条任务用一个普通空格拼起来，只留前 3029 字。任务拼起来正好就是正文时不设这个字段。正文和 `textSha256` 仍按 ADR 0057，标题优先。
- 第 3030 字起不进事件。主机名仍从整段任务抽取，包括被截掉的尾巴。
- 完成者名字、任务编号和完成时间不进这个字段。新加任务的服务消息仍按 ADR 0089 成为正文，不另留这个字段。
- 关键词和 `regex` 同时看正文、`senderTag`、`buttonText`、`authorSignature`、`mirrorSignature`、`pollOption`、`checklistTask` 和 `profile`。证据仍是原来的摘要。任务原文不进证据，也不进日志。
- `regex` 命中时带上 `places`，只写命中的字段名。`checklistTask` 加入这份名单。`checklist_task_regex` 只在 `places` 含有 `checklistTask` 时算命中。检测器没有 `places` 时仍按分数。
- 规则条件增加 `checklistTask: true`。消息上有这个字段时为真。
- 新规则 `checklist_task_regex` 默认打开。条件是这个字段，检测器是现有的 `regex`，命中后 `delete`。
- 「免费领取」和「加微信」仍走已经打开的关键词规则。
- `regex_hint` 仍默认关闭。正文里的「加微x」不会因为旁边有干净的任务就被删掉。
- 不改 ADR 0026 的基础检测器名单。`keyword` 和 `regex` 已经在里面，超额后这条仍会跑。
- `chats.json` 整份替换的群不会自动带上这条规则。
- 不新增命令。菜单仍是 99 条。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 默认打开 `regex_hint` | 普通消息会被同一份模式删除。这次要读的是标题旁边的任务。 |
| 把任务拼进标题 | 会改变 `textSha256`。ADR 0057 已经拒绝。 |
| 完成者名字和任务放进同一个字段 | 完成者不是广告正文。这一轮仍不读名字和编号。 |
| 给任务单独做一个检测器 | 关键词和正则已经会扫旁路字段。名单不用再加一项。 |

## 后果

- 任务含「免费领取」或「加微信」时按关键词删除。含 `t.me/+`、「加微x」或「加微X」时按 `checklist_task_regex` 删除。证据不含任务原文。
- 任务干净时消息留下。任务自己就是标题时，「加微x」仍要打开 `regex_hint`。
- 第 3030 个字符起不进事件。主机名仍从整段任务抽取。写在任务里的路径会留在 `checklistTask`，不进审计。
- 完成者名字、任务编号和完成时间仍不进事件。新加任务的服务消息仍按原来的正文处理。
- 关掉这条规则后，任务回到只看关键词和短链。
- 整份替换规则的群要自己加上这条，才会删除任务上的「加微x」。
- 30 天保留期没有改。
- `places` 后来由 ADR 0539 加上 `mediaName`。文件名和音频标题的规则只认自己的字段。ADR 0540 再加上 `performer`。表演者的规则只认自己的字段。
