# ADR 0524：私聊可以接着看后面的放行主机

- 状态：已接受
- 日期：2026-11-05

## 背景

一个群最多放行 32 台主机，每台最长 253 个字符。32 台都写满时，回复有 8140 个字符。适配器把 `sendMessage` 切到 4096，最后一台机会停在主机名中间。管理员会把没写完的名字当成已经放行的主机。

## 决策

- `/allowhost <chatId> [add|remove <host>|reset|skip <count>]`。`add`、`remove` 和 `reset` 不变。
- `count` 是 0 到 99999 的整数，不允许前导零。不写 `skip` 或 `count` 为 0 时，回复与原来相同。
- `count` 大于 0 时，先按存储顺序跳过前面的 `count` 台，再从下一台开始列。放不下 3500 字时只保留完整主机名，最后一行写剩下的台数。
- 标题仍是名单里的总台数。中文写「还有 N 个」，英文写 `N more`。
- 跳过的台数已经不少于名单台数，或空名单写了大于 0 的 `count` 时，回复「参数无效」。缺数字、数字不合法也是「参数无效」。多出来的词回复用法。
- 不改名单上限，也不改主机折叠。菜单仍是 99 条。`/allowhost` 的菜单描述改为带上 `skip`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续交给适配器切到 4096 | 切口会落在主机名中间。 |
| 只回复台数 | 短名单现在能看到每台主机。放不下时仍应列出前面的完整名字。 |
| 在「还有」后面写下一页的命令 | 下一页的起点就是已经看过的台数。 |

## 后果

- `/allowhost <chatId> skip 31` 只列出第 32 台。不写 `skip` 时，第一页只含完整主机名。
- 已经设过命令菜单的部署，要再执行一次设置命令，菜单描述才会带上 `skip`。
- 没列出来的主机仍在放行。30 天保留期没有改。
