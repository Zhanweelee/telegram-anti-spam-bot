# ADR 0461：每个群可以追加关键词

- 状态：已接受
- 日期：2026-11-04

## 背景

关键词检测器的词表写在 Worker 里，默认是「免费领取」和「加微信」。云上的群管改不了这份表。`/blocklist` 只收成员编号和正文哈希，收不进一个可见的词。

## 决策

- `RuntimeStore` 增加 `listKeywords`、`addKeyword`、`removeKeyword`、`clearKeywords`。记录的是这个群额外的词，不替换内置词。
- 一个词先按检测器的同一套折叠收成小写，再保存。折叠后为空、含空白，或超过 32 个字符，回复「参数无效」，不写入。
- 一个群最多 32 个额外词。已经有的词再添加成功，并且不重写。内存最多 256 个群。新群放不下时回复「参数无效」，日志是 `keyword_full`，日志里没有这个词。
- 配了 `POLICY_KV` 时写在 `runtime-keyword` 键。原来的运行时文档、动作键、上报键和洪泛键都不改。坏文档读成空列表。每个 isolate 缓存 60 秒。
- 私聊 `/keyword <chatId>` 只列出额外的词和条数，不列出内置词。`add` 追加，`remove` 删掉一个，`reset` 清掉额外的词。没有这个词时回复「没有这个关键词」，回复里不重复这个词。
- 群聊里的同样文本不执行。接入目录里的人只能改自己的群。读或写失败回复「参数无效」，日志是 `operator_rejected`。不写姓名、消息原文或 token。这条命令不调用 Telegram。
- 检测在创建关键词检测器之前读这份列表。有额外词时，内置词和额外词合成一份。读失败时记 `runtime_failed`，只用内置词。同一份检测器也看入群可见名字。
- 不改 `default.json`。命中证据仍是 `keyword:` 加折叠后的词，不写整句消息。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 用额外词替换内置词 | 清掉之后，「免费领取」会在这个群漏过。追加更安全。 |
| 把词表写进现有运行时文档 | 旧 Worker 看到多出来的字段会把开关和 dry-run 一起丢掉。 |
| 把命中的原文存下来 | 和「原文默认不落盘」冲突。词是群管写的配置。 |
| 允许带空格的词 | 命令按空白拆开。一个参数先够用。 |

## 后果

- `/keyword -100 add 发票` 之后，这个群里含「发票」的消息按关键词删除。别的群仍只看内置词。
- 同一个词也会用在入群可见名字上。关掉 `join_name` 后，名字不再因为这个词封禁。
- 菜单多一条 `/keyword`，一共 94 条。
- 云额度的基础检测器名单没有改。30 天保留期没有改。
