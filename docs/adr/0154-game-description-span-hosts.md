# ADR 0154：空正文的游戏说明只留高亮主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

游戏消息没有正文时，Android 把 `game.description` 画在预览里。`generateLinkDescription` 对这段文字调用 `Linkify.WEB_URLS`。点说明里的链接，打开的是高亮那一段。

说明不进正文，正文扫描看不到。整段解析会把 `∕` 后面的 `@` 认成新的主机。短链和裸 IP 可以只写在前面。

消息已经有正文，或者游戏附带了说明文字时，这段说明不画出来。账单说明在气泡里被清掉，付款页只当普通文字。

## 决策

- 消息没有 `text`、`caption`，游戏也没有 `text` 时，`game.description` 里的 `http` 或 `https` 再取 Android 高亮会打开的那一段主机名。只留主机名。
- 整段解析出的主机名仍然保留。两边都走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。最多 8 个。
- 有正文或游戏附带文字时，说明不按高亮截断。账单说明、按钮文字和已经写明的链接同样不截断。
- 路径不进证据。没有新的主机名时不另记。说明仍不进入正文，也不参与内容哈希。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 有正文时也按高亮截断 | 客户端这时不画说明，点不到前面的短链。 |
| 账单说明同样截断 | 气泡里不画这段说明，付款页也不做链接。 |
| 把说明拼进正文 | 哈希会变。ADR 0058 和 ADR 0078 拒绝的就是这个。 |

## 后果

- 只有标题和说明的游戏消息，说明是 `http://bit.ly∕@example.com/…` 时按短链删除。证据仍只有主机名。
- 同一段说明是 `http://example.com∕@bit.ly` 时，整段里的 `bit.ly` 仍删除。
- 小写 `%e2%88%95` 仍打开后面的主机。
- 再套一层仍放行。路径不进证据。
