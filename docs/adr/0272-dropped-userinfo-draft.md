# ADR 0272：接不上的用户信息前面仍留下主机名

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 先把 `@` 前面当成用户信息。`@` 后面能接上主机名、路径、端口或 `_` 时，用户信息成立，打开的是 `@` 后面的主机名。接不上时，打开的是 `@` 前面的主机名。

看得见的正文已经这样切。隐藏的分享 `text` 在 `@.` 后面还能靠高亮范围留下短链。`@!` 会被收成空主机名。分享 `url` 整段解析时，主机名是点开头的尾巴，前面的短链或裸 IP 会漏。

`http://bit.ly@example.com`、`http://bit.ly@/…`、`http://bit.ly@:80/…`、`http://bit.ly@` 和 `http://bit.ly@_…` 的用户信息仍然成立。`http://user@bit.ly` 打开的是后面的主机名。

## 决策

- 分享 `text`、分享 `url`、私聊预填 `tg://msg` 的 `text` 和用户名草稿的 `text`，在 `http://` 或 `https://` 后面看 `@`。
- `@` 后面接不上时，留下 `@` 前面的主机名，尾巴不再另算。
- `@` 后面能接上时，仍是一条。打开的是 `@` 后面的主机名。
- `https://t.me@.…/+…` 不改记成邀请。
- 路径、尾巴和邀请码不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 整段交给地址解析 | `@!` 和点开头的尾巴对不上短链或裸 IP。 |
| 只要有 `@` 就留下前面的主机名 | `user@bit.ly` 和 `bit.ly@example.com` 会记错主机名。 |
| 接不上之后的路径改记成邀请 | `t.me@.…/+邀请码` 打开的是没有这段路径的主机名。 |

## 后果

- `t.me/share/url?text=http://bit.ly@.…` 和 `http://bit.ly@!` 删除。证据仍只有主机名。
- 分享 `url` 里同样的短链，以及 `@.` 前面的裸 IP，同样删除。
- `bit.ly@example.com`、`bit.ly@/…`、`bit.ly@:80/…`、单独的 `bit.ly@`、`bit.ly@_…` 和 `user@bit.ly` 留着。`example.com@.…` 留着。`t.me@.…/+…` 不改记成邀请。
- 主机名后面的标点再打开的短链，后来同样留下。见 ADR 0273。
