# ADR 0053：内联按钮只保留主机名

- 状态：已接受
- 日期：2026-11-01

## 背景

ADR 0029 从 `text_link` 取出主机名。垃圾消息常把短链或邀请放在内联按钮的 `url` 上，正文里没有这段地址。按钮文字、路径和查询都不能进事件。

## 决策

- `reply_markup.inline_keyboard` 里字符串形式的 `url`，和 `text_link` 使用同一套规则：只要 `http` 和 `https`，URL 最长 2048，只留小写主机名。
- 邀请路径仍只记主机名，并写入 `invites`。重复主机名丢掉。`hosts` 和 `invites` 各自最多 8 个，和隐藏链接合在一起计数。
- 不读取按钮文字、`callback_data`、`login_url` 和 `web_app`。
- 不新增检测器。默认规则 `links` 仍只删除短链、裸 IP、邀请和黑名单。普通网址保留。
- 不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把按钮文字并进正文再跑关键词 | 按钮文字会改变内容哈希，也可能把原文带进事件。 |
| 默认删除每一个按钮链接 | 普通群的投票和工具按钮会被删掉。短链和邀请已经有规则。 |
| 单独再做一个按钮检测器 | 主机名已经进 `hosts`。链接检测不用改。 |

## 后果

- 按钮上的 `bit.ly` 会走现有短链删除。`t.me/+邀请码` 只留下 `t.me`，并记成邀请。
- 按钮指向普通域名时保留，除非它在黑名单或信誉源里。
- `callback_data` 里看起来像网址的字符串不会变成主机名。
- 隐藏链接已经占满 8 个主机名时，后面的按钮主机名不再写入。
- `copy_text` 后来由 ADR 0055 走同一份规则。句子里的网址后来由 ADR 0075 只留下主机名。
- 没有更前面的正文时，按钮文字后来由 ADR 0063 成为正文。已有正文时仍不并进去。`login_url` 和 `web_app` 的地址后来由 ADR 0074 只留下主机名。
- 按钮文字后来由 ADR 0787 要求长度大于 0。空文字和缺文字不再留下主机名。一个空格仍读。
