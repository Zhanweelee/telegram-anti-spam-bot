# ADR 0021：log 与 report 不携带消息原文

- 状态：已接受
- 日期：2026-11-01

## 背景

决策里已经有 `log` 和 `report`，规则也可以写下这两个动作。流水线找不到对应插件时记 `missing_action`。操作者无法只记录或只通知，只能删除、禁言、封禁或验证。

上报如果把消息原文发给管理员，私聊就变成第二份内容仓库。ADR 0003 不允许默认保存原文。

## 决策

- `log` 动作写一条 `moderation_logged`。字段只有事件 id、租户、群、分数、规则 id 和 reason。reason 与规则 id 必须是短标识。句子、空格和原文会被丢掉。
- `report` 动作调用 `Notifier`。通知体是 strict object：租户、群、事件 id、分数、最多 8 个 reason、最多 8 个规则 id。不复制证据摘要。
- 没有 `Notifier` 时动作返回 `report_unavailable`。`notify` 抛错时记 `report_failed`，不写异常文本，决策保持不变。
- Worker 在同时有回复端口和至少一个管理员 id 时，把通知发给第一个管理员，一条 `sendMessage`。正文由 `formatReportNotice` 生成。其余管理员不逐个发送，避免打满子请求。
- 默认规则不加入 `log` 或 `report`。要通知时，在规则的 `actions` 里写上它们。
- core 和动作包不出现 Telegram 方法名。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把证据摘要放进通知 | 关键词证据带配置里的词，链接证据带主机名。私聊通知保持只有标识。审计里仍然有截断后的摘要。 |
| 给每个管理员各发一条 | 管理员列表最多 64 个。一次命中会变成几十次子请求。 |
| 默认规则在删除之外再 report | 每条垃圾消息都会私聊管理员。需要的群自己打开。 |

## 后果

- 一条规则同时写下 `delete` 和 `report` 时，两个动作都会执行。删除仍是一次 Telegram 请求，上报再加一次。
- 管理员没有先和 bot 私聊过时，`sendMessage` 会失败，动作记 `report_failed`，删除不受影响。
- 重启不影响这个动作。通知不进 D1 或 KV。
- 目的地后来可以按群改。没改过仍是配置里的第一个管理员。见 ADR 0459。
