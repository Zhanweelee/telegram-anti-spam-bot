# ADR 0210：主机名里的除号不再收成短链

- 状态：已接受
- 日期：2026-11-03

## 背景

高亮段里的除号 U+2215 和分数斜杠 U+2044 会先换成 `/`。写在主机名开头，或标签末尾再接 `/`、`?` 时，Android 仍把它们留在同一条链接里。换成斜杠以后，`http://∕bit.ly/…` 和 `http://bit.ly∕/…` 会被记成 `bit.ly`。`http://∕203.0.113.10/…` 会被记成裸 IP。

Android 在 `@` 或 `#` 前面会退回除号之前的主机名。`http://bit.ly∕@example.com` 仍打开 `bit.ly`。没有协议的 `∕bit.ly` 仍从 ASCII 单词开始。路径里的除号仍换成 `/`。大写的 `%E2%88%95` 仍换成 `/`。

## 决策

- 主机名里的除号和分数斜杠留下，不换成 `/`。
- 标签可以在这两种斜杠上结束，只要后面是 `/` 或 `?`。
- 匹配停在除号上，而后面不是 `/`、`?` 或结尾时，主机名退回除号前面。
- 路径里的这两种斜杠，以及大写百分号编码，仍换成 `/`。
- 查询文字走同一条高亮。
- 每段仍走现有的短链、裸 IP、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 除号一律换成 `/` | `http://∕bit.ly` 会变成短链。Android 打开的不是 `bit.ly`。 |
| 除号后面一律不再退回 | `http://bit.ly∕@example.com` 会漏掉短链。 |
| 没有协议的 `∕bit.ly` 也留下 | `点击bit.ly` 和 `∕bit.ly` 仍要从 ASCII 单词开始。 |

## 后果

- `http://∕bit.ly/…`、`https://⁄bit.ly/…`、`http://bit.ly∕/…` 和 `http://bit.ly∕?…` 留着。
- `http://∕203.0.113.10/…` 和 `http://203.0.113.9∕/…` 留着。`http://bit.ly∕http://bit.ly/…` 留着。
- `∕bit.ly/…`、`http://bit.ly∕@example.com/…`、`http://user∕@bit.ly/…` 和 `http://bit.ly%E2%88%95@example.com/…` 仍删除。
- `http://bit.ly∕#evil.com/…` 和 `http://203.0.113.9∕@example.com/…` 仍删除。路径不进证据。
