# ADR 0658：移入或移出社区的人画出的短名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

群被移入社区或移出社区时，Android 的 `TL_messageActionChangeCommunity` 把操作者画进服务消息。这个人是用户时，名字来自 `DialogObject.getShortName`，也就是 `UserObject.getForcedFirstName`。名为空时改用姓。空白不算空。从下标 2 起找第一个空格，找到就把后面丢掉。下标 0 或 1 上的空格不截断。用户名不在这行里。

自己操作时这行写“你”，不写名字。别的成员看到的是操作者的短名。Bot 站在群里，读的是这条短名。

加入社区是另一条服务消息，`TL_messageActionChatJoinedViaCommunity` 用 `replaceWithLink` 画全名。全名仍按 ADR 0636，空格不截断。

Bot API 把移入放在 `community_chat_added`，移出放在 `community_chat_removed`，加入放在 `community_chat_joined`。几种同时出现时仍先认移入。移入要有社区对象。移出的空对象也读。社区名字仍只留主机名，排在前面。见 ADR 0115。

短链可以只写在空格后面。先前按整段名读取，会删掉客户端没有画出的后半段。

## 决策

- 已经会标成 `added` 或 `removed` 时，从 `from` 会画出来的短名留主机名。`first_name` 的长度大于 0 时用名，不读姓。名缺失或正好是空字符串，且 `last_name` 是非空字符串时，改用姓。空白名挡住姓。
- 从下标 2 起的第一个空格后面不读。这个空格之前的前缀才抽主机名。没有这样的空格时，整段名字都读。下标 0 或 1 上的空格不截断。
- 先认成 `joined` 时仍按全名。名和姓都去掉两端空白，名在前。空白名不挡住姓。空格不截断。见 ADR 0636。
- 主机名仍进消息已有的 `hosts`。邀请仍进 `invites`。社区名字里已有短链时，证据仍先记那段名字的主机名。短名不进正文，也不改内容哈希。关键词因此不命中。
- 用户名、社区编号、本群群名和移出对象上的其它字段不读。没有 `from` 对象时不读。没有社区对象的移入不读。普通消息不读 `from`。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`community_notice` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不把群移出社区。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 移入和移出继续读空格后面 | 客户端的短名不画这段。会删掉没有出现在这行里的网址。 |
| 加入也按短名截断 | 加入这行用的是全名。见 ADR 0636。 |
| 空白名也改去读姓 | `TextUtils.isEmpty` 只把 null 和长度为 0 当成空。空白名仍挡住姓。 |
| 新命令 `/communityname` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 移入或移出社区的人，短名里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。群是否留在社区不变。
- 从下标 2 起被空格截掉的后半段不读。下标 0 或 1 上的空格后面仍读。空白名挡住姓。
- 短名原文、路径和用户名不进事件。内容哈希不变。关键词不命中短名。
- 加入仍按全名，空格后面的网址仍读。社区名字仍排在前面。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 没有 `from` 对象、没有社区对象的移入，以及普通消息，仍不读发送者。管理员仍豁免。干净的提示在 `community_notice` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
