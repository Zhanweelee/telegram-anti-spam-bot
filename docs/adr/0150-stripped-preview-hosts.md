# ADR 0150：去掉预览 s 之后的一段仍只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

Android 在 `t.me`、`telegram.me` 和 `telegram.dog` 上，如果路径第一段正好是小写 `s`，会先拿掉这一段。`t.me/s/用户名/123` 和 `t.me/s/用户名/shop` 因此变成已经会写草稿的帖子路径和应用名路径。`s.t.me/用户名/123` 会先收成 `t.me/s/用户名/123`，再走同一条。

桌面端的用户名正则对不上这三段。大写 `S` 不会被拿掉。`www.t.me/s/...` 会先把 `www` 当成用户名，而不是预览。

`用户名.t.me/应用名` 仍按 ADR 0146 不读。

## 决策

- `t.me`、`telegram.me`、`telegram.dog` 上，路径正好是 `s`、公开用户名、再加一段时，从 `text` 抽出主机名。这一段可以是帖子数字，也可以是应用名。
- `s.t.me/用户名/这一段` 同样读取。
- 这个主机名走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。
- 用户名、数字和应用名不进证据。`text` 不进入正文，也不参与关键词。
- 大写 `S`、一层 `www.`、保留名、更长的路径和 `s.telegram.me` 不读。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 只读两段的 `t.me/s/用户名` | Android 拿掉 `s` 之后，第三段仍会写草稿。 |
| `S` 也拿掉 | 比较用的是原来的路径段，大写不会被拿掉。 |
| 连 `www.t.me/s/...` 一起读 | `www` 会先变成用户名。 |

## 后果

- 这些路径的 `text` 是裸 IP、短链或邀请时，现有链接规则删除这条消息。证据仍只有主机名。
- 大写、`www`、保留名和更长的路径留着。
- 再套一层仍放行。用户名不进证据。
- 联系人卡片里的 `URL` 后来由 ADR 0151 只留下主机名。电话、邮箱和备注仍不读。
