# ADR 0123：没有说明的富文本媒体参加重复判断

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0052 让没有正文的贴纸、图片、视频笔记和语音用文件摘要参加 `repeat`。富文本里的图片、语音、动图、视频、音频和文件可以单独成一条消息。没有说明时正文是空字符串。摘要目前只看顶层字段，同一张图可以连发而不触发默认的 `repeat`。

把 `file_id` 或 `file_unique_id` 放进事件会把平台标识带进日志。

## 决策

- 顶层已经有媒体类别时，仍按 ADR 0052 的顺序取那一个，不改用富文本里的文件。
- 顶层没有媒体时，按块的文档顺序取第一块媒体。嵌套只进入列表项、`details`、`blockquote`、`collage` 和 `slideshow`。
- `animation`、`video`、`audio`、`document` 和 `photo` 用同名类别。`voice_note` 记成 `voice`。图片用最后一张尺寸的 `file_unique_id`。
- 能读到长度在 1 到 256 的 `file_unique_id` 时，写 `mediaSha256`。摘要是类别和这份 id 的 sha256。id 不进事件。过长或缺失的 id 只留类别，并且不再看后面的块。
- 正文非空时，`repeat` 仍用 `textSha256`。没有说明时用这份摘要。
- 不读付费媒体和 live photo。不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 另做检测器 | `repeat` 已经默认开启。 |
| 把文件 id 原样放进事件 | 审计和日志会带上平台文件标识。 |
| 有说明时改按文件摘要计次 | 和 ADR 0052 冲突。说明文字仍是正文。 |
| 顶层和富文本各计一次 | 一条消息只应有一个媒体类别。 |

## 后果

- 60 秒内同一份没有说明的富文本文件出现 3 次，现有 `repeat` 规则会删除。
- 不同文件各自计数。只有类别、没有摘要的消息仍不参加重复。
- 有说明或已有正文时仍按正文计次。文件 id 不进事件。
- 付费媒体和 live photo 仍不参加这份摘要。付费图片、视频和实况照片后来由 ADR 0124 用同一份摘要参加重复。顶层媒体和富文本仍优先。文件 id 仍不进事件。
