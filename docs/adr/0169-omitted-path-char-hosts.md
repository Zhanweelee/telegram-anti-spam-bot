# ADR 0169：路径类没有的字符后面打开的主机名也留下

- 状态：已接受
- 日期：2026-11-02

## 背景

Android `LinkifyPort.WEB_URL` 的路径只收标签字符、一小部分标点和完整的 `%HH`。表情、C1 控制符、私用区和第一增补平面的字母都不在这个类里。匹配在这里结束，后面如果还有网址，会再打开一次。

`http://example.com` 后面接表情再接 `http://bit.ly/…` 因此会打开 `bit.ly`。整段当成一个地址时，主机名只剩 `example.com`。斜杠后面的表情也一样。汉字仍算标签字符，写在路径里时后面的地址不会单独打开。

## 决策

- 抽网址时，路径类没有的码位结束这一段。后面的网址按自己的一段来抽主机名。
- Android 仍当作标签字符的后几个平面留在这一段里。BMP 里的汉字、希腊字母也留在这一段里。
- 每段仍走现有的裸 IP、短链、邀请和 denylist 判断。只拆一层。最多 8 个。证据只留主机名。
- 切开之后单独的邀请地址仍按邀请读取。同一段里被这个字符挡住的路径不改记成邀请。
- 已经写在 `text_link`、按钮或其它结构化字段里的地址整段打开。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 整段只留第一个主机名 | 表情后面的短链和裸 IP 点得开。 |
| 所有非 ASCII 都切开 | 汉字在路径里时，后面的地址仍属于前一个网址。 |
| 被挡住的路径改记成邀请 | `t.me` 和表情后面的 `/+邀请码` 打开的是没有这段路径的主机名。 |

## 后果

- `http://example.com` 后接表情或 U+10140 再接 `http://bit.ly/…`，以及 `http://news.example` 后接表情再接 `http://203.0.113.136/…`，按现有短链或裸 IP 规则删除。证据仍只有主机名。
- `http://example.com/点击http://bit.ly/…` 留着。`http://bit.ly` 后接希腊字母 `α` 再接别的标签也留着。
- `https://t.me` 和表情后面的 `/+…` 不记成邀请。`http://example.com/` 后接表情再接 `https://t.me/+…` 按邀请删除。路径不进证据。
