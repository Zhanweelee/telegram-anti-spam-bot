# ADR 0361：`/forget` 按页删除审计

- 状态：已接受
- 日期：2026-11-04

## 背景

ADR 0326 让 `/forget` 不再先导出审计，D1 用一条 `DELETE` 返回 `meta.changes`。D1 的说明写明：一次改掉几十万行或几百 MB 的语句会超出执行限制，应当拆成大约 1000 行一批。审计没有 30 天清理，表会一直变长。一条删不完的语句失败后，管理员只看到「参数无效」，范围里的审计还在。

免费计划每次调用最多 50 次查询。冷启动先跑 4 条建表，再查一次挑战表的列。这一次结果按数据库缓存。

## 决策

- D1 的 `deleteAudits` 每次删除最多 1000 行：`DELETE ... WHERE rowid IN (SELECT rowid ... LIMIT 1000)`。某一页的 `meta.changes` 小于 1000 就停止。满页则继续，最多 32 页，合计最多 32000 行。
- 返回值仍是这一次实际删掉的行数。没有非负整数条数时仍抛出 `delete_changes_missing`。
- 群范围的子查询带 `chat_id`。其它群和其它租户不动。规则和白名单不动。
- 删除成功之后，`/forget` 再调用一次 `countAudits`。还剩行时回复「已删除 N 条，还剩 M 条」。剩下 0 条时仍回复「已删除 N 条」。
- 删除抛错时不计数。日志仍是 `operator_rejected`，不写数据库返回的文本。
- 内存适配器仍一次删完该范围。它没有 D1 的单条语句限制。
- 不先 `exportAudits`。不添加 30 天清理。保留期仍是 ADR 0003。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续一条 `DELETE` | 官方说明这种语句会超出执行限制。失败时管理员看不到删了多少。 |
| 删到空为止 | 32 页再加上计数，已经接近 50 次查询。更多页会把同一次调用用完。 |
| 用负数表示还剩多少 | 调用方分不清删掉的条数和剩下的条数。 |
| 删到预算仍有剩余时抛错 | 行已经删掉，私聊却变成「参数无效」。 |

## 后果

- 超过 32000 行时，一次 `/forget` 删掉 32000 行，并写明还剩多少。再执行一次继续删。
- 删除和计数之间新写入的审计，会让回复写上剩余条数。再执行一次即可。
- 某一页没有条数时，前面的页可能已经删掉，回复仍是「参数无效」。
- 冷启动的 `/forget` 大约是 4 次建表、1 次列检查、最多 32 次删除和 1 次计数，留在 50 次查询以内。
- 30 天保留期不动。
