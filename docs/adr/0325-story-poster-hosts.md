# ADR 0325：故事发布者的名字只留主机名

- 状态：已接受
- 日期：2026-11-03

## 背景

转发一条故事时，Android 在头像旁边画出发布者的名字。回复一条故事时，回复条上同样画出这个名字。频道和群用标题，私人用名和姓。名字里可以只放短链或邀请。故事说明不在 Bot API 的 `story` 对象里。

`story.chat` 和 `reply_to_story.chat` 还会带上用户名、编号，完整对象里还有简介和邀请链接。这些都不是头像旁边的那一行。所在聊天的标题和发送者姓名会附在每一条消息上。

## 决策

- 从 `story.chat` 和 `reply_to_story.chat` 的 `title`、`first_name`、`last_name` 抽出网址，只留主机名。先读转发的故事，再读回复的故事。折叠、长度、邀请判断和 8 个主机名的上限与旁路纯文本相同。
- 这些名字不进入 `message.text`，也不参与关键词或内容哈希。没有别的正文时，正文仍是空字符串。
- 不读取 `username`、故事编号、聊天 id、简介、说明和邀请链接。不读取 `chat.title` 和 `from` 上的姓名。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 没有正文时把名字当成正文 | 名字会进事件和哈希。短链只需要主机名。 |
| 同时读取用户名 | 头像旁边画的是标题或姓名，不是 `@用户名`。 |
| 每条消息都扫 `chat.title` | 群名会跟着每条消息重复计一次主机名。 |

## 后果

- 故事发布者的标题或姓名里的短链、裸 IP 或邀请按现有链接规则删除这条消息。证据仍只有主机名。
- 名字里的关键词留着。`example.com` 留着。没有正文时正文仍是空字符串。
- 用户名、故事编号、简介、邀请链接、发送者姓名和所在聊天的标题不进事件。
- 云额度的基础检测器名单没有改。
- 某个群后来可以打开 `shared_story`，删除转发来的故事卡片。名字仍只留主机名。只回复一条故事不带这个标记。见 ADR 0472。
