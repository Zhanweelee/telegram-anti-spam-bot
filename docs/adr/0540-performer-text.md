# ADR 0540：标题旁边的表演者也走关键词和默认正则

- 状态：已接受
- 日期：2026-11-05

## 背景

ADR 0092 在没有文件名和音频标题时，用 `audio.performer` 当正文。已有标题、文件名或说明时，表演者只留主机名。播放器把表演者写在标题旁边。「免费领取」可以整段留在表演者上，标题本身是干净的。短链仍会删除，关键词看不见。

Bot API 没有写 `performer` 的长度。正文回退已经把这段文字截到 4096。旁路字段用同一个上限。

## 决策

- 已有别的正文，且表演者去掉两端空白后仍有字时，事件另留 `performer`。只读这条消息自己的 `audio.performer`。只留前 4096 字。表演者自己就是正文时不设这个字段。正文和 `textSha256` 仍按 ADR 0092。
- 第 4097 字起不进事件。主机名仍从整段表演者抽取，包括被截掉的尾巴。
- 投票媒体、富文本音频、贴纸表情和贴纸包名不进这个字段。`file_id`、`file_unique_id` 和 `mime_type` 也不进。
- 关键词和 `regex` 同时看正文、`senderTag`、`buttonText`、`authorSignature`、`mirrorSignature`、`pollOption`、`checklistTask`、`mediaName`、`performer` 和 `profile`。证据仍是原来的摘要。表演者原文不进证据，也不进日志。
- `regex` 命中时带上 `places`，只写命中的字段名。`performer` 加入这份名单。`performer_regex` 只在 `places` 含有 `performer` 时算命中。检测器没有 `places` 时仍按分数。
- 规则条件增加 `performer: true`。消息上有这个字段时为真。
- 新规则 `performer_regex` 默认打开。条件是这个字段，检测器是现有的 `regex`，命中后 `delete`。
- 「免费领取」和「加微信」仍走已经打开的关键词规则。
- `regex_hint` 仍默认关闭。正文里的「加微x」不会因为旁边有干净的表演者就被删掉。
- 不改 ADR 0026 的基础检测器名单。`keyword` 和 `regex` 已经在里面，超额后这条仍会跑。
- `chats.json` 整份替换的群不会自动带上这条规则。
- 不新增命令。菜单仍是 99 条。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 默认打开 `regex_hint` | 普通消息会被同一份模式删除。这次要读的是标题旁边的表演者。 |
| 把表演者拼进标题或说明 | 会改变 `textSha256`。ADR 0092 已经拒绝。 |
| 连投票媒体和富文本音频的表演者一起留下 | 正文回退只读这条消息自己的 `audio.performer`。嵌套的表演者仍只留主机名。 |
| 给表演者单独做一个检测器 | 关键词和正则已经会扫旁路字段。名单不用再加一项。 |

## 后果

- 表演者含「免费领取」或「加微信」时按关键词删除。含 `t.me/+`、「加微x」或「加微X」时按 `performer_regex` 删除。证据不含表演者原文。
- 表演者干净时消息留下。表演者自己就是正文时，「加微x」仍要打开 `regex_hint`。
- 第 4097 个字符起不进事件。主机名仍从整段表演者抽取。写在表演者里的路径会留在 `performer`，不进审计。
- 文件 id、mime、贴纸包名、投票媒体和富文本音频的表演者仍不进这个字段。
- 关掉这条规则后，这种表演者回到只看关键词和短链。
- 整份替换规则的群要自己加上这条，才会删除表演者上的「加微x」。
- 30 天保留期没有改。
