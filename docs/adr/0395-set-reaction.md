# ADR 0395：私聊可以在一条消息上设置一个反应

- 状态：已接受
- 日期：2026-11-04

## 背景

管理员想给一条消息加上一个反应。官方有一次改写这条消息上所选反应的调用。

`setMessageReaction` 改变一条消息上选中的反应。有些服务消息不能被反应。频道自动转发到讨论组的消息，可用反应和频道里一样。bot 不能使用付费反应。成功时返回 True。

必填参数是 `chat_id` 和 `message_id`。可选的 `reaction` 是 `ReactionType` 数组。非会员 bot 最多设置一个反应。自定义表情只有在已经出现，或管理员允许时才能用。可选的 `is_big` 会放大动画。一组媒体里，反应会落到还没有被删掉的第一条。

官方表情表列出 73 个 `ReactionTypeEmoji`。红心是 U+2764，后面不带变体选择符。带变体选择符的写法不在这张表里。

没有 token 时不能把内存记录回复成已经设置。

## 决策

- 私聊命令 `/react <chatId> <messageId> <emoji>`。群 id 匹配 `^-?\d{1,20}$`。消息 id 是不带前导零的正安全整数，`1` 原样送出。表情必须和那 73 个字符串完全一致。少一个参数、多出来的参数、变体选择符或名单外的表情都不发出请求。群聊里的同样文本不执行。
- 配置中的管理员可以操作任意群。接入目录里的人只能操作自己的群。
- 调用 `ModerationPort.setReaction`。适配器调用 `setMessageReaction`，始终带 `reaction: [{ type: "emoji", emoji }]`。不送 `is_big`。不送自定义表情，也不送付费反应。
- 回复写明别人的反应还在，一组媒体会落到还在的第一条。回复带上管理员刚写出的这个表情。
- 没有 token、没有这个方法，编号或表情不合法，或调用失败时回复「参数无效」。日志只写 `operator_rejected`，带上 eventId、chatId 和命令名。不写异常文本、token、表情或原文。
- 没有 token 的 Worker 不把内存记录回复成已经设置。
- 不调用 `deleteMessageReaction` 或 `getChat`。不修改黑名单、白名单、封禁或禁言。不读取消息正文。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 省略 `reaction` 来清掉反应 | 文档没有写省略和空数组的差别。`/unreact` 已经按人撤下。 |
| 默认送出 `is_big` | 放大动画不是这次命令要做的事。 |
| 接受带变体选择符的红心 | 表里的红心没有这个字符。折过去会发出表外的表情。 |
| 接受自定义表情 id | 自定义表情还要已经出现或被管理员允许。这次只送官方表情。 |

## 后果

- 成功只表示 Telegram 接受了这一次 `setMessageReaction`。服务消息、付费反应或缺少权限时，回复是「参数无效」。
- 别人已经点过的反应还在。一组媒体上的反应会落到还在的第一条，回复里写明这一点。
- 一次设置是一次 Telegram 子请求。封禁、禁言和黑名单都不变。
- 30 天保留期不动。
