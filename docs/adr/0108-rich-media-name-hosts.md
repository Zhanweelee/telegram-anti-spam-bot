# ADR 0108：富文本媒体名称只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0076 从富文本段落和按钮里取主机名。动图、视频、音频和普通文件也可以放在富文本块里。文件名、音频标题和表演者是看得见的字。短链可以只写在这些字段里。

照片和语音没有可当网址的名称。文件 id 仍然不是网址。

## 决策

- 从富文本的 `animation`、`video`、`document` 读取 `file_name`。从 `audio` 读取 `title`、`file_name` 和 `performer`。
- 嵌在列表、引用或拼贴里的块同样读取。
- 抽出的网址走和旁路纯文本相同的折叠，事件里只留主机名。长度、邀请判断和 8 个主机名的上限不变。
- 音频先标题，再文件名，再表演者。
- 这些名称不进入正文，也不改内容哈希。已有正文时，块上的说明文字仍不并进去。
- 不读取照片、语音、地图、文件 id 和 `callback_data`。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把文件名拼进正文 | 同一条消息的哈希会变，路径也会进事件。 |
| 连照片和语音的文件 id 一起读 | 文件 id 不是网址。消息本身上也不读它。 |
| 只读最外层块 | 拼贴和列表里的文件同样看得见。 |

## 后果

- 这些名称里的短链、邀请或裸 IP 按现有链接规则命中。
- 普通域名仍保留。路径和邀请码不进主机名名单。这些名称后来由 ADR 0561 另留在 `richName`。审计仍不留原文。
- 照片、语音和文件 id 里的字符串仍不进事件。
- 块上的说明后来由 ADR 0564 另留在 `richText`，仍不并进正文。文件名仍留在 `richName`。
