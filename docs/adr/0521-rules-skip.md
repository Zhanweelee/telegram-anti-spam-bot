# ADR 0521：私聊可以接着看后面的规则

- 状态：已接受
- 日期：2026-11-05

## 背景

私聊 `/rules` 在 3500 字处停下，并写上还没列出的条数。默认规则现在有 76 条，第一条回复在 `button_emoji` 结束。后面的 `sticker_emoji`、`llm_hint`、`regex_hint`、`via_inline`、`new_member`、入群规则、`shared_contact` 和 `service_notice` 仍在执行，回复里只剩「还有 12 条」。没有参数能把这 12 条列出来。

## 决策

- `/rules [chatId] [skip <count>]`。`count` 是 0 到 99999 的整数，不接受前导零。
- 不写 `skip`，或 `count` 为 0 时，回复与现在相同：从第一条规则开始，放不下就保留前面的完整行，最后写上剩下的条数。
- `count` 大于 0 时，先按原来的顺序跳过前面的 `count` 条，再从下一条开始用同一条 3500 字的规则往下列。这一页放得下时不再写「还有」。
- 只有一个群的管理员可以写 `/rules skip <count>`。能看全部群的管理员仍要写出群号。
- 跳过的条数已经不少于规则条数、数字不合法，或空规则还写了大于 0 的 `count` 时，回复「参数无效」。
- 不改规则文件，也不为了缩短回复去改每一行的字段。菜单仍是 99 条。`/rules` 的菜单描述改为带上 `skip`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把入群规则挪到文件前面 | 文件顺序也是检测顺序。为了回复去改顺序会改掉正在执行的规则。 |
| 缩短每一行来塞进 76 条 | 自定义规则仍会超过 3500 字。字段少了，状态和动作要另查。 |
| 在「还有」后面写下一页的命令 | 现有回复用「还有 N 条」解析。下一页的起点就是已经看过的条数。 |

## 后果

- 默认规则的第一页仍从 `spam_keywords` 开始。`/rules <chatId> skip 64` 能看到后面的入群验证和 `service_notice`。
- 已经设过命令菜单的部署，要再执行一次设置命令，菜单描述才会带上 `skip`。
- 没列出来的规则仍在执行。30 天保留期没有改。
