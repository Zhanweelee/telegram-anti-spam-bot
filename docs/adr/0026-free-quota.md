# ADR 0026：免费额度用配置，超额退回基础规则

- 状态：已接受
- 日期：2026-11-01

## 背景

公共 bot 需要每群一个免费额度。用完之后继续跑基础规则，而不是停掉。维护者要求这些数字做成配置，并先给定默认值。付费渠道不在这次范围内。

core 不能知道自己跑在自部署还是云上。ADR 0002 要求降级发生在把规则送进流水线之前。

## 决策

- 默认关闭。`DEPLOYMENT_MODE=cloud` 时默认打开。`QUOTA_ENABLED=true` 或 `false` 可以覆盖这两种部署。
- 打开后的默认值：每群每个 UTC 自然月 3000 次检测。`QUOTA_LIMIT` 改次数，`QUOTA_PERIOD=rolling_30d` 改成从第一次计数起的 30 天。
- 一次检测记 1。管理员消息不记。第 3001 次起，只保留 `QUOTA_BASIC` 里的检测器。默认保留 keyword、join、flood、repeat、link、blocklist、forward、regex。`llm` 不在里面。
- 计数在 isolate 内存，最多 256 个群。放不下、时间无效或抛错时放过，规则不降级。重启后从 0 开始。不写 KV 或 D1。
- `/quota <chatId>` 只读这组数字。没有打开时回复 quota off。
- 不接支付，不接 Telegram Stars。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把 3000 和自然月写死 | 维护者要求可配置。部署方式只决定默认开关。 |
| 超额后停止检测 | 验收要求退回基础规则，bot 继续处理消息。 |
| 每条消息写 D1 或 KV | 写额度比检测次数更紧。热路径不能为了计数再写一次。 |

## 后果

- 自部署不设置变量时行为和以前一样。
- 云模式下一个很忙的群在当月后段会失去 `llm`，关键词、洪泛、频道转发还在。
- isolate 重启会把已用次数清零。这是内存计数的上限，不是账单。
