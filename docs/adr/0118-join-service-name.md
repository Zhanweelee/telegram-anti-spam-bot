# ADR 0118：入群服务消息的可见名字命中就删除

- 状态：已接受
- 日期：2026-11-02

## 背景

人入群时，Telegram 除了 `chat_member`，还会发一条服务消息 `new_chat_members`。客户端把昵称、姓氏和用户名显示在这行「某人加入了群组」上。ADR 0117 会封禁短链名字，但封禁不删除消息，这行广告仍留在群里。

这条服务消息通常没有 `text`。发送者的 `from.first_name` 和退群的 `left_chat_member` 不是这行看得见的加入名单。

## 决策

- `new_chat_members` 里每个用户的 `first_name`、`last_name`、`username` 去掉首尾空白后，用一个普通空格拼起来，最长 4096 字符。
- 没有更前面的正文时，这段名字成为正文。关键词和链接规则因此能删除这条服务消息。路径留在正文里。
- 已有正文时，名字只贡献主机名。路径、用户名片段和关键词不进事件。
- 不读取 `left_chat_member`、`from` 上的姓名、`language_code` 和用户 id。用户 id 只在它本来就是 `actor.id` 时出现。
- 不新增检测器，不加新的默认规则。删除仍走现有的 `spam_keywords` 和 `links`。封禁仍走 `chat_member` 上的 `join_name` 和 `join_link`。
- 不改 ADR 0026 的默认次数、周期和基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 名字永远只留主机名 | 关键词广告名会留在「某人加入了群组」这行上。 |
| 读取退群的人 | 退群行不是入群广告。正常离开的人会被关键词误删。 |
| 读取每条消息的 `from` 姓名 | 会把普通发言者的姓名送进检测。 |
| 封禁时顺便删掉服务消息 | `chat_member` 更新没有这条服务消息的 `message_id`。 |

## 后果

- 可见名字里的默认关键词、短链或邀请会删掉入群服务消息。证据仍只有关键词或主机名。
- `example.com`、普通名字和公开的 `t.me/名字` 留着。
- 退群服务消息仍是空正文。
- 入群和退群服务消息后来可以带 `notice`。默认不因此删除。见 ADR 0467。退群的人仍不读。
- 视频聊天邀请上的可见名字后来由 ADR 0119 按同一套规则删除。
- 只收到 `message`、没有 `chat_member` 时，人还在群里，但这行广告会被删掉。封禁仍要靠入群更新。
- 名字里的默认正则后来由 ADR 0533 删除这行。证据是 `regex:hit`。退群仍不读。
