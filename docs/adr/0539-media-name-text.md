# ADR 0539：说明旁边的文件名也走关键词和默认正则

- 状态：已接受
- 日期：2026-11-05

## 背景

ADR 0062 在没有更前面的正文时，用动图、视频、音频或普通文件的名称当正文。音频先用标题，没有标题再用文件名。已有说明时，名称只留主机名。「免费领取.pdf」可以整段留在文件名上，说明本身是干净的。短链仍会删除，关键词看不见。

Bot API 没有写 `file_name` 的长度。正文回退已经把这段名称截到 4096。旁路字段用同一个上限。

## 决策

- 已有别的正文，且这段名称去掉两端空白后仍有字时，事件另留 `mediaName`。顺序与 ADR 0062 相同：动图、视频、音频、普通文件，然后付费视频的文件名。音频先用 `title`，没有标题再用 `file_name`。只留前 4096 字。名称自己就是正文时不设这个字段。正文和 `textSha256` 仍按 ADR 0062。
- 同一条消息后面的文件名不进这个字段。它们的网址仍只留主机名。
- 第 4097 字起不进事件。主机名仍从整段名称抽取，包括被截掉的尾巴。
- `file_id`、`file_unique_id`、`mime_type`、缩略图、表演者、贴纸包名和表情不进这个字段。
- 关键词和 `regex` 同时看正文、`senderTag`、`buttonText`、`authorSignature`、`mirrorSignature`、`pollOption`、`checklistTask`、`mediaName` 和 `profile`。证据仍是原来的摘要。名称原文不进证据，也不进日志。
- `regex` 命中时带上 `places`，只写命中的字段名。`mediaName` 加入这份名单。`media_name_regex` 只在 `places` 含有 `mediaName` 时算命中。检测器没有 `places` 时仍按分数。
- 规则条件增加 `mediaName: true`。消息上有这个字段时为真。
- 新规则 `media_name_regex` 默认打开。条件是这个字段，检测器是现有的 `regex`，命中后 `delete`。
- 「免费领取」和「加微信」仍走已经打开的关键词规则。
- `regex_hint` 仍默认关闭。正文里的「加微x」不会因为旁边有干净的文件名就被删掉。
- 不改 ADR 0026 的基础检测器名单。`keyword` 和 `regex` 已经在里面，超额后这条仍会跑。
- `chats.json` 整份替换的群不会自动带上这条规则。
- 不新增命令。菜单仍是 99 条。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 默认打开 `regex_hint` | 普通消息会被同一份模式删除。这次要读的是说明旁边的文件名。 |
| 把文件名拼进说明 | 会改变 `textSha256`。ADR 0062 已经拒绝。 |
| 同一条消息的每个文件名都留下 | 正文回退只取第一个名称。后面的名称仍只留主机名。 |
| 给文件名单独做一个检测器 | 关键词和正则已经会扫旁路字段。名单不用再加一项。 |

## 后果

- 文件名或音频标题含「免费领取」或「加微信」时按关键词删除。含 `t.me/+`、「加微x」或「加微X」时按 `media_name_regex` 删除。证据不含名称原文。
- 名称干净时消息留下。名称自己就是正文时，「加微x」仍要打开 `regex_hint`。
- 第 4097 个字符起不进事件。主机名仍从整段名称抽取。写在名称里的路径会留在 `mediaName`，不进审计。
- 文件 id、mime、表演者和贴纸包名仍不进这个字段。表演者后来由 ADR 0540 另留。音频有标题时，文件名后来由 ADR 0559 另留在 `audioFile`。没有标题时，文件名仍留在这个字段。付费视频里更后面的文件名后来由 ADR 0560 另留在 `paidFile`。
- 关掉这条规则后，这种名称回到只看关键词和短链。
- 整份替换规则的群要自己加上这条，才会删除文件名上的「加微x」。
- 30 天保留期没有改。
