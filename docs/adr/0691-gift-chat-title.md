# ADR 0691：送礼的发送者是聊天时只读聊天标题

- 状态：已接受
- 日期：2026-11-06

## 背景

有人送出普通礼物、独特礼物或升级购买时，Android 的 `TL_messageActionStarGift` 和 `TL_messageActionStarGiftUnique` 用 `replaceWithLink` 画送礼的人。`fromObject` 先看用户，没有用户就看聊天。聊天画出整段标题，空格不截断。

Bot API 把这个聊天放在 `sender_chat`，`from` 是占位用户。见 `telegram-bot-api` 的 `messageSenderChat`。

ADR 0648 仍从 `from` 的全名留主机名。占位用户的名字不在这行里。编号和本群相同时，通用代发规则本来就不读标题。礼物上另有的 `from_id` 仍没有单独字段。

## 决策

- 已经会标成 `gift` 的提示上，`sender_chat` 是对象时，只从 `sender_chat.title` 留主机名，不从 `from` 留主机名。标题不截断。频道、群和超级群都一样。编号和本群相同时也读。
- 没有 `sender_chat` 时，仍从 `from` 会画出来的全名留主机名。名和姓都去掉两端空白，名在前。空白名不挡住姓。空格不截断。
- 不从 `chat.title` 另读。附言、收藏名和发布者用户名仍按原来的方式。
- 空的外层对象、布尔值和只有附言的对象仍不读发送者。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`gift_card` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。星星不退回。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续读 `from` | 占位用户的名字不在这行里。短链会删掉一条没有这个名字的提示。 |
| 标题也按短名截断 | 聊天的 `replaceWithLink` 画整段标题。空格后面的短链仍在这行里。 |
| 本群群名也读 | 送礼从一开始就不读本群群名。这里读的是发送者自己的标题。 |
| 新命令 | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 聊天送出礼物时，标题里的短链会删掉这条提示。证据只有主机名。占位名字不进事件。
- 别的聊天发到这个群时不豁免。本群自己送出时默认仍按管理员豁免留下。关掉豁免后会删。
- 用户仍按全名。`example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。
- 30 天保留期没有改。
