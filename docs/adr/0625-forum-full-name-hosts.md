# ADR 0625：关话题的人画出的全名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

论坛话题被关掉、重新打开，或者通用话题被隐藏、重新显示时，Android 的 `MessageObject` 在 `TL_messageActionTopicEdit` 上用 `replaceWithLink` 把这个人画进这行服务文字。这里没有打开短名，所以名字是 `UserObject.getUserName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。

Bot API 把这四条放在 `forum_topic_closed`、`forum_topic_reopened`、`general_forum_topic_hidden` 和 `general_forum_topic_unhidden`。这四个对象本身没有字段。见 ADR 0485。当时只读名。见 ADR 0589。这四条通常没有别的正文。

短链可以只写在姓上。名的长度大于 0 时如果丢掉姓，这条短链就留在提示里。把整段收成正文会改变内容哈希，关键词也会命中名字。

## 决策

- 只在已经会标成 `forumNotice` 的提示上，从 `from` 会画出来的全名留主机名。关掉、重开、隐藏和重新显示都是对象时读。空对象也读。几种同时出现时仍先认关掉，再认重开，再认隐藏，再认重新显示。
- 名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读。空格不截断。用户名不读。
- 全名不进正文，也不改内容哈希。关键词因此不命中。话题名、图标和话题号不读。本群群名不读。正文里已有短链时，证据仍先记正文的主机名。
- 布尔值不读发送者。新建和改名仍按 ADR 0605 只读名。普通消息不读 `from`。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`forum_notice` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不调用关闭、打开、隐藏或显示话题的方法。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续只读名 | 客户端把姓画在同一行里。姓上的短链会留在提示里。 |
| 把名字整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0485。 |
| 新建和改名这次一起改成全名 | 新建这行不画这个人。改名是另一条提示。见 ADR 0605。 |
| 每条服务提示的人都改成全名 | 助推这行用的是名。付款成功这行也只读名。见 ADR 0583 与 ADR 0618。 |
| 新命令 `/forumname` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 关话题、重开、隐藏或重新显示的人，全名里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。话题开关不变。
- 全名原文、路径和用户名不进事件。内容哈希不变。关键词不命中全名。
- 空白名不挡住姓。空格后面的网址仍读。话题名、图标和话题号仍不进事件。
- 正文里已有短链时，证据仍先记正文的主机名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 布尔值仍不读。管理员仍豁免。干净的提示在 `forum_notice` 关闭时仍留下。新建后来不再读发送者。见 ADR 0665。改名后来按全名，见 ADR 0626。云额度的基础检测器名单没有改。30 天保留期没有改。
