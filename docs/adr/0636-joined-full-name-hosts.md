# ADR 0636：加入社区的人画出的全名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

自己加入社区时，Android 的 `MessageObject` 在 `TL_messageActionChatJoinedViaCommunity` 上用 `replaceWithLink` 把这个人画进这行服务文字。这就是 `UserObject.getUserName`。名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。社区名字画在这个人前面。自己加入时这行不画自己，只画社区。

移入和移出用的是 `TL_messageActionChangeCommunity`。那一行用 `DialogObject.getShortName`。现有条件仍只读名。

Bot API 把加入放在 `community_chat_joined.community`。见 ADR 0477。当时名的长度大于 0 就丢掉姓。见 ADR 0594。社区名字仍只留主机名，不进正文。见 ADR 0115。短链可以只写在姓上。把整段收成正文会改变内容哈希，关键词也会命中名字。

## 决策

- 只在已经会标成加入的提示上，从 `from` 会画出来的全名留主机名。`community_chat_joined.community` 是对象时读。几种同时出现时仍先认移入，再认加入，再认移出。先认成移入时不读全名。
- 名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读。空格不截断。用户名不读。
- 移入和移出仍只读名。名的长度大于 0 时不读姓。空白也算有名。空格不截断。
- 社区名字仍按 ADR 0115 只留主机名，排在全名前面。名字不进正文，也不改内容哈希。关键词因此不命中。社区编号不读。移出对象上的其它字段不读。本群群名不读。
- 自己加入时这行不画自己。现有条件仍读 `from`。这条只改加入的名字怎么切。
- 没有社区对象的加入不读发送者。普通消息因此仍不读 `from`。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`community_notice` 仍默认关闭。短链仍走已有的 `links`。8 个主机名的上限不变。不把群移出社区。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 加入继续只读名 | 客户端把姓画在同一行里。姓上的短链会留在提示里。 |
| 把名字整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0115。 |
| 移入和移出也改成全名 | 这两行用的是短名。姓上被空格截掉的部分不是这行里的字。 |
| 自己加入时不读发送者 | 现有条件已经读 `from`。这条只改名字怎么切。 |
| 新命令 `/communityname` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 加入社区的人，全名里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。群是否留在社区不变。
- 全名原文、路径和用户名不进事件。内容哈希不变。关键词不命中全名。
- 空白名不挡住姓。空格后面的网址仍读。移入和移出仍只读名，空白名仍挡住姓。
- 社区名字里已有短链时，证据仍先记那段名字的主机名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 没有社区对象的加入、以及普通消息，仍不读发送者。管理员仍豁免。干净的提示在 `community_notice` 关闭时仍留下。云额度的基础检测器名单没有改。30 天保留期没有改。
- 移入和移出后来按短名截断。从下标 2 起的第一个空格后面不读。加入仍按全名。见 ADR 0658。
