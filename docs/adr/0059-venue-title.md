# ADR 0059：场馆标题进入正文

- 状态：已接受
- 日期：2026-11-01

## 背景

场馆消息往往没有 `text`，也没有 `caption`。前面的回退停在游戏和账单标题，场馆标题仍绕过关键词。地址、坐标和地点 id 如果一并写进事件，会把精确位置哈希进去。纯位置消息没有名称。

## 决策

- 没有更前面的正文时，用 `venue.title` 当正文。截断到 4096，并以此计算 `textSha256`。顺序在 `game.title` 和 `invoice.title` 之后。
- 不读取 `venue.address`、`venue.location`、`foursquare_id`、`google_place_id` 和纯 `location` 的坐标。
- 不新增检测器，也不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把地址拼进正文 | 地址常是街道和门牌。它会改变哈希，也把位置写进事件。 |
| 把经纬度收成文本 | 纯位置没有名称。坐标不是关键词能比较的正文。 |
| 单独做一个场馆检测器 | 标题已经是正文。关键词和正则不用改。 |

## 后果

- 场馆标题里的「免费领取」会命中现有关键词。同一标题在重复窗口里按这段正文计次。
- 地址里的关键词仍然看不到。坐标和地点 id 不进事件。
- 只有坐标、没有场馆标题的位置消息，正文仍是空字符串。
- 已有账单标题时，场馆标题不参与比较。
- 手动引用后来由 ADR 0061 接在这些回退之后。自动引用和被回复的原消息仍不进事件。
