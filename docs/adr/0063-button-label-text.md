# ADR 0063：按钮文字在没有正文时进入正文

- 状态：已接受
- 日期：2026-11-01

## 背景

一条消息可以只有内联按钮，没有 `text` 和 `caption`。按钮上的「免费领取」是用户能看见的文字。ADR 0053 只从 `url` 取主机名，并让按钮文字留在事件外面，避免改掉已有正文的哈希。普通域名的按钮因此会绕过关键词。`login_url` 和 `web_app` 的地址仍然不读，按钮上的字却同样可见。

## 决策

- 没有更前面的正文时，按行把 `inline_keyboard` 里非空的 `text` 用一个普通空格拼起来，截断到 4096，并以此计算 `textSha256`。
- 这段文字排在文件名和音频标题之后、手动引用之前。已有正文、说明、题干、标题或文件名时，按钮文字不参与比较。
- 不读取 `callback_data`、`copy_text` 的句子、`login_url` 和 `web_app` 的地址。回复键盘不读。`url` 和整段是一条网址的 `copy_text` 仍只贡献主机名。
- 不新增检测器，也不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 另做按钮文字检测器并默认关闭 | 操作者要先打开它。关键词名单已经够用。 |
| 有正文时仍把按钮文字接在后面 | 同一条消息的哈希会变。ADR 0053 拒绝的就是这个。 |
| 把复制到剪贴板的句子也当正文 | 句子里的路径和口令会进事件。ADR 0055 只在整段是一条网址时留主机名。 |

## 后果

- 只有按钮、文字是「免费领取」时，会命中现有关键词。几个按钮用普通空格分开，所以「免」和「费领取」不会粘成一个词。
- 这段文字参加重复计数。三张相同的按钮会算成同一次重复。
- 已有正文或文件名时，按钮上的关键词仍然看不到。有按钮文字时，手动引用上的短链不参与比较。
- `login_url` 和 `web_app` 指向短链时，地址后来由 ADR 0074 只留下主机名。复制句子里的网址仍不扫描。回复键盘上的字不进事件。
