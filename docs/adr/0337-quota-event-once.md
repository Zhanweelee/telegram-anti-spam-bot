# ADR 0337：同一事件只计一次额度

- 状态：已接受
- 日期：2026-11-04

## 背景

免费额度在流水线之前计数，每条非管理员消息记 1。计数在 isolate 内存里。Telegram 重试同一个 update 时，事件 id 不变。同一次投递落到这个 isolate，会把 3000 次额度再扣一次。

ADR 0026 不把额度写进 KV 或 D1。默认次数和周期不动。

## 决策

- `consume` 可以带 `eventId`。同一个群、同一段窗口里，这个 id 已经在最近 64 次计数中出现过，就不再加 1。
- id 只接受 1 到 128 个字符的字母、数字、下划线、点、冒号和连字符。其它值照旧每次都计。
- 窗口重置时清掉这 64 个 id。`read` 不加计数，也不记下 id。
- Worker 把事件 id 传进去。没传 id 的调用仍每次加 1。
- 默认仍是每群每个 UTC 自然月 3000 次。不写 KV 或 D1。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 记住这个月的全部事件 id | 一个忙群会把 isolate 内存撑满。重试只发生在刚处理过的几条里。 |
| 把已计 id 写进 KV | ADR 0026 拒绝为额度再写存储。 |
| 改掉 3000 或自然月 | 这次只避免同一次投递被记两次。 |

## 后果

- 同一个 isolate 上的重试不再多扣额度。
- 落到另一个 isolate 的重试仍会计一次。那边的计数本来就是另一份内存。
- 超过最近 64 次之后，同一个 id 可以再计一次。
- 30 天保留期不动。
