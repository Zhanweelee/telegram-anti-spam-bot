# ADR 0604：投票选项增删的人，名字只留主机名

- 状态：已接受
- 日期：2026-11-05

## 背景

有人给投票加上选项，或删掉一个选项时，客户端把这个人的名字画在服务消息上。名字写在 `from`。选项文字当时已经按原来的方式成为正文。见 ADR 0089 和 ADR 0494。短链可以只写在这个人的名字里。

选项旁边画出的添加者仍按 ADR 0577，那是投票对象上的另一个名字。这两条服务消息上没有那个字段。

把 `from` 收成正文会让普通发言者的姓名也进检测。`poll_notice` 默认关闭，干净的选项仍留下。空对象、空字符串和布尔值仍然不是这条提示。新加的清单任务仍按 ADR 0603，不因为这条改条件。

## 决策

- 只在已经会标成 `pollNotice` 的提示上，从 `from` 的可见名字留主机名。`poll_option_added.option_text` 是长度大于 0 的字符串时读。空白也算有文字。否则改看 `poll_option_deleted.option_text`，条件相同。同时出现时先认新加。新加的文字是空字符串时落到删除。
- `first_name` 的长度大于 0 时只读名。空白也算有名。名缺失或正好是空字符串时改读姓。用户名不读。抽出之前不截断。
- 选项文字仍按 ADR 0089 成为正文。已有别的正文时仍留在 `addedText`。这个人的名字不进正文，也不改内容哈希。关键词因此不命中这个人的名字。选项编号和嵌套的原投票不读。被删选项里已有的主机名仍排在这个人前面。本群群名不读。
- 空对象、空字符串和布尔值不读发送者。普通消息不读 `from`。新加的清单任务不因为这条改条件。选项旁边的添加者仍按 ADR 0577。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`poll_notice` 仍默认关闭。8 个主机名的上限不变。不调用 `stopPoll`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把这个人整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0494。 |
| 并进 `poll_notice` | 打开选项增删的群并不一定要按名字里的短链删。选项文字仍是正文。 |
| 连新加的任务一起改条件 | 任务文字已经是另一条提示。加选项的人只在选项增删上。 |
| 新命令 `/pollname` | 菜单只剩一个空位。现有 `links` 已经能删短链。 |

## 后果

- 加选项或删选项的人，名字里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。投票还在。
- 这个人的名字原文、路径和用户名不进事件，内容哈希不变。名字里的关键词不命中。
- 名的长度大于 0 时，姓和用户名不进事件。选项文字仍按原来的正文。选项里已有短链时，证据仍先记那段文字的主机名。被删选项的主机名仍排在这个人前面。
- `example.com` 和公开的 `t.me/名字` 留着。付费帖仍不删除。见 ADR 0356。
- 空对象、空字符串、布尔值和普通消息仍不读发送者。空白文字仍读。本群群名仍不读。嵌套原投票仍不读。干净的选项在 `poll_notice` 关闭时仍留下。新加的任务仍按 ADR 0603。选项旁边的添加者仍按 ADR 0577。云额度的基础检测器名单没有改。30 天保留期没有改。
- 后来按短名截断。从下标 2 起的第一个空格后面不读。下标 0 或 1 上的空格不截断。见 ADR 0659。
