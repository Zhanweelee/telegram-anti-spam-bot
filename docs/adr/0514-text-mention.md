# ADR 0514：普通消息里按用户标识的提及按群删除

- 状态：已接受
- 日期：2026-11-05

## 背景

普通消息的 `text_mention` 把用户编号放在实体上。看得见的字是正文里的一段，关键词看不见被点的人。富文本里的同类提及已经由 `rich_text_mention` 决定。打开那条规则不会删除普通消息上的实体。

用户名实体的名字就在正文里。手动引用、投票选项和清单任务属于另一段文字。这一轮不给它们加这个标记。

## 决策

- `entities`、`caption_entities`、投票 `question_entities` 或清单 `title_entities` 里，`type` 正好是 `text_mention`，并且 `user.id` 是大于 0 的安全整数时，事件带 `asTextMention: true`。
- 缺用户、布尔值、字符串编号和 0 不带这个标记。用户名实体不带。富文本按标识提及不带。手动引用、投票选项和清单任务上的实体不带。
- 用户编号和名字不进事件，也不进证据。看得见的字仍是正文。已有 `text` 或 `caption` 时正文不变，编号不并进去。
- 检测器在 `@tasb/detector-mention`，id 是 `text_mention`。只在 `message.asTextMention` 为 true 时返回 score 1。证据是 `entity:text_mention`。
- 默认规则关闭。私聊 `/rule <chatId> text_mention on` 之后删除这种正文，`off` 回到留下。
- 不并进 `rich_text_mention`。不调用读取或改写用户的方法。付费帖仍不删除。
- 不新增命令。菜单仍是 99 条。
- 不改 ADR 0026 的基础检测器名单。`text_mention` 不在里面。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 并进富文本按标识提及 | 只想删富文本的群会把普通消息也删掉。 |
| 把用户编号接到正文后面 | 同一条消息的哈希会变，编号也会进事件。 |
| 把用户编号写进证据 | 用户编号不进事件。 |
| 默认打开 | 有的群会点名。打开之前不改现有群。 |
| 新命令 `/user` | 菜单还剩 1 个位置，留给以后的操作命令。 |

## 后果

- 规则关闭时，普通消息里按标识的提及留下。看得见的字仍参与关键词。用户编号仍不进事件。
- 打开 `text_mention` 后，这个群里的这种提及会删除。打开 `rich_text_mention` 仍不删除它。付费帖仍留下。
- 自部署没有额度，打开后就会删除。云模式超过当月次数后，还要把 `text_mention` 写进 `QUOTA_BASIC`，否则超额时这条规则会停。
- `chats.json` 整份替换的群要自己加上 `text_mention`，否则 `/rule` 会拒绝。
- 30 天保留期没有改。
- 自定义表情后来由 ADR 0515 另开 `custom_emoji`。打开按标识提及仍不删除这种表情。编号仍不进事件。
- 清单任务和后加任务上的按标识提及后来由 ADR 0567 也带上 `asTextMention`。投票选项和手动引用仍不带。用户编号仍不进事件。
- 投票说明和描述上的按标识提及后来由 ADR 0568 也带上 `asTextMention`。用户编号仍不进事件。
- 礼物附言上的按标识提及后来由 ADR 0569 也带上 `asTextMention`。发布者用户名仍不进事件。
- 游戏附加文字上的按标识提及后来由 ADR 0570 也带上 `asTextMention`。封面和动图文件编号仍不进事件。
- 正文上的按标识提及后来由 ADR 0754 要求起点落在正文里。正文不是字符串时仍按原来的方式读取。长度越过末尾时仍算画出来。
- 说明上的按标识提及后来由 ADR 0755 要求起点落在说明里。说明不是字符串时仍按原来的方式读取。长度越过末尾时仍算画出来。
- 投票题干上的按标识提及后来由 ADR 0756 要求起点落在题干里。题干不是字符串时仍按原来的方式读取。长度越过末尾时仍算画出来。
- 测验说明上的按标识提及后来由 ADR 0757 要求起点落在说明里。说明不是字符串时仍按原来的方式读取。长度越过末尾时仍算画出来。
- 投票描述上的按标识提及后来由 ADR 0758 要求起点落在描述里。描述不是字符串时仍按原来的方式读取。长度越过末尾时仍算画出来。
- 清单标题上的按标识提及后来由 ADR 0759 要求起点落在标题里。标题不是字符串时仍按原来的方式读取。长度越过末尾时仍算画出来。
