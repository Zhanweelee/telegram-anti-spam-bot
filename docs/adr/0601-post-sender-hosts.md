# ADR 0601：建议帖提示上的人，名字只留主机名

- 状态：已接受
- 日期：2026-11-05

## 背景

建议帖被通过、付款失败、付完款或退款时，客户端把这个人的名字画在服务消息上。名字写在 `from`。这四条提示的正文是空的。见 ADR 0488。短链可以只写在这个人的名字里。

把 `from` 收成正文会让普通发言者的姓名也进检测。`post_notice` 默认关闭，干净的提示仍留下。空的通过对象、负数、其它币种和其它原因仍然不是这四条提示。拒绝仍按 ADR 0600，不因为这条改条件。

## 决策

- 只在已经会标成 `postNotice` 的提示上，从 `from` 的可见名字留主机名。通过要有大于等于 0 的发表时间。失败要有价格对象，空的价格对象也读。付款的币种正好是 `XTR` 或 `TON`。退款原因正好是 `post_deleted` 或 `payment_refunded`。同时出现时仍先认通过，再认失败，再认付款，再认退款。
- `first_name` 的长度大于 0 时只读名。空白也算有名。名缺失或正好是空字符串时改读姓。用户名不读。抽出之前不截断。
- 这个人的名字不进正文，也不改内容哈希。关键词因此不命中这个人的名字。发表时间、价格、星星数量、退款原因和嵌套的原帖不读。本群群名不读。
- 空的通过对象、负数、其它币种、其它原因和布尔值不读发送者。普通消息不读 `from`。拒绝仍不读这条。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`post_notice` 仍默认关闭。8 个主机名的上限不变。不调用 `approveSuggestedPost` 或 `declineSuggestedPost`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把这个人整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0488。 |
| 并进 `post_notice` | 打开这四种提示的群并不一定要按名字里的短链删。稿子状态仍不变。 |
| 读取嵌套原帖 | 原帖是另一条消息。这四条提示的正文仍是空的。见 ADR 0488。 |
| 新命令 `/postname` | 菜单只剩一个空位。现有 `links` 已经能删短链。 |

## 后果

- 通过、失败、付款或退款建议帖的人，名字里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。稿子状态不变。
- 这个人的名字原文、路径和用户名不进事件，内容哈希不变。名字里的关键词不命中。
- 名的长度大于 0 时，姓和用户名不进事件。发表时间、价格和退款原因仍不进事件。嵌套原帖仍不进事件。
- `example.com` 和公开的 `t.me/名字` 留着。付费帖仍不删除。见 ADR 0356。
- 空的通过对象、负数、其它币种、其它原因、布尔值和普通消息仍不读发送者。本群群名仍不读。干净的提示在 `post_notice` 关闭时仍留下。拒绝仍按 ADR 0600。云额度的基础检测器名单没有改。30 天保留期没有改。
- 付款失败和退款后来另读话题用户画出的全名。发言人不是这个人时也读。见 ADR 0650。金额大于 0 的通过后来也读。没标价或金额为 0 的通过，以及付款，仍不读。见 ADR 0651。
- 发送者是聊天时后来不读占位名字，也不读这个聊天的标题。用户仍只读名。见 ADR 0692。
