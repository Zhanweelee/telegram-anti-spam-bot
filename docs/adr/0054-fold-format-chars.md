# ADR 0054：匹配前去掉格式字符

- 状态：已接受
- 日期：2026-11-01

## 背景

关键词和正则按原文做包含或 `test`。在字与字之间插入零宽空格、软连字符或双向控制符，可见内容不变，规则却匹配不到。把正文改掉会改变 `textSha256`，重复计数和审计哈希都会变。

## 决策

- `foldMatchText` 放在 core。它删掉这些格式字符：`U+00AD`、`U+061C`、`U+180E`、`U+200B`–`U+200F`、`U+202A`–`U+202E`、`U+2060`–`U+2064`、`U+2066`–`U+2069`、`U+FEFF`。
- 空格和可见文字保留。事件里的正文和 `textSha256` 不变。
- 关键词先折叠关键词和正文（以及入群昵称），再做大小写和包含判断。折叠后为空的关键词不参与匹配。证据里的词也折叠，最长 80。
- 正则只折叠待测正文，不改模式。`test` 抛错仍记 `regex_failed` 并返回未命中。
- 不新增检测器，也不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 在归一化时改掉正文 | 哈希变了，同一句话的重复计数会拆开。审计里的摘要也不再对应原文。 |
| 引入同形字库 | 新依赖，而且会把合法的多语言文字折成误判。这一项只处理不可见的格式字符。 |
| 连空格一起删掉 | 「免 费」这种正常间隔会被当成关键词。 |

## 后果

- `免\u200b费领取` 会命中关键词 `免费领取`。`免 费领取` 仍然不会。
- `加\u200b微信` 会命中默认正则 `加微[信xX]`。
- 只含格式字符的关键词不会让每条消息都命中。
- 变体选择符和同形字仍按原样比较。
