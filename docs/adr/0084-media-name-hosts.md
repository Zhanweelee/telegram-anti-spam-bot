# ADR 0084：文件名和音频标题里的网址只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0062 在没有更前面的正文时，用动图、视频、音频或普通文件的名称当正文。音频先用 `title`，没有标题再用 `file_name`。已有正文时，这些名称留在事件外面。短链可以只写在文件名或音频标题里。

把名称拼进已有正文会改变 `textSha256`。表演者、文件 id、mime 和贴纸包名仍不能进事件。

## 决策

- 从 `animation.file_name`、`video.file_name`、`audio.title`、`audio.file_name` 和 `document.file_name` 里抽出网址，只留主机名。长度、折叠、邀请判断和 8 个主机名的上限不变。顺序与正文回退相同：动图、视频、音频、普通文件。音频先标题，再文件名。
- 已有正文时，名称原文不进正文，也不改内容哈希。
- 没有更前面的正文时，名称仍按 ADR 0062 整段成为正文。这条正文里的网址由链接规则从正文看见，同时也记在主机名列表里。
- 不读取 `file_id`、`file_unique_id`、`mime_type`、缩略图、`audio.performer`、贴纸 `set_name` 和 `emoji`、语音和视频笔记。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 已有正文时把文件名拼进去 | 文件名会改变哈希。短链只需要主机名。 |
| 只抽最终成为正文的那一个名称 | 同一条消息可以同时带标题和文件名。后面的名称里仍可能有短链。 |
| 连表演者和贴纸包名一起抽 | ADR 0062 把它们留在事件外面。包名更像标识，不是文件名。 |

## 后果

- 已有正文时，文件名或音频标题里的 `https://bit.ly/…` 会走现有短链删除。`https://t.me/+…` 和 `https://t.me/%2B…` 只留下 `t.me`，并记成邀请。
- 普通域名仍保留。名称原文、路径和邀请码在已有正文时不进事件。
- 名称成为正文时，整段名称仍参与关键词和内容哈希。已有正文时，名称看得见的前 4096 字后来由 ADR 0539 交给关键词和默认正则。写在名称里的路径留在 `mediaName`，不进审计。同一条消息里更后面的文件名后来由 ADR 0566 另留在 `laterName`。音频文件名仍留在 `audioFile`。
- 贴纸包名和文件 id 里的网址仍然不读。没有说明时，预览行上的表情后来由 ADR 0708 只留下主机名。表情仍不进正文。表演者里的网址后来由 ADR 0092 只留下主机名。没有文件名和音频标题时，表演者整段成为正文。
