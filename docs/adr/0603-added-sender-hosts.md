# ADR 0603：新加清单任务的人，名字只留主机名

- 状态：已接受
- 日期：2026-11-05

## 背景

有人往清单里新加任务时，客户端把这个人的名字画在服务消息上。名字写在 `from`。任务文字当时已经按原来的方式成为正文。见 ADR 0089 和 ADR 0495。短链可以只写在这个人的名字里。

把 `from` 收成正文会让普通发言者的姓名也进检测。`checklist_added` 默认关闭，干净的任务仍留下。空字符串、空数组和布尔值仍然不是这条提示。完成和取消完成仍按 ADR 0602，不因为这条改条件。任务上的完成者仍只留主机名。

## 决策

- 只在已经会标成 `asChecklistAdded` 的提示上，从 `from` 的可见名字留主机名。`tasks` 里至少有一条长度大于 0 的文字时读。空白也算有文字。空文字后面还有文字时仍读。
- `first_name` 的长度大于 0 时只读名。空白也算有名。名缺失或正好是空字符串时改读姓。用户名不读。抽出之前不截断。
- 任务文字仍按 ADR 0089 成为正文。已有别的正文时仍留在 `addedText`。这个人的名字不进正文，也不改内容哈希。关键词因此不命中这个人的名字。任务编号、完成时间和嵌套的原清单不读。完成者仍按原来的主机名，排在这个人前面。本群群名不读。
- 空字符串、空数组和布尔值不读发送者。普通消息不读 `from`。投票选项不读发送者。完成和取消完成不因为这条改条件。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。`checklist_added` 仍默认关闭。8 个主机名的上限不变。不调用 `editMessageChecklist`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把这个人整段当成正文 | 关键词会命中人名。普通消息的 `from` 也会被打开。见 ADR 0495。 |
| 并进 `checklist_added` | 打开新加任务的群并不一定要按名字里的短链删。任务文字仍是正文。 |
| 连投票选项一起读发送者 | 选项文字已经是另一条提示。加任务的人只在新加任务上。 |
| 新命令 `/addedname` | 菜单只剩一个空位。现有 `links` 已经能删短链。 |

## 后果

- 新加清单任务的人，名字里出现短链、邀请或裸 IP 时，会删掉这一条。证据只有主机名。任务还在。
- 这个人的名字原文、路径和用户名不进事件，内容哈希不变。名字里的关键词不命中。
- 名的长度大于 0 时，姓和用户名不进事件。任务文字仍按原来的正文。任务里已有短链时，证据仍先记那段文字的主机名。完成者的主机名仍排在这个人前面。
- `example.com` 和公开的 `t.me/名字` 留着。付费帖仍不删除。见 ADR 0356。
- 空字符串、空数组、布尔值、投票选项和普通消息仍不读发送者。本群群名仍不读。嵌套原清单仍不读。干净的任务在 `checklist_added` 关闭时仍留下。完成和取消完成仍按 ADR 0602。云额度的基础检测器名单没有改。30 天保留期没有改。
