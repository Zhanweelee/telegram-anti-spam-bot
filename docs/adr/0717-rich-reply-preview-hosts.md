# ADR 0717：被回复的富文本预览只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

回复一条富文本时，Android 先用 `formatRichMessage` 拼出预览，把它当成这条消息的文字，再在引用条上只画前 150 个 UTF-16 码元。有说明时仍先画说明。`text` 不画。

Bot API 把这篇文章放在 `reply_to_message.rich_message`。旁边可能仍有 `text`。ADR 0711 读的是说明或 `text`，所以富文本预览里的短链会漏掉，旁边的 `text` 反而会被读进来。

置顶提示上的同一份预览只取前 20 个码元。见 ADR 0714。引用条取前 150 个。

这段预览不进正文。关键词不命中这 150 个字。

## 决策

- 当前消息会画引用条，被回复的消息有 `rich_message`，并且没有说明时，按 ADR 0714 的预览规则拼出文字，只读前 150 个 UTF-16 码元里的主机名。不再改读 `text`。
- 有说明时仍读说明的前 150 个码元，不读富文本预览。
- 图片、视频、动图、拼图、幻灯片、地图和公式占满剩下的 150 个码元，后面的块不读。表格格子不读。
- 服务公告不读。任务、选项、引用、投票、外部媒体、话题名、游戏和账单仍先占住这一行。
- 预览不进正文，内容哈希仍按当前消息自己的正文。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 仍改读 `text` | 有富文本时客户端画的是预览，不是 `text`。 |
| 整篇文章都读 | 引用条只画前 150 个码元。 |
| 有说明时两段都读 | 说明占住这一行，预览不画。 |
| 把预览抄进正文 | 关键词会命中这 150 个字。内容哈希也会变。 |

## 后果

- 被回复的富文本预览前 150 个码元里出现短链、邀请或裸 IP 时，会删掉这条回复。证据只有主机名。被回复的原消息还在。
- 第 151 个码元起的路径、`text`、表格格子和文件名不进事件。内容哈希不变。关键词不命中预览。
- 有说明时仍只读说明。服务公告仍不读这行。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
- 思考块后来由 ADR 0718 从这份预览里拿掉。气泡里的整篇文章仍读。
