# ADR 0177：裸域名和裸 IP 的问号仍属于这一段

- 状态：已接受
- 日期：2026-11-02

## 背景

Android 没有协议时，裸域名和点分 IPv4 可以接一到五位端口，以及以 `/` 或 `?` 开头的路径。`example.com?http://bit.ly/…`、`example.com:80?http://bit.ly/…` 和 `203.0.113.144?http://bit.ly/…` 都是一条链接。带协议的网址和 `www.` 已经按这个尾巴收。点号后面的路径不属于这一段：`example.com./http://bit.ly/…` 会丢掉这个点，再打开后面的短链。端口后面如果不是路径，下一段也会打开。六位数字不是端口。

## 决策

- 裸域名和裸 IP 收下 1 到 5 位端口，以及以 `/` 或 `?` 开头的路径。问号里的主机名不另记。
- 点号不跟进这段路径。后面的网址仍单独打开。
- 端口后面接不上路径时，下一段仍单独打开。六位数字不是端口。
- 第一段自己是短链或裸 IP 时，仍按现有规则删除。证据只留这一段的主机名。
- 只拆一层。最多 8 个。不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 把带协议的尾巴直接套上，连点号一起收 | `example.com./http://bit.ly` 会把后面打开的短链吞进前一段。 |
| 问号仍从裸域名上切开 | `example.com?http://bit.ly` 会删掉 Android 留成一条普通链接的消息。 |
| 端口也不收 | `example.com:80?http://bit.ly` 同样是一条链接。 |

## 后果

- `example.com?http://bit.ly/…` 和 `example.com:80?http://bit.ly/…` 留着。
- `bit.ly?http://t.co/…` 仍按短链删除。证据只有 `bit.ly`。
- `203.0.113.144?http://bit.ly/…` 仍按裸 IP 删除。证据只有这个地址。
- `example.com:80!http://bit.ly/…`、`example.com:123456-http://bit.ly/…` 和 `example.com./http://bit.ly/…` 仍删除后面的短链。
- `t.me/+…?http://bit.ly/…` 仍按邀请删除。邀请码和问号里的主机名不进证据。
- 路径里的单引号仍属于这一段。见 ADR 0178。
