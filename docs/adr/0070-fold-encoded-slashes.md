# ADR 0070：比较前把 %2F 收成斜线

- 状态：已接受
- 日期：2026-11-02

## 背景

ADR 0069 把没有协议的 `%2E` 收成点。`%2F` 仍把路径拆开。`t.me%2F+…` 只剩主机名 `t.me`，邀请正则看不到。`https://t.me%2F+…` 这种按钮地址也会让 URL 解析失败，主机名和邀请都进不了事件。

## 决策

- 新增 `foldEncodedSeparators`。它把 `%2E` / `%2e` 收成 `.`，把 `%2F` / `%2f` 收成 `/`。
- 链接检测在抽主机名前调用它。`hostFromUrl` 在 `new URL` 之前也调用它。
- `%252E` 和 `%252F` 不含这两段字符，仍原样留下。
- 只影响这次比较。正文和哈希不变。证据仍只留主机名。
- 公开用户名 `t.me/durov` 仍保留。普通域名仍保留。
- 关键词和正则仍只用 `foldMatchText`。
- 不改 ADR 0026 的基础检测器名单。不引入同形字库。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 只改没有协议的正文 | 按钮上的 `https://t.me%2F+…` 仍解析失败。 |
| 把每个 `%25` 都还原 | `%252F` 会变成斜线，两层编码的路径会被收成邀请。 |
| 放进关键词折叠 | 斜线不是格式字符。关键词不该因为 `%2F` 改变比较。 |

## 后果

- `t.me%2F+…`、`joinchat` 和按钮上的 `https://t.me%2F+…` 会记成邀请。`bit.ly%2F…` 会记成短链。
- `t.me%2Fdurov` 和 `t.me%252F+…` 仍放过。
- 邀请码不进事件。直接调用 `extractHosts` 的代码仍扫描原字符串。
