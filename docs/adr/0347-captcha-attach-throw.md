# ADR 0347：记不上按钮 id 时删掉刚发出的提示

- 状态：已接受
- 日期：2026-11-04

## 背景

验证按钮发出之后，`attachPrompt` 把 `message_id` 写进 nonce 仍然一致的那一行。写不上时返回 false，Worker 删掉刚发出的这一颗。存储调用抛错时，这个 id 还在当次请求的内存里，异常路径却只记 `captcha_prompt_failed`。按钮留在群里，挑战上没有这个 id，以后的通过、到期、离群和再发都找不到它。

## 决策

- `attachPrompt` 抛错时记 `captcha_prompt_failed`，然后删掉刚发出的这一颗。日志只有事件 id 和群 id。
- 挑战留在原处。不解除限制。
- 这次是再发时，已经记下的旧 id 不动。删的是刚发出、没写上的那一颗。
- 删除再抛错时记 `captcha_prompt_delete_failed`。按钮会留在群里。
- 返回 false 的路径不变：删掉刚发出的这一颗，不另记 `captcha_prompt_failed`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 抛错后什么都不删 | id 一离开这次请求就找不回来，按钮会一直留在群里。 |
| 抛错后解除限制并删掉挑战 | 成员可能已经看到按钮。存储只是暂时失败，挑战还在就能再发一次。 |
| 再发失败时连旧按钮一起删 | 旧 id 仍然有效。成员手里还有一颗点得中的按钮。 |

## 后果

- 存储没把新 id 写上时，刚发出的按钮会被删掉。成员仍被限制，下一次入群投递可以再发。
- 再发时，上一颗已经记下的按钮还在。
- 删除也失败时，这颗按钮留在群里，挑战上仍然没有它的 id。
- 30 天保留期不动。
