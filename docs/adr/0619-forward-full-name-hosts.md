# ADR 0619：已知用户转发抬头画出的全名只留主机名

- 状态：已接受
- 日期：2026-11-06

## 背景

群里转发一条已知用户的消息时，Android 的 `ChatMessageCell` 把抬头写成 `UserObject.getUserName`。这个名字是 `ContactsController.formatName`：名和姓都先去掉两端空白，名在前，姓接在后面。名去掉空白后是空的，就只画姓。空格后面仍画。用户名不在这行里。

Bot API 把这个用户放在 `forward_origin.type === "user"` 的 `sender_user`。没有现代来源时，旧字段是 `forward_from`。隐藏显示名仍画在另一段上。群来源画的是标题。频道标题和签名已经另有规则。

短链可以只写在姓上。名的长度大于 0 时如果丢掉姓，这条短链就留在抬头里。把整段收成正文会改变内容哈希，关键词也会命中名字。

## 决策

- `forward_origin` 是对象且 `type === "user"` 时，从 `sender_user` 会画出来的全名留主机名。名和姓都先去掉两端空白。两边都还有字时，名在前、姓在后，中间一个空格。名去掉空白后是空的，且姓去掉空白后还有字时，只读姓。两边都空时不读。空格不截断。
- 没有现代来源，且 `forward_sender_name` 不是长度大于 0 的字符串时，对 `forward_from` 用同一套全名。布尔值的 `forward_origin` 不是现代来源。
- 主机名仍进消息已有的 `hosts`。邀请仍进 `invites`。正文里已有短链时，证据仍先记正文的主机名。全名不进正文，也不改内容哈希。关键词因此不命中。
- 用户名不读。发言人 `from`、本群群名、外部回复不读。已有隐藏显示名时不读旁边的 `forward_from`。群来源仍只读标题，不读姓。频道标题和签名仍按 ADR 0610 与 ADR 0611。
- 不新增检测器，不新增命令。菜单仍是 99 条。不改 ADR 0026 的基础检测器名单。短链仍走已有的 `links`。8 个主机名的上限不变。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 继续只读名 | 客户端把姓画在同一个抬头里。姓上的短链会留在群里。 |
| 服务消息的发送者也改成全名 | 那些行用的是另一套可见名。付款成功这行仍只读名。见 ADR 0618。 |
| 连用户名一起读 | 抬头不画用户名。 |
| 新命令 `/forwardname` | 菜单只剩一个空位。现有 `links` 已经能删除短链。 |

## 后果

- 已知用户抬头里的短链、邀请或裸 IP 会删除这条消息。证据只有主机名。姓上的短链也算。
- 全名原文、路径和用户名不进事件。内容哈希不变。关键词不命中全名。
- 空白名不挡住姓。空格后面的网址仍读。名的主机名排在姓前面。
- 正文里已有短链时，证据仍先记正文的主机名。
- `example.com` 和公开的 `t.me/名字` 留下。付费帖仍不删除。见 ADR 0356。
- 隐藏显示名旁边的真实姓名、外部回复、群标题和普通发言人的名字仍不读。管理员仍豁免。云额度的基础检测器名单没有改。30 天保留期没有改。
