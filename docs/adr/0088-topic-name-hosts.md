# ADR 0088：论坛话题名里的网址只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

论坛群里新建或改名话题时，成员看见的是一条服务消息，名字在 `forum_topic_created.name` 或 `forum_topic_edited.name`。这条消息通常没有 `text` 和 `caption`。关键词和链接都看不见话题名时，短链可以只写在名字里。

把名字拼进已有正文会改变 `textSha256`。图标颜色和自定义表情 id 不是这段名字。

## 决策

- 从 `forum_topic_created.name` 和 `forum_topic_edited.name` 抽出网址，只留主机名。长度、折叠、邀请判断和 8 个主机名的上限不变。顺序是新建，然后改名。
- 已有正文时，话题名原文不进正文，也不改内容哈希。
- 没有更前面的正文时，第一段非空话题名整段成为正文，并以此计算 `textSha256`。`is_name_implicit` 不改变这一点。这条正文里的网址由链接规则从正文看见，同时也记在主机名列表里。
- 不读取 `icon_color` 和 `icon_custom_emoji_id`。没有 `name` 的改名不产生正文。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 已有正文时把话题名拼进去 | 名字会改变哈希。短链只需要主机名。 |
| `is_name_implicit` 时跳过 | 默认名字仍然显示给群成员。 |
| 把自定义表情 id 当网址 | 它是平台标识，不是用户写下的地址。 |

## 后果

- 已有正文时，话题名里的 `https://bit.ly/…` 会走现有短链删除。`https://t.me/+…` 和 `https://t.me/%2B…` 只留下 `t.me`，并记成邀请。
- 普通域名仍保留。话题名原文、路径和邀请码在已有正文时不进事件。
- 话题名成为正文时，整段名字仍参与关键词和内容哈希。
- 只改图标时，自定义表情 id 里的网址仍然不读。
- 关掉、重开、隐藏和重新显示没有话题名。某个群可以以后打开 `forum_notice`，删除这四条提示。新建和改名的名字仍成为正文。见 ADR 0485。
