# ADR 0411：私聊可以查看默认菜单按钮

- 状态：已接受
- 日期：2026-11-04

## 背景

默认菜单按钮已经可以设置。查看调用是 `getChatMenuButton`。

`chat_id` 可选。不送时返回 bot 的默认菜单按钮。某个私聊里单独设过的按钮不在这次结果里。

返回值是一个 `MenuButton`。`commands` 打开命令列表。`default` 表示没有单独指定。`web_app` 还带按钮文字和 Web App 地址。

## 决策

- 私聊命令 `/button`。没有参数。多出来的参数不发出请求。别的单词回复「参数无效」。群聊里的同样文本不执行。
- 只有配置里的管理员可以看。接入目录里的人即使管着自己的群也不能看。
- 调用 `ModerationPort.readMenuButton`。适配器调用 `getChatMenuButton`。正文是空对象。不送 `chat_id`。
- `type` 是 `commands` 时回复「菜单按钮 命令」。`default` 回复「菜单按钮 默认」。`web_app` 回复「菜单按钮 应用」。
- 按钮文字、地址和其它字段不进回复，也不进日志。
- 别的类型、空结果或非对象让整份回复变成「参数无效」。
- 没有 token 或调用失败时回复「参数无效」。日志只写 `operator_rejected`，带上 eventId、chatId 和命令名 `button`。不写异常文本、token 或原文。
- 没有 token 的 Worker 不编一个状态。
- 不调用 `setChatMenuButton`。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 查看某一个私聊的按钮 | 那要送 `chat_id`。这次只读默认按钮。 |
| 把 Web App 地址写进回复 | 地址会离开 Worker。 |
| 不认识 `web_app` 就当成失败 | 官方三种类型都是合法按钮。失败会让已经设过的按钮看起来不存在。 |

## 后果

- 成功只表示 Telegram 返回了默认菜单按钮的类型。某个私聊里单独设过的按钮不受这次查看影响。
- 一次查看是一次 Telegram 子请求。封禁、禁言和黑名单都不变。
- 30 天保留期不动。
