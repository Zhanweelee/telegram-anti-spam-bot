# ADR 0277：没有斜杠的 tg: 后面仍留下主机名

- 状态：已接受
- 日期：2026-11-03

## 背景

Android 的协议是 `tg://`，两个斜杠不能少。`tg:http://bit.ly/…` 和 `tg:203.0.113.244/…` 打开的是后面的短链或裸 IP。`tg://http://bit.ly/…` 整段是一条 `tg://` 链接，后面的短链不再打开。`tg://msg?…&to=` 里的地址也不单独抽出来。

看得见的正文已经这样切。隐藏的分享 `text` 把 `tg:` 和后面的网址收成一条，主机名停在 `tg`，短链留在路径里。

## 决策

- 分享 `text`、分享 `url`、私聊预填 `tg://msg` 的 `text` 和用户名草稿的 `text`，只有 `tg://` 盖住后面的主机名。
- 没有两个斜杠、后面紧挨着 `http://`、`https://` 或点分 IPv4 时，从协议后面另抽网址。
- `tg:join?invite=` 仍按邀请读取。`tg:https://t.me/+…` 按它自己的邀请读取。
- `tg://` 里面的 `text`、`url` 和代理参数仍按原来的规则读。`to=` 不单独抽主机名。
- 前面紧挨着字母、数字或下划线的 `tg:` 不在这里切开。
- 路径和邀请码不进证据。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 所有 `tg:` 都盖住内部地址 | `tg:http://bit.ly` 点得开的是 `bit.ly`。 |
| `tg://` 也切开 | `tg://http://bit.ly` 打开的是 `tg://http`，不是后面的短链。 |
| 没有斜杠的 `tg:join` 不再记邀请 | 这条深链本来就会打开邀请。 |

## 后果

- `t.me/share/url?text=tg:http://bit.ly/…`、`see tg:http://t.co/…` 和 `tg:203.0.113.244/…` 删除。证据仍只有主机名。
- 分享 `url` 里的 `tg:http://bit.ly/…` 同样删除。
- `tg://http://bit.ly/…` 和 `tg://203.0.113.244/…` 留着。`tg://msg?…&to=` 不因为这个参数删除。
- `tg:join?invite=…` 和 `tg:https://t.me/+…` 仍按邀请删除。邀请码和路径不进证据。
