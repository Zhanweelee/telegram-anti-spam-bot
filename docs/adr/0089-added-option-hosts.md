# ADR 0089：后加选项和清单任务里的网址只留主机名

- 状态：已接受
- 日期：2026-11-02

## 背景

投票允许补选项时，新选项以 `poll_option_added` 到达。删掉选项时，`poll_option_deleted` 仍带上那段选项文字。清单允许别人补任务时，新任务在 `checklist_tasks_added.tasks`。这些都是服务消息，通常没有 `text` 和 `caption`。原来的投票或清单已经扫过，后加的文字还没有。

把后加文字拼进已有正文会改变 `textSha256`。`poll_message` 和 `checklist_message` 是已经送达过的原消息。选项 id、任务 id 和完成者名字不是这段文字。

## 决策

- 从 `poll_option_added.option_text`、`poll_option_deleted.option_text` 和 `checklist_tasks_added.tasks[].text` 抽出网址，并读取同一处的 `text_link`。只留主机名。长度、折叠、邀请判断和 8 个主机名的上限不变。顺序是新选项、被删选项，然后按任务数组顺序。
- 已有正文时，这些原文不进正文，也不改内容哈希。
- 没有更前面的正文时，第一段非空选项文字成为正文。没有选项文字时，非空任务文字用一个普通空格拼成正文，并以此计算 `textSha256`。
- 不读取 `poll_message`、`checklist_message`、`option_persistent_id`、任务 id、`completed_by_user` 和 `completed_by_chat`。
- 不新增检测器。不改 ADR 0026 的基础检测器名单。

## 备选

| 方案 | 放弃原因 |
| --- | --- |
| 已有正文时把后加文字拼进去 | 后加文字会改变哈希。短链只需要主机名。 |
| 连原消息一起再扫一遍 | 原消息自己的更新已经扫过。嵌套对象会把旧地址再算一次。 |
| 被删选项不读 | 删除服务消息仍然把选项文字显示给群成员。 |

## 后果

- 已有正文时，后加选项或任务里的 `https://bit.ly/…` 会走现有短链删除。`https://t.me/+…` 和 `https://t.me/%2B…` 只留下 `t.me`，并记成邀请。
- 普通域名仍保留。后加原文、路径和邀请码在已有正文时不进事件。
- 后加文字成为正文时，整段文字仍参与关键词和内容哈希。
- 原消息和选项 id 里的网址仍然不读。完成者画出的名字后来由 ADR 0578 只留下主机名。
- 标成完成或取消完成时没有新文字。删除这两种提示不会改任务状态，新加的任务文字仍成为正文。见 ADR 0489。
- 名字干净的后加选项和删除选项仍留下。某个群可以以后打开 `poll_notice`，把这两种服务消息删掉。选项编号和原投票仍不进事件。见 ADR 0494。
- 名字干净的新加清单任务仍留下。某个群可以以后打开 `checklist_added`，把这种服务消息删掉。任务编号、完成者名字和原清单仍不进事件。打开 `checklist_notice` 仍不删除新加的任务。见 ADR 0495。
- 已有别的正文时，后加选项和任务后来由 ADR 0552 另留在 `addedText`。关键词和默认正则可以删除。编号、原消息和完成者仍不进事件。
- 新加任务四条起，后来由 ADR 0660 只读前三条。第四条起的文字、文字链接和完成者不读。三条及以内仍全部读。清单自己的任务不受影响。画出的任务上，文字链接的起点后来由 ADR 0727 必须小于这条任务文字。投票选项仍读全部文字链接。
- 后加或删除的选项上，文字链接的起点后来由 ADR 0731 必须小于这条选项文字。选项不是字符串时仍按原来的方式读取。投票描述仍读全部文字链接。
